#### Major

- `agents/pm-spec.md:70` / T-1043's frozen `K2` block (`.shell-team/specs/T-1043-pm-spec-check-conventions.md:54`) — The #186 amendment's new second-choice alternative, `git ls-files -z -- '<pathspec>' | xargs -0 grep -n -- '<pattern>'`, is unsound when used (as K2's own surrounding prose implies) as a **negated absence** assertion over a large tracked-file population. When `git ls-files -z | xargs -0` splits the population into multiple `grep` batches, one batch containing the forbidden pattern exits 0 while a separate, pattern-free batch exits 1 (no match); GNU `xargs` reports the aggregate exit as nonzero whenever *any* batch is nonzero. Negating that aggregate (the idiomatic `! ... | xargs ... grep -q ...` construction an absence criterion needs) therefore reports "absence" even when the forbidden pattern genuinely occurs in the tracked set — a false pass on exactly the failure mode this bullet exists to prevent. Reproduced directly by the adversarial Codex pass by forcing a one-file-per-batch split with one matching and one non-matching file: negation incorrectly succeeded. This alternative is new in this diff — the superseded `O186` text never offered it, only `--include`. Fix: drop the `xargs` alternative from K2's prose (keep `git grep -n -- pattern -- pathspec`, which does not have this failure mode, as the sole tracked-file-enumeration form), or state the caveat and the aggregation-safe construction explicitly. Note for context: this exact `xargs` shape was literally issue #186's own suggested fix text, not something pm-spec invented independently — the defect predates this task but is shipped for the first time here.
- Same location — The same `xargs` alternative also dereferences a tracked **symlink** operand: `git ls-files` correctly lists a tracked symlink's own path, but the external `grep` invoked by `xargs` follows the link and reads whatever it points to, which can be untracked or gitignored content. This directly contradicts K2's own stated rationale for preferring this form — "a tracked-file enumeration cannot reach an untracked or gitignored file at all" — which is true of `git grep` but false of `git ls-files | xargs grep` in the presence of a tracked symlink. Confirmed live by the adversarial pass with a constructed symlink test. Same fix as above.
