#### Major

- `bin/check-refreeze-grant.sh:148-155, 170-198` — An empty string passed to `--base` or `--config` (e.g. `--base ""`) is indistinguishable from the flag never having been given: the presence test is `[ -n "$BASE_ARG" ]` / `[ -n "$CONFIG_ARG" ]`, so `--base ""` silently falls through to `$TEAM_REFREEZE_GRANT_BASE` / `team-paths.sh --get base`, and `--config ""` silently falls through to the `--base` resolution path. Both Codex passes independently identified this. It sits squarely inside the spec's own declared threat model (Non-goal / Input-space item 2: "the operator and the working directory are trusted... what is defended against is accidents, typos and stale upgrades") — an empty-string operand from a caller's own broken variable expansion is exactly that class of accident, and a caller who intended to point the reader at an isolated scratch base (a test harness, say) could silently get the real repository's base dir or an environment override instead. It does not break D-3's core safety property (no input still resolves to a grant except *some* conformant declaration), so this is not a Blocker, but it is a genuine correctness gap in argument handling on a privilege-relevant script. Mitigating context: this is not a novel defect — `bin/check-oversight.sh:205-212`/`:237-246` (the sibling this task's own Notes for engineer name to copy "member for member") carries the byte-for-byte identical presence-test pattern, unaddressed there too, and the shipped consumer (`skills/run/SKILL.md`) never passes `--base`/`--config` at all (confirmed by the fixture suite's own item-8 assertion and by direct read). See Fast-follow disposition below.
- `tests/check-refreeze-grant/run.sh:167-177` — When the suite runs as root, the unreadable-regular-file branch prints `pass "occupancy: unreadable-file case skipped (running as root defeats chmod 000)"` instead of failing, so a root-run CI would see this CI-wired, full-consumer-class suite report full success without ever exercising one of AC4's thirteen never-dropped refusal shapes. This is the opposite of the design principle the spec's own AC4 text states for exactly this scenario ("a run as a user who can read everything is reported rather than silently reducing coverage") — the spec's own inline check-acs criterion for AC4 does fail hard under root (`test ! -r ... || exit 1`), so the never-dropped safety property is not silently masked end-to-end (an independent, required verification path — `check-acs`'s own AC4 — still catches a root-run environment), but the shipped fixture suite's own AC10 contract ("the fixture suite exists, passes, covers the never-dropped shapes by name") is weakened for this one shape under root, a real scenario for adopters running root containers even though this repository's own current CI runner is non-root. Both Codex passes independently flagged this.
