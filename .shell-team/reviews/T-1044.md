## Major

- **`tests/scratch-root-hygiene/run.sh:96-105`** — a tracked `tests/` entry that `git ls-files` reports but is missing, unreadable, or non-regular on disk (e.g. a locally deleted-but-unstaged tracked file, a permissions accident, a submodule/gitlink-as-directory) is silently `continue`'d past: `n_total` still counts it, but its content is never scanned and it contributes `0` to `n_bad`. A real fixed-scratch-root violation in that exact file would pass undetected. This is a genuine fail-open path in a suite whose own design principle (DP2's population-source failure closes; DP8's per-file scan is meant to be exhaustive over "every tracked file under tests/") does not extend the same fail-closed discipline to the per-entry read. Not covered by any Input-space out-of-scope bullet — "Untracked files under `tests/`" names a different class (extra files, not missing tracked ones). Fix: treat `[ -r "$f" ]` failure or a `cat` failure as a suite failure (or at minimum decrement `n_total`/report it explicitly), not a silent skip that still counts toward the population size printed in the pass message.
- **`tests/scratch-root-hygiene/run.sh:70-80`, specifically the trailing `grep -vc 'mktemp'`** — the `mktemp` exemption is an unanchored substring test over the whole line, not a check that the line's own assignment invokes `mktemp`. Empirically confirmed: a line such as `TMP="$HERE/tmp-fixed-example" # migrated away from mktemp, revert if flaky` matches `FSR_HERE`, but is then silently exempted because the word "mktemp" appears anywhere on the same line — even inside a trailing, non-code comment fragment on a code line (this is distinct from the already-excluded full-line-comment case). I grepped the current corpus and found no line today that accidentally triggers this (so AC8's HEAD sweep is not currently compromised), but this is exactly the "what mutation would this rule be blind to" question DP10 calls for: a future edit that reverts a converted site back to a fixed root while leaving (or adding) an inline comment mentioning "mktemp" nearby on the same physical line defeats the lock silently, with no red anywhere. Fix: require `mktemp` to appear as the invoked command on the right-hand side of the assignment (e.g. anchor on `=\"\\\$\\(mktemp` or equivalent), not merely as a substring anywhere on the line.
