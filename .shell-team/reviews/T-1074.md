#### Major
- `bin/aggregate-verdicts.sh:398-410` — The sentinel-exclusivity check (Phase 2e) only tests `v==0 && s==0` (→ `missing-sentinel`) and `v>0 && s>0` (→ `sentinel-with-verdicts`). It never tests `s>1` with `v==0`. **Reproduced live**: a part carrying two `- sentinel: u2 — exit=2 no-verdict-lines` lines for the same claimed, zero-verdict unit, with no verdict line, aggregates at **exit 0** and the printed `verdict-region` carries the sentinel line twice (`- summary: units: 2 — verdicts: 1 — sentinels: 2`). D3 states a zero-verdict unit "carries **exactly one** `- sentinel:` line" — this is a real, silent violation of that requirement and of the tool's own header claim ("no partial, incomplete or malformed verdict is ever promoted"). Class lineage: not gated by any of the 19 frozen ACs (AC4/AC8/AC9 test missing-sentinel and sentinel-with-verdicts, never duplicate-sentinel-alone) — fixable at the implementation level using the existing closed 13-token vocabulary (an interpretive classification choice, recorded via provenance, the same way the "unreadable `--population` file → `usage` not `empty-population`" ambiguity was already resolved for this task) — **does not require touching any frozen `- check:` line or the D6 prose**, so this is a rework item, not a freeze-conflict escalation.
- `bin/aggregate-verdicts.sh` (blank-line filter at line 238/278, checked against `has_control_char` immediately after) — A line consisting **solely** of whitespace (e.g. one literal TAB, or a form-feed) matches the "blank line" filter `grep -v '^[[:space:]]*$'` and is stripped **before** `has_control_char` ever inspects it, so it never reaches the `control-character` refusal. **Reproduced live**: a part file with a valid `- unit:`/`- verdict:` sequence plus one line containing only a TAB aggregates at exit 0, silently dropping the offending line rather than refusing. The Input space's own reachable/out-of-scope split treats "any control character" as unconditionally refused (`control-character`) with no whitespace-only carve-out, so this is a genuine narrowing of that promise. Not gated by AC6 (whose fixture embeds the TAB *inside* a valid-shaped `- verdict:` line, never as a standalone whitespace-only line). Fixable purely at the implementation level (validate control characters before, not after, the blank-line filter, or narrow "blank" to strictly zero-length) — no frozen check line or D6 prose is touched.

- `tests/aggregate-verdicts/run.sh:36` — The suite's own top-level `mktemp -d` assignment (`T="$(mktemp -d ...)"`) is unguarded; a setup failure would exit via `set -e` before any `PASS:`/`FAIL:` line is printed. CI would still fail (fail-closed), just without a legible suite-level diagnostic.
