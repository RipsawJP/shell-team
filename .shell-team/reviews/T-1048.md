#### Blockers

- `bin/close-out.sh:112-131` (`_abspath()`'s symlink-blind canonicalization defeats the divergence check it exists to run) — `_abspath()` canonicalizes a path by `cd`-ing into its `dirname` and appending its `basename`, explicitly disclaiming symlink resolution as "unnecessary" under the TRUSTED-operator threat model (its own comment, lines 121-122). That disclaimer is wrong for a reason that has nothing to do with defeating a hostile operator: Bash's builtin `cd` resolves `..` **logically** (lexically, against `$PWD`'s string), while the real file the OS opens when close-out.sh later reads/writes `$BOARD="$TEAM_TODO"` (the *same* raw override string, used verbatim for the actual file I/O, not the canonicalized form) is resolved **physically** by the kernel, following any symlink component before applying `..`. When an override path contains an ordinary symlink followed by `..` — a completely mundane, non-adversarial shell idiom (e.g. `"$(some_dir)/../record"`, the same shape this repo's own scripts use for `SCRIPT_DIR/..`-relative resolution) — the two resolutions diverge, and `_abspath` reports **no divergence** even though the real file differs.
