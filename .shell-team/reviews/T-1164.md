#### Blockers
- bin/check-setup.sh:188 — N1 (zero writes outside the temp dir) is defeated on the Codex CLI host path. Measured on macOS bash 3.2.57 (`/bin/bash`): a here-string creates its temp file in the current directory even with TMPDIR set (`cat <<< x` in a mode-555 directory fails with "cannot create temp file for here document: Permission denied"). The comparator reaches here-strings (bin/resolve-executor.sh:234, :240, :247, :256, :388, :409, :435; bin/gen-codex-agents.sh:310) with the caller's cwd, which is the repository root or a subdirectory of it. Measured consequence: a complete Codex setup exits 0 from a writable cwd and exits 2 from a read-only repository root, with the message "executor binding did not resolve" (a false stop that names neither cause nor remedy). The tree is byte-identical afterwards, so AC7's checksum listing cannot see it (tests/check-setup/run.sh:194). The outcome is fail-closed, not a false pass, but it is a runtime write into the repository by the checker's call chain under a never-dropped, no-carve-out criterion. Fix (stays inside bin/check-setup.sh, which AC14 does not protect): run the comparator in a subshell whose cwd is a scratch directory under the temp dir, and pin `TEAM_RUN_BASE` to the absolute resolved base for that call (see the first Major: a bare cwd change is not equivalent); add a fixture that runs the Codex path from a mode-555 repository root and expects exit 0 plus an in-sync report.

#### Major
- bin/check-setup.sh:188 — the comparator result depends on the invoking cwd, so the checker can report "in sync" where the same repository run from its root reports drift. bin/resolve-executor.sh:295 resolves the base from the cwd (`team-paths.sh --get base` with no root), so its host `binding.conf` is looked up under the cwd. Measured: with a host `binding.conf` present in a Codex-set-up repository, the checker run from the repository root exits 1 (drift), and run from `sub/d` exits 0; the same split appears with a binding that makes resolution refuse (root exits 2, a non-git scratch cwd exits 0). A run started from a subdirectory therefore never sees the host binding and fails open. The existing subdirectory case (tests/check-setup/run.sh:178) passes only because the fixture has no host binding. This also shows the naive form of the Blocker fix (a scratch cwd alone) would hide a binding refusal; pinning `TEAM_RUN_BASE` to the absolute base makes the scratch-cwd result equal to the root result (measured: exit 2 in both).
- agents/code-reviewer.md:24 — the review-transfer text states what is sent inaccurately, in two directions. It says it covers "every `codex exec` block", but the spec-review block (agents/code-reviewer.md:191) sends no diff, only the spec document. And for the diff passes it understates the payload: the reviewer is told to let Codex read the real files itself, under a read-only repository-rooted sandbox, so any file in the repository can be read, not only the `<base>...HEAD` diff, the spec and the hand-offs. A text whose purpose is to let the operator approve with the payload named should not narrow it. The same understatement is in templates/prompt-blocks/host-dispatch.md:17 and its copy in skills/run/SKILL.md (the `claude -p` pass has Read, Grep and Glob over the repository). Fix: name the diff, the spec and hand-offs as the intended payload and state that the reviewer may read other files in the repository; scope the first sentence to the passes that send a diff, or add the spec-review pass's own payload. This is wording inside frozen decision 8 (spec line 69-71), so the coordinating session decides whether it is a re-freeze.
