#### Domain-premise findings (mandate item 1 — is the checker's trust argument sound)

#### Verification of round 1's three Majors

1. **Major 1 (stem misses case/width variants) — CLOSED.** The frozen collect-wide stem at **AC3** is now byte-pinned to `^[[:space:]]*-[[:space:]]+[Cc][Oo][Uu][Nn][Tt][[:space:]]*(:|：)[[:space:]]*`: case tolerance spelled as explicit ASCII character alternatives (never `grep -i`, which would leak into every other pattern the file matches), and colon tolerance spelled as an **alternation** `(:|：)` rather than a bracket expression. The stated reason — that under `LC_ALL=C` a bracket expression containing the three-byte UTF-8 sequence for U+FF1A (`0xEF 0xBC 0x9A`) decomposes it into individual bytes and would then match a lone byte, whereas an alternation of a one-byte and a three-byte alternative does not — is technically sound POSIX bracket-expression semantics under a byte-oriented C/POSIX locale (confirmed independently by reasoning about POSIX bracket-expression collating-element rules; a local macOS/BSD `grep` did not reproduce the decomposition in a quick empirical probe, but the claim is about GNU grep under `LC_ALL=C` on the CI/Linux hosts this loop actually runs on, and the byte-decomposition behavior for a bracket expression containing a raw multibyte sequence under `C` locale is well-documented GNU grep behavior, not a claim this round found reason to doubt). The strict grammar is unchanged (lowercase `count`, ASCII colon, exactly one space), so every shape the widened stem newly collects is still refused rather than accepted. **AC3**'s fixture list now includes both `- Count: sites — 6 — command: printf 6` and `- count： sites — 6 — command: printf 6` as required exit-`1` cases, exactly the two shapes round 1 measured as falling through. #### The fix's own self-caught side effect — remedy-message idiom

The engineer's fix commit correctly identifies that enabling `pipefail` breaks the pre-existing `grep -c pattern file | wc -l` remedy for a legitimate zero-match measurement, and changes both the header comment (`:62`-`:73`) and the runtime failure message (`:296`-`:298`) to point at `(grep zzz file || true) | wc -l` (no `-c`, `|| true`-guarded) instead. - `grep zzz file | wc -l` (no `-c`, **no** `|| true` guard) → prints `0` but **exits `1`** (grep's own exit-1-on-no-match status propagates through `pipefail`; `wc -l`'s own exit `0` does not clear it).
