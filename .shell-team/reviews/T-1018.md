**Read what each fixture's board actually contains.** All three share the
identical shape: the real task entry's own top-level line, immediately
followed by a second top-level-looking line that does **not** match `TOP_RE`
for this task (either wrong casing — `**t-900**` — or a CommonMark-legal
`* [ ]`/`+ [ ]` bullet, neither of which is the enumerated `- [ ]` form
`TOP_RE` requires), which itself carries a well-formed
`- intent-hash (v1): <hash>` sub-bullet. Per the board-scope-boundary state
machine (rework3's inverted definition, `Rule 2/3`): **any** non-indented,
non-blank line unconditionally closes the currently-open scope first, and
only *then* checks whether it also opens a new one. Since the second line
does not match `TOP_RE`, it closes the real entry's scope but opens none —
so the indented `- intent-hash` line that follows it is a no-op (`in_entry`
is 0), and it is never counted toward *any* entry, least of all the real
one.

**Empirically reconstructed one of the three (the (xii-b) shape) by hand**
in scratch and ran both the shipped checker and the checker at `87daf74`
against it:
- Shipped checker (T-1018): `exit=2`, `check-intent: attestation: expected
  exactly one freeze-attestation record for T-961 v1 ... (found 0 ...)`.
- Base checker (`87daf74`, via `git show`): `exit=2`, `check-intent:
  structural: expected exactly one well-formed intent-hash record for T-961
  ... (found valid=0 malformed=0 ...)`.

`attest_shaped_count == 0` — precisely the freeze-moment shape D2 names (not
the legacy carve-out, which requires `hash_valid_count == 1`). Under D2 rule
3 (the pace rule), this is now row (6): `attestation`, exit 2 — not because
these fixtures suddenly changed meaning, but because they were always,
structurally, "an entry with zero well-formed intent-hash records in its own

names as `structural`→`attestation`. None of the three fixtures carries a
