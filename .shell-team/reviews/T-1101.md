#### Major

- `bin/check-pii-shapes.sh` — `RE_HOME_ENCODED='[-_](Users|home)[-_][A-Za-z][A-Za-z0-9_.]{2,}[-_]'` — this is a genuine, reproduced coverage gap against the round's own explicit question ("does the new pattern fire on the leak's whole shape family, not only the one spelling this machine's own generator emits"). The name-continuation class requires the first character to be an ASCII letter and the whole name to run at least 3 characters before the closing separator can be reached. Two independent, live-reproduced consequences: (1) a short account name (2 characters or fewer, e.g. `-Users-<ab>-`, or a hyphenated name whose first component is under 3 characters, e.g. `-Users-<a-b>-`) is silently not detected; (2) a name beginning with a digit or underscore (e.g. `-Users-<1234>-`, or `-Users-<_www>-` — the real macOS system-account naming convention) is silently not detected, because the class requires `[A-Za-z]` first. Both were confirmed live in a scratch fixture (`bash bin/check-pii-shapes.sh --base <scratch-base>` against `-Users-<a-b>-`, `-Users-<_www>-`, `-Users-<1234>-`: all three exit 0 clean, while a control line with a ≥3-char letter-led name at the same position fires correctly). This matters because the already-shipped sibling rule for the *same* conceptual class — `RE_HOME_PATH_RAW='/(Users|home)/[A-Za-z0-9_.-]+'`, the slash-delimited form — has no such length floor and no such leading-character restriction; the new encoded-form rule is measurably less capable than the rule it is meant to extend coverage alongside, for account-name shapes that are common in practice (short names, and the leading-underscore system-account convention) rather than synthetic extremes. Neither gap is named in the spec's `## Input space` out-of-scope list (which excludes undashed-hex UUIDs, non-`-`/`_` separators, non-ASCII names, and unusual root-word case — not short/digit/underscore-led ASCII names), and neither is documented as a declared limitation in `docs/pii-controls.md`/`.ja.md`. Suggested fix: broaden the name-continuation class to match the shipped `home-path` rule's own `[A-Za-z0-9_.-]+`-shaped tolerance (adjusted to still exclude the encoding separator itself from the continuation class, and to keep the `<`/`>` exclusion that makes the placeholder form a non-match), and add regression fixtures for a short name and a leading-underscore/leading-digit name.

#### Minor / nits

- `bin/check-pii-shapes.sh` — `RE_TEMP_SESSION_ROOT='(/private/tmp/|/tmp/|/var/folders/)[A-Za-z0-9_./-]*'` — the prefix character class between the temp root and the UUID excludes some rare-but-possible path characters (e.g. `=`, an embedded space), so a temp/session path whose intermediate directory component contains one of those would not be detected even though it carries a genuine UUID under a documented root. Confirmed live: `/var/folders/xy=z/<uuid>` is not reported. Kept at Minor rather than Major because no `mktemp`-style generator in this repository's own reach produces such characters (this repository's own suites build their work roots from `${TMPDIR:-/tmp}`/`mktemp`, which never emit `=` or whitespace), and the negative-control population measured in this task's own `## Blast radius` (thirteen `/private/tmp/` citations across five files) carries none of these characters either — so the gap is real but currently has no live carrier and a low-probability future one. Worth a documented limitation or a small widening in a follow-up, not a merge blocker on its own.
