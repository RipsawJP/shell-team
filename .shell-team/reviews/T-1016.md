#### Blockers

- `bin/check-handoff.sh:110-128`(TASK_LINE_RE と format-validation ゲートの強度不一致)— 新設のストランド検知が、D4「一つの欠陥に一つのメッセージ」という凍結済み Settled Decision に違反する形で、実際に再現できるカスケード誤検知を起こす。`TASK_LINE_RE='^- \[[x ]\] '`（チェックボックス閉じ括弧の直後に半角スペースを要求）は、フォーマット検証を発火させる緩いリテラルプレフィクス判定 `content != "- [ ]"* `より厳格。閉じ括弧の直後にスペースが無いトップレベル行（例: `- [ ]broken title`）は `in_entry` を 1 にできないため、その行自身の正当な継続行（サブバレット）が軒並み「stranded continuation line」として誤検知される。チェック済みタスク行（`- [x]done ...`）の場合はさらに悪く、フォーマット検証自体が発火しない（`"- [ ]"*` は unchecked 行にしか適用されないため）ので、根本原因の行に一切メッセージが出ないまま、正当な子行だけがストランド扱いされる。両方とも実機で再現済み（下記 fixture）。この入力形状は spec の Input space に "A malformed top-level line (a `- [ ]` line that fails `LINE_RE`) followed by its own continuation lines" として明示的に reachable と宣言されており、out-of-input-space の対象ではない。
  - 再現コマンド（unchecked 版）:
    ```
    printf '# Tasks\n\n## Active\n\n- [ ]broken no space after bracket\n  - a note under the malformed line\n  - another note\n\n## Done\n' > fixture.md
    bash bin/check-handoff.sh fixture.md
    ```
    実際の出力: `:5: format mismatch: ...` に続けて `:6:`/`:7:` の 2 行が誤って `stranded continuation line` として出る（正しくは format mismatch 1 件のみのはず）。
  - 再現コマンド（checked 版、根本原因メッセージ皆無）:
    ```
    printf '# Tasks\n\n## Active\n\n- [x]done no space after bracket\n  - a closed note\n\n## Done\n' > fixture2.md
    bash bin/check-handoff.sh fixture2.md
    ```
    実際の出力: `:6: stranded continuation line ...` の 1 行のみ。`- [x]done...` 自体へのメッセージは一切出ない。
  - suggestion: エントリを開く判定に使う正規表現を、フォーマット検証の対象選定と揃った緩い形（例: `^- \[[x ]\]` — 末尾スペース不要）にするか、両者を同じ土台（例えば既存の `"- [ ]"*` プレフィックス＋ `- \[x\]` チェック済み版を包含する共通述語）から導出する。合わせて、`tests/check-handoff/fixtures/bad-format.md` に子行を持つ malformed トップレベル行のケースを追加し、「stranded continuation line が 0 件」を明示的に assert する回帰テストを足す（下記 Major 参照）。
