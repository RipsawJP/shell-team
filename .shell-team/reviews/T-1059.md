#### Major
- `CLAUDE.md:36` — the reviewer working-rule bullet says `codex-reviewer` "ships bound to the Codex CLI in `binding.conf`". That is not where the shipped default lives: `bin/resolve-executor.sh` reads `$BASE_DIR/binding.conf` (a host-authored override) only when that file exists, and otherwise resolves the plugin-shipped default from `templates/binding-default.conf` (`bin/resolve-executor.sh:319-325`; `templates/binding-default.conf`'s own header comment: "consumed by `bin/resolve-executor.sh` when no host-authored `<base>/binding.conf` exists"). The sentence's second half ("A host may rebind `codex-reviewer` ... in its own `binding.conf`") is correct — that really is what an override does — but the first half misattributes the *default* binding to the *override* file. The sibling apply-sites avoid exactly this error: README.md:208 and both `AGENTS.md` copies say "`codex-reviewer` ships bound to Codex CLI" with no file name attached, then separately name `binding.conf` only as the host-authored rebind path. CLAUDE.md is the one apply site that names `binding.conf` for AC1's literal-presence check, and in doing so introduces a factual inaccuracy the other four sites do not have. This lands squarely inside this round's primary judgment target: element (a)/(c) of DP2 is "the shipped default" and "what a rebind changes" respectively, and misnaming the file the default lives in blurs exactly that line, on the single highest-trust surface in the repository (`CLAUDE.md`'s own Security invariant section calls it "a trusted instruction channel"). Fix is a one-line rewording, e.g. "ships bound to the Codex CLI in the plugin's shipped `templates/binding-default.conf`... A host may override this in its own `<base>/binding.conf`" — which still satisfies AC1's literal `binding.conf` check while being accurate.
