Sibling scripts sampled for comparison (`bin/check-binding.sh`) print a caller-supplied `$CONFIG` value back (relative unless the caller passes an absolute path), not a value the script itself resolves to an absolute path by design — this checker's own `$SCRIPT_DIR`-relative default resolution (DP-10) is what turns an ordinary echo-back into an absolute-path emission on the no-argument path CI actually exercises. Not a defect in the checker's own logic (nothing here is user-controlled input, and no AC governs the `ok:` message's content), but a latent transcription-hygiene risk with a cheap fix (print the resolved conf path relative to the repository root, or omit it from the success line entirely, leaving it in a `--verbose`-only or debug channel if it is needed at all).
