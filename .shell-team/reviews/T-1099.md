#### Blockers
- `bin/check-board-headings.sh` (the `other_dupes=$(awk -F'\t' '$1 == "OTHER" { print $2 }' "$HEADINGS_LOG" | sort | uniq -d)` line and its `[ -n "$other_dupes" ]` guard, in the structural-heading block added after `extract_ids_to_file`) — two headings whose normalized identity is the empty string (the bare-`##` form the spec's own Input space names as reachable class 6, e.g. two `##` lines each followed by prose) silently pass instead of failing the at-most-once rule. `log_heading("OTHER", "")` writes a bare `OTHER` line (no tab) for an empty identity; `uniq -d` on two such empty identities emits a single blank duplicate line; bash command substitution strips an all-blank-lines result down to the empty string, so `[ -n "$other_dupes" ]` is false and `emit` is never called. Reproduced directly: a board with two bare `##` sections plus one legitimate `## Active`/`## Done` pair exits **0** against the real, shipped `bin/check-board-headings.sh` — the exact silent-pass class this task and `CLAUDE.md` both exist to forbid, on the exact assertion (AC8's at-most-once rule) this task adds. Suggested fix: encode a non-empty sentinel for the empty-identity case before the `sort | uniq -d` pipeline (or count duplicates by comparing adjacent identical lines including blanks, rather than trusting a raw command-substitution truthiness test on the tail output).

#### Major
- `bin/check-board-headings.sh` (`log_heading()`'s `tag "\t" ident` write, and the paired `awk -F'\t' '{print $2}'` read in the structural-heading block) — two textually **distinct** headings whose titles share a common prefix up to an internal literal tab byte (e.g. `## Foo<TAB>Bar` vs `## Foo<TAB>Baz`) are falsely reported as duplicates, because the tab-delimited log format truncates the read-back identity at the identity's own first internal tab. This directly contradicts decision (b)'s own stated identity rule ("internal whitespace preserved literally... `## Active Backlog` and `## Active###` stay distinct"). Reproduced directly: such a board exits **1** with `duplicate structural heading: Foo` against the real script, for two headings that are not duplicates. Lower likelihood than the Blocker (a heading title containing a literal tab is unusual) but a real false-positive that would block a legitimate PR. Suggested fix: pick a log delimiter that cannot appear in a heading identity (e.g. a control byte awk can write/read unambiguously, or NUL-separated records), consistent with the file's own stated reason for choosing `awk -F'\t'` over `grep` in the first place (portability, not correctness against embedded delimiters).
