#### Blockers
- bin/team-commit.sh:231-267 (found by the reviewer's own probe; neither Codex pass reported it) — a directory that replaces a tracked file lets a requested path carry a deletion of that file. Setup: HEAD tracks a regular file `a`; the work tree has `a` moved away and a new directory `a/` holding `b.txt`; request `-- a/b.txt`, no hook involved. Every precondition passes (no leading directory is a symlink or nested repository; `git ls-tree HEAD -- a/b.txt` is empty so the path is treated as new; `git diff --raw -- a/b.txt` is empty). `git add -- a/b.txt` then replaces the `a` index entry, and the commit contains `D a` and `A a/b.txt`; verification catches it afterwards (exit 3, "D:a") but the commit is kept. Measured: exit 3, `git show --name-status HEAD` lists `D a` and `A a/b.txt`. This is a deletion reaching a commit through a requested path with the preflight green, defeating never-dropped N1 and the Goal's "no deletion" guarantee. Suggested fix: refuse in preflight when any proper leading directory prefix of a requested path is tracked in HEAD as a non-tree entry (`git ls-tree HEAD -- <prefix>` returning a blob or gitlink), and add a fixture; consider also comparing `git diff --cached --raw` with the requested set after `git add` and before `git commit`, refusing without committing on any entry beyond the requested paths.

#### Major
- bin/team-commit.sh:174 (found by the reviewer's own probe; neither Codex pass reported it) — the strict-empty-index precondition can be defeated by repository configuration. `git diff --cached --quiet --no-renames` honours `diff.ignoreSubmodules` (and a `.gitmodules` `ignore` setting): with `diff.ignoreSubmodules=all` and a pre-staged gitlink `sub`, the command exits 0, the script proceeds, and `git commit` commits the unrelated staged gitlink beside the requested file. Measured: exit 3, the new commit lists `README` and `sub` (mode 160000). The script itself stages only what was requested, but it commits anything already staged that the config hides, contrary to "commits exactly the requested paths". Suggested fix: add `--ignore-submodules=none` to the index check (or use `git diff-index --cached --quiet --ignore-submodules=none HEAD`), with a fixture that sets `diff.ignoreSubmodules=all`.
- bin/team-commit.sh:356-359 — primary pass P2 normalized to major, confirmed by the reviewer's probe. Verification accepts the old and new modes independently, so a hook that stages a mode change on a requested tracked file (`git update-index --chmod=+x README`) yields exit 0 and a printed SHA, although the contract refuses mode changes. Measured: exit 0, commit raw entry `100644 100755 ... M README`. Suggested fix: for status `M`, require old mode equal to new mode (and equal to the mode the preflight recorded); fixture `post-mismatch-mode`.
- tests/team-commit/run.sh:511-543 and bin/team-commit.sh:303 — adversarial pass: **blocker** ("hooks can commit forbidden changes and execute other commands"; a hook that stages a removal gives a kept commit holding the deletion, exit 3; a post-commit hook can run another commit). The reviewer prices this lower, at major: frozen decision 5 says hooks run normally and decision 6 (D4) says a mismatch is reported and never undone; it is the briefing's named open risk (2); a repository's own hook is the operator's trusted code, and the script cannot sandbox it. It stays at least major because the shipped guarantee "never a deletion" is then true only of what the script stages, and exit 3 is loud but the deletion is already committed. The coordinating session decides whether to accept the frozen risk, to pre-validate the staged set between `git add` and `git commit` (which does not stop a pre-commit hook mutating the index afterwards), or to state in the docs that hook behaviour is trusted.
- bin/team-commit.sh:231, 298, 303 — adversarial pass: **blocker** (preflight checks race with the writes: a requested file swapped for a symlink or directory, or an unrelated path staged, after preflight is committed; the post-check runs only afterwards and keeps the commit). It is held at major by the briefing's floor (anything other than the requested regular files committed); a snapshot-bound fix is not available in plain git and the reviewer does not require one.
- bin/team-commit.sh:149-152 — adversarial pass: major, the briefing's named open risk (1), agreed. `GIT_CONFIG_COUNT` set (the Claude Code sandbox exports it with `safe.directory` pairs) refuses every invocation with exit 2 before git runs; per-command approval cannot help, the refusal text names no remedy, and nothing in the Rule or the guides says what to do.
