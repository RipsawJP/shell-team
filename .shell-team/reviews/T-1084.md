#### Major

- `bin/close-out.sh` (T-1084 gate, ground-field check, ~line 273) — **an empty
  priced-line id passes the ground-shape check.** The check is
  `grep -qE -- '^(saving|recommendation|break-even|cost-input): '` — it verifies
  the prefix and the following space only, never that a non-empty `<id>` token
  follows. A record such as
  `- dispatch: implement — serial — unconditional — recommendation: ` (prefix,
  space, nothing) satisfies this regex and is accepted. Reproduced live: a board
  entry carrying exactly that line closes out with exit 0 and is moved to
  `## Done` unchanged. This directly contradicts the shipped grammar's own text
  (`templates/prompt-blocks/dispatch-record.md`: "`<ground>` opens with a priced
  line id the note already records ... `recommendation: <id>` ... so a routing
  choice cites a recorded price and never an invented one") and this
  repository's own fail-closed discipline (`CLAUDE.md` Working rules: "A check
  that cannot evaluate its input reports an error; it never silently passes").
  Not covered by the spec's `## Input space` "Out-of-scope synthetic extremes"
  list (that list is about megabyte-long/NUL/control-character ground fields
  and unicode-lookalike separators, not an empty id) — this is a realistic
  authoring slip (dropping the id while leaving the label), not a synthetic
  extreme, so no `out-of-input-space` downgrade applies.
  Suggested fix: require a non-empty `[a-z0-9-]+`-shaped (or otherwise
  non-whitespace) token immediately after the matched prefix before accepting
  the ground field, and add an id-less-ground fixture to `tests/close-out/run.sh`.

- `bin/close-out.sh` (T-1084 gate, candidate-line scan, ~line 230) — **the
  initial candidate-detection anchor requires a literal ASCII space
  immediately after `dispatch:`, so a line opening `- dispatch:` with anything
  else there (a tab is the reproduced case) is invisible to the whole gate —
  not merely refused on a looser check, but never even inspected.** The scan is
  `grep -E -- '^[[:space:]]*- dispatch: '`, which is a literal-string match
  requiring the exact byte `0x20` right after the colon. Reproduced live: a
  board entry carrying
  `  - dispatch:<TAB>verify — serial — maybe — because I said so` (a line that
  is simultaneously malformed on *three* independent axes — a modality outside
  `unconditional|conditional`, and a ground opening with none of the four
  priced-line prefixes) closes out with **exit 0, no stderr output at all**, and
  is copied verbatim into `## Done`. This is a full bypass of the gate's central
  purpose (fail-closed validation of every `- dispatch:` sub-bullet present),
  triggered by a single-character typo that is entirely plausible in hand-edited
  or copy-pasted board content, and it is not caught by any other safety net —
  unlike the Unicode-indentation finding below, the line stays correctly nested
  inside the entry's continuation extent (`bin/check-handoff.sh`'s canon and
  `bin/close-out.sh`'s own `A_START..A_END` awk-based extent computation both
  still see it as part of the entry), so there is no downstream re-validation
  failure to catch it. I confirmed by contrast that a *recognized* candidate
  with a non-em-dash separator (e.g. `- dispatch: verify - serial - maybe - ...`
  with hyphen-minus) **is** correctly refused, because it reaches the
  field-extraction `sed` passes and those fail closed when a field doesn't
  extract — the defect is specifically that the wrong internal separator after
  `dispatch:` prevents the line from ever reaching that extraction path at all.
  Suggested fix (matches the adversarial pass's own suggestion, confirmed by my
  own reproduction): loosen the candidate-scan anchor to
  `^[[:space:]]*- dispatch:` (no trailing-space requirement) and let the
  existing field-extraction `sed` passes do the fail-closed rejection of
  anything that doesn't decompose into the four ` — `-separated fields — the
  same pattern the gate already uses correctly for a wrong separator. Add a
  wrong-whitespace-after-colon fixture to `tests/close-out/run.sh`.

  **Root-cause observation, common to both Major findings above:** the
  engineer's own 18-mutation self-check and QA's own 8 additional empirical
  probes are unusually thorough (per the board's `### Local test result` and
  `### QA round 1` sub-bullets), yet neither tried "prefix present, id empty"
  nor "correct-shaped opener, wrong internal separator" — both are typo classes
  a real board author would plausibly produce, and both are input-space gaps
  in the fixture matrix rather than gaps the spec's own Input space section
  discusses. I recommend the fixed matrix explicitly add these two shapes.

#### Minor / nits

- `bin/close-out.sh` (shared, pre-existing `A_START..A_END` entry-extent scan,
  `pass 1`, ~line 172) vs. `bin/check-handoff.sh`'s `CONTINUATION_RE`
  (~line 131) — **the two share the identical pattern text
  `^[[:space:]]+[^[:space:]]` but apply it through two different regex
  engines (awk vs. bash `[[ =~ ]]`), which classify at least one real
  character differently on this host.** Reproduced directly on this checkout
  (macOS, bash 3.2.57, "one true awk" 20200816, `en_US.UTF-8`): a line
  indented with U+3000 (IDEOGRAPHIC SPACE, a full-width space real in
  Japanese-authored text, which this very repository's board and
  `CLAUDE.local.md` already carry elsewhere) matches bash's `[[:space:]]`
  class (`bash: MATCH`) but **not** awk's (`awk: NO MATCH`). Consequence: a
  malformed `- dispatch:` sub-bullet indented that way is excluded from
  `close-out.sh`'s own `A_START..A_END` scan window (so the T-1084 gate never
  sees it), while `check-handoff.sh` still considers it part of the entry.
  I reproduced the full end-to-end consequence: close-out.sh's own final
  safety step — re-validating the rewritten temp board against
  `check-handoff.sh` before it may replace the real board (this script's own
  stated design, header comment lines 51–53) — catches the resulting
  "stranded continuation line" and **refuses the whole close-out (exit 1, real
  board byte-untouched)**. So the fail-closed guarantee holds in practice: the
  malformed record never reaches `## Done`. The residual defect is a
  **misleading refusal message** (a strand-violation message from
  `check-handoff.sh`, not this gate's own `malformed dispatch record` message
  naming the actual defect) that could misdirect an operator's diagnosis.
  This is **inherited, not new**: the `A_START..A_END` computation predates
  T-1084 (T-1084 only adds a scan *inside* that pre-existing window) and the
  same divergence risk already applies identically to the T-068 `pending:`
  gate this task is explicitly required to mirror — so it is a
  shared-infrastructure property, not a defect this task's own diff
  introduces. Not gating this task's merge; recommended as a fast-follow (see
  below).
