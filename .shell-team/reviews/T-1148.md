#### Major

- `README.md:27` / `README.ja.md:27` — The new opening sentence's parity claim ("the same roles, the same status-flag gates, the same cross-provider review") is immediately followed, in the very next sentence, by a role roster that names a UI Designer and a Scrum-Master. Read together — and both the primary and the adversarial pass independently read it together this way — the passage claims host parity for all seven named roles. That is not what ships: `bin/gen-codex-agents.sh`'s own default `ROLES=` list (line 144) generates exactly five Codex custom agents (`tech-lead`, `pm-spec`, `engineer`, `qa-verifier`, `code-reviewer`); `docs/adopting.md`'s "Using shell-team from Codex CLI" runbook never once mentions `ui-designer` or `scrum-master` in its eleven numbered steps; and `scrum-master` sits entirely outside the six-role vocabulary `templates/binding-template.conf`/`bin/check-binding.sh` even recognize (that vocabulary is `tech-lead, pm-spec, engineer, qa-verifier, code-reviewer, ui-designer` — six, and still without `scrum-master`). A `--roles` override could, in principle, ask the generator to emit a `ui-designer` TOML, but this is undocumented for the Codex path and the runbook this README links to never describes it; `scrum-master` has no path to Codex generation at all, documented or not. A Codex CLI host adopter — the spec's own Input-space class 2, "the class the current text serves worst, and the reason this task exists" — reading this sentence would reasonably expect to be able to spawn a Scrum-Master or a UI Designer agent the way the five inner-loop roles are spawned in step 10, and would find neither exists.
  - Suggested fix: scope the parity claim to the five roles that actually carry the status-flag chain to `READY_FOR_MERGE` on both hosts (`tech-lead, pm-spec, engineer, qa-verifier, code-reviewer`), and either drop `ui-designer`/`scrum-master` from the same sentence's immediate vicinity or explicitly mark them Claude-Code-only / opt-in-and-undocumented-for-Codex. Apply the identical fix to `README.ja.md:27`, which carries the same structure and the same silent parenthetical ("＋ UI 作業時のみ参加する UI Designer・＋ Scrum-Master").
