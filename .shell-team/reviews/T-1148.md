That is not what ships: `bin/gen-codex-agents.sh`'s own default `ROLES=` list (line 144) generates exactly five Codex custom agents (`tech-lead`, `pm-spec`, `engineer`, `qa-verifier`, `code-reviewer`); `docs/adopting.md`'s "Using shell-team from Codex CLI" runbook never once mentions `ui-designer` or `scrum-master` in its eleven numbered steps; and `scrum-master` sits entirely outside the six-role vocabulary `templates/binding-template.conf`/`bin/check-binding.sh` even recognize (that vocabulary is `tech-lead, pm-spec, engineer, qa-verifier, code-reviewer, ui-designer` — six, and still without `scrum-master`). A Codex CLI host adopter — the spec's own Input-space class 2, "the class the current text serves worst, and the reason this task exists" — reading this sentence would reasonably expect to be able to spawn a Scrum-Master or a UI Designer agent the way the five inner-loop roles are spawned in step 10, and would find neither exists.
