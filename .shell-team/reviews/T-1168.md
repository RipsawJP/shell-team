#### Major
- templates/prompt-blocks/host-dispatch.md:5 (and its byte-identical copy skills/run/SKILL.md:182, docs/adopting.md:594-599, docs/adopting.ja.md:597-603) — the wording lets the run ask the operator to approve "that commit ... one concrete command at a time" but does not say who executes the approved command, and the fallback reports only "the one commit command". The dispatched engineer is bound by agents/engineer.md:150 to stop BLOCKED on any sandbox refusal, so an orchestrator model reading this has no stated way to get from the child's BLOCKED to an approved, executed command; and a git staging command (writes .git/index, runs before the commit) is a refused write that neither the approval sentence nor the fallback names. The path to READY_FOR_QA can therefore still stop at the first refusal, which is the failure the task exists to remove. Suggested fix, inside the never-dropped wording and without touching agents/: say that the role's own commit is each git command the commit needs (staging, then the commit), approved one at a time; that when the role returns BLOCKED with the refusal, the run asks the operator to approve that exact command and, once approved, runs it itself (or resumes the role); and that the fallback names every command still to be run, not only the commit. Apply identically to the dispatch line, the EN and JA step 6.
