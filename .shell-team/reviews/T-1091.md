- `skills/run/SKILL.md:44` — the operator-authored branch's spec-landing instruction (`bash bin/team-paths.sh --get specs`) is a hardcoded relative path that fails for a normal marketplace-plugin adopter (no local `bin/`), contradicting this same file's own Step 0 convention (bare `team-paths.sh`, PATH-resolved when the plugin is loaded). Neither the `- entry-mode:` nor `- flagged-gap:` hand-off fields are required on the board by any checker, and nothing verifies `pm-spec`'s conformance pass actually ran before the freeze proceeds. The stated safety rationale for the whole mode (avoiding pure self-attestation) currently rests entirely on the orchestrator's own good-faith compliance with prose, with no artifact trail a later reader (or a checker) could use to confirm it happened. — Suggested fix: either require `- entry-mode:` on the board entry and have `bin/close-out.sh` (or a small new check) verify its presence whenever `- dispatch: specify — operator-authored` is recorded, or explicitly disclose this as an unenforced duty with the same "no checker ships for it yet, tracked as issue #NNN" pattern this repo already uses for the Adopter-facing-documentation gate (T-1061) and the Stacked-branch base-ref-discriminator gate (T-1081) — the current text makes a stronger claim ("mandatory and non-waivable") than either of those two precedents without matching their disclosed-limitation honesty.
