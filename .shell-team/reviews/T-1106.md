#### Major

- **`tests/check-binding/run.sh:664` (the `cb-adapters-not-forwarded-population` guard, issue #221) — the `|| true` on the live `git grep -l` enumeration is not scoped to the documented "no match" case; it swallows every exit status uniformly, including a fatal producer error.** The line reads `(cd "$REPO_ROOT" && git grep -l -e 'check-binding.sh' -- 'bin/*.sh' '.github/workflows/*.yml') > "$popall" || true`, and its own comment at `:659-663` states the guard is meant to "absorb only that 'no match' status" (git grep's exit 1) so a producer's genuine failure is never hidden — but a bare `||` cannot distinguish exit 1 from a fatal exit 2+ (git's own documented convention: 0 = match, 1 = no match, ≥2 = fatal error); both are silently treated as success. Two consequences, independently verified: (a) if `git grep` dies fatally with zero output already written, `[ -s "$popall" ]` catches it — a fail-closed outcome, but reported as "the live enumeration returned nothing," misdiagnosing an operational git failure as a legitimate empty population; (b) if `git grep` dies fatally *after* emitting a partial (non-empty) match list — plausible on a corrupted object, a resource limit, or a `git` version incompatibility mid-scan — the guard proceeds to judge that truncated population as if it were complete, and the two present-member positive controls (`bin/resolve-executor.sh`, `.github/workflows/check-handoff.yml`) would very likely still be in a partial list built from a lexicographically-ordered small population, masking the loss of any later-enumerated member that might actually forward `--adapters`. This is exactly the falsifiability direction the frozen `## Reviewer scope` asks for ("does it fail when its own search form is broken") and exactly the class this repository's own doctrine names ("Checkers must fail closed … suppressing a non-zero exit status to keep output tidy converts a real failure into a false pass" — `CLAUDE.md`). Both the primary Codex pass and the targeted adversarial pass independently converged on this finding (native `P2`, both times) without my prompting either toward it in the primary pass.
  - Fix: capture the exit status explicitly and only treat `1` as the documented empty-match case; any other non-zero status should `fail` loudly. E.g. `set +e; (cd "$REPO_ROOT" && git grep -l -e 'check-binding.sh' -- 'bin/*.sh' '.github/workflows/*.yml') > "$popall"; grc=$?; set -e; [ "$grc" -eq 0 ] || [ "$grc" -eq 1 ] || fail "cb-adapters-not-forwarded-population: git grep exited $grc (not a clean no-match)"`. This is a same-file, same-suite fix confined entirely to `tests/check-binding/run.sh` — it does not touch `bin/check-binding.sh`, does not change any refusal token, and does not require a re-freeze.
  - Not a design-premise defeat: this is the guard's **first** review round (the spec's own `## Pre-commitment` never-dropped/droppable framework triggers only on two consecutive rounds of new defects on the same component), so it routes back to engineering for a targeted fix rather than to the drop path.
