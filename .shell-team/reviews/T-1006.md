## 7. FAIL finding — `tests/errexit-safe/run.sh` regression (stale cross-suite line:content pin)

**Root-cause class: stale `file:line:content` pin in a cross-suite registry, caused by a line-number shift in an edited `bin/` script that the engineer's own verification did not re-run.**

`tests/errexit-safe/run.sh` is listed in `.github/workflows/check-handoff.yml` (`Run errexit-safe regression suite`) and is therefore part of this repo's authoritative "must pass" list per `.shell-team/test-recipe.md` ("CI … is the authoritative list of every suite + dogfood step that must pass"). ### Reproduction

```
$ bash tests/errexit-safe/run.sh
...

FAIL: completeness self-audit: found errexit-unsafe candidate site(s) NOT in NOT_APPLY, by exact content (regression — a `|| true` guard removed, an exempted line rewritten to something unsafe, or a new checker shipped unfixed) — fix with `|| true` or add to NOT_APPLY with a (a)-(e) reason:

```
Exit code 1. Reproduced twice, deterministic.

### Cause

`tests/errexit-safe/run.sh`'s `NOT_APPLY` registry (around line 313) pins:
```
gen-playbook-blocks.sh:436:        "$role" "$line_count" "$LINE_WARN_THRESHOLD" >&2
```
This task's edit to `bin/gen-playbook-blocks.sh` (the resolver wiring plus the permitted `--help` window widening `2,45p`→`2,48p`, which the provenance file documents) inserted lines earlier in the file, so this exact line of content — byte-identical — now sits at line **449**, not 436 (`git diff d691a6f -- bin/gen-playbook-blocks.sh` shows a `@@ -78,20 +78,33 @@` hunk, a net +13 lines, landing before the original line 436). The pin is now stale: the content still exists (so it's a "real" errexit-unsafe candidate that must be in `NOT_APPLY`, per that line's own pre-existing `(d) accumulator/warning site` exemption), but at the wrong line number, so the suite's exact-line-and-content match fails both directions (new candidate not found in `NOT_APPLY`, old `NOT_APPLY` entry not found among candidates).

This is not a new defect introduced by the resolver logic itself — the underlying line (`printf`-based warning to stderr, exempted as a `(d)` accumulator/warning site) is unchanged in content — but the diff **did** shift its line number, and nothing in the engineer's build order or hand-off re-ran or updated this suite's registry.
