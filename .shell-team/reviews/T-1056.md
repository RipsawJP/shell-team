#### Major

- `bin/check-liveness.sh:194-210` — **TOCTOU race between the state file's mtime sample and its content read.** `STATE_MTIME_RAW` is captured via `stat` at L194-199, and `start_epoch`/`iteration` are read separately via `read_state_key`'s `awk` open at L206-207. `bin/goal-state.sh`'s `write_state` rewrites the file in place (`printf ... > "$f"`, not a `mktemp`+`mv` replace) with no locking anywhere in either script (confirmed: no `flock`/lock file in `bin/goal-state.sh` or `bin/check-liveness.sh`). If a `bump` completes between these two reads, the classifier pairs the **pre-bump mtime** with **post-bump content**, so `A_STATE` is computed from a stale, older mtime than the state file's true current one — a genuinely ticking loop can be misreported `STALLED`, or `DEAD` if `HEAD` is also old. This is not a synthetic extreme: the spec's own `## Input space` names "a timer invoking the classifier repeatedly, including twice within one second, and an invocation that overlaps a tick's own write to the state file" as a reachable class this task's deliverables "must handle correctly" (line 165). The fixture suite's state-file fixtures are all static/immutable, so no case exercises an overlapping write. Suggested fix: read the mtime and the two keys within a single bracketed window and re-stat after the content read, refusing `state-unreadable` (or a new closed-set token) if the mtime moved between the two samples, and add a fixture that injects a `bump`-shaped rewrite between them.
- `bin/check-liveness.sh:350-366` (`write_out`, `mv` at L364) — **an existing-directory `--out` target is silently accepted, and the named path never receives the verdict document.** `write_out` refuses a symlink at `$OUT_PATH` (L352) but not a pre-existing directory. Reproduced live in this round: `LIVENESS_NOW=... bash bin/check-liveness.sh --state <s> --declaration <none> --out <existing-empty-dir>` exits `0`, prints `RUNNING`, and leaves the target **still a directory** with an untracked `.liveness-verdict.XXXXXX` file created *inside* it (`mv` treats an existing directory as a move-into-container target and returns success). This violates two things the spec states: DP9's fail-closed symlink-refusal precedent ("a symlink at that target... counts as occupied and is refused... without following it") should extend to any non-regular target by the same reasoning, and the Goal sentence's "writes nothing except an optional `--out` verdict file" containment guarantee — an extra, randomly-named file is created at a path the caller never named. A caller (the external timer) that checks the named `--out` path's existence/mtime to confirm the classifier ran would be misled: stdout and the exit code both report a normal verdict while the actual artifact is absent. AC11 does not test a directory-valued `--out` target, and the refusal token table's `out-unwritable` condition text ("the `--out` target is a symlink... or the guarded temp write or replace failed") does not literally cover this case either, since the `mv` does not fail. Suggested fix: refuse `out-unwritable` when `$OUT_PATH` exists and is not a regular file (in addition to the existing symlink check), before creating the temp file.

#### Major

- `bin/check-liveness.sh:225-238` (the `LIVENESS_TEST_RACE_MTIME_BUMP` seam) — **production code contains a live write path to its own read-only input, reachable by a non-hostile, non-default environment variable, and it can fabricate a `RUNNING` verdict for a genuinely dead loop.** Reproduced live in this round: a state file backdated to the year 2000 (clearly `DEAD`-band by any real measure) with `LIVENESS_NOW` set near real wall-clock time, invoked with `LIVENESS_TEST_RACE_MTIME_BUMP=always`, causes the script's own `touch -- "$STATE_PATH"` (L238) to update the state file's mtime to the current real time, and the classifier reports `RUNNING` at exit `0` — the exact failure DP5 names as "the exact failure this artifact exists to prevent" ("a wedged loop reported healthy... by a broken clock"), achieved here by a different mechanism (an inherited test env var) rather than a floored clock-skew. This is a genuinely new defect: it did not exist in round 1's shipped code (there was no retry loop, no touch, at all) and is not a partial/incomplete fix of M1 — M1 was a concurrent-write TOCTOU; this is an ambient-environment-triggered self-mutation of the observed input, reachable with **zero concurrency** (no second process needed at all). It also directly contradicts the Goal sentence's "writes nothing except an optional `--out` verdict file" and the AC11 read-only guarantee's own spirit (the `git hash-object` proof only holds because AC11's fixtures never set this variable). Both the primary pass and a dedicated adversarial pass confirmed this independently, and the adversarial pass's own words: "It therefore satisfies the pre-committed consecutive-round Major trigger against this component." Suggested fix: delete the env-var-gated `touch` entirely from `bin/check-liveness.sh`; reproduce the race in the test suite the way QA's own round-2 verification already did independently of the shipped seam (a `PATH`-shadowed `awk` wrapper that forwards to the real `awk` then performs the touch from the *test* process, never from inside the classifier) — recorded on the board's QA round-2 bullet as already proven to work.
