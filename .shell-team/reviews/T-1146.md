#### Major

- `bin/check-codex-agents.sh:167` — The legacy-file remedy hint now unconditionally appends `--roles "$ROLES"` (this invocation's own resolved role list) and still claims `(removes this file by name)`. When the checker was itself invoked with a `--roles` value that excludes `code-reviewer` (a reachable shape under the spec's own Input space item 6 — "a checker invocation scoped with `--roles` to a subset of the five"), the checker still flags the legacy occupant (the "owned" test only checks membership in the resolved role list, unrelated to the removal gate), and the printed remedy carries that same excluding `--roles` value. Running that literal command does **not** remove the file, because `bin/gen-codex-agents.sh`'s own removal step is gated on `code-reviewer` being among the *generator* invocation's requested roles (Input space item 7) — the command silently exits 0, emits **zero** removal-notice bytes, and the legacy symlink is still present afterward. I reproduced this live end-to-end (seeded a dangling symlink under `--roles 'pm-spec engineer'`; the checker flagged it and printed `--roles "pm-spec engineer" (removes this file by name)`; running that exact printed command left the symlink in place with empty stderr). This is a regression this task's own fix introduces: before this diff, the printed remedy never carried `--roles` at all, so the bare command always fell through to the generator's own *default* role list — which always includes `code-reviewer` — so the pre-existing remedy was always truthful (if over-widening, which is exactly what issue #546 asked to narrow). Narrowing the scope to match the invocation, as this task does, is the right fix for the widening complaint, but it was not cross-checked against the case where that narrower scope itself excludes `code-reviewer` — a case neither AC5's nor AC6's own fixture exercises (`SCOPED_ROLES='pm-spec engineer code-reviewer'` in both `tests/codex-agents/run.sh` includes `code-reviewer`). Suggested fix: have the checker's hint distinguish whether `code-reviewer` is in `$ROLES_ARR` before choosing the hint text — e.g. print the scoped command plus an explicit note that it will not remove the file because `code-reviewer` is not in this invocation's role list, and name the actual removal command (with `code-reviewer` added) or a manual `rm` as the real remedy — and add a regression fixture that executes the extracted hint under a `--roles` value excluding `code-reviewer`, asserting the file is still present and no notice was printed, so the assumption is pinned rather than silently reintroduced.
