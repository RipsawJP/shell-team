#### Major
- bin/team-setup.sh:170 — `tp()` strips only the `export NAME=` prefix, so the `%q` escaping that `team-paths.sh --export` applies stays in the value. With `TEAM_RUN_BASE` containing a character such as `$` (accepted by the resolver), the symlink preflight at line 212 checks a literal path that does not exist while `team-init.sh` writes the real one. Probed in a scratch repository under a temp HOME: a committed symlink `.a$b` pointing at a directory outside the repository, run with `TEAM_RUN_BASE='.a$b'`, exits 0 and creates `todo.md`, `specs` and `retros` in the outside directory. That is a write outside the repository, the never-dropped component (a). The drift checks and report paths are wrong for the same inputs. Fix: read each path raw with `team-paths.sh --get <KEY>` (or decode the exports with `eval` in a controlled subshell) and add a test with a metacharacter base and an outward symlink.

#### Minor / nits
- bin/team-setup.sh:257 — a scaffold refusal prints `bash team-init.sh <root>`, whose write set is the whole scaffold (and on a legacy layout, `docs/specs` too), not the single artifact decision 6 and AC6 promise. It stays inside the repository and writes only plugin-owned scaffold files, and team-init never overwrites, so it is not a breach of (a) or (b); report the failure without a `run yourself` line, or print a command scoped to the refused path.
- bin/team-setup.sh:324 — the regeneration refusal branch keys on `[ ! -w "$AG" ]`; a sandbox denial that leaves the mode bits writable, and the first-generation path where `mkdir -p` succeeds but the generator is refused, exit 2 with a diagnostic and no `run yourself` line. Nothing is written, so it fails closed; the operator just gets less help.
- bin/team-setup.sh:275 — the ignore probe names one fake file without the `.toml` suffix, so a rule like `.codex/agents/*.toml` makes the probe miss and setup appends one redundant exclude line (harmless), while an exact-path rule on the probe name alone would suppress the append; both are far-fetched.
- bin/team-setup.sh:143 — command substitution strips trailing newlines from `rev-parse`/`pwd` output, so a root path ending in a newline slips past `unsafe_path`. Reachable only on a deliberately hostile path.
- docs/distribution.md:91 and docs/distribution.ja.md — the pre-existing copyable `sandbox.excludedCommands` / `permissions.allow` block remains. It is now framed as the operator's decision and setup never writes it; I read it as a reference example, not an imperative, but a stricter reading could ask for the block to move behind the operator-only framing.
- In-repo symlinks (a committed `.shell-team` or `.codex` link into the repository) are refused with exit 2 and a clear message, nothing written. That is acceptable for adopters: the case is outside the spec's reachable input classes, the message names the path and leaves the decision to the operator, and a refusal costs one manual step where silent following could write outside. Worth a one-line mention in the adopting guide, not a change.
