## Problem

`bin/check-intent.sh` shipped a fail-open hole inside a fail-closed gate: a grammar-conformant leading-zero count (`verdict=08P/00F`) crashed a `$(( ))` expansion inside an `if` condition — a position `set -e` does not cover — so the cross-check was silently skipped and a self-contradictory attestation was accepted as `aligned`. One line was fixed in T-1018. Nobody has asked whether the same shape exists anywhere else in `bin/`.

It does. Reading the source (pm-spec has no shell; every number below is `pm-spec-measured-by-reading` and is re-measured by the engineer with the pinned commands): `bin/goal-state.sh`'s `require_int()` validates `^[0-9]+$` and then feeds the value straight into three arithmetic sites, so a state file carrying `iteration=010` makes `bump` print `9` instead of `11`, and `start_epoch=01000000000` makes `elapsed-min` report `14429714` instead of `10`. `bin/loop-guard.sh` width-bounds `MAX_ITER` to `^[0-9]{1,9}$` but never normalizes it, so a contract writing `max_iterations: 010` shrinks the cap to 8 and stops the loop early — and `max_iterations: 08` is worse: the arithmetic error makes `(( MAX_ITER > 0 ))` return non-zero inside an `if` condition, which **silently disables the runaway guard entirely**. `bin/rollup-runs.sh`'s `field_num()` captures `([0-9]+)` out of a runs JSONL row and sums it, so `"tokens":010` reports 8 and `"tokens":08` aborts the script mid-output with a raw bash arithmetic message and no `rollup-runs:`-namespaced diagnostic.

Two things make this a sweep rather than three more patches. First, "we fixed the ones we found" is not a claim anyone can verify — the corpus lesson `2026-08-03 — A completeness claim attaches its accounting` requires the population total, the literal search method, and a reason per exclusion, attached at the claim site. Second, the same-class discipline has a second half nobody has decided yet: a width bound. `bin/loop-guard.sh` and `bin/rework-digest.sh` already carry `^[0-9]{1,9}$`; `bin/goal-state.sh` carries none, so a 20-digit grammar-conformant `iteration` silently wraps through `INTMAX_MAX` and `bump` prints a negative number with exit 0.

## Goal

<!-- BEGIN intent-block: T-1021 -->

A committed audit document accounts for **every** arithmetic-evaluation site in `bin/` — all 35 files, every one of the eight bash contexts that evaluate an operand as an arithmetic expression, the literal search command for each, and a raw-hit-to-inventory reconciliation whose every excluded occurrence carries a reason. Each inventoried site carries exactly one of four classification values, a per-site width decision, and (where it needed one) the lock case that proves the fix. The three measured fail-open behaviours are closed: a leading-zero operand reaching `bin/goal-state.sh`, `bin/loop-guard.sh` or `bin/rollup-runs.sh` from a state file, a loop contract or a runs JSONL row either yields the correct base-10 answer or is refused at the grammar with the script's own namespaced diagnostic — never a silently re-based value, and never bash's raw `value too great for base` line standing in for a decision. Rejection happens at the regex, fail-closed; no site relies on an arithmetic error aborting the script, because the error inside an `if` condition does not abort it. Every fix is local to its own script — `bin/` has zero `source` directives and standalone-per-script is the contract — and every width bound names the quantity it bounds, the headroom over the largest real value, and the point at which it would become wrong. `test` / `[` comparisons are untouched, with the measurement that grounds that exclusion cited rather than the exclusion merely asserted.

### Terms

| term | definition |
|---|---|
| **arithmetic context** | a bash construct that evaluates an operand as an *arithmetic expression*, and therefore applies bash's leading-zero-means-octal rule. Exactly eight are in scope; the closed list is in D1 |
| **a site** | one arithmetic-context *occurrence* in a `bin/` file **whose operand set contains at least one variable or command-substitution term**, addressed as `<file>:<line>`. A single line can hold several sites (`y=$((10#$1)); m=$((10#$2))` is two). An occurrence whose operands are *all literal constants* — `${BASH_REMATCH[1]}`, `${BASH_SOURCE[0]}`, `${v:0:1}` — is **not** a site: no digit string can reach an operand that is a literal. Such occurrences are counted and excluded at the reconciliation step with that reason, never silently dropped |
| **untrusted digits** | a digit string whose value is not produced by the script's own counter or a canonical-decimal producer: a regex capture (`BASH_REMATCH`), a value read out of a file (a state file, a loop contract, a runs JSONL row, a board sub-bullet, a spec), an environment variable, or a command-line argument |
| **canonical-decimal producer** | a tool whose numeric output cannot carry a leading zero or a sign: `grep -n`, `cut -d: -f1` over `grep -n` output, an `awk` integer `print`, `${#var}`, `$#`. Its output is *file-derived* but not untrusted digits |
| **reachable** | untrusted digits can arrive at this site's operand along some real path through the shipped code |
| **the audit document** | `docs/loop-engineering/arith-base10-audit.md`, the task's accounting deliverable |
| **a ledger line** | one flat markdown bullet carrying machine-read data, `- <key>: <value> — <key>: <value> …`. Never a markdown table (D9) |
| **the population** | every regular file directly under `bin/` — 35 of them, including the extensionless `bin/install` |
| **a lock case** | an assertion in an owning `tests/*/run.sh` that fails if the fix is reverted |

### Settled decisions

Each decision below is resolved. Nothing here is left to implementation judgment.

- **D1 — the arithmetic-context surface is a closed list of eight, and it includes `[[ … -eq … ]]`. This is a stated, reasoned widening of the routing map's "`test`/`[ -eq ]` not affected" constraint.**

  | # | context | label used in the audit document |
  |---|---|---|
  | 1 | arithmetic expansion | `$(( ))` |
  | 2 | arithmetic command | `(( ))` |
  | 3 | arithmetic `for` | `for (( ))` |
  | 4 | `let` builtin | `let` |
  | 5 | indexed-array subscript (`a[i]`, `${a[i]}`, `a[i]=`) | `array subscript` |
  | 6 | substring expansion (offset and length are arithmetic expressions) | `${v:off:len}` |
  | 7 | bash's `[[` arithmetic binary operators (`-eq -ne -lt -le -gt -ge`) | `[[ -eq ]]` |
  | 8 | bash `printf`'s numeric conversion | `printf '%d'` |

  - **Why `[[ -eq ]]` is in and `[ -eq ]` is out — the distinction is the `[[` command, not the operator.** The T-1018 QA measurement that grounds the exclusion (`.shell-team/reviews/T-1018.md`, section `### Regression / adjacent code paths`) ran `[ "08" -eq 8 ]` — the **single-bracket** `test` builtin, which parses base 10 only. Bash's manual scopes the arithmetic behaviour of the same operator names differently: *"When used with the `[[` command, arg1 and arg2 are evaluated as arithmetic expressions."* Excluding `[[ … -eq … ]]` on the strength of a `[`-only measurement would be exactly the over-broad exclusion this task exists to prevent, so the routing map's constraint is narrowed to `[` / `test` and the double-bracket form is inventoried. **AC19 does not assert this from the manual — it measures both forms live and requires them to disagree**, so the widening is grounded by execution and a wrong premise is caught before the intent block freezes rather than after.
  - **`printf '%d'` is in scope for the search, and the expected accounting outcome is zero reachable sites.** Bash's `printf` evaluates a `%d` argument as an arithmetic expression, so it is the same class in kind. Measured by reading: 15 `%d` occurrences in `bin/`, every operand an internal counter (`$violations`, `$pass`, `${#installed_files[@]}`) or awk-internal. In-scope because the adjacency is real; recorded as an accounting row, not as a fix.
  - **The literal-constant rule keeps contexts 5 and 6 tractable without weakening the sweep.** Contexts 5 and 8 are the two whose raw hit counts are dominated by literal-index forms (`${BASH_REMATCH[1]}` alone accounts for most subscript hits in `bin/`, and every `printf '%d'` operand in the tree is an internal counter), and both `${v:off:len}` sites in `bin/` carry literal offsets. Per the Terms table, a wholly-literal occurrence is **not** a site — it is an excluded occurrence carried with its count and reason into AC4's reconciliation identity, so the exclusion is measurable rather than a judgement call, and an inventory of several hundred `[1]` subscripts is avoided without any variable-operand occurrence escaping.
  - **awk's own arithmetic is out.** `bin/` embeds awk programs in single-quoted strings, and text inside them that looks like a bash arithmetic context is awk syntax evaluated by awk, not bash — `bin/close-out.sh:333` and `bin/gen-project-status.sh:144` (`while ((getline l < f) > 0)`) are the measured instances. They are reconciliation exclusions with that reason, not sites.
- **D2 — classification is a four-leaf decision procedure, applied in this order. First match wins, so exactly one value lands on every site and "unclassified" is unreachable by construction.**
  1. Can untrusted digits reach this operand? No ⇒ **`NOT-REACHABLE`**.
  2. Otherwise: does the operand enter arithmetic without base-10 normalization? Yes ⇒ **`NEEDS-10#`**.
  3. Otherwise (already normalized): does its grammar admit a digit string wide enough to cross bash's signed 64-bit range and change a comparison's answer? Yes ⇒ **`NEEDS-WIDTH-BOUND`**.
  4. Otherwise ⇒ **`NORMALIZED`**.
  - **Why an ordered procedure rather than four independent labels.** A site can genuinely need both `10#` and a bound, which would make four free-standing labels non-exclusive and "one value per site" unenforceable. The ladder resolves it: the *class* names the arithmetic-side status, and the width decision rides on every row as its own mandatory `width:` field (D4), so a `NEEDS-10#` site that also wants a bound is fully described without a fifth value.
  - **`NOT-REACHABLE` is a judgment that must state its producer.** A row is not allowed to say "internal"; it names why — the script's own loop counter, a literal constant, or a canonical-decimal producer (`grep -n` / `cut` at `bin/gen-loop-replay.sh:193→353/356` and `bin/check-pii-shapes.sh:195→198`, an `awk` integer `print` at `bin/check-retro.sh:249→252`, `${#quotes}` at `bin/check-run.sh:204`).
- **D3 — no shared helper, no `source` directive, no new file under `bin/`. Every fix is local to the script it fixes.** Measured: `bin/` contains **zero** `source` / `.` directives; standalone-per-script is this repository's existing contract, and `tests/is-span-row-parity/run.sh` exists precisely because two copies of one function are maintained on purpose (T-1011 hazard H4). Recorded here so review does not relitigate DRY: a shared arithmetic helper would need a sourcing mechanism that does not exist, would break every script's ability to run standalone from `PATH`, and would buy nothing a five-character prefix already buys.
- **D4 — every width bound is decided per site and names its headroom. No blanket `{1,9}`.** Each site row carries a mandatory `width:` field, either `none (reason: …)` or `<bound> (headroom: …, stale-at: …)`.
  - **Two bounds are settled here, because the wrong one is a shipped regression rather than a style choice.** `bin/goal-state.sh`'s `iteration` gets `^[0-9]{1,9}$` — the same bound `bin/loop-guard.sh:88` already applies to the same quantity arriving as `--iteration`, so the two ends of one pipe agree instead of disagreeing; headroom 10^9 iterations against a real ceiling in the tens. `start_epoch` (and `now`/`$GOAL_NOW`) get `^[0-9]{1,11}$`, **not** `{1,9}`: a Unix epoch is 10 digits today and 11 from 2286, so a `{1,9}` bound would reject every legitimate value the script writes. Headroom: 11 digits reaches ≈ year 5138, and 11 digits cannot overflow signed 64-bit (19 digits) even after the `− start` and `/ 60` arithmetic.
  - **A site may legitimately decline a bound.** Where the operand is already bounded upstream, or an overflow cannot change any comparison's answer, `width: none (reason: …)` is the correct row. What is forbidden is silence.
- **D5 — `10#` is never applied where the operand can be empty, and the guarantee is the grammar's, not the arithmetic's.** `$((10#$x))` with an empty `x` is a syntax error, so every site that gains the prefix must sit downstream of a check that has already proven at least one digit is present. Three shapes already in the tree are the models: `bin/rework-digest.sh:116`'s short-circuit (`[[ ! "$2" =~ ^[0-9]{1,9}$ ]] || (( 10#$2 < 1 ))` — the regex arm runs first, so the arithmetic is unreachable on a non-match), `bin/goal-state.sh`'s `require_int` call placed before the arithmetic, and `bin/rollup-runs.sh`'s `[[ -n "$tk" ]]` guard, which is sufficient **only because** `field_num`'s capture is `([0-9]+)`, so non-empty implies at least one digit. A new guard that only tests non-emptiness against a grammar admitting non-digits is not sufficient.
- **D6 — rejection happens at the grammar side, fail-closed. No site may rely on bash's arithmetic error to stop anything.** Grounded, not assumed: T-1018's Blocker showed the error inside an `if` condition is exempt from `set -e`, so the enclosing condition simply evaluates false and execution continues — which is how `max_iterations: 08` disables `bin/loop-guard.sh`'s runaway guard today. Even in a position where `set -e` *does* abort (`bin/rollup-runs.sh:156`), the observable result is a raw bash message with no `rollup-runs:` namespace after stdout has already been partially written, which the repository's "checkers must fail closed" rule does not accept as a decision. The invariant every fixed site must satisfy: on a rejected input, the script emits its **own** namespaced diagnostic and its **own** contract exit code, and bash's `value too great for base` / `syntax error` text never reaches stderr.
- **D7 — every fix class gets a lock case in the owning suite, and its leading-zero fixture uses values where octal and decimal actually diverge.** `08` (invalid as an octal literal) and `010` versus `10` (valid octal, different value) are the two admissible shapes; `07` proves nothing because it means 7 either way, and a lock built on it passes against the unfixed code. T-1018's two leading-zero cases in `tests/check-intent/run.sh` are the model. Each lock case declares its fixture value inline as a `zero-fixture=<value>` tag so completeness is greppable rather than recounted by hand (AC14), and carries a grep-able `T-1021-…` id so a failure maps back to a site row (AC13).
- **D8 — the audit document's commands are declared runnable from this repository's checkout root, and the adopter cell of the execution-context matrix is explicitly not applicable.** The document ships literal commands a reader is meant to run, so the corpus lesson `2026-08-02 — A spec that ships runnable commands verifies them across an execution-context matrix` applies. Cell 1 (this checkout's root, plugin not on `PATH`) is the declared context and is verified by execution — AC2 re-runs the pinned `$((` command live and requires the document's declared total to match. Cell 2 (an adopter repository with the plugin loaded) is **not applicable, with a reason**: the document is a source-tree accounting of *this* repository at a named base ref, not an adopter-facing procedure, and its commands read `bin/` relative to the checkout root. The document states its run context so a reader cannot mistake the boundary.
- **D9 — machine-read data lives on flat ledger lines, never in a markdown table.** A one-line shell parser cannot survive a table's cell padding, alignment changes or added columns, and this document exists to be re-derived mechanically by QA. Prose tables are welcome; the site inventory, the file accounting, the search commands, the reconciliation, the overflow decisions, the exclusions, the mirror rows and the probes are ledger lines with the field order fixed as follows.

  ```
  - file: <bin/path> — sites: <N>
  - searched: <context label> — raw occurrences: <N> — files: <M> — command: <literal command>
  - run-context: <context> — <status and reason>
  - reconcile: <context label> — raw occurrences: <N> — inventoried sites: <N> — excluded occurrences: <N>
  - excluded: <file>:<lines> — count: <N> — reason: <why these occurrences are not sites>
  - excluded-context: <context> — reason: <why> — grounding: <citation>
  - site: <file>:<line> — context: <label> — class: <CLASS> — width: <none (reason: …) | bound (headroom: …, stale-at: …)> — n10: <k> — lock: <tests/<suite>/run.sh:<id> | none>
  - overflow: <file>:<line> — decision: <BOUND|NO-BOUND> — reason: <why this is or is not the cheap fail-closed answer>
  - mirror: <file> ↔ <file> — surface: <what is duplicated> — applied: <mirrored|not-applicable (reason)>
  - probe: <command> — exit: <N>
  ```

  `n10:` is the number of operands at that site that carry the `10#` prefix after the change (`0` where none do). `lock:` names one existing suite file and one colon-free id. `class:` is never the last field on its line. Three ledger values are fixed literals, because a criterion greps for them:

  ```
  - run-context: repository checkout root — <the declared runnable context, plus how it is verified>
  - run-context: adopter repository with the plugin loaded — not applicable (reason: <why>)
  - excluded-context: [ ] / test — reason: <why> — grounding: <citation>
  ```

  The two `- run-context:` lines are D8's execution-context matrix, one row per cell. The `- excluded-context:` line is the `[` / `test` exclusion, and its context label is exactly `[ ] / test` so it cannot be confused with the `[[ -eq ]]` row.
- **D10 — the parallel-surface pair is audited explicitly.** `bin/rollup-runs.sh` and `bin/cluster-failures.sh` maintain deliberately duplicated `field_str()` and `is_span_row()` copies (T-1011 H4, regression-locked by `tests/is-span-row-parity/run.sh`). Measured: `field_num()` exists only in `bin/rollup-runs.sh`, and `bin/cluster-failures.sh`'s arithmetic is entirely over its own counters — so the expected mirror verdict is `not-applicable (reason: …)` rather than a second edit. The row is required either way; a same-class fix applied to one of two parallel surfaces and not audited against the other is the failure mode the mirror table exists to catch.
- **D11 — `tests/errexit-safe/run.sh` stays byte-identical, and that constrains how a rejection is emitted.** Measured against the real registry: its `NOT_APPLY` set pins `file:line:content` triples in `check-handoff.sh`, `check-acs.sh`, `check-contract.sh`, `check-board-headings.sh`, `close-out.sh` and `gen-playbook-blocks.sh` — **no line in any of this task's expected targets is pinned**, so line shifts in `bin/goal-state.sh`, `bin/loop-guard.sh`, `bin/rollup-runs.sh` or `bin/check-intent.sh` move nothing. The obligation is the other direction: every new stderr write must go through the script's existing already-`|| true`-guarded helper (`require_int` in `goal-state.sh`, `guard_error` in `loop-guard.sh`, the two guarded `printf … >&2 || true` sites in `rollup-runs.sh`), so the suite's candidate derivation gains nothing to account for. AC17 asserts byte-identity **and** green, which is what makes that a measurement rather than a hope.
- **D12 — no adopter-facing document, agent, skill, template, workflow or version changes.** Each exclusion measured: `CONTRIBUTING.md` contains zero occurrences of `10#` / `base-10` / `octal` / `leading-zero`, so there is no documented procedure to keep in sync; the corpus lesson that governs this discipline is already promoted and already generated into the playbook blocks, so editing `.shell-team/lessons.md` would regenerate `agents/*.md` and widen the diff into files this task has no reason to touch; `.github/workflows/check-handoff.yml` already runs every suite this task touches, so no new step and no new `shellcheck` argument is needed. No version bump, no `README*`, no `CHANGELOG*`.

## Non-goals

- **Any change to a `test` / `[ … -eq … ]` comparison.** Grounding: `.shell-team/reviews/T-1018.md`'s `### Regression / adjacent code paths` section measured `[ "08" -eq 8 ]` directly and found the single-bracket builtin parses base 10 only. Recorded as an explicit exclusion with its citation, not as silence — and narrowed to `[` / `test`, because `[[ … -eq … ]]` is a different context (D1).
- **Anything outside `bin/`.** `skills/**`, `agents/**`, `.github/**`, `templates/**`, `docs/**` other than the audit document itself, and the arithmetic inside `tests/*/run.sh` helpers are all out of scope. A test helper's own counter arithmetic is not a shipped surface.
- **A shared arithmetic helper, a `source`-based library, or any new file under `bin/`** (D3).
- **General input-validation hardening beyond digit strings.** A non-numeric field (`prev_sig`, `--verdict-hash`, a `run_id`) is a different task. So is quoting, path handling, or JSON well-formedness.
- **Unrelated shellcheck cleanups, refactors, or comment rewrites** in the touched scripts. The diff carries the fix, its lock, and nothing else.
- **Floating-point comparison.** `max_usd` is compared through `awk`, not bash arithmetic; it is not an arithmetic-expansion context and it is not touched.
- **Retro-annotating any already-frozen spec, or editing `.shell-team/lessons.md`** (D12).
- **Making a rejected input *work*.** A `+10`, `0x10`, `1e3`, `2#101` or full-width-digit operand stays rejected; proving the rejection is in scope, widening the grammar to accept it is not.
- **Any change to `.shell-team/todo.md` beyond this task's own entry.**

1. **Loop-contract integer values** — `budget.max_iterations`, `budget.max_wallclock_min` in a hand-authored `*.contract.yaml`, in this repository or an adopter's. Real authors write `10`; a column-aligned or copy-pasted `08` / `010` is a plausible hand edit, and nothing validates the file between the author and `bin/loop-guard.sh`.
2. **Goal-loop state-file values** — `start_epoch`, `iteration` in the gitignored state file. Written by `bin/goal-state.sh` itself (never padded), but the file is plain text an operator can hand-repair after an interrupted tick, and `$GOAL_NOW` is an operator-supplied environment variable on the same path.
3. **Command-line integer arguments** — `--iteration`, `--elapsed-min` to `bin/loop-guard.sh` and `--round` to `bin/rework-digest.sh`, supplied by the run skill from `bin/goal-state.sh` output or typed by hand during a manual tick.
4. **Runs-JSONL numeric fields** — `tokens`, `duration_ms` read by `bin/rollup-runs.sh` / `bin/rollup-track.sh`. Written by `bin/log-run.sh` in the normal path, but a hand-appended or third-party-generated row is reachable and no validator runs between writer and reader; `field_num`'s `([0-9]+)` accepts a leading zero even though JSON forbids one.
5. **Board ledger sub-bullet counts** — `- intent-hash (vN)`, and `lines=<n>/<n> verdict=<n>P/<n>F` on a `- freeze-attestation` line. Hand-written by the freeze-runner; this is the exact class that produced T-1018's Blocker.
6. **Zero-padded date components** — `MM` / `DD` from a lessons-corpus entry heading or a board sub-bullet. Padded *by definition*, which is why `bin/check-playbook.sh:210` and `bin/playbook-promote.sh:144` already carry `10#`; this class is the reason the convention exists.
7. **Canonical-decimal producer output** — `grep -n` line numbers, `cut -d: -f1` over them, `awk` integer prints, `${#var}`, `$#`. File-derived and therefore in the search surface, but structurally unable to carry a leading zero or a sign; the correct classification is `NOT-REACHABLE` with the producer named.
8. **Grammar-conformant huge counts** — a 19-to-20-digit digit string in any of classes 1–5 (a held keyboard key, a generated value, a corrupted write). Reachable, and the reason the existing `^[0-9]{1,9}$` bounds were written; the width decision for each site is the issue's fifth requirement.
9. **Boundary shapes within `[0-9]+`** — `0`, `00`, `08`, `010`, an empty value, and an absent key. Every one is producible by classes 1–5 and each must land on a defined outcome (correct value, or the script's own namespaced refusal).

**Out-of-scope synthetic extremes** — inputs this spec explicitly declines to protect, so an adversarial gate has a boundary to push back against rather than an open ladder:

1. **Digit strings wider than the widest reachable class.** A 100-digit, 10,000-digit or megabyte-long numeric operand. No producer in any of the nine classes above can emit one: a hand-authored YAML scalar, a `log-run.sh`-written JSONL field, a board sub-bullet, an epoch and a `grep -n` line number are all bounded well under 20 digits. Once a site's width decision is recorded, proposing a wider value at that same site is not a new finding.
2. **Non-ASCII digit forms** — full-width `０１０`, Arabic-Indic digits, any Unicode `Nd` character outside `[0-9]`. Every reachable grammar is ASCII `[0-9]`, so these are rejected before arithmetic; making them *evaluate*, or localizing a diagnostic for them, is not a goal.
3. **Signed, based and expression operands** — `+10`, `-10`, ` 10`, `10 `, `0x10`, `1e3`, `2#101`, `64#z`, `1+1`, `$(…)`. Confirming they are rejected at the grammar is in scope (class 9); widening any grammar to accept one is not.
4. **Arithmetic injection through a non-digit field** — a payload in `prev_sig`, `--verdict-hash`, a `run_id` or an error string. Structurally impossible once a field's grammar is `^[0-9]+$`, and a task about the non-numeric fields is a different task.
5. **A shell other than bash, or bash in a non-default mode** — `dash` / `zsh` / `ksh`, `set -o posix`, an exotic `LC_NUMERIC`. Every file in `bin/` declares `#!/usr/bin/env bash`; the audit's claims are bash claims and are not portability claims.
6. **awk's, `expr`'s or `bc`'s numeric parsing.** Out of scope by D1; an awk program's own arithmetic is not a bash arithmetic context and is recorded as a reconciliation exclusion, not fixed.
7. **The 64-bit boundary as an infinitely refinable target.** Once a `- overflow:` row records `BOUND` or `NO-BOUND` with a reason, re-litigating the same site with a larger constant is not a finding.

**What the static half of the instrument cannot see, stated up front.** The pinned search commands are text scans and cannot, in principle, trace an arithmetic context assembled at runtime — inside an `eval`, behind a variable holding a construct, or in a dynamically built command line. Measured rather than assumed: `bin/` contains **zero** `source` / `.` directives and exactly two `eval` sites (`bin/retro-inputs.sh:375`, `bin/team-init.sh:147`), both evaluating only `export VAR=<%q-quoted path>` lines emitted by `bin/team-paths.sh --export`, which contain no arithmetic operator. The completeness guarantee for that class therefore rests on reading `--export`'s output shape, not on the grep — and the behavioural criteria (AC7–AC12) are what cover the runtime half, because a static scan alone cannot establish that a fix changed an outcome.

## Pre-commitment on rework rounds

Set before the first round, so the disposition is not decided under pressure. **Factual trigger**: the inventory or the classification draws independent Blocker/Major findings in **two consecutive** review rounds. **Contextual trigger**: a third round of rework on the inventory or classification is about to start. The default threshold is this repository's standing "two consecutive rounds" and it is not loosened. When the two conditions disagree, the factual one decides.

On trigger, the third round does **not** open with another patch. It presents the human with a split-or-redesign choice, each option carrying its actual content:

- **(a) Split the overflow class out.** Ship the `10#` sweep and the accounting; move every `- overflow:` decision and the two settled `goal-state.sh` width bounds to a follow-up task, leaving the wrap behaviour documented as accepted rather than fixed. This is the cheapest option and the one the routing map's own framing anticipates by treating the overflow class as a separate requirement.
- **(b) Redesign the classification.** Replace the four-leaf ladder with a two-axis record (reachability × normalization state) and drop the `NEEDS-WIDTH-BOUND` value, which is the leaf that carries the ordering tension D2 resolves by fiat.
- **(c) Keep the design and route back to pm-spec** to re-derive the ledger grammar, if the defects concentrate in the document's machine-read shapes rather than in the code.

Put the id in the text of the assertion it names, alongside its `zero-fixture=<value>` tag, so a reader of the suite output can map a failure back to a site row.
