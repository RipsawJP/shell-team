# Declared verification ceiling: a per-spec machine-readable declaration of the verification level QA can actually reach, carried onto QA's hand-off and the board's `READY_FOR_REVIEW` record so a green flag reads "green *up to*", and gated at a task's first freeze as a coordinating-session read

## Problem

`READY_FOR_REVIEW` is one token whose effective meaning varies per repository and per task. When a task's acceptance criteria include things the agents cannot do — a real-environment end-to-end (storage put → queue → worker), a manual deploy, anything behind cloud credentials — QA's PASS can only ever attest *unit tests plus static verification*, yet nothing in the loop declares or displays that level. A green flag therefore invites the misreading "green = done" at exactly the moment the load-bearing verification is still a human's. What exists today is adjacent but not this: `- verification-class: mechanism | no-mechanism` prices *review depth by deliverable class*, and QA hand-offs in this repository's own history mark individual items `environmentally-unverified` ad hoc. Neither is a declared, machine-readable ceiling, and neither reaches the board line a reader actually looks at.

**Goal (one sentence).** A spec declares, on one line in the declaration region it already has, the **verification ceiling** QA can actually reach for it — `unit-and-static` or `real-environment`, a closed pair with a mandatory non-empty rationale — and names, criterion by criterion, whichever criteria sit *above* that ceiling and therefore stay human-owned after the gate; `agents/qa-verifier.md` carries that declared value onto its own PASS block and onto the board line its `READY_FOR_REVIEW` hand-off appends, so a green flag reads "green *up to* this level; these items remain above it" rather than bare green; `agents/pm-spec.md` carries the authoring-time duty as one more `## Spec completion self-check` bullet; and `skills/run/SKILL.md` carries a fifth first-freeze read beside the four declaration-region gates it already has, refusing a freeze whose declaration is missing, duplicated, out-of-vocabulary or contradicted by a criterion demanding capabilities above the value declared — the mismatch case #333's third bullet asks for, in the same shape the existing gates ship, with **no new checker, no new `bin/` file and no new prompt-block file**.

**The grammar, frozen as a design rather than as an implementation detail.** One top-level `- verification-ceiling: unit-and-static | real-environment — <rationale>` bullet, in the region between the intent block's `BEGIN` marker and the `## Non-goals` heading, a sibling of the three keys already there (`- user-visible:`, `- verification-class:`, `- base-ref-discriminator:`) and never a region of its own. The vocabulary is **closed at two values in both directions**: `unit-and-static` means the loop's own gate can reach unit tests plus static and textual verification and nothing beyond the checkout; `real-environment` means it can additionally exercise the real runtime the criteria name. The above-ceiling list #333 asks for is carried as an indented `- above-ceiling: <who owns this criterion after the gate>` sub-bullet under **each** criterion that sits above the declared ceiling — reusing the shipped indented-sub-bullet idiom `- adopter-surface:` already uses, never a new free-text list section, and never one line standing for several criteria; where no criterion sits above the ceiling the rationale says so and no such sub-bullet appears. **Neither value is all-or-nothing, and this is the semantics rather than a permission:** the declared value states what the gate reaches for **every criterion not marked above it**, and the `- above-ceiling:` sub-bullet marks per-criterion exceptions under **either declared value**. A `real-environment` declaration carrying `- above-ceiling:` sub-bullets on the criteria the gate still cannot reach is therefore the honest form of the **mixed case** — a spec whose criteria span more than one real-environment capability class at different reach, say a staging storage-to-queue-to-worker path the gate genuinely exercises alongside a production deploy or credentialed work it cannot. That case has an honest declaration precisely because the pair partitions what the gate reached *by default* while the per-criterion sub-bullet carries every exception to it, which is why two values suffice and a third is neither needed nor added. **The exception set is bounded by a non-vacuity rule, so the symmetry cannot be used to say nothing: a declared value attests `at least one criterion at it`.** A spec every one of whose criteria would sit above a candidate value declares instead the **highest value at which at least one criterion is actually verified** — so the all-above-`real-environment` case cannot exist at all: a `real-environment` declaration under which *every* criterion is marked `- above-ceiling:` is refused as vacuous (it is interchangeable with `unit-and-static` and tells a reader nothing), and that spec's honest declaration is `unit-and-static` with its exceptions marked. `unit-and-static` is the floor and cannot be lowered further, so the one remaining degenerate case is documented rather than refused: a spec declaring the floor value while every criterion sits above even that must say so **in the declaration line's own machine-readable form**, by carrying the fixed token `no criterion verified at this ceiling` immediately after the declared value, ahead of the rest of its rationale. **The token exists to travel, and that is the point of making it a fixed string rather than free prose**: the artifacts an operator actually reads are the QA PASS block and the board line, not the spec, so a floor-case declaration whose disclosure stayed in the spec would still put a bare `unit-and-static` in front of a reader as if it meant baseline coverage — the exact green-equals-done misreading this whole task exists to remove. The record line therefore carries the declared value **transcribed verbatim** from the declaration, `including that token` whenever the declaration carries it, into both the PASS block and the board append. Transcription is copying, not judging: QA never decides whether a spec is a floor case, never adds the token to a declaration that lacks it and never drops one that has it, so the enforcement boundary is unchanged — the vacuity determination is made once, at authoring, and read by the freeze gate. Refused above the floor, disclosed at the floor and carried forward from there — in no case silent. QA reads the declared value **from the spec** and never invents, upgrades or infers it; reports each above-ceiling item with the **existing** `environmentally-unverified` token at the granularity the sub-bullet declared, under either declared value; and an above-ceiling item, standing alone, never forces a `FAIL` — exactly the footing that token already has at three sites in `agents/qa-verifier.md`. ## Input space

**Reachable input classes** — what this declaration, this gate and these criteria really encounter, and which the change must handle correctly:

- A spec every one of whose criteria the loop's own tooling can exercise from a plain checkout: declares `unit-and-static`, carries no `- above-ceiling:` sub-bullet, and says so in its rationale. This spec is that case.
- A spec with **one** criterion above the ceiling — a real-environment end-to-end (a storage put feeding a queue feeding a worker), a manual deploy, or work reachable only behind cloud credentials — carrying one `- above-ceiling:` sub-bullet naming who owns it after the gate.
- A spec with **several** criteria above the ceiling, each carrying its own sub-bullet. The grammar is per-criterion precisely so one line never stands for several, and the norm text is written for the plural case rather than assuming one.
- A spec whose loop genuinely can exercise the real runtime **every one of** its criteria names: declares `real-environment` and carries no `- above-ceiling:` sub-bullet, because nothing is left above what the gate reached.
- **The mixed case** — a spec whose criteria span more than one real-environment capability class at different reach: the gate genuinely exercises a staging storage-to-queue-to-worker path for one criterion while another needs a production deploy, or credentialed work, that it cannot reach. Declares `real-environment` for what the gate reached and carries an `- above-ceiling:` sub-bullet on **each** criterion it did not, which is the honest form for this class and the reason the closed pair needs no third value: the sub-bullet is available under **either declared value**, so neither value is all-or-nothing. Staying `unit-and-static` here would misclassify the criterion that genuinely *was* exercised, and a bare `real-environment` would overstate coverage of the one that was not; this shape does neither. **Its boundary, which is what keeps the symmetry informative**: the exception set must leave a non-empty complement — `at least one criterion at it` — so this class is reachable only while some criterion is genuinely verified at the declared value.
- **The vacuous declaration** — `real-environment` with **every** criterion marked `- above-ceiling:`, so the declared value attests nothing and is interchangeable with `unit-and-static`. Reachable because an author can write it, and **refused** at the first freeze by the non-vacuity rule, routed back with the canonical resolution named: the honest declaration for that spec is `unit-and-static` with the same exceptions marked. The refusal is about the empty complement, never about how many exceptions there are.
- **The floor case** — `unit-and-static` with every criterion sitting above even that. The floor cannot be lowered, so this one is **documented rather than refused**: the declaration stands and must carry the fixed token `no criterion verified at this ceiling` immediately after its declared value, ahead of the rest of its rationale. **The token is then carried forward** — the QA PASS block and the board append transcribe the declared value verbatim, `including that token`, so the reader who never opens the spec sees the disclosure on the line they actually read rather than a bare value that looks like baseline coverage. This is the one place a declared value legitimately attests nothing, and it says so in its own words on every artifact that repeats it. A floor-case declaration missing the token is refused at the first freeze exactly as a vacuous `real-environment` declaration is; a carried-forward record line that drops a token the declaration carries is a transcription defect, not a judgment call.

## Singular-determiner sweep

The declaration norm is one rule authored once and mirrored into two gate surfaces (`agents/pm-spec.md` and `skills/run/SKILL.md`) plus a consuming one (`agents/qa-verifier.md`), so its wording is read here for implicit cardinality-one assumptions about the things it governs. A finer enum (`integration`, `staging`, `production`) would encode an environment taxonomy this repository cannot observe, cannot validate and cannot bound — and #333 itself proposes exactly these two by name. The precision a finer enum would carry is instead carried per criterion by `- above-ceiling:`, which names the owner rather than the tier. **The mixed case is what makes this hold rather than an exception to it**, and the semantics are stated for **both** values rather than only for `unit-and-static`: the declared value says what the gate reached for every criterion not marked above it, and the per-criterion sub-bullet carries every exception under **either declared value** — so a spec exercising a staging queue-worker path for one criterion while a production deploy sits unreached for another declares `real-environment` and marks that one criterion above the ceiling.
