## Problem

The second of those two is missing outright: **there is no orchestration step anywhere in this repository that can launch N instances of one role for a single phase and reduce their partial verdicts to one authoritative verdict.** The first precondition's telemetry half landed since (T-1072's `--instance` discriminator, T-1076's append lock and `--seq auto`), and the harness question the pilot could not answer has since been measured — `docs/loop-engineering/harness-agent-concurrency.md` records `verdict: concurrent-overlapping`, a genuine four-way agent overlap on this harness. So the measurement, the telemetry substrate and the harness capability all exist, and the one thing that does not exist is the mechanism that would use them: a way to fix a population, split it disjointly across N instances, and combine what comes back without ever promoting a partial or torn result to the verdict a phase's existing gate reads.

**Goal (one sentence).** This task ships a Tier-1 fan-out mechanism in two halves — an orchestration step in `skills/run/SKILL.md`, canonicalized as a registered prompt block, that fixes a unit population before launch, splits it disjointly and exhaustively across N instances of one role, requires a per-instance liveness check and one orchestrator-emitted span per instance, and a new `bin/aggregate-verdicts.sh` that reduces the N per-instance part files to one authoritative verdict block whose verdict region is byte-identical under every partition of the same population, or **refuses** with a classified exit code and empty stdout rather than promoting a partial, incomplete or malformed result — and it wires neither: no phase is rewired to fan out by default, and adoption stays a later decision.

**D1 — one instance, one file; nothing appends to a shared target.** Each instance writes its own part file, at a path the orchestrator assigns it, and no two instances ever write to one file. This is `per-worker-output-files` (`phase-multiplexing.md:131`) taken as a contract rather than as a pilot convenience, and it is what makes `handoff-attributable` (`:165`) reachable: the aggregate carries a per-unit `- attribution:` line naming the instance that produced it, so the merged, board-visible record stays attributable to the instance that produced each of its parts. The rejected alternative is named with its ground: a single shared append target guarded by `bin/log-run.sh`'s new lock would serialize exactly the work the fan-out exists to parallelize, and the lock guards a telemetry row, not a verdict stream.

**D2 — the part-file grammar, byte-exact.** A part file is line-oriented. Blank lines are ignored; every other line matches exactly one of three shapes, where ` — ` is a space, U+2014 EM DASH, space:

```
- unit: <unit-id>
- verdict: <unit-id> — <payload>
- sentinel: <unit-id> — exit=<n> no-verdict-lines
```

A `- unit:` line is a **claim**: it declares that this instance was assigned this unit, and it exists so that coverage is decidable independently of whether the unit produced any output. `<unit-id>` is a non-empty string free of control characters and free of the ` — ` separator; `<payload>` is free-form and, being the last field on its own line, cannot forge a field — the same discipline `bin/derive-populations.sh` states at its own lines 34–37. `<n>` is one or more digits. A unit may carry **zero or more** `- verdict:` lines: the pilot measured 135 verdict rows over 9 units, so one-to-many is the ordinary case.

**D3 — the sentinel is mandatory for a zero-verdict unit, and exclusive of verdicts.** A claimed unit that produced no verdict line carries exactly one `- sentinel:` line, in the measured shape `exit=<n> no-verdict-lines` (`phase-multiplexing.md:111` — the pilot's own real instance recorded `SENTINEL: exit=2 no-verdict-lines` identically in all ten arm/rep runs). A claimed unit with zero verdict lines and no sentinel is a **refusal**, never a silently-empty result, because those two are exactly the cases a fan-out must never conflate: a unit that legitimately produces nothing, and a unit whose instance died before producing anything. A sentinel and a verdict line for the same unit is likewise a refusal — the sentinel asserts an absence the verdict contradicts.

**D4 — reconciliation is by value, as a multiset, never by row position.** The aggregate's verdict region is the record multiset of every part, ordered by one `LC_ALL=C sort` over whole lines. Positional pairing is banned outright, for the reason the pilot recorded (`:111`): a unit quoting an illustrative example inside a fenced block produces a **duplicate-labelled** record, and positional pairing turns that into a spurious difference that is an artefact of ordering rather than of concurrency. Two consequences follow, and both are contracts here. First, **duplicate verdict payloads are legitimate input and are preserved verbatim**, because a duplicate-labelled AC from a fenced example (`:182`, a documented real hazard in this corpus) is exactly what produces them — refusing a duplicate record would convert that measured hazard into a refusal, so the only duplicate this tool refuses is a duplicate **claim**, which is a partition defect rather than a datum. Second, **partition-independence**: for one fixed population, the emitted verdict region is byte-identical under every disjoint, exhaustive partition into parts, and under any ordering of records within a part or of the parts themselves. That property is what licenses reducing N partial verdicts to one authoritative verdict at all, and it is the generalization of the pilot's own measured result (nine of nine non-baseline arm/reps `identical`, `:115`–`:123`).

**D5 — the population is fixed before launch, disjointly and exhaustively assigned, and machine-checked.** The orchestrator enumerates the unit population once, before any instance is launched, and writes it to a population file; it is never re-selected after a verdict has been seen (`:90`, `:181` — the pilot's own deterministic-selection discipline, and the reason its abandoned first attempt contributed no data). Every unit is assigned to exactly one instance. The aggregator checks both halves against that file: a unit claimed by two parts, or claimed twice within one part, is a refusal; a population unit claimed by no part is a refusal; and a claimed unit absent from the population is a refusal. The union of claims equalling the population is therefore a machine-checked property of every successful aggregation, not a promise in prose.

**D6 — failure semantics: fail closed, with the retry case separable from the corruption case.** Exit codes are `0` aggregated, `1` refusal about the parts' **content**, `2` usage error about the **invocation**, `3` refusal because the fan-out is **incomplete** — the same 0/1/2 split `bin/derive-populations.sh` documents at its lines 51–61, extended by one code whose separateness earns itself: `3` is the case whose remedy is to re-run the missing assignments against the same fixed population, and `1` is the case where re-running blindly would repeat a defect. On every non-zero exit **stdout is empty**: no partial verdict is ever promoted to the authoritative one. Every refusal prints one classified first line on stderr in the shape `aggregate-verdicts: <class>: <detail>`, with `<class>` drawn from this closed vocabulary and from no other: `usage` (exit 2); `empty-population`, `duplicate-population-entry`, `out-of-population`, `duplicate-claim`, `unclaimed-record`, `malformed-record`, `control-character`, `missing-sentinel`, `sentinel-with-verdicts` (exit 1); `missing-part`, `empty-part`, `uncovered-unit` (exit 3). A declared part whose file is missing or empty is `3`, not `1`, because an instance that died and an instance that wrote nothing are the same operational fact: the fan-out did not finish.

**D7 — the degree rule, and why no number is hardcoded.** The orchestration step states the decision rule as `N = min(<unit count>, cap)`, where `cap` is `TEAM_FANOUT_MAX` when it is set to a positive integer, otherwise the host's own measured core count (`getconf _NPROCESSORS_ONLN`), otherwise 2. The measured knee (`n≥4` on an 8-core host) is recorded as **machine-local and not portable** (`phase-multiplexing.md:180`), so no degree literal is written into the shipped text. The wall-clock floor is disclosed in the same place rather than promised away: no degree of fan-out can push a phase below its single most expensive unit's own serial cost (`:56`, `:109`).

**D8 — per-instance liveness and the two harness constraints, stated as requirements rather than as a script.** The shipped step requires that an active liveness check run alongside each instance, started at the moment that instance is launched, and it requires the two mechanics the harness probe measured: a watchdog launched with a bare shell `&` inside a foreground Bash call **dies with that call**, so only a harness-tracked background launch survives (`harness-agent-concurrency.md:115`); and a sub-agent's default foreground Bash timeout is **120 s**, so any unit that can exceed it must be launched with an explicit per-call timeout (`:116`). The step names no particular watchdog script, because the one this operator uses is host-side tooling this repository does not ship (`:87`) — the requirement is that a liveness check exists, and which mechanism supplies it is the operator's choice.

**D9 — telemetry: one span per instance, emitted by the orchestrator, never by the instance.** Each instance's call gets its own span row carrying `--instance <role-qualified-id>`, and the ids follow the writer's own shipped grammar `^[a-z][a-z0-9-]*$` (`bin/log-run.sh:372`), so `qa-1` is accepted and a bare `1` is a validation error — this is a measured behaviour of the shipped writer, not a naming preference. Concurrent appends use `--seq auto` (T-1076), so no counter is carried across N instances. The emitting party is fixed: **the orchestrator emits every span row**, because an agent cannot see its own token/duration usage and, as evidence channel ③ recorded, agent-level fan-out cannot self-emit its own spans (`harness-agent-concurrency.md:143`). The aggregation step's own cost is recorded as `--span orchestrator --phase gate`, the T-1072 convention already shipped at `skills/run/SKILL.md:128`–`135`.

**D10 — the seven invariants, each declared and each labelled with what this task actually does to it.** The shipped block carries one `- invariant-lock: <id> — <declared|implemented> — <text>` line per id in `phase-multiplexing.md:15`'s closed seven-id vocabulary, and the criterion derives that id set from that line at run time. Three move from **declared** to **implemented** here: `fail-closed-checkers` (the aggregator refuses rather than promoting a partial verdict), `bin-pure-bash` (the new script is bash-3.2, zero-dependency and shellcheck-clean), `handoff-attributable` (per-instance part files plus the attribution region). One is implemented as **usage** of an already-shipped field: `per-instance-telemetry-discriminator` (`--instance` per instance, with T-1076's lock and `--seq auto` making the concurrent appends safe). Three stay **declared** and unrelaxed: `both-gates-green` (the aggregate feeds a phase's existing, unchanged gate; QA's `PASS` and the cross-provider `APPROVE` are both still required — `:160`), `human-gate-set` (no human gate added or removed), and `frozen-intent-no-concurrent-attest` (the freeze is attested by one role at one point in time at Specify, and the shipped step states that Specify is never fanned out).

## Input space

**Reachable input classes** — what real data and real usage in this repository and in an adopter's can produce, and which this mechanism must handle correctly:

1. **A unit population enumerated from this repository's own committed tree** — the spec corpus under the resolved specs dir is the measured example (the pilot's own stride-9 subset of a 73-file corpus, `phase-multiplexing.md:90`); unit ids are therefore repository paths carrying `/`, `-`, `.` and mixed case.
2. **A unit producing many verdict records.** Measured: 135 verdict rows over 9 units, with a per-unit fan-out of one-to-many (`:98`, `:125`).
3. **A unit producing zero verdict records.** Measured, and real: `design-note-T-1012.md` is a design note rather than a spec, `check-acs.sh` exits 2 against it with no `AC<n>:` line, and all ten pilot arm/rep runs recorded the identical sentinel row (`:111`).
4. **Duplicate verdict payloads within one unit**, produced by a spec quoting a duplicate-labelled AC inside a fenced illustrative example — a documented real hazard of this corpus (`:182`) that the value-matched method exists to survive and that must therefore be accepted, not refused.
5. **Verdict payloads containing arbitrary free text** — a checker's own message, an em dash, quotes, brackets. The payload is the last field on its line for exactly this reason.
6. **An instance that dies, stalls or is stopped mid-run**, leaving a missing part file, an empty one, or one whose claims are not all answered. The negative-control arm of the harness probe produced a real stall (`harness-agent-concurrency.md:104`–`:111`), so this is measured behaviour, not a hypothetical.
7. **Degrees from 1 to roughly one host's core count.** The pilot swept `n=1,2,4,8,9` on an 8-core host; the harness probe ran four concurrent agents. `N=1` (a degenerate single-part fan-out) is explicitly inside the space, because that is what makes partition-independence checkable against a serial baseline.
8. **Part files arriving in any order, with records in any order within a part** — N instances finish in whatever order they finish, and no ordering may change the authoritative verdict.
9. **A host without GNU coreutils** — this repository's own development host is macOS with bash 3.2, and adopters run these scripts in repositories this project knows nothing about.

**Out-of-scope synthetic extremes** — inputs this spec explicitly declines to protect, named concretely so the boundary is falsifiable:

- **Concurrency degrees far beyond one orchestrator session's reach** — hundreds or thousands of instances, or a sustained fan-out rate. The fixture floors (at least 4 parts, at least 8 units) bound what is protected; escalating that ladder further is not a defect this spec accepts.
- **Unit ids or payloads carrying control characters, newlines or the ` — ` separator.** These are refused (`control-character`, `malformed-record`), and a finding demanding that they be escaped, quoted or round-tripped is out of the input space: the format is line-oriented by construction, exactly as `bin/derive-populations.sh`'s is.
- **Ever-larger synthetic payloads or populations** — a single verdict payload of megabytes, or a population of tens of thousands of units chosen to make the sort cost visible. The tool's cost is O(records log records) and is disclosed rather than bounded.
- **Adversarial or forged part files** — a hostile local process writing a part file that claims another instance's units, or racing the aggregator by rewriting a part file mid-read. The aggregator reads complete files after every instance has finished; a hostile local process with write access to the scratch directory is outside this task's threat model.
- **Cross-host and network-filesystem fan-out.** Instances on two machines writing parts to a shared network path; declined outright, as in the sibling telemetry car.
- **Partial or streaming aggregation.** A "best available so far" result while instances are still running is precisely what D6 refuses; a finding asking for one is a request for a different mechanism.
- **Reconciling *disagreeing* verdicts for one unit.** The partition is disjoint, so no unit is ever run twice; a voting, quorum or tie-break rule is not designed here and a finding demanding one is out of scope.
- **Fanning out anything that writes.** Implementation work, worktree merges, board edits or freeze attestation. The 2+ concurrent-worktree reconcile stays NOT covered (`skills/run/SKILL.md:61`), and Specify is never fanned out.
