# Tier-1 fan-out adoption wiring + value-anchored versioning rule canonicalization

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1075

## Problem

Two gaps close in this car, the sprint's seventh and last.

T-1074 shipped the fan-out mechanism — `bin/aggregate-verdicts.sh` plus a registered prompt block carried by the run skill — but nothing in the loop's own phase sequence ever *reaches* it. The block sits after the Telemetry-binding paragraph in `skills/run/SKILL.md`, describing how a fan-out would work; no phase step tells the orchestrator that a choice exists at a particular moment, on a particular class of work. A capability documented but never reachable from the procedure that would use it is, from the loop's point of view, not adopted.

Separately, the operator ruled on 2026-08-16 that version numbers in this repository must encode how much more useful the deliverable became for whoever receives it — that work volume, diff size and invasiveness are not inputs, and that a large invasive change producing no user-felt difference is pure wasted cost. That ruling currently lives only in `.shell-team/interventions/T-1074.md`, a per-task record nobody consults when naming a release. `CONTRIBUTING.md`'s `## Cutting a release` says only that the number "follows semantic versioning applied to the surface this project declared stable at v1.0.0" — a definition of the *stable surface*, which answers what may break, not how much value the increment carries.
