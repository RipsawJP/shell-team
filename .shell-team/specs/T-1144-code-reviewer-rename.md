# The review role is renamed `code-reviewer`, with a one-release configuration alias, and its executor call sites name an explicit timeout

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1144

## Problem

The review role is named after the executor it happens to ship bound to. That binding is the shipped default and not an invariant — `CLAUDE.md`'s own "Working rules" section says so in as many words, and `templates/binding-default.conf` is where the default lives and where a host overrides it — so the role's name asserts something the project has already stopped guaranteeing, and a host that rebinds the role is left running an agent whose name contradicts its configuration. Separately, and independently of the name: the role owns three `codex exec` invocation sites, every one of which is a foreground pass that can run for tens of minutes, and none of them states the timeout the harness should hold the call open for. A pass that outlives the Bash tool's default is backgrounded, the role's turn ends, nothing resumes it, and the coordinating session discovers the stall only by watching a capture file grow — which is what the predecessor task's round-3 review pass did before its round-4 pass, which waited in a foreground poll, completed normally.

## Decision points, resolved

Design decisions are labelled `DP1`…`DP6` with no separating hyphen, matching the predecessor's convention and for its reason: the hyphenated form matches the opt-in tracker-key shape this repository's own checker looks for.

**DP1 — the record machine tokens and the capture stems are not renamed.** Three grounds. (i) They name the *pass and its executor family*, not the role: the stems are `codex-primary`, `codex-adversarial`, `codex-specreview`, and none of them contains the role name at all, so there is nothing here the rename reaches. (ii) The stem vocabulary is closed at three values by the role file's own canonical-naming Rule and read by `bin/check-review-input.sh` from the review record's `raw-capture` field; widening or renaming it is a change to a parsed contract, which is its own task. (iii) `### Codex Review verdict:` is parsed by `bin/close-out.sh`, `bin/check-spec-review.sh` and `bin/goal-state.sh`'s signature grep and appears in every already-committed review record; renaming it would either red every merged record's parse or require a dual-token reader, buying nothing. The coordinating session's note that new capture stems *may* use the new name is therefore declined with this ground rather than taken up: there is no stem component carrying the role name to change. **AC16** locks all five literals as a base-relative invariant.

**DP2 — the generated playbook blocks, and every consumer copy of those same regions, are exempt on a mechanical ground.** `.github/workflows/check-handoff.yml:174`–`:187` regenerates every prompt block from the resolved lessons corpus into a scratch copy and compares it against the shipped one. `.shell-team/lessons.md` is a record and is not edited, so an edit to `templates/prompt-blocks/playbook-*.md` would fail that comparison in CI. The exemption is therefore not a judgement about how much staleness is tolerable; it is what the shipped mechanism permits, and the alternative — editing the lessons corpus — is editing a record.

The exemption is **not confined to the block files**, and confining it there was the defect the freeze sweep caught before this spec was frozen. `bin/check-prompt-sync.sh` byte-copies each generated block into every consumer the registry names, and `bin/gen-codex-agents.sh` carries the marker lines through into the generated Codex agent files, so one token sitting in the lessons corpus is mechanically present at five further paths: inside a `<!-- BEGIN prompt-block: playbook-… -->` region in `agents/engineer.md`, `agents/qa-verifier.md` and `agents/tech-lead.md`, and inside the same markers in `.codex/agents/shell-team-tech-lead.toml`. A residual-absence criterion whose pathspec set includes `agents` and `.codex` while excluding only `templates/prompt-blocks/playbook-*.md` is therefore **unsatisfiable by any implementation that honours this task's Non-goals** — the only way to reach a zero count would be to edit `.shell-team/lessons.md` — and the red it produces after implementation is permanent rather than an absence the rename removes. The correction is to exclude by **marker region** rather than by path, which is what **AC14**'s two-stage read does: the regions are skipped wherever the generator put them, and every other line of those same files is held to the same absence as the rest of the renamed surfaces. The alternative considered and rejected: dropping `agents` and `.codex` from the pathspec set, which would buy satisfiability by abandoning the one surface the rename most has to reach.

**DP3 — `docs/loop-engineering/` keeps the superseded spelling; the operational documents do not.** Those files are dated analysis notes whose occurrences are, in the ones sampled, measurement rows and quotations attributing an observation to the role as it was named when the observation was made; rewriting the actor label of a recorded measurement edits a record. The live-rule concern is real and is answered rather than waved away: the dispatch target a role is actually launched under comes from `agents/*.md`'s frontmatter `name:` and from `skills/run/SKILL.md`, both renamed here, so a stale prose mention in an analysis note is a documentation inconsistency and not a dispatch failure. The cost is disclosed in `## Non-goals`, one sentence of the adopter documentation tells a reader why the old name still appears there, and the alias-removal task inventories it. The alternative considered and rejected: renaming them too, which enlarges the diff by the largest single block of occurrences in the repository and rewrites recorded measurements to buy consistency in documents nothing parses.

**DP4 — the block file `language-codex-reviewer.md` is renamed.** Its registry row is `contain` mode, which places no markers in the consumer, so the rename is a two-place edit — the file and its row — with nothing to change inside `agents/`. Left alone it would need a named, permanent exemption in **AC14**'s pathspec for a file whose name is the role's name, which is the one place a reader would most reasonably expect the rename to have reached.

**DP5 — the frozen-spec flips are accepted as a documented rename class, not papered over with a stub.** 27 merged specs carry `- check:` lines naming `agents/codex-reviewer.md` and flip to FAIL when the file moves; a further set names the role string. The alternative — a stub file at the old path — was priced and rejected on three consequences, each independently sufficient: it registers a duplicate role with the harness (two agents answering to two names for one role), it must satisfy the content assertions those criteria make (so it is not a stub but a second copy that drifts), and it needs its own row in every six-role table, which is the exact set of tables this task is consolidating. The flips are disclosed in `## Blast radius` with the command that derives them, and no merged criterion is repaired here.

**DP6 — the deprecation line is emitted where it reaches the operator, and exactly once.** `bin/resolve-executor.sh:329` calls `check-binding.sh --print-binding` with `2>/dev/null`, so a line written to stderr inside the validator is discarded on the resolver path — which is the path the loop actually runs. **AC7** therefore asserts the line at both levels and the engineer chooses the mechanism (stop swallowing, or emit from the resolver after normalization); what is fixed is that exactly one line appears in each case, never zero and never two. The line never goes on stdout: `parse_canonical_binding` re-asserts the delegated stdout line by line and refuses anything that is neither the schema line nor a six-field `bound` row, so a warning there is a refusal, not a warning.
