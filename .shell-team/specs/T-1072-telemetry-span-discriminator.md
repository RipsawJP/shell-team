## Problem

Issue #273 records three gaps in what this loop's telemetry can answer, and issue #277's first precondition names a fourth: a merged hand-off record cannot be attributed to the role instance that produced it, which is exactly what an N-instance fan-out (the Tier-1 width axis T-1069 measured) would produce. Two of #273's gaps were relayed to this task on a premise the tech-lead measured false — span rows already carry `duration_ms`, and `--seq` is caller-supplied so append locking cannot repair the duplicate-seq pairs — so the design questions this task actually faces are not the ones the ticket's original framing poses. What remains is a schema question with one field in it, a count that is stated in six places and is already wrong in two of them, and two emission conventions that need somewhere to live.

- user-visible: yes — the deliverable adds a field that appears in every span row an adopter's own `<base>/runs/*.jsonl` accumulates from the moment they update the plugin, adds a CLI flag to a script that is on their `PATH`, and changes what `/shell-team:run` emits in their repository. - verification-class: mechanism — the diff reaches `bin/` (the telemetry writer and its linter), `tests/`, and `skills/`, all executing surfaces, and it changes a checker's semantics (a key added to `check-run.sh`'s forbidden-on-event-rows array changes which inputs that checker refuses). Every item of the freeze-time protocol applies exactly as written, including the full-population downstream-impact diff; **nothing is priced down**.

**Goal (one sentence).** A span row gains exactly one new nullable field, `instance`, appended after `adapter` so the frozen key order and offsets ahead of it do not move; the span-only key count is settled to the same measured value at every one of its definition points across `bin/log-run.sh` and `bin/check-run.sh`, arrays and prose alike; gate and orchestration work becomes cost-bearing by being emitted as **span** rows under a documented naming convention rather than by relaxing the event-row grammar; and a substrate-reading checkpoint gets a convention built on the `parent_span_id` field that already exists, so neither of the two conventions adds a schema key.

**What the discriminator is, and what it is not.** `instance` is a **declared** label naming which instance of a role produced the row — the field an N-instance fan-out needs so that merged hand-off records stay attributable, per the closed invariant `per-instance-telemetry-discriminator`. It is never an observation of what executed, exactly as `provider`, `effort` and `adapter` are never observations. Its value is a bare lower-case token under the **same** character class the writer already applies to `--provider` and `--adapter` (`^[a-z][a-z0-9-]*$`, `BINDING_TOKEN_RE`), reused rather than widened, so `bin/log-run.sh` carries one identifier grammar and not two. A bare numeric id (`--instance 2`) is therefore **refused**: the field names an instance, and a name that is only a count carries nothing a merged record can be attributed by — the convention's own spelling is role-qualified (`qa-1`, `qa-2`, `engineer-a`), which is legal under the existing class and strictly more informative in a merged record than a digit. Omitting the flag records `null`, the `--tokens` precedent; an explicitly empty value records `null` too, the `--provider ""` precedent. The value is validated by the **writer only**: `bin/check-run.sh` does not charset-check `provider` or `adapter` today and does not gain a charset check for `instance` either, so the linter's job stays structural.

**Why the count is a multi-site settlement rather than a number.** The span-only key set is defined in two arrays and stated in four prose sentences, and at the branch point two of those sentences already disagree with the arrays (`bin/check-run.sh:147` says 13 against an array of 16). A task that adds a key to the arrays and edits the one sentence it happens to read leaves the corpus in exactly that state again. So the settlement is stated as an **invariant** the criteria re-derive rather than as a value: the two arrays agree as a set; every "`<n>` span-only" sentence in either file carries either the measured array length or that length minus one (the "other than `--span`" phrasing); and each file's stated span-row and event-row key counts equal the counts of a row the writer actually emits.

**Why gate cost becomes a span rather than a field.** Gate and orchestration work is recorded today as an EVENT row, and event rows carry no cost fields — a shape enforced twice over, by the writer's `SPAN_ONLY_FLAGS` rejection loop and by the linter's shape-mixing rule. Relaxing that would mean changing two mechanisms and reopening a grammar T-1011 closed. The cheaper and more honest repair is that work with a duration is a **span**: the orchestrator emits `--span orchestrator --phase gate … --duration-ms <d>` for gate and orchestration work it performs itself, alongside the event row that records the transition. The event row keeps recording *that* the transition happened; the span row records *what it cost*. The event-row grammar is frozen by this task, not merely left alone: a criterion below measures an event row written by this task's writer against one written by the branch point's writer and requires them byte-identical.

**Why the rehydration checkpoint needs no schema at all.** A substrate-reading checkpoint is a child span: `--span engineer-rehydration` with `--parent-span-id` naming the span it belongs to, using the field the row has carried since T-014. No key is added for it, no flag is added for it, and no agent prompt block is edited to emit it — the convention is documented where the orchestrator's own emission guidance lives, and the emission itself is the orchestrator's, not an agent's.

**What the task leaves behind.** Two edited `bin/` scripts, their two test suites extended, the run skill's telemetry section carrying both conventions, one note at `docs/loop-engineering/telemetry-span-discriminator.md` carrying the definition-point symmetry table and a dogfooded derivation of the two arrays' agreement, the adopter-facing clause in both READMEs, an appended line in `.shell-team/test-recipe.md`, and this task's records.

## Input space

**Reachable input classes** — what `bin/log-run.sh` and `bin/check-run.sh` really meet in this repository and in an adopter's, and what this task's criteria must handle correctly:

- **Instance ids this loop and an adopter would actually pass**: a bare role letter (`a`, `b`), a role-qualified id (`qa-1`, `qa-2`, `engineer-a`, `pm-spec-1`), and omission (the overwhelmingly common case today, since nothing fans out yet). All are the existing binding token class; omission records `null`.
- **Instance ids a caller will plausibly try and be refused**: a bare number (`1`, `2`) — the obvious spelling for the Nth instance of a fan-out and the one this task deliberately refuses; an upper-case or mixed-case token; an underscore form; a path-shaped value; the bare `-`. Each is exit `2` with nothing written, and a caller wrapping the call in `|| true` (as every in-repo caller does) loses that row silently — which is why the conventions spell instance ids explicitly rather than leaving the caller to guess.
- **Every existing span and event invocation shape**, unchanged: all 16 pre-existing span-only flags in every combination of supplied and omitted, all five `--event` ids with their per-id requiredness, `--effort -`, an empty-string value for any nullable flag, and a zero-flag invocation.
- **The committed telemetry corpus as it stands**: `shell-team.jsonl` and `close-out.jsonl` under the resolved runs dir, mixing span rows written before T-1058 (17 keys), after T-1058 (20 keys) and after this task (21 keys), plus event rows — all in one file, all of which both the branch point's linter and this task's linter must accept.
- **Rows carrying arbitrary `instance` values at lint time**, including values the writer would have refused: a hand-edited row, a row from a future writer with a widened grammar, a row from a third-party emitter. The linter accepts them on a span row and refuses them on an event row, matching how it already treats `provider` and `adapter`.
- **Both invocation forms**: `bash bin/log-run.sh` from this repository's checkout root, and the bare name `log-run.sh` with the plugin on `PATH` in an adopter's repository, from a different cwd and in either supported layout, with and without `TEAM_RUNS_DIR`/`RUNS_DIR` exported.
- **Both bash floors** — macOS stock `/bin/bash` 3.2 and a bash 5 build — and both collations, the caller's UTF-8 locale and `C`.
- **A checkout where the sibling `bin/check-run.sh` is missing or non-executable**, in which the writer's post-write self-check is skipped entirely and the writer still exits `0` — the documented behaviour the base-blob arms of **AC2** and **AC5** rely on.
- **A host with no `shellcheck`** (fails **AC14** closed).

**Out-of-scope synthetic extremes** — inputs this spec explicitly declines to protect against:

- **Instance ids beyond a short identifier** — a value of hundreds or thousands of characters, or a set of thousands of distinct instance ids in one run. The field names one of a handful of concurrent role instances; there is no length contract beyond the token grammar and no cardinality contract at all, and a finding demanding a bound, a truncation or an ever-longer synthetic id is `out-of-input-space`.
- **Instance ids containing NUL bytes, invalid UTF-8, a non-UTF-8 encoding, control characters, newlines or shell metacharacters.** The token grammar refuses every one of them at the writer; a finding demanding that the writer escape, round-trip or normalise them instead of refusing is `out-of-input-space`.
- **A telemetry file that is not this loop's own output** — arbitrary JSON, a JSON array, a pretty-printed object spanning lines, a file with a BOM, a binary file. `bin/check-run.sh` is a structural lint over a single canonical writer's output and says so in its own header; a finding demanding full JSON-parser behaviour is `out-of-input-space`.
- **Corpus sizes beyond this repository's own order of magnitude.** A finding demanding a streaming linter, a bounded-memory roll-up or a performance contract on a million-row file is `out-of-input-space`; no performance claim is made and none is asked for.
- **Concurrent writers appending to one telemetry file.** Interleaved or torn appends, duplicate `seq` values and lock contention are the **successor car's** subject by explicit split; a finding in this task demanding a lock, a retry or a `--seq` assignment mode is `out-of-input-space` and belongs on that car's issue.
- **Shells other than bash 3.2 and bash 5**, awk implementations beyond the POSIX feature set, and locales other than `C` and one UTF-8 locale.
- **Semantic validation of an instance id** — whether the id names a role that exists, whether two rows claiming the same id really came from one instance, whether the id agrees with `--span`. The field is a **declared** label exactly as `provider`/`effort`/`adapter` are; a finding demanding cross-field consistency checking, a closed vocabulary or an observation of what actually executed is `out-of-input-space`.
- **Consumption of the new field.** No roll-up column, no cluster dimension, no replay UI element and no report groups by `instance` in this task; a finding that nothing reads it yet is a correct description of this task's declared scope, not a defect in it.
- **Enforcement of either emission convention.** The gate-span and rehydration conventions are prose the orchestrator acts on; no checker enforces them here and the spec says so rather than implying a gate that does not exist. A finding that they are unenforced is `out-of-input-space`.
- **A checkout with no local `feature/1071-record-set-derivation` ref, a detached `HEAD` with no merge base, or a rebased branch whose base has moved.** Every criterion fails closed on the first two and none is widened for the third.
