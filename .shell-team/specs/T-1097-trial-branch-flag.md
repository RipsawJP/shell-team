# team-init --trial-branch: create and switch to the trial branch before scaffolding

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1097

## Problem

`docs/adopting.md`'s trial-adoption route (shipped by T-1094) is two manual lines: `git switch -c trial/one-ticket`, then `team-init.sh .`. Issue #348 — the deferred mechanical half of #334 — asks for the first line as a flag, so the route an adopter is told about is also the route the shipped scaffolder can perform. The capability is not blocked by anything: `bin/team-init.sh` invokes no `git` command at all today, and neither does the only script it calls (`bin/team-paths.sh`), so the flag is convenience over a capability that already ships whole. The cost is that adding a git write to a previously git-free script makes two adopter-facing claims false as written, in both language mirrors, and opens three states the flag must refuse rather than proceed from.

**Goal (one sentence).** `bin/team-init.sh` gains an opt-in `--trial-branch <name>` flag that, in the target repository and before any scaffold file is written, creates that branch and switches to it — refusing with exit 2 and a remedy-bearing message in the three states it cannot safely proceed from — while the no-flag path stays observably git-free, and the two adopter-facing claims that say otherwise are corrected in both language mirrors without changing anything else the trial section's shipped structure guarantees.

**The flag's shape and its ordering, frozen as a property rather than as an implementation note.** The flag is the two-token form `--trial-branch <name>`, parsed beside `--force`, accepted in any position an option may occupy, and combinable with `--force`. Its git work happens **after** argument and target validation and **before the first scaffold byte is written**, so a refusal leaves the target exactly as it was found: no base dir, no partial scaffold, no moved HEAD. That ordering is the property, and it is what makes a refusal cheap enough to be the right answer in the three cases below. The single-token `--trial-branch=<name>` spelling is deliberately **not** accepted — no flag in this script accepts it — and falls through the existing `--*` branch to exit 2, so there is one spelling rather than two.

**The three refusals, each with its own remedy in the message.** (1) The target does not resolve inside a git work tree — it is in no repository at all, or in a bare one. (2) The target resolves inside a work tree but is **not that work tree's top level**: creating and switching a branch is a whole-repository operation, so proceeding would move the branch of an *enclosing* repository the adopter never named — the single most damaging thing this flag can do, and the state the suite's own `$HERE/tmp-targets.*` fallback root sits in. (3) The named branch already exists in that repository. Each refusal exits 2 through the existing `die()` and prints a message naming both `--trial-branch` and an act the adopter can perform: `git init` for (1), `repository root` for (2), `already exists` for (3). Argument-level refusals are held to the same standard: a missing value, a value beginning with `-`, a second occurrence of the flag, and a name `git` itself rejects each exit 2 with a message naming `--trial-branch`.

**The dirty worktree is permitted, and that is a decision with a measured ground rather than an omission.** Issue #348's own sketch named a dirty worktree as a third fail-closed case; this spec decides otherwise, on four grounds. `git switch -c <new>` at HEAD moves only HEAD and creates a ref — it rewrites no working-tree file, so the switch itself cannot lose or corrupt uncommitted work. The documented commit step is path-scoped (`docs/adopting.md:328`), so unrelated dirt is never swept into the trial commit and survives the `git branch -D` teardown in the worktree. The flag's whole contract is the manual line it replaces, and refusing what `git switch -c` permits would fork the flag from the recipe it exists to shorten — pushing an adopter with ordinary local edits back to the manual route, which is the flag's only reason to exist. And the overwrite hazard a dirt refusal is sometimes reached for — clobbering uncommitted work under the base dir — is already governed by this script's skip-with-warning default and by `--force` being an explicit opt-in; the flag adds no new overwrite path. The permission is therefore carried as a **verified property, not a silence**: **AC8** requires that a dirty target survives the flag byte-for-byte, with nothing stashed, committed or reverted.

**`git switch -c`, not `git checkout -b`, with no fallback between them.** The shipped trial recipe already types `git switch -c` (`docs/adopting.md:326`, `docs/adopting.ja.md:331`), so the flag and the recipe it replaces stay one vocabulary rather than two; `switch` also carries a narrower surface than `checkout`'s pathspec/DWIM overloading, which matters for a write a script performs on the adopter's behalf. The portability objection is answered by measurement rather than by preference: an adopter whose `git` predates `git switch` cannot follow the shipped recipe today either, so the flag introduces no new floor. There is deliberately **no** `checkout -b` fallback path: where `git switch` is unavailable or refuses, git's own error surfaces and the flag exits 2.

**Scope boundary.** The flag creates the branch and switches to it. It does not `git add`, does not commit, does not push, does not set upstream, and does not tear anything down; those stay the adopter's own documented lines. The set of git subcommands the script may invoke is closed to what the flag's validation and switch actually need, and **AC9** measures that set from the script's own non-comment bytes.

## Input space

**Reachable input classes** — what real adopter usage and this repository's own fixtures can produce, all of which the implementation must handle correctly:

1. Target is the top level of an ordinary non-bare repository with at least one commit, clean worktree — the trial route's own shape (`team-init.sh --trial-branch trial/one-ticket .`).
2. The same, with a **dirty** worktree: modified tracked files, staged changes, untracked files. Permitted; preserved (**AC8**).
3. The same, with an **unborn HEAD** — a fresh `git init` with no commit yet. `git switch -c` is legal there (it renames the unborn branch), so the flag proceeds; the trial route's own commit step creates the first commit.
4. Target inside a repository but **not** its top level (a subdirectory). Refused with the flag; unchanged without it (**AC5**).
5. Target in **no** repository at all, and target inside a **bare** repository's directory (no work tree). Both refused by the same condition, with `git init` named as the remedy (**AC4**).
6. Target reached through a **symlinked** path that canonicalizes to the repository root — ordinary vendoring; accepted, because the top-level comparison is between OS-canonical paths (**AC5**).
7. A branch name that already exists; and a fresh name sharing a prefix with an existing one (**AC6**).
8. A branch name `git` itself rejects (`bad..name`, a leading `-`, an empty value) (**AC7**).
9. Flag placed before or after the positional; combined with `--force`; given twice; in the `--trial-branch=<name>` spelling; after a `--` terminator (**AC2**, **AC7**).
10. Both supported layouts and the `$TEAM_RUN_BASE` override — the flag is orthogonal to base-dir resolution and must not perturb it.
11. A target path containing a space (the suite already covers this class for the no-flag path).
12. A `git` executable on `PATH` that fails or is absent — reached in this repository's own fixtures by the **AC9** shim, and in the field by a `PATH` without git; the no-flag path must be indifferent to it and the flag must fail closed with exit 2.

**Out-of-scope synthetic extremes** — named concretely, and declined:

1. A `git` older than 2.23, with no `switch` subcommand: the flag surfaces git's own error and exits 2. No `checkout -b` fallback is built, on the measured ground that the shipped recipe already requires `git switch`, so no new floor is introduced.
2. A repository whose hooks (`post-checkout`, `reference-transaction`, `pre-commit`), local rulesets or server-side protections veto, alter or side-effect a local branch creation. Real, but not decidable from this checkout at any seam this loop owns; the flag reports git's own failure and exits 2.
3. `GIT_DIR` / `GIT_WORK_TREE` / `GIT_INDEX_FILE` environment overrides pointing the git plumbing somewhere other than the target, submodule and `git worktree`-linked checkouts where the named branch is checked out in a sibling worktree, and repositories mutated concurrently by another process during the run.
4. Branch names carrying newlines, NUL or other control characters, names longer than the host filesystem's component limit, and names differing from an existing branch only by Unicode normalization or case on a case-insensitive filesystem. `git check-ref-format`'s own verdict is the boundary; nothing beyond it is protected.
5. A hostile `git` on `PATH`. The **AC9** shim is a *fixture* that measures reachability, never a threat model: a `PATH` an attacker controls already owns every command this script runs.
6. Network operations of any kind — remotes, fetch, push, upstream tracking, credentials, and any repository this checkout does not create itself.
