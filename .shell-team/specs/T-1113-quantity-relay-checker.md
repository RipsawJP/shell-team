# T-1113 — A relayed count carries its own derivation command on the board entry, validated and re-run by a fail-closed checker

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1113

## Problem

A count one role writes in prose and another role relays keeps arriving wrong. The corpus lesson that names the class (`.shell-team/lessons.md`, 2026-08-24, extended 2026-08-31) already states the consumer-side remedy in prose — "a downstream consumer re-derives a relayed count from its co-located command instead of quoting the prose number, and a relayed count arriving with no derivation command is handled as the defect, not as data" — and prose alone has not closed it: six instances are on record in this repository, five of them from the two most recent sprints, and one of them is still live on the board today. The diagnosis is structural rather than a matter of care: the error rate tracks a role's *exposure* to transcribing a bare numeric literal, so the remedy has to remove the transcription rather than ask for more diligence. This task promotes that remedy from prose to a checker, which the lesson's own final sentence says is filed as its own backlog item.

## Non-goals

- **No bare-number prose hunting.** The checker never scans free prose for numbers and never tries to decide whether a sentence contains a count. The issue's own open design question — "what grammar marks a claim as derivable vs. free prose" — is answered by requiring an explicit opt-in row, and a count left in prose is invisible to this checker by construction. Instance 6 (`.shell-team/todo.md:3790`, spelled in words) is the standing demonstration that a bare-number hunt would not have caught it either.
- **Non-numeric relay claims are out of scope, and this is the disclosed gap.** Instance 2 — a reversed divergence *direction* — has no numeric value to compare and is not covered by anything this task ships. It is named here rather than folded into a count of instances addressed. A follow-up issue for direction/ordering/polarity claims is filed at close-out if wanted.
- **The live specimen is not edited.** `.shell-team/todo.md:3790`'s "five of the nine definitions carry a `Bash` token" sentence stays exactly as it is. It sits inside a merged-era board bullet, repairing another task's record is out of scope, and leaving it is what makes it available as evidence.
- **Surfaces other than the board entry are out of scope in v1.** Review records, spec files, provenance records, QA verdict prose and retro inputs are not read. A whole-board or whole-corpus scan is explicitly rejected rather than deferred: it would execute historical commands against dead refs, which is a different and much larger trust decision. Follow-up issues for the review-record and retro surfaces are filed at close-out if wanted.
- **No `--accept-status` field in v1.** A command whose legitimate outcome is a non-zero exit (`grep -c` finding nothing) is refused with a remedy naming the `| wc -l` idiom rather than accommodated by a status-declaration field. `bin/derive-populations.sh` already ships such a flag and its shape is the obvious import, but adding a second grammar field is a widening this task declines; it is named as an explicit follow-up.
- **No agent-hosted execution.** No agent definition is instructed to run this checker with execution enabled, and no hook, no CI step and no automatic path ever runs it outside `--no-exec`. Live execution is an explicit human/QA invocation, on the trust basis `bin/check-acs.sh:15`–`:31` states for itself **minus its second ground**, which this task does not inherit: that paragraph's subject is a spec, which this loop's freeze and review gates have passed before `check-acs.sh` is normally run against it, and this checker's subject is a board hand-off entry, which any role edits at any point in a task's life and which passes a gate only as part of the whole task at a seam. Both artifacts are equally committed and equally operator-owned; they are not equally reviewed at the moment of execution. The difference is **disclosed in the header** (**AC9**) and surfaced at run time by an advisory warning (**AC18**), never papered over by citation.
- **The collecting stem is not an attempt to enumerate every malformation, and its boundary is stated rather than left implicit.** The stem is widened on exactly the two axes round 1 measured as reachable near-misses — the field name's **case** and the colon's **width** — on top of the whitespace tolerance inherited from `bin/check-entry-mode.sh:309`. A row using an arbitrary synonym (`- tally:`, `- number:`) or an arbitrary misspelling (`- cout:`, `- counts:`) matches neither the widened stem nor the strict grammar and is therefore invisible to this checker, exactly as a count left in free prose is. This is a limit by construction, not a defect to patch in a later round: a collector cannot enumerate the set of things a writer might have typed instead, and each further widening buys one shape at the cost of collecting more ordinary prose. The measured near-miss classes are covered; the unbounded ones are declined here and in `## Input space`.
- **Live mode does not refuse an uncommitted board, and that is a decision rather than an omission.** A `git diff --quiet -- <board>` **refusal** gate was considered as the hardening for the provenance difference above and rejected on three measured grounds: it would redden this task's own dogfood (**AC13** runs live against the working board mid-task, when the entry is by definition uncommitted); it would refuse in ordinary adopter environments this repository declines to coerce — a board that is untracked, ignored, or in a checkout that is not a git repository at all, none of which `bin/team-paths.sh` requires; and it would buy less than it appears to, since a board committed on the task's own branch by the same role that wrote it is committed but still not reviewed, so the gate would trade a real cost for a provenance claim that still does not hold. The **advisory** form — one stderr line, exit status unchanged — is what ships (**AC18**), because it puts the fact in front of the operator at the moment of execution without deciding for them.
- **No existing checker's semantics are changed.** `bin/check-entry-mode.sh`, `bin/check-spec-review.sh`, `bin/check-handoff.sh` and `bin/derive-populations.sh` are byte-identical to their base blobs. `bin/close-out.sh` gains a delegation and changes in no other way (**AC10**).
- **No merged criterion is repaired.** Criteria this task's own files redden are **disclosed** in `## Blast radius` and left alone; repairing another task's frozen criterion is a class-B re-freeze of someone else's intent.
- **The lesson is not re-worded and no new norm is minted.** `.shell-team/lessons.md` is not edited. The sentence added to the prompt block is the mechanism's own grammar hook, not a restatement or an extension of the rule.
- **Merging any pull request, and the sprint batch GO, are out of scope.**

## Input space

**Reachable input classes** — what the checker and the criteria must handle correctly:

- A board file as this loop's own roles write it: LF-terminated UTF-8 markdown, `## Active` and `## Done` level-two headings, top-level entries of the form `- [ ] **T-NNN** <title> — \`<FLAG>\` — spec: <path>.md` (and `- [x] ` in `## Done`), sub-bullets indented two spaces, em dashes (`—`) used as field separators, and `### ` level-three narrative blocks interleaved between entries inside `## Active` — the shape this repository's own board carries today.
- The same board CRLF-terminated, per line, in whole or in part — the tolerance `bin/check-entry-mode.sh:131`–`:136` already applies for the same reason.
- `- count:` rows in every value shape the grammar admits: unsigned (`6`), explicitly positive (`+3`), negative (`-2`), zero (`0`), **signed zero** (`-0`, which compares equal to `0` — the one shape where a sign-strip-then-compare implementation and a string compare visibly disagree), and leading-zero (`08`, which compares as decimal eight and is never read as octal); one row per entry, several rows per entry with distinct labels, and zero rows per entry.
- Commands of the shapes this repository's records actually carry: a `grep -c`/`grep -c .` count, a `wc -l` of a pipeline, a `git show <ref>:<path> | grep -c` read of a committed blob, a `bash bin/derive-populations.sh …` invocation piped through `sed`/`awk`, and a command whose own text contains an em dash, a colon, quotes or a `#` — all of which must parse, because `command:` is the last field on the line by construction.
- Near-miss row shapes a human writing the record actually produces, in two families. **Field-name and separator shape**: a **capitalized or mixed-case field name** (`- Count:`), a **full-width colon** (`- count：`, U+FF1A — what an IME in Japanese input mode produces when the operator does not switch back, and this loop's own operator language makes that reachable rather than synthetic), a doubled space after the bullet dash, a space before or after the field colon, and a doubled space inside a ` — ` separator. **Field content shape**: a missing trailing field, an empty command, a label carrying a space / `+` / leading underscore, a non-numeric or **trailing-signed** value (`3-`, a suffix the leading-`[+-]?` grammar does not admit), and a duplicated label. Every one of these is **collected by the widened stem and refused**, never read as the conformant zero-row case.
- Command outcomes that are not a usable measurement: multi-line output, empty output, non-numeric output, output carrying **internal** whitespace (`6 7` — two tokens, refused as one piece rather than parsed down to its first token), and a non-zero exit status (refused, with the `| wc -l` remedy) — alongside one that **is** usable after normalization, output with **surrounding** whitespace (`printf "  6  "`), which is trimmed and compared rather than refused. The internal and surrounding cases are named together deliberately: they are the pair a single trimming implementation gets right or wrong at once.
- A board in any of the **four** git states an ordinary checkout produces, counted as four rather than three after spec review round 2 measured that two of them had been folded together: **(i)** inside a git work tree, tracked, committed-and-unmodified; **(ii)** inside a git work tree, tracked, carrying uncommitted modifications (which every task's own board is, mid-task, including this one's under **AC13**); **(iii)** inside a git work tree but **untracked or gitignored** — a fresh adopter install before the board's first commit, which is an ordinary environment and not the same state as (iv); and **(iv)** not inside a git work tree at all, which `bin/team-paths.sh` never requires the board to be. Live mode warns on (ii) alone and is silent on (i), (iii) and (iv); all four exit on the record's own merits. **AC18** exercises each of the four separately, and freezes the warning's condition as a tracked path's modification rather than as a `git status` `??` entry, which is what decides (iii).
- A board in which the requested task appears zero times or more than once in `## Active`, and a board path that is absent or unreadable — each an exit-2 environment or usage outcome, never a silent pass.
- An adopter checkout with the plugin loaded, where `bin/` is on `PATH` and scripts are invoked by bare name from a cwd other than this repository's root, and where `close-out.sh` runs against a board whose entries carry no `- count:` rows at all.
- A host with no GNU `timeout` binary on `PATH` — the measured state of this machine (`.shell-team/test-recipe.md:1484`–`:1495`) — on which the wrapper is skipped and commands run unbounded, disclosed in the header rather than silently assumed.

**Out-of-scope synthetic extremes** — inputs this spec explicitly declines to protect:

- A board file crafted to defeat the entry extractor by nesting a `## Active` heading inside a fenced code block, or by carrying a task id in a form no `bin/close-out.sh`-written board ever produces (a `- [x]` line inside `## Active`, a `- [ ]` line inside `## Done`). Live execution is arbitrary code execution by design and by disclosure, on the `bin/check-acs.sh:15`–`:31` trust basis **as qualified in `## Non-goals`** — its first and third grounds inherited, its second ("specs are trusted, committed, reviewed artifacts") replaced by the weaker and honestly-stated fact that a board entry can be executed before any review of the entry itself. The checker bounds runtime where it can, warns about the board's uncommitted state (**AC18**), and does not attempt to sandbox. Escaping `bash -c` is out of scope under either the strong or the weakened ground: an operator who invokes live mode has already decided to run the record's commands, and a sandbox is a different and much larger design than this task.
- Adversarially large inputs: a board with thousands of entries, a `- count:` row whose command emits megabytes, a label at the limit of the identifier grammar's length, or an entry carrying hundreds of rows. Real hand-off records carry single-digit numbers of count rows.
- Non-scalar claims: a direction, an ordering, a polarity, a set difference stated in prose, a percentage, a ratio, a duration or any value that is not a single signed integer. Instance 2 is the named live example, and it is a Non-goal rather than a gap this grammar is stretched to cover.
- Counts written anywhere other than a `- count:` row on the task's own `## Active` board entry — in prose on the same entry, in a review record, in a spec, in a retro. Out of scope by the surface decision, not by oversight.
- Multibyte, RTL, zero-width or combining characters inside a label. The identifier grammar is closed to `^[A-Za-z0-9][A-Za-z0-9_-]*$` by construction, so any such character is refused as a grammar violation and no further behaviour is specified for it.
- **Field names that are neither `count` in some case nor `count` with a full-width colon**: an arbitrary synonym (`- tally:`, `- number:`, `- total:`) or an arbitrary misspelling (`- cout:`, `- counts:`, `- ocunt:`). These match neither the widened collect stem nor the strict grammar and are invisible to the checker, exactly as a count in free prose is. This is the declared boundary of the collect-wide widening and is not a gap a later round patches: the two axes the stem **is** widened on (case, colon width) are the classes round 1 measured as reachable near-misses of a correctly-spelled field name, whereas the set of words a writer might have used instead is unbounded, and each further widening buys one shape at the cost of collecting more ordinary prose sub-bullets and refusing them.
- **A board whose uncommitted state is adversarial rather than incidental** — a board modified between the checker's git-state read and its execution of a row's command, or a `.git` directory crafted so `git` reports a clean tree that is not. The **AC18** warning is an advisory disclosure for an operator, not a synchronization primitive or a tamper detector, and no criterion claims it is one.
- Other multibyte colon-like characters (U+2236 RATIO, U+A789 MODIFIER LETTER COLON, a colon followed by a zero-width joiner). U+FF1A is admitted to the collect stem because this loop's own operator writes Japanese and a full-width colon is what an un-switched IME produces; the rest are declined on the same unbounded-set ground as the synonyms above.

1. **The collect-wide/parse-strict discipline is the defect class this checker is most likely to reproduce — and it already caught this spec once.** `bin/check-entry-mode.sh` had it defeated three times at three different marker families (T-1096 Blocker 2, Codex round-1 Major 4, and again in round 2) — every time the same way: a stem net narrow enough that a malformed line matched neither the stem nor the strict grammar and so read as the conformant empty-family case. This spec's own round-1 stem reproduced it a fourth time: it was copied from `bin/check-entry-mode.sh:309`, which is still lowercase and ASCII-only on its field name, so `- Count:` and `- count：` fell straight through. Write the stem **exactly** as:

   ```
   ^[[:space:]]*-[[:space:]]+[Cc][Oo][Uu][Nn][Tt][[:space:]]*(:|：)[[:space:]]*
   ```

   **AC3** byte-pins that string, and three properties of it are deliberate rather than stylistic. (i) The case-insensitivity is spelled as explicit ASCII character alternatives instead of `grep -i`, so it cannot leak into any other pattern the file matches. (ii) The colon tolerance is an **alternation**, never a bracket expression: under `LC_ALL=C` — which every criterion here exports and which the shipped script should not assume away — a bracket expression containing the three-byte U+FF1A decomposes it into its individual bytes and would then match a lone `0xEF`, `0xBC` or `0x9A`; an alternation of a one-byte and a three-byte string does not. A bracket expression additionally risks the POSIX `[:` character-class opener where the ASCII colon lands first. (iii) The full grammar stays **strict** — bare lowercase `count`, an ASCII colon, exactly one space after it — so every shape the widened stem newly collects is refused, which is the whole point of widening it. **The boundary is declared, so do not keep widening**: synonyms and misspellings of the field name are out of scope by construction (`## Non-goals`, `## Input space`), and a round-3 finding proposing `- tally:` or U+2236 is answered by that declaration rather than by another character class.
2. **`grep -c` exits 1 on no match.** This is the trap the remedy message exists for, and it is also a trap in the checker's *own* code: every internal `grep -c` needs `|| true` or an equivalent, or `set -e` turns a legitimate zero into an abort. `bin/derive-populations.sh:373` and `:439` show the idiom this repository uses.
3. **Numeric comparison, not string comparison — and trim before you compare.** `+3`, `3` and `03` all equal three; `08` must not be read as octal (bash's `$((08))` is an error — use a sign-strip plus `10#`, or `awk` arithmetic). `-0` equals `0`, and it is the shape where a string compare and a numeric compare visibly disagree, so it is the one worth probing first. A measurement carrying surrounding whitespace (`printf "  6  "`) is **trimmed and compared**, never refused — trimming is part of "is this a single numeric token", not a separate leniency, and it must not be so aggressive that it turns an internal space (`6 7`) into a single token: strip leading and trailing whitespace, then require what remains to match `^[+-]?[0-9]+$` in one piece, which refuses `6 7` and the multi-line case for the same reason.
