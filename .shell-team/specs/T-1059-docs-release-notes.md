# The reviewer invariant becomes a default with a stated rationale, and the release presentation gets a shipped template

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1059

## Problem

Five shipped documentation sites still assert cross-provider review as an **unconditional invariant** of this loop — "the reviewer stays cross-provider", "cross-provider review is mandatory", "keep the Codex reviewer in the loop — it is not optional". Sprint v2.0.0 made that assertion false as stated: `bin/resolve-executor.sh` resolves every bound role's executor from a config a host may author, and a host-authored `binding.conf` may legally bind `codex-reviewer` to a Claude-family executor. What actually remains true is narrower and has four parts — it is the **shipped default**, it exists for a stated reason, a rebind changes specific things, and the loop no longer structurally guarantees cross-provider review. Separately, issue #223 records that the two presentation surfaces of a GitHub Release (title and body) drifted across nine releases because `CONTRIBUTING.md`'s `## Cutting a release` procedure specifies neither, and ratifies two forward-only rules whose disposition is this task.

## Summarized sources

- `templates/binding-default.conf` (comment block at the `codex-reviewer` row; the `bind codex-reviewer codex provider-configured - codex-cli` row) — the distinction carried over: the reviewer's Codex binding is the *shipped default* of a configurable mechanism, not a hard-wired property; the sentence this spec restates is "remains the shipped default", and the word **default** rather than **invariant** is the distinction.
- `docs/loop-engineering/task-envelope.md` `## The generalized invocation pattern` (the availability-probe sentence) — the distinction carried over: an unavailable or unauthenticated Codex CLI is `BLOCKED` **with the exact error, never a silent substitution of a same-family reviewer**. This bounds what fails closed (a *silent* substitution at invocation time) and says nothing about whether a *declared* same-family binding is legal. The rewrite must not flatten those two into "same-family review is impossible".
- `templates/prompt-blocks/executor-resolution.md` (single-line canonical block) — the distinction carried over: refusals are blockers, "Never substitute another executor for a role whose resolution refused", and the block's own closing clause bounds its telemetry claim honestly rather than papering over it ("a role's actual invocation still routes through that role's own pinned model value, not through this resolution"). That last clause is the measured basis for element (d): resolution is rebindable, the invocation surface is not yet wired to it.
- GitHub issue #223 (operator-ratified 2026-08-10; body captured first-hand by the coordinating session) — the distinctions carried over: the title rule (bare tag name, no prefix, no suffix), the five body properties of the template (no in-body version heading; `## Highlights` transcribed verbatim from `CHANGELOG.md`; `## Migration notes` **omitted, not left empty**, when not applicable; `## Install / update` static boilerplate; `## Links` with both changelogs and a compare link), and that **both rules are forward-only** — past bodies are not edited. The issue's disposition names "T-1058" as the shipping task; that naming predates the #227 insertion that renumbered the docs task, and the obligation is this task's (recorded in `## Assumptions`).
- `.shell-team/specs/T-1015-cutting-a-release.md` AC1 / AC2 / AC3 and the criterion asserting the section's vocabulary — the distinction carried over: those criteria pin **ten whole bullet lines** of `## Cutting a release` with `grep -qxF`, and one further criterion forbids the substrings `host`, `terminal`, `laptop` and the word `gh` inside that section while requiring `semantic versioning`. Read at HEAD's working tree, first-hand. This is why #223's "two lines" land as **two new bullets** and never as edits to a pinned bullet.
- `.shell-team/specs/T-1000-operating-conventions.md` (the two `CONTRIBUTING.md` check lines at its PII/vocabulary and duplication criteria) — the distinction carried over: `CONTRIBUTING.md` must carry `sandbox` exactly once, `Merging always requires the maintainer` exactly once, `goes through the loop this` exactly once, and must **not** contain `claude --plugin-dir`, `one entry per release, newest first` or `plugin marketplace update`. The last of these is why the `marketplace update` boilerplate lives in the template file and not in `CONTRIBUTING.md`.
- `tests/team-init/run.sh` (its `AGENTS.md` block, read at HEAD) — the distinction carried over: the scaffolded `AGENTS.md` is content-asserted by a live suite — it must match `Codex` case-insensitively, must name `todo.md`, `READY_FOR_ARCH`, `project_status` and `MEMORY.md`, and must contain **no `YYYY-MM-DD`-shaped date**. This contradicts the relayed claim that this task's executional blast radius is zero.

## Goal
