## Problem

T-1144 gave the Codex agent generator and its checker a migration path for an adopter's pre-rename `shell-team-codex-reviewer.toml`, and the cross-provider review's final round reproduced two gaps in it, both judged Minor and carved out to issue #546. The generator's removal gate tests `-f` and the checker's audit loop skips any entry failing `-e`, so a **dangling symlink** at that one name is neither removed nor reported — the checker prints `in sync` while a broken artefact sits in the out-dir under a name the project itself owns. Separately, a checker invocation scoped with `--roles` prints a remedy carrying the resolved `--root` and `--out-dir` but not the role list, so following the printed command widens the regeneration to roles the invocation had deliberately scoped away from. Issue #545 is the documentation half of the same T-1144 change: `bin/check-binding.sh`'s header "Refusal matrix" comment — the enumerated, closed list readers and fixtures treat as the contract — still lists the pre-alias set and omits the `collision` token the script can now emit.

## Input space

**Reachable input classes** — the situations these two predicates and this printed remedy really meet, which the implementation must handle correctly:

1. An out-dir holding `shell-team-codex-reviewer.toml` as an ordinary **regular file**, written by a pre-rename release of this same generator. The shipped, already-handled migration case.
2. The same name as a **dangling symlink** — an adopter who symlinked generated TOMLs in from another checkout or a vendored directory that has since moved or been deleted. Reachable from real adopter usage; nothing this project ships creates it.
3. The same name as a **symlink resolving to a regular file** elsewhere, and as a **symlink resolving to a directory**.
4. The same name participating in a **symlink resolution loop**, the shape an interrupted or hand-made relink leaves behind.
5. The same name as a **directory**, or as another non-regular occupant such as a **FIFO**, created by an adopter's own tooling.
6. A checker invocation scoped with `--roles` to a subset of the five, and a checker invocation on the default list; each with the default `--root`/`--out-dir` and each with either or both overridden.
7. A generator invocation whose `--roles` **excludes** `code-reviewer`, which must still leave the legacy occupant untouched whatever its type — the gate T-1144 round 4 established and this task does not widen.
8. An out-dir additionally holding an unrelated `shell-team-*.toml` the run does not own, which must still receive the generic message rather than the legacy hint.
9. A reader — a human, a fixture, or a later task's author — treating `bin/check-binding.sh`'s header refusal-matrix comment as the closed contract of what that script can emit.

**Out-of-scope synthetic extremes** — inputs this spec explicitly declines to protect:

1. Symlink chains of ever-increasing depth, or occupants nested behind more than one level of indirection. One hop is what the predicates decide; a chain that resolves is an ordinary resolving symlink and a chain that does not is an ordinary broken one.
2. Time-of-check-to-time-of-use races: the occupant changing type between the gate's predicate and the `rm -f`, or between the checker's predicate and its report. No locking, no re-stat, no atomicity claim is introduced, and the existing `die` on a failed removal remains the whole story.
3. An unwritable or read-only out-dir, an occupant whose removal needs elevated privileges, and a full or read-only filesystem. These already surface through the shipped refusal paths and are not re-engineered here.
4. Filenames carrying control characters, newlines or non-UTF-8 bytes anywhere in `--out-dir`, and `--roles` values carrying shell metacharacters, newlines or hundreds of tokens. Role-token validation is the generator's own existing surface, unchanged by this task; the hint quotes what it was given.
5. An adversarially constructed `.codex/agents` designed so that following the printed remedy harms the adopter — for instance a symlink at the legacy name the adopter deliberately relies on. The threat model is this repository's own: the operator and the working directory are trusted, and what is defended against is accidents and stale upgrades.
6. Any occupant at a basename other than the one hardcoded legacy name, and any general stale-file or orphan cleanup in `--out-dir`.
7. Refusal tokens `bin/check-binding.sh` might emit in some future version, or tokens reachable only through code paths that do not call `refuse`. The set identity is measured over the file as it is, at each ref, and re-derives both sides at run time.
