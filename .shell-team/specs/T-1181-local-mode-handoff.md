# In `local` record mode the loop's records are written and never committed: one canonical record-mode block for the four roles and both run skills, with tracked text kept byte-for-byte

**Owner**: pm-spec

## Problem

#711 task A (T-1180) gave a clone a declared record mode: `git config shell-team.mode local`, read by `bin/team-mode.sh`. Under that mode `check-durability.sh` skips and `team-commit.sh` refuses base-dir paths. No role or skill text knows about the mode yet. Nothing tells the orchestrator to read it, a Bash-less role has no way to learn it, and every instruction that commits a record (the interventions append, the Implement-to-Validate seam, the pre-merge backstop, the host-dispatch commit rule) still says "commit". An adopter who sets the key today gets an orchestrator that tries to commit records the clone deliberately keeps out of git, and then `team-commit.sh` refuses those commits. This task is #711's task B of three: it carries the `local` branch into the shipped role and skill text. Setup, init, the PII scan's explicit-path mode, the shipped docs and the live two-gate run stay with task C.
