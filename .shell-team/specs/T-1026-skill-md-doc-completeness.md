## Problem

Two shipped surfaces in `skills/run/SKILL.md` describe a mechanism narrower than the one that actually runs, and in both cases the operator who follows the document lands in a state the document does not name.

**#84.** The replay rail derives the board flag from a bare `READY_FOR_*` token in **any** event row's `label`, uniformly across all five event kinds — `templates/loop-replay.html`'s `adaptRow` calls the single match rule `flagFromLabel(row.label)` on the `handoff`, `rework`, `gate`, `human` and `release` arms alike, with no per-event-id branch. The Telemetry section states that convention only under the `handoff` bullet; the `human` bullet never mentions it. An operator who settles the flag directly at a gate — the exact case the template's own comment names — has no way to learn from the document that putting the bare token on that `human` row reaches the rail.

**#105.** The step-2 `attestation` branch is written as a three-way post-append outcome: `structural` → record the vN hash, `aligned` → record nothing, `drift-detected` → escalate. A fourth outcome is reachable and unnamed: `bin/check-intent.sh`'s pace rule walks `v=1..N` and refuses at the **first** version whose record count is not exactly one, so when more than one version's record is missing, appending the named version's record makes the re-check report `attestation` **again**, naming the next missing version. The document's enumeration says "branch on what it now reports" and then lists three branches that do not include the one the operator is looking at.

Neither gap is a code defect — both mechanisms behave correctly. The defect is documentation completeness on a file whose readers are agents executing a gate procedure.
