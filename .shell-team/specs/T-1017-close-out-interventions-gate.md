# Close-out refuses a task whose interventions record is missing or non-conformant

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1017
**Source**: GitHub issue #90 — the tooling half of the promoted corpus lesson `## 2026-08-01 — Close-out verifies the task's interventions record exists`, whose human-facing half landed with T-1015 as `CONTRIBUTING.md`'s records-complete bullet. Backlog item of the v1.3.0 sprint goal (mechanize unenforced loop invariants).
**Base**: the T-1016 close-out commit `e18e50d`, on top of `develop` @ `e63b286`
**Branch**: `feature/90-close-out-interventions-gate`

## Problem

The loop's interventions record is the only durable channel for the moments a retro cannot reconstruct: a human interrupted, a measurement contradicted an assumption, work was deferred or abandoned. `bin/check-interventions.sh` (T-1002) can verify one, `agents/qa-verifier.md` is told to run it, and `CONTRIBUTING.md` line 53 tells a contributor the record must exist before the board entry moves. Nothing enforces any of that at the one moment where the omission becomes permanent — the close-out that moves the entry into `## Done` and ends the task.

The gap is not hypothetical in this repository. `.shell-team/interventions/` carries records for T-1002 through T-1016 with exactly one hole: T-1010 has none, and its board entry is closed. Nothing failed when it was closed, nothing has failed since, and nothing would catch the next one — the same shape as T-1016's incident one layer up. `bin/close-out.sh` already carries two fail-closed gates that refuse before any board write (T-068's pending-disposition gate, and the pre-write `check-handoff.sh` interlock that now surfaces the checker's own stderr), so the mechanism this needs already exists in the file, applied to two other invariants.

This is pattern-following work — a third gate of a shape the script runs twice — with one part that is genuinely new and gets the careful treatment: `bin/check-interventions.sh` conflates *usage* and *structural* into a single exit code `2`, so a straight pass-through would tell an operator with a broken record that they invoked close-out wrong.

## Goal

<!-- BEGIN intent-block: T-1017 -->

At `--task T-NNN` close-out, `bin/close-out.sh` resolves the task's interventions record and verifies it through `bin/check-interventions.sh --task T-NNN`, before any board write. A missing, unreadable or non-conformant record refuses the close-out fail-closed, leaves the board byte-identical, prints the checker's own stderr followed by a one-step remedy naming the record path and the exact bytes of a conformant zero-entry record, and exits `1`. An unusable checker or an unresolvable interventions directory exits `2` and never falls back to a guess. The gate inspects only the task being closed: `## Done` history, the repository's own historical gap and every other task's record are untouched, and no backfill or migration is performed. `bin/check-interventions.sh` itself is unchanged.

### Terms

| term | definition |
|---|---|
| **the record** | the single file `<interventions-dir>/<TASK>.md` for the task named by `--task`, where `<interventions-dir>` is resolved per D2 |
| **conformant** | `bin/check-interventions.sh --task <TASK> -- <record>` exits `0` — its own structural-and-schema judgment, not a new one |
| **classification token** | the first field the checker prints on stderr on every rejection path — `usage`, `structural` or `schema`; its header states this exists so a caller "can distinguish usage/structural errors from a genuine schema violation without parsing prose" |
| **the gate** | the block this task adds to `bin/close-out.sh`: resolution, screening, checker invocation, classification, refusal |

### Settled decisions

Each decision below is resolved. Nothing here is left to implementation judgment.

- **D1 — the gate is unconditional on every `--task` close-out, and there is no escape hatch.** No flag, no environment variable, no "warn instead of refuse" mode, no exemption for a task whose id is absent from the interventions directory.
  - **Why none.** An opt-out on a records gate makes the gate advisory, and an advisory gate is what this repository already had — a sentence in `CONTRIBUTING.md`. The remedy is never expensive: the conformant zero-entry record is three lines of literal text the refusal message prints in full, so no legitimate "I cannot produce one" case exists for a task that reached close-out. The precedent this mirrors, T-068's pending-disposition gate, has no escape hatch either, and adding one here would make the two gates disagree about how seriously the script takes its own refusals.
  - **The compat cost is real, accepted and bounded.** An adopter who has been running `bin/close-out.sh` without ever writing interventions records is newly refused. It is bounded by the remedy being one file of three lines, by the message printing those bytes verbatim, by the gate reading only the task being closed (so no historical record is demanded — D8/D10), and by the refusal leaving the board untouched so nothing is half-done.
- **D2 — resolution honors `$TEAM_INTERVENTIONS_DIR` at the same precedence `$TEAM_TODO` already has for the board, else `bin/team-paths.sh --get interventions`; a resolver failure is exit `2` with no guessing fallback.** The record path is `<dir>/<TASK>.md`. An empty `$TEAM_INTERVENTIONS_DIR` is treated as unset, matching the `${TEAM_TODO:-}` semantics in the board-resolution block directly above.
  - **Why the override is honored.** `bin/team-paths.sh --export` already emits `TEAM_INTERVENTIONS_DIR`, so a caller that eval'd the export block and then changed directory would otherwise have close-out silently disagree with the environment it was handed. The board resolution six lines above is the same shape; a second resolution in the same script with a different precedence rule is a dialect, and this repository has just spent a task removing one.
  - **Why no fallback.** The board resolution's own comment states the rule: writing to a guessed path is worse than failing. Guessing here is worse still — a guessed directory that happens to be empty produces a *refusal* attributed to the operator's missing record, and a guessed directory that happens to hold a same-named file verifies the wrong task's record.
  - **Measured consequence, accepted deliberately: every existing happy-path fixture in `tests/close-out/run.sh` newly fails.** Those fixtures `cd` into a scratch root passing only `TEAM_TODO=…`, and no scratch root has an interventions directory; under D2 the resolver returns a path relative to that root and finds nothing. Updating them is required work in this task, not collateral damage — `tests/close-out/run.sh` is on the scope-lock allow-list for exactly this reason, and AC13 is what forces it.
- **D3 — the exit-code mapping is total, and the checker's exit `2` is normalized by classification token rather than passed through.** `bin/close-out.sh`'s taxonomy is unchanged: `1` = a refusal about the state of the work (board or records), `2` = usage, validation, resolver or install error. Every condition the gate can reach maps into it:

  | # | condition | close-out exit | reason string |
  |---|---|---|---|
  | (0) | checker exits `0` | gate passes | — |
  | (i) | the record path is absent, is not a regular file, or is not readable (screened by close-out itself, before the checker runs) | **1** | A |
  | (ii) | checker exits `1` (`schema`) | **1** | B |
  | (iii) | checker exits `2` and its stderr carries the `structural` classification token | **1** | B |
  | (iv) | checker exits `2` and its stderr carries the `usage` classification token | **2** | C |
  | (v) | `bin/check-interventions.sh` is absent or unreadable next to `bin/close-out.sh` | **2** | C |
  | (vi) | checker exits `2` with no recognized token, or exits with any other non-zero status | **2** | C |
  | (vii) | the interventions directory cannot be resolved (no `$TEAM_INTERVENTIONS_DIR`, and `team-paths.sh --get interventions` fails) | **2** | D |

  - **Why normalize rather than pass through.** Rows (iii) and (iv) share the checker's exit `2` and belong on opposite sides of close-out's own taxonomy. A structural defect — absent, duplicated or reversed markers, a BEGIN/END id mismatch, or a `--task` disagreement because the file was copied from another task — is a defect in *the operator's record*, remediable by editing it, and therefore the same class as row (ii): a refusal about the state of the work, exit `1`. A `usage` classification means the checker rejected the arguments *close-out itself constructed*, which no edit to the record can fix; reporting it as `1` would send the operator to rewrite a file that is not the problem. Passing `2` through for both would tell an operator with a wrong-id record that they invoked close-out wrong.
  - **The token is a contract, not a guess.** `bin/check-interventions.sh`'s header states that every rejection path prints a classification token to stderr precisely "so a caller … can distinguish usage/structural errors from a genuine schema violation without parsing prose". Close-out is that caller. Matching is on the classification prefix the checker's own `die()` emits (`check-interventions: <token>: `), never on message prose.
  - **Row (vi) is the fail-closed floor.** An unrecognized shape is never treated as a pass and never guessed into row (iii); it is exit `2`, "cannot evaluate the input", which is what this repository's checker contract requires.
  - **Four frozen reason strings**, each appearing on one physical line of `bin/close-out.sh` and in its refusal output: **A** = `has no readable interventions record`; **B** = `interventions record does not conform`; **C** = `cannot verify the interventions record`; **D** = `cannot resolve the interventions directory`.
  - **The header's Exit section is realigned with this table, and the `--help` truncation is fixed as part of that — in scope, minimally.** `--help` prints `sed -n '2,40p'` of this file's own header, and the Exit lines at ~:43–45 are already outside that window today; so is the `--note` option line at :41. This task adds header text and changes the exit taxonomy, so leaving the window alone would either hide the new taxonomy from the one surface an operator reads at refusal time, or push `--date` and `--note` off the end as well — actively worsening `--help`. The fix is the end bound of one `sed` range, re-derived so `--help` prints the whole header comment block and no script code. No other change to `--help` is in scope. Two frozen phrases, each on one physical line of the header: **`a missing or non-conformant interventions record refuses the close-out before any board write`** and **`a missing, unreadable or non-conformant interventions record is exit 1; an unusable checker or resolver is exit 2`**.
- **D4 — the gate sits immediately after T-068's pending-disposition gate and before the Done entry is built; the disposition message wins when a task trips both.** Order: argument validation → board resolution → pass-1 locate → T-068 disposition gate → **this gate** → build entry → pass-2 rewrite → pre-write `check-handoff.sh` interlock → write.
  - **Why the disposition gate keeps precedence.** It is shipped behaviour with fixtures asserting its message, and inserting ahead of it would change what an existing board reports for no gain. It is also the cheaper test — it reads bytes already located in pass 1, while this gate resolves a path and shells out to a sibling. Both refuse with exit `1` and leave the board byte-identical, so the ordering decides only which single message the operator sees first; the second is waiting on the next attempt.
  - **The interventions directory is resolved inside the gate, at this position — not hoisted up next to the board resolution.** Hoisting would make a resolver failure (exit `2`) pre-empt board-state refusals that are more informative and more likely, e.g. reporting an unresolvable directory for a task that is not in `## Active` at all.
- **D5 — the checker's stderr is captured and printed before the refusal, T-1016 D6's pattern.** On every refusal in rows (ii)–(iv) and (vi), the captured stderr is written to close-out's stderr *first*, then close-out's own reason string and remedy. A gate that refuses without naming the cause is the failure mode T-1016 fixed one layer up in this same script; this gate does not reintroduce it.
- **D6 — an absent or unreadable checker is exit `2`, fail-closed, and the pre-existing implicit behaviour of the `check-handoff.sh` dependency is not touched.** The gate explicitly tests for the sibling script before invoking it and refuses with reason C rather than letting `bash` produce a bare `127`. The pre-write `check-handoff.sh` gate has no such explicit test today — a missing sibling there surfaces as a lint failure and exit `1` — and this task deliberately leaves that asymmetry in place: fixing it is a change to a shipped refusal's exit class with its own compat surface, and it is not what issue #90 asks for. Recorded as a fast-follow candidate, not filed from this role.
- **D7 — the remedy is one step, and it contains no runnable command.** On every exit-`1` refusal of this gate the message names, in this order: the record path exactly as close-out resolved it, the working directory it was resolved against, and the three literal lines of a conformant zero-entry record — `<!-- BEGIN interventions: <TASK> -->`, the sentinel `no interventions occurred`, `<!-- END interventions: <TASK> -->`, with the real task id substituted. The exit-`2` refusals (rows iv–vii) name reason C or D and **do not** print that remedy block: the problem is the install or the environment, and telling the operator to write a record they may already have is a wrong instruction.
  - **Why no runnable command, and why the execution-context matrix requirement is discharged rather than filled in.** A printed command would have to be correct in both execution contexts this plugin ships into — a checkout where scripts are called as `bash bin/…`, and an adopter repo with the plugin loaded where `bin/` is on `PATH` and the bare name is correct — and would need a matrix in this spec plus maintenance forever after. Printing the file's *content* instead is context-free: the same three lines in every environment, with no shell quoting to get wrong. The path is printed as resolved rather than absolutized, because absolutizing it requires resolving a directory that, in the most common refusal, does not exist; the working directory is printed alongside so the pair is unambiguous.
- **D8 — adopter compatibility is bounded by scope, and `CONTRIBUTING.md`'s existing bullet gains one sentence.** The gate reads one path for one task. No `## Done` entry is inspected, no directory is enumerated, no migration or backfill script is written or run, and no other task's record is required to exist.
  - **`CONTRIBUTING.md` line 53 is edited — yes.** The bullet states the discipline; this task makes a script enforce it. Prose that states a discipline and the code that governs it are one canonical pair, and a contributor who hits the refusal needs the document to say the refusal exists. It is one sentence appended to the existing bullet, not a new bullet — a new bullet would state the same discipline twice. The frozen full line is quoted in AC16.
  - **`README.md`, `README.ja.md`, `CHANGELOG*`, `docs/**`, `agents/**`, `skills/**` and `templates/**` show no diff at all**, and there is no version bump. `agents/qa-verifier.md` already requires running `bin/check-interventions.sh`; the run skill's conversational seams already name the interventions record. Neither needs a word about where a bash script now also checks it.
- **D9 — the change surface is one `bin/` script, two test suites and one contributor document.** No new script under `bin/`, no new `tests/*/run.sh`, no new argument on the workflow's `shellcheck` line, and no change to `.github/**` at all.
  - `bin/close-out.sh` — the gate, the header text, the realigned Exit section, the `--help` range bound.
  - `tests/close-out/run.sh` — the fixtures D2 breaks, plus this task's own assertions.
  - **`tests/errexit-safe/run.sh` — mechanically coupled, required, not optional.** Its `NOT_APPLY` registry pins `close-out.sh:264:` by exact `file:line:content`, and its mutation self-check block references that same pin three times. Any line this task adds above :264 — the gate itself, and every header line — shifts it. The registry is re-grounded (line number re-measured with the suite's own derivation, quoted content confirmed byte-identical), never relaxed: no pin deleted, widened to a range, or converted to a `NOT_APPLY`-by-omission.
  - `CONTRIBUTING.md` — D8's one sentence.
- **D10 — backfill is forward-only and is not performed.** `.shell-team/interventions/` has one historical hole (T-1010, closed long ago); it stays. The gate never looks at it, so it blocks nothing. The self-referential consequence is the point: **T-1017's own close-out must pass this gate**, so `.shell-team/interventions/T-1017.md` is a required artifact of this task rather than an optional one, and AC18 verifies it with the real checker under `--task T-1017`.

## Non-goals

- **`bin/check-interventions.sh` itself.** Not a line. Its schema, its structural rules, its classification tokens, its exit taxonomy and its trust boundary are consumed as they stand; AC14 asserts the file is byte-identical to the base ref.
- **Judging whether a record is *true*.** The checker declares itself a discipline aid for a trusted, committed, reviewed artifact rather than a security boundary against an adversarial author. This gate inherits that boundary verbatim and adds no truth check: a record carrying the sentinel while ten interventions happened passes, by design.
- **Backfilling or migrating any existing record**, repairing the T-1010 hole, or inspecting `## Done`.
- **`no-task.md` flows.** `bin/close-out.sh` requires `--task T-NNN`; the taskless record has no close-out to gate.
- **The run skill's conversational seams**, the interventions reminder hook, `agents/*.md`, and any other place the record is named. This task adds one mechanical gate at one seam.
- **`bin/close-out.sh`'s other features** — telemetry, the printed issue-close procedure, `project_status` regeneration, `--note` validation, the flag rewrite, the T-068 disposition gate's own logic, the pre-write `check-handoff.sh` interlock.
- **The `check-handoff.sh` dependency's implicit missing-sibling behaviour** (D6).
- **A new script under `bin/`, a new `tests/*/run.sh`, a new `shellcheck` argument, or any change to `.github/**`.**
- **`README*`, `CHANGELOG*`, `docs/**`, `agents/**`, `skills/**`, `templates/**`, and any version bump.**
- **Any change to `.shell-team/todo.md` beyond this task's own `## Active` entry.**

## Input space

**Reachable input classes** — what real close-outs in this loop and in an adopter repo produce, and the gate must handle correctly:

- A task whose record exists and carries the zero-entry sentinel. The dominant class: most records in this repository are sentinel-only.
- A task whose record exists and carries one or more well-formed entries. Also present here (T-1002, T-1013, T-1016).
- A task with **no record at all**. Not hypothetical: `.shell-team/interventions/` has exactly this hole for T-1010, and it is why issue #90 exists.
- A record that exists but violates the schema: an unrecognized class token, an incomplete or fieldless entry, a malformed date, a wrapped field value, the sentinel coexisting with an entry, an empty region. All of these are the checker's exit `1`.
- A record that exists but is structurally broken: markers absent, duplicated, reversed, or with mismatched BEGIN/END ids — and the wrong-file case, a record copied from another task so its marker id disagrees with `--task`. All of these are the checker's exit `2` with the `structural` token.
- A record path that exists but is not a readable regular file: a directory of that name, an unreadable file, a dangling symlink. Reachable from a partially restored checkout or a scaffolding accident.
- Both layouts — `.shell-team/interventions/` and the legacy `tasks/interventions/` — resolved through `bin/team-paths.sh`, plus a `TEAM_RUN_BASE` override, plus an explicit `TEAM_INTERVENTIONS_DIR` (absolute or relative), plus the existing `$TEAM_TODO` board override in use at the same time. The last combination is exactly the shape `tests/close-out/run.sh` already uses.
- CRLF-terminated records; the checker strips CR per line and the gate adds no normalization of its own.
- A task that trips more than one gate at once — an unresolved pending disposition together with a missing record.
- An incomplete install: `bin/check-interventions.sh` or `bin/team-paths.sh` absent or unreadable beside `bin/close-out.sh`, including a vendored subset of `bin/`.
- Records of ordinary size: a sentinel of three lines, or a handful of entries with multi-hundred-character `summary:`/`effect:` values.

**Out-of-scope synthetic extremes** — declined deliberately; a finding grounded only in one of these is out of contract:

- **Adversarial record content aimed at the checker's own judgment** — a sentinel string quoted inside an entry's `summary:`, ten real interventions recorded as a sentinel, an entry whose `effect:` contradicts its `class`. The checker declares itself a discipline aid for a trusted, committed, reviewed artifact rather than a security boundary against an adversarial author; this gate inherits that boundary verbatim and asserts no truth about content.
- **Ever-more-exotic non-conformant record shapes** beyond the classes the checker's own contract enumerates. The gate delegates the whole structural-and-schema judgment; a newly invented malformed shape is a finding against `bin/check-interventions.sh` (unchanged here, AC14), not against this gate.
- **TOCTOU between the gate and the board write** — a record deleted or corrupted in the milliseconds after it verified. No locking is added and the existing temp-file-then-copy write path is unchanged.
- **Hostile `$TEAM_INTERVENTIONS_DIR` values** — a path outside the repository, a device or FIFO path, a value carrying newlines or shell metacharacters. It is an operator-supplied override consumed verbatim and then screened with `-f`/`-r`, exactly as `$TEAM_TODO` already is; no new validation is promised for either.
- **Any task other than the one being closed** — `## Done` history, `no-task.md`, the T-1010 hole, and every record belonging to another id. The gate reads one path.
- **Pathological scale**: a multi-megabyte record, tens of thousands of entries, a single field value of megabyte length. No performance bound is promised.
- **Localization or translation of the refusal messages.** The frozen reason strings are English literals, as every other message in `bin/` is.
- **A close-out invoked without `--task`.** The flag is required and validated before anything here runs; there is no flow for this gate to have an opinion about.
