# Concurrent-worktree reconcile: a single serializing coordinator lands N workers' work onto one task branch behind a never-stealing lock, refuses on a machine-checked path-disjointness violation, and rewrites nobody's commits

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1077

**Base ref / branch point — one discriminator for the whole spec.** Every base-side blob read in this spec reads **the branch point**, resolved at check time by one two-arm expression that every criterion spells identically: try the train-head branch `chore/lesson-promotion-2026-08-16` first, and fall back to `develop` only when that branch no longer resolves. The choice is stated once and applied uniformly, because two refs in one document is exactly the inconsistency a sibling-clause cross-check exists to catch.

The two arms exist because the correct ref has two eras, both measured rather than assumed. **Today**, this task's branch is stacked on PR #296 (`chore/lesson-promotion-2026-08-16`), which is **open and unmerged**: its tip sits on top of `develop`'s tip, so `git merge-base develop HEAD` resolves `develop`'s tip and **not** this branch's point — a bare `develop` spelling would put PR #296's own `agents/`, `templates/prompt-blocks/` and lessons-corpus changes permanently inside every `<base>...HEAD` range, making this spec's byte-identity and scope-lock criteria structurally unsatisfiable rather than merely red. **After the batch GO**, PR #296 merges and its branch is deleted; `git merge-base develop HEAD` then resolves the same commit the first arm resolves today, because `develop` has come to contain it. The two-arm form is therefore not a hedge between two candidate refs — **both arms resolve the same commit, each in the era where it is the one that can**.

The fallback is written as an explicit branch-existence test rather than as a `2>/dev/null ||` chain on purpose: a `||` chain cannot distinguish "the train-head branch is gone" (the expected era change, which must fall back) from "`git merge-base` failed for some other reason" (which must fail closed), and collapsing the two would let a broken read silently resolve a different, earlier commit. Each arm's own failure still exits non-zero. One residual case is disclosed rather than engineered away: if the train-head branch were deleted **without** merging — an abandoned car — the second arm would resolve `develop`'s tip, which is not this branch's point; that scenario invalidates the whole stack this task sits on, and is a route-back rather than something a criterion should paper over. No 40-hex literal is written into any criterion: every criterion resolves the ref itself and fails closed when it does not resolve.

**Branch**: `feature/1077-worktree-reconcile` (created by the orchestrator before this spec was written), stacked on `chore/lesson-promotion-2026-08-16` (PR #296, open), which is itself stacked on `develop`. PR base stays `develop`; the PR is held open and merges at the sprint batch GO.

## Problem

`skills/run/SKILL.md` declares, in its own Implement-phase isolation bullet, that integrating 2+ concurrent worktrees into one branch is not covered, and states the mechanism of the failure in the same sentence: after the first `--ff-only` merge advances HEAD, a second worktree reset onto the same original base can no longer fast-forward. That single sentence is the named blocker for the width axis's Tier-3 work-splitting (`docs/loop-engineering/phase-multiplexing.md`'s `tier3-work-splitting` sits at `not-yet` because of it) and for the depth axis's inter-task pipelining (`docs/loop-engineering/agent-concurrency.md`'s `intertask-pipelining` sits `undetermined` for the same reason). Both notes describe, in prose, what closing it would need — a single serializing coordinator of the merge-queue shape — and both deliberately build nothing. Meanwhile the same depth-axis note measures `shared-git-index` as `serialize` for concurrent writers with "no safe mechanism today," and measures `shared-state-lock-primitive` as `absent` across the whole of `bin/`. The gap this task closes is therefore not a missing convenience: it is the one mechanism that makes N-way landing possible at all, and until it exists every concurrency design in this repository terminates at the same sentence.

## Goal

- user-visible: yes — this task adds a new adopter-reachable executable, `bin/land-worktree.sh`, which the plugin puts on `PATH`, together with a new opt-in orchestration step in the run skill that an adopter follows and a new environment variable bounding the coordinator's wait for its turn. An adopter running the loop in their own repository can invoke all of it.
- verification-class: mechanism — the deliverable is a new executing surface under `bin/`, a new CI-wired fixture suite under `tests/`, and an edit to a shipped skill document. Nothing is priced down: the downstream-impact inventory is taken as a **full-population diff** over every merged spec's criteria run at the branch point's committed blobs and again at HEAD, CI-equivalence is run in full, and the mutation-probe matrix covers every criterion this spec freezes rather than only the check lines it adds.

**Goal (one sentence).** A single serializing coordinator — `bin/land-worktree.sh`, invoked once per worker, its turn taken behind a never-stealing directory lock outside the working tree — lands N concurrent worktrees' committed work onto one task branch by verifying, against a mechanically derived claim set, that the worker's changed paths are disjoint from everything already landed, refusing with a classified exit class and empty stdout on any overlap, divergence, missing input or lost turn, and otherwise composing the landing so that the worker's own commits are preserved unrewritten and no worktree, index or branch other than the coordinator's own target is touched.

**D1 — which gates re-run, and why the priced alternative is rejected.** `docs/loop-engineering/agent-concurrency.md`'s sketch names this as the open policy hole: what happens when the coordinator's rebase-to-current-tip invalidates an already-approved verdict. This design answers it in two parts. **First, there is no rebase** (D5), so no worker's commits are rewritten and no verdict computed against a worker's own commit is invalidated by the coordinator. What survives is the narrower, real question: a verdict computed against a worker's own tip was computed against a tree that is not the composed tree, so it does not transfer. Two options were considered. **Option A — a full agent-gate re-run per landing**: `qa-verifier` and `codex-reviewer` against every intermediate composed tip. Priced from this repository's own telemetry rather than guessed: `docs/loop-engineering/agent-concurrency.md` records a per-round `codex-reviewer` average of `1442049` ms over eleven tasks, so N landings cost a review round each before QA is counted at all — for three workers, over an hour of review wall clock spent certifying trees that never ship, which is the entire saving `docs/loop-engineering/phase-multiplexing.md`'s own break-even condition requires the split to produce. **Option B — a disjointness-justified reduced re-run — is chosen.** Each landing is followed by the orchestrator's own *mechanical, deterministic* verification of the composed tip (this repository's checkers and suites; the adopter's equivalent), and the two agent gates run **once**, against the final composed tip, before `READY_FOR_MERGE`. Three grounds: the measured price above; the fact that an agent gate at an intermediate tip cannot certify what path-disjointness leaves open (D2) any better than the same gate at the final tip, since every intermediate tip is a strict prefix of the final composition and only the final tree ships; and that the `both-gates-green` invariant is a claim about the tree that reaches `READY_FOR_MERGE`, which still requires `qa-verifier` `PASS` and `codex-reviewer` `APPROVE`. What Option B costs is stated rather than engineered away: a composition defect introduced by landing *k* surfaces at landing *k* only if the mechanical verification can see it, and otherwise not until the final agent gate, at which point attributing it to a specific landing is the orchestrator's problem and not the mechanism's.

**D2 — the guarantee is path-level, and nothing more.** The disjointness this mechanism verifies is **textual and path-level only**: it decides that two workers' changed-path sets do not intersect. It **does not guarantee semantic or interface independence** — worker A may change a function's signature while worker B, in a file A never touched, calls it, and both landings succeed. This is not a limitation to be closed later by a stricter check; it is a consequence of what does not exist: `docs/loop-engineering/phase-multiplexing.md` measures that the spec-partition grammar — non-overlapping file sets assigned per instance with pre-agreed interfaces recorded as frozen spec artefacts — is "a written requirement, not a built grammar," and no spec in this repository has ever been authored that way. Any wording implying semantic independence would therefore be false on arrival, and the shipped prose must say what is not guaranteed in the same place it says what is.

**D3 — mutual exclusion lives outside the working tree, and there is no persistent queue state at all.** The coordinator's turn is taken with the **T-1076 directory-lock idiom, reused rather than reinvented**: a directory created with a plain `mkdir` (never `mkdir -p`); a bounded wait defaulting to 10 seconds and overridable through `TEAM_LAND_LOCK_TIMEOUT` (an absent, non-integer, zero or negative value falls back to the default and warns on stderr naming the variable); acquisition failure writes nothing, changes nothing, and exits **3** with the lock directory's full path on stderr; the lock is **never stolen** — no age heuristic, no PID probe — and is released with `rmdir` only, wired to EXIT/INT/TERM, firing only for a lock this process itself acquired. No `flock`: it is not part of the macOS base system this repository's own host runs on. The lock's **location** is decided against a measured constraint: this repository re-includes `.shell-team/` at the root so the base dir is tracked, and `bin/team-paths.sh` resolves no key for lock state — so a lock under the base dir would be both a tracked artifact showing in every scope lock and a new unresolvable path convention. The lock therefore lives under the **shared git directory** (`git rev-parse --git-common-dir`), which is per-repository, shared across every linked worktree by construction, never tracked, never reached by any `.gitignore` rule, and never visible to `git status`. **The gitignore question is therefore answered by not arising**: there is nothing in the working tree to ignore. **Queue state is derived, never stored**: the set of paths already landed is `git diff --name-only -z <base>...<coordinator tip>`, read from git at the moment the lock is held, so it cannot go stale, cannot disagree with the repository, needs no format, no cleanup and no gitignore decision. A sidecar queue file is rejected with its reason — it would need its own atomicity story and would add a second piece of state that can disagree with the branch it describes.

**D4 — a diverged worker is refused, classified; nothing is auto-rebased, ever.** When a worker's history does not descend from the declared base, or its worktree carries uncommitted or untracked-non-ignored work, the coordinator **refuses** with the `diverged` class, changes nothing, and says which condition failed. It never rebases, resets, checks out, rewrites or deletes another agent's branch: auto-rewriting committed work sits on the destructive side of this repository's own operating rules, and the composition below makes a rebase unnecessary for the ordinary case in any event. The worktree-cleanliness half is opt-in by argument (`--worker-tree <path>`) because a worker's checkout may legitimately be gone by landing time; when it is omitted, the landing record itself carries `- worker-tree: not-checked`, so a landing that ran without that guard **discloses it on its own record** rather than reading as one that passed it.

**D5 — the landing composes; it does not rebase, and it touches no working tree.** With `B` the declared base, `T` the coordinator ref's current tip and `W` the worker tip, the landed commit's tree equals `T`'s tree with **exactly** the worker's claimed paths taking their state at `W` — content, file mode and entry kind, including removal for a path the worker deleted and including a symlink carried as a symlink entry rather than as its target's contents. The landed commit records **two parents**, `T` first and `W` second, so the worker's own commits stay reachable and unrewritten. The coordinator ref advances by compare-and-swap against the tip it read, so a ref that moved underneath the operation refuses (`ref-moved`) rather than clobbering. No worktree is checked out, reset or modified; no index other than a private scratch index is written; no branch other than the coordinator ref is updated. `--onto` is refused (`structural`) when it is checked out in any worktree of the repository, because advancing a checked-out branch's ref leaves that worktree's index and working tree silently disagreeing with it.

**D6 — the closed exit-class vocabulary, and the missing-input / content-defect separation.** Seven classes, closed, each printed as exactly one stderr line in the shape `land-worktree: <class>: <detail>`, and **on every non-zero exit stdout is empty** — nothing is printed to stdout until every check has passed, so no partial or unauthorized landing record can ever be read as an authorization. Exit **0**: landed (or, in `--check-only` mode, authorized), the record on stdout. Exit **1** — a refusal about the landing's own **content**: `overlap` (the worker's claim set intersects what is already landed), `diverged` (the worker's history or worktree, per D4), `empty-landing` (the worker tip carries nothing beyond the base), `ref-moved` (the coordinator ref advanced outside this mechanism between the read and the write; the remedy is to re-derive the claim sets, not to retry the same landing). Exit **2** — a usage error about the **invocation**: `usage` (a missing, unknown or malformed flag) and `structural` (a named input is not there or not usable — not a git repository, a ref that does not resolve, an `--onto` that is checked out, a `--worker-tree` that is not a worktree of this repository). Exit **3**: `lock` — the coordinator could not take its turn inside the bounded wait. The separation is deliberate and mirrors `bin/aggregate-verdicts.sh`'s: a named input that is *absent* is exit 2 because the invocation named something that is not there, while an input that resolves and whose *content* collides or diverges is exit 1, and exit 3 is never a judgment about data at all.

**D7 — disjointness is checked as a class, not as one case.** Two claim sets overlap when any of three relations holds, and all three refuse identically. **(a) Exact** — the same path in both. **(b) Prefix** — a path in one is a directory prefix of a path in the other (`x` and `x/y`), the directory↔file replacement case, which no string-equality test can see. **(c) ASCII case-fold** — two paths equal after ASCII case folding but not byte-equal (`README.md` and `readme.md`), which are distinct tree entries but collide on checkout on the case-insensitive filesystem this repository's own host runs by default. Claim sets are derived NUL-separated and rename-blind, so a path containing a space, a tab or a newline is carried intact and is unaffected by `core.quotepath`, and a rename claims **both** its old and its new path rather than only the new one. A deletion, a mode-only change and a symlink entry each claim their path exactly as a content change does. Whatever cannot be represented on a line — a path carrying a newline — is emitted into the landing record **C-escaped**, so one claimed path is always exactly one record line and no path can forge a field or a marker.

**Pre-commitment (AI self-discipline — self-imposed by this loop, never operator-ratified).** Factual trigger: two consecutive review rounds landing an independent Blocker or Major against the same component. Contextual trigger: before a third round of rework on that component starts; where the two disagree, the factual trigger governs. Disposition, decided here rather than at the moment it fires. Drop **①** the composing landing itself — the tree composition, the two-parent commit and the compare-and-swap ref advance — degrading the tool to its own `--check-only` mode as the only mode: it still verifies disjointness and divergence and still prints the authorized claim set, and the orchestration step performs the landing with ordinary git commands under the same lock, one worker at a time. Then **②** the lock, degrading to a caller-asserted `--serialized` declaration that landings are being run one at a time within one orchestrator session, with the bounded-wait surface and its environment variable dropped with it. Each dropped component goes to a follow-up issue carrying that round's findings as its requirement list rather than having them re-derived there. **Never dropped**: the fail-closed path-disjointness verification of D7 and the refusal contract of D6 — if that mechanism is defeated across two design generations, the task **stops and returns to planning**, because a mechanism defeated across consecutive design generations is evidence about the design premise rather than about the implementation's craft. One note on this disposition's provenance, recorded rather than silently reconciled: the Routing Map's own drop order named an auto-rebase and a persistent queue state as the first two droppables, and **neither has a referent in this design** — D4 rebases nothing and D3 stores nothing — so the order above is re-derived over the components this design actually has.

## Non-goals

- **No semantic, interface or behavioural independence guarantee.** The disjointness verified is path-level and textual only (D2); nothing here detects that one worker changed a signature another worker calls.
- **No spec-partition grammar.** The authoring-side discipline — disjoint file sets assigned per engineer instance, pre-agreed interfaces frozen as spec artefacts — is not designed, not required and not implied by this task.
- **No rebase, reset, checkout, cherry-pick, force update, branch deletion or any other rewrite of a worker's committed work**, and no modification of any worktree, index or branch other than the coordinator's own `--onto` ref.
- **No execution surface in the coordinator.** `bin/land-worktree.sh` runs no caller-supplied command, creates no scratch worktree and executes no verification of its own; D1's chosen policy is carried by the orchestration step, not by the script.
- **No move of `tier3-work-splitting` off `not-yet`.** That disposition needs a pilot and is a separate task; nothing in this spec re-prices it, and neither `docs/loop-engineering/phase-multiplexing.md` nor `docs/loop-engineering/agent-concurrency.md` is edited.
- **No prompt-block registration for the new section.** A `contain` registration exists to keep one text in sync across more than one consumer; this text has exactly one consumer, so it is authored directly in `skills/run/SKILL.md` and `templates/` stays byte-identical.
- **No change to `bin/log-run.sh`, `bin/aggregate-verdicts.sh`, `bin/team-paths.sh` or any other existing script**, and no change to the telemetry row schema — the landing span uses only flags the shipped writer already accepts.
- **No cross-host, network-filesystem or multi-machine locking claim.** The lock is correct on a POSIX local filesystem; NFS and SMB are declared out of scope rather than assumed.
- **No repair of the board's two `## Done` headings** (measured, pre-existing, unrelated to this task's diff), and no board archiving, rotation or reformatting beyond this task's own entry.
- **No retro-fit, repair, widening or annotation of any merged spec's criteria**, including any this task's diff reddens. Every red is disclosed in `## Blast radius` and differenced against the branch point; none is fixed here.

## Input space

**Reachable input classes** — what real data and real usage in this repository and in an adopter's can produce, and which this task must handle correctly:

1. **Two or more workers, each having committed work in its own linked worktree, all branched from one declared base SHA.** The Tier-3 case this mechanism exists for, and the case `skills/run/SKILL.md`'s `isolation: worktree` parameter already makes reachable today for one worker.
2. **Paths carrying a space, a tab or a newline.** All three are legal in a git tree and all three are producible by an ordinary editor or a generated file; a newline in particular defeats every line-oriented derivation.
3. **A rename.** Git records it as a delete plus an add unless rename detection is on, and the two spellings claim different path sets — the reason the derivation is rename-blind and claims both.
4. **A deletion, a mode-only change (the executable bit), and a symlink entry.** Each is a real change this repository's own history contains; each claims its path exactly as a content change does, and a symlink is carried as a symlink entry rather than as whatever it points at.
5. **A directory replaced by a file, or a file replaced by a directory.** `x` and `x/y` do not intersect as strings but cannot coexist in one tree — the case a string-equality disjointness test silently passes.
6. **Two paths differing only in ASCII case.** Distinct tree entries; a collision on checkout on the case-insensitive filesystem this repository's own development host runs by default.
7. **A worker whose history no longer descends from the declared base** — it rebased or reset itself mid-flight — and **a worker whose worktree carries uncommitted or untracked-non-ignored work** at landing time.
8. **A worker with nothing to land** (its tip equals the base), and **a coordinator ref that moved between the read and the write**.
9. **A repository whose `core.quotepath` is set either way**, and an operator with an arbitrary ambient locale and an arbitrary global git config.
10. **A stale lock directory left by a process killed with `SIGKILL`**, and a second coordinator invocation arriving while a first holds the lock.
11. **Hosts without `flock`, and hosts whose `sleep` rejects a fractional argument.** This repository's own development host is macOS with bash 3.2; adopters run these scripts in repositories this project knows nothing about.
12. **A `--onto` branch that is checked out in some worktree of the repository**, which advancing by ref would leave silently disagreeing with its own index.

**Out-of-scope synthetic extremes** — inputs this spec explicitly declines to protect, named concretely so the boundary is falsifiable:

- **Semantic or interface coupling between disjoint file sets.** Worker A changes a signature, worker B calls it from a file A never touched; both land and the composition is broken. Declared out of scope by D2, with its measured ground (`docs/loop-engineering/phase-multiplexing.md`'s finding that the spec-partition grammar does not exist), and no escalation of this class is a defect this spec accepts.
- **Non-ASCII case-folding collisions.** Two paths colliding on a case-insensitive filesystem only under Unicode case folding or Unicode normalization (NFC/NFD) rules. The fold is ASCII-only, stated, because pure bash 3.2 has no Unicode folding; a wider fold is a future task's problem, not a defect in this one.
- **Cross-host or network-filesystem concurrency.** Two machines landing onto one repository over NFS or SMB, where `mkdir`'s atomicity guarantee does not hold as stated. Declined outright; correctness is claimed for a POSIX local filesystem only.
- **Concurrency degrees far beyond one orchestrator session's reach** — dozens or hundreds of simultaneous coordinators, or a sustained landing rate. The fixture floors (at least 3 workers) bound what is protected; escalating that ladder further is not a defect this spec accepts.
- **Adversarial tampering with the lock while it is held** — another process renaming the lock directory, changing its permissions mid-run, or replacing it with a symlink. The never-steal rule and `rmdir`'s refusal to remove a non-empty directory are the whole of the defence; a hostile local process with write access to the git directory is outside this task's threat model.
- **A repository whose objects are corrupt, whose refs are damaged, or whose git version predates the plumbing this composition uses.** No repair, no fallback and no version-probe is built; a git that cannot perform the composition fails visibly rather than being worked around.
- **Crash consistency and durability.** Power loss mid-landing, a filesystem that reorders or discards a completed write, or any claim that exit 0 means the new tip survived a reboot. No `fsync` is added and none is claimed.
- **Submodules, `.gitattributes`-driven content filters, and LFS pointers.** The composition copies tree entries; whether a filter would have produced different bytes on checkout is not modelled and is declared out of scope.
