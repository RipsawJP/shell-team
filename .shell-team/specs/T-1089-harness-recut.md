## Problem

T-1086 stopped `BLOCKED` on its own frozen pre-commitment: two consecutive cross-provider review rounds landed independent Majors on the same never-dropped components — the oracle (contract-coverage defeats in rounds 1 and 2) and the baseline's fabrication-resistance (`rep=2`→`rep=1` in round 1, `rep=01`/`rep=1` zero-padding in round 2) — and the pre-decided disposition was to stop rather than patch a third time. The operator chose that route (route A, 2026-08-21) over an override. The reviewer's own synthesis named the design-premise question in one sentence: an enumerated-case oracle that is read as claiming full conformance to a frozen contract invites unbounded adversarial rounds, because every round can find one more concrete violator (`+5`, 64-bit integers, CRLF, duplicate header names) that the fixture set does not cover.

The re-cut settles that question by narrowing the claim instead of widening the fixture set. **The strong claim was never written down.** Measured first-hand at authoring, not inherited: a case-insensitive sweep of `docs/loop-engineering/` for `reject|violat|any candidate|every candidate|all candidates` returns, inside the harness and its note, only per-case labels (`case10-leading-whitespace-rejected`, `case11-trailing-whitespace-rejected`) and one per-column comment ("proving the rejection is per-column, not a whole-row wipeout") — no sentence anywhere asserts that the oracle rejects any candidate violating the frozen contract. The strong claim was **implicit**, carried by the oracle's position as the judge contract's `check-results` input rather than by any text. So the boundary this task writes is **new explicit text**, not a rewrite of an overreaching sentence, and that distinction is what keeps the re-cut honest: nothing is being walked back, something that was never stated is being stated.

Two further defects survive T-1086's own v2 ratification and are closed here, each **as a class** rather than as the instance a reviewer happened to find: the note's `- baseline-basis:` line still asserts that this arm's machine-time and calendar-clock figures coincide — the exact conflation the v2 re-freeze corrected two sections later, leaving the note self-contradictory to anyone who reads the earlier line and stops; and the frozen input pattern `^-?[0-9]+$` admits zero-padded spellings whose bash-arithmetic value silently differs from their decimal reading, or errors outright, with no case covering any of them.

**The claim, stated once and precisely.** `acceptance.sh` verifies that a candidate reproduces the exact stdout bytes, stderr bytes and exit code its enumerated cases specify, for the inputs those cases construct. It is **not** a decision procedure for conformance to `interface.md`'s frozen contract: a candidate can pass every enumerated case and still violate the contract on an input no case constructs, and that possibility is a property of every finite instrument, not a defect to be patched away. What the instrument is *for* is supplying the judge contract's `check-results` input at a fixed, reproducible strength — and a judge reading those results is entitled to know the strength it is reading, which is what the named limits below give it.

**Two defect classes, closed as classes.** **(1) Zero-padded arithmetic spellings.** The class is every string matching the frozen pattern `^-?[0-9]+$` whose bash-arithmetic value differs from its decimal reading, or errors. The behaviors that define it were measured on the operator host at authoring time and are named in the contract rather than left for a candidate to discover: `$((010))` → `8` (silent octal reinterpretation), `$((08))` and `$((09))` → an arithmetic **error**, `value too great for base` (a *different* failure mode from the silent one, which is why the class cannot be described as "octal" alone), `$((-010))` → `-8`, `$((00))` → `0`. The closure is a contract obligation — a candidate must read every pattern-matching field as a **decimal** integer, `10#`-normalized or equivalent — plus a named limit stating that the enumerated cases do not exhaustively verify it. **(2) Byte-distinct, decimal-equal rep spellings.** The class is any pair of `rep=` values that differ as bytes and agree as decimals (`01`/`001`/`1`). The closure is ordering: normalize with `10#` **before** deduplicating, never after, so uniqueness is a property of the numbers rather than of their spelling.
