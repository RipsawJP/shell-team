# The reviewer's host self-classification becomes a recorded, checkable field instead of an implicit inference

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1138

## Problem

`agents/codex-reviewer.md` carries a host-conditional instruction: on a Claude Code host the review pass runs the file's own `codex exec` blocks, and on a Codex CLI host it runs the `claude -p` recipe in `templates/prompt-blocks/host-dispatch.md` instead, because reviewing Codex's output through Codex again does not carry the cross-provider property the role exists for. That instruction tells the role what to do once it knows which host it is on, and says nothing about how it decides. On the adopter run the coordinating session relayed as b run #4, the spawned `shell-team-codex-reviewer` agent ran `codex exec review` anyway; both gates went green and the cross-provider property was silently absent, with nothing in the record naming the classification that produced it. The decision is unrecorded, so it is unreviewable: no gate, no checker and no reader can see which host the role believed it was on, or on what observation. This task makes that one decision explicit — a decidable test built only from observations measured on both hosts, a recorded field carrying the classification and its ground, a fail-closed grammar over that field, and the one cross-field contradiction committed bytes can actually settle.

## Goal

`codex-reviewer` stops inferring its host silently. Its own prose carries an ordered ladder of observations, every rung of which was measured on both hosts before it was written down, whose positive rung is the presence of `CODEX_THREAD_ID` in the role's own shell before it launches anything, and whose absent or indeterminate reading resolves to `claude-code` and today's unchanged `codex exec` path rather than to a refusal. The role records that classification and its ground in the review record as an optional fifth per-pass field, `self-detected-host (<pass>): claude-code | codex-cli — <ground>`, whose ground names the observation it actually made — which variable, and whether it was set — and never that variable's value. `bin/check-review-input.sh` validates that field fail-closed **when it is present**: at most once per pass id, its first token inside the closed pair `claude-code|codex-cli`, a non-empty ground after the ` — ` separator, and one cross-field refusal — a pass declaring `codex-cli` whose own `executor-invocation` begins with the two whitespace-delimited tokens `codex` then `exec`, anchored on those first two tokens and never on a substring, so a `claude -p` invocation whose prompt text merely contains `codex exec` is accepted. Its refusals name a refusal token and a pass id and echo no byte of either field's value. Every record already committed under the reviews directory, carrying none of this, still exits 0 — the contract stays forward-only, and the four-field presence test still requires exactly its four. And both adopter guides state the observable a Codex-host operator can read for themselves: on that host the review pass is a `claude -p` invocation logged as a `claude`-provider span, and a `codex exec` invocation recorded there means the cross-provider property was lost even when the verdict is `APPROVE`. What this does not close is stated in the same breath rather than left to be discovered: no checker can catch a role that declares `claude-code` while actually running as a spawned Codex agent, because no record artifact carries host ground truth.

## Non-goals

- **No mechanism claiming to detect a misclassified host.** The checker refuses exactly one contradiction — `codex-cli` declared beside an `executor-invocation` whose first two tokens are `codex exec` — and nothing else. The b run #4 shape, a role declaring `claude-code` while actually running as a spawned Codex custom agent, is **not detectable by any in-repo checker**: no record artifact carries host ground truth, and every field the record holds is written by the same role whose classification is in question. Ask 3's operator-facing observable is what addresses that direction, and it addresses it by disclosure rather than by enforcement. **AC12** and the Goal's own final sentence are the promotion; no criterion here asserts detection of that shape.
- **No refusal, no `BLOCKED`, and no behaviour change on an indeterminate reading.** A rung that cannot be read, a shell that reports neither state, or any ambiguity resolves to `claude-code` and the `codex exec` path the role runs today, with the observation it actually made written into the field's ground. Making an unreadable environment stop a review would convert a disclosure mechanism into an outage. **D1** rules it; **AC7** promotes the prose half.
- **No change to the four-field grammar, its two closed vocabularies, the pass-id charset, the raw-capture stem-prefix rule, the cross-record stem-collision refusal, the per-section completeness rule, the three exit codes or the `--task`-only leniencies.** The fifth field joins `FIELD_RE` and nothing else moves. In particular the four-field presence test still requires all four, so a pass carrying only the new field is refused `field-missing` exactly as it would be today. **AC5**, **AC6** and **AC10** are the promotion.
- **No new required field.** The contract stays forward-only at record granularity and at section granularity: a record carrying zero input-fidelity fields exits 0, a section carrying none is conformant, and a conformant four-field pass with no `self-detected-host` line is conformant forever. No criterion in this spec requires any record — this task's own included — to carry the field. **AC1** and **AC6** are the promotion.
- **No environment-variable semantics inferred from documentation, a help text, or a plausible reading.** Every rung of the ladder is an observation measured on a real process on a real host, with the measured value recorded in `## Assumptions`; the one shape that could not be measured from this session is excluded from the shipped test and declared unmeasured rather than assumed (**D7**, **AC13**).
- **No recording of any identifier's value.** The field's ground names a variable and whether it was set. `CODEX_THREAD_ID`'s value is a session identifier, review records are permanently tracked git history, and `bin/check-pii-shapes.sh` runs over records — the same reasoning the `executor-invocation` field's own contract already applies to argv. **D3** rules it; **AC7** requires the prose to say so.

The new refusals live inside the existing `bin/check-review-input.sh`, and the new fixture arms inside the existing `tests/check-review-input/run.sh`. The workflow's hand-maintained `shellcheck` argument list therefore does not move. **AC12** promotes the measurable half.

## Pre-commitment

- **Never-dropped**: the checker's fail-closed grammar over the new field and its cross-field contradiction refusal — **AC2**, **AC3**, **AC4**, **AC5** and **AC6**. They are the load-bearing, in-repo-verifiable deliverable; **AC4** and **AC6** are as never-dropped as **AC2** and **AC3**, because a refusal that fires on a legitimate record, or that breaks a record already committed, is a worse outcome than no refusal at all. Defeat of any of them across two consecutive review rounds **stops the task and returns it to planning** rather than buying a third patch round, per the operator-ratified ruling of 2026-09-06 (T-1121), cited here as an operator ruling and not as AI self-discipline.
- **Droppable, in this order, decided now rather than at the moment a trigger fires** — and when one is dropped, the findings accumulated against it travel with it as its requirement list rather than being re-derived at the destination:
  1. **AC7** and **AC13**, ask 1's host test in the agent prose — the ladder itself. On a trigger it goes to a new issue the coordinating session files at the moment of dropping, carrying the ladder text, the measured arm values from `## Assumptions` and the rounds' findings as its requirement list. The field, its grammar, its refusals and the docs ship without it, with the field's ground then written from the coordinating session's own briefing for that round rather than from a rung the role reads itself. Ground for it being first: it is the one component whose correctness depends on an environment this repository cannot fully reproduce (arm C is unmeasured by construction), and the deliverable's value — a recorded, checkable classification — survives its removal, where removing any never-dropped item leaves nothing.
  2. **AC9**, the `## Recording review-input fidelity` update in both languages. Same destination and shape. Ground for it being droppable before **AC8**: that section documents the record grammar for an author who is already writing the field, whereas **AC8**'s Codex-section observable is what an operator reads to catch the direction no checker covers. Dropping **AC9** leaves an under-documented field; dropping **AC8** leaves the honest limit undisclosed.
  3. **AC8**, the Codex-section observable in both languages. Last among the droppables, and the English and Japanese halves drop together or not at all — a one-language edit is exactly the mirror drift this repository's review rounds keep catching.
- **Trigger (same-class-2)**: two consecutive review rounds producing independent new defects in the same component. Factual condition — the same component drew a new, independent finding in each of two consecutive rounds; contextual condition — before a third repair round on that component starts. When the two disagree, the factual condition rules. A trigger on a droppable component executes the drop above; a trigger on a never-dropped component stops the task and returns it to planning.
- **Named fragile component, priced now rather than mid-task**: the cross-field contradiction rule. It reads one field's first two tokens to judge another field on the same pass id, both fields are free text a role writes by hand, the value may carry leading whitespace that `FIELD_RE`'s single optional space does not consume, and the failure directions are asymmetric — a false refusal blocks a legitimate close-out while a missed refusal is merely the silence that exists today. A rule written as a substring search, or one that takes the first token alone, is the expected failure mode. The answer is the token-anchored rule **D4** fixes plus **AC4**'s explicit non-refusal arms, not a widened pattern.

**Gotchas, each measured rather than guessed.**

1. `FIELD_RE` consumes **one** optional space after the colon (`:[[:space:]]?`), so a value can legitimately arrive with leading whitespace still attached. Normalize it before taking the two tokens (**D4**, **AC3**'s second arm), and normalize it before testing the host token too.
2. The pass-id list at `:274` is built from every matched field line, so adding the fifth field to `FIELD_RE` means a pass declared **only** by that field enters the four-field presence test. That is the correct outcome and **AC5**(a) locks it — do not add an exemption.
3. Section ownership at `:336`–`:340` requires all of an id's field lines to resolve to one heading. The fifth field inherits that, and **AC5**(b) locks it. Again, correct — no exemption.
4. Refusal messages: name the token and the pass id, never a byte of either field's value. **AC2** and **AC3** assert sentinel strings are absent from output, so an "improved" message quoting the offending invocation fails the criterion, by design (`bin/check-review-input.sh:40`–`:48`).
5. The em-dash separator is multi-byte. The script runs under `export LC_ALL=C`, so compare it as a fixed byte sequence (a `case` pattern or a fixed-string test), never as a character class or a regex range. `bin/check-handoff.sh:87` and `bin/check-count-claims.sh:7` are the two shipped precedents to copy from.
6. `bin/` stays **bash 3.2, zero-dependency, shellcheck-clean and fail-closed**. No `grep -P`, no associative arrays, no `mapfile`, no GNU-only flags. A read that cannot be evaluated reports an error rather than passing (`## Truth sources`, `CLAUDE.md`).
7. `bin/gen-codex-agents.sh` derives the Codex custom-agent TOML from `agents/codex-reviewer.md`'s prose after its frontmatter, so editing that prose changes the generated TOML. `.codex/agents/` is gitignored and nothing is committed, but `tests/codex-agents/run.sh` compares the generated output against a scratch regeneration and must stay green (**AC10**).
8. `.shell-team/reviews/` records are permanently tracked git history and `bin/check-pii-shapes.sh` runs over them. Never write an identifier's value into an example, a fixture or a docs snippet — write the variable name and its set-or-unset state (**D3**). The fixtures in this spec's own check lines follow that rule and are safe to copy.

**Measured-at-ref commands.** This task's deliverables print no `measured at <ref>` label, no `**Base ref**:` header and no per-row `- measurement:` field — not applicable. Where this spec's own criteria read a base-side blob they do so with `git show "$B:<path>"`, reading that ref's committed blob and never the working tree; the declaration region fixes the one expression that resolves `$B`, and every such criterion spells it byte-identically.
