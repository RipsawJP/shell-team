# The board-flag rail derives its stops from real telemetry

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1014

**Branch**: `feature/83-flag-rail-data-path`

## Problem

T-1012 shipped the replay page with a board-flag rail: five stops carrying the verbatim machine tokens, a *current* stop, a *reached* trace behind it, and a rework flash. The rail reads its data from `flagEvents`, which is `events.filter(function(e){ return !!e.flag; })` — and nothing anywhere sets `flag`. `adaptRow()` maps a `kind:"event"` row onto `type`/`from`/`to`/`label`/`agent` and never derives a `flag` property, so `flagEvents` is empty for **every** run that has ever been recorded. The rail therefore can never light; it always shows its empty-state caption, and the `bNowFlag` chip is always hidden.

The other half is missing too. T-1011's emission instructions tell the orchestrator to put phases into `--from`/`--to` and verdicts or intervention slugs into `--label`; nothing tells it to put a `READY_FOR_*` token anywhere. So even with a derivation in place there would be no data to derive from. The rail was ratified as a real affordance of issue #77's design — the current flag lights, a rework steps back — and it is currently decoration.

How this was found is part of the canon. Every static acceptance criterion T-1012 wrote passed; both QA rounds were environmentally unverified on pixels (no browser reachable in the sandbox); the cross-provider review found three Blockers, none of them this. The maintainer, performing T-1012's AC29 visual check at the merge gate, opened the page and saw the empty-state caption on the full-fidelity fixture. `.shell-team/interventions/T-1012.md`'s second entry records it: *"Static AC13 anchors passed; both QA rounds were environmentally-unverified on pixels; the human eye caught the class reserved for it."* This task closes the data path, and — because the class that escaped was "an anchor that was already green" — it closes it with anchors that are red at the base ref and with a behavioural proof that runs in the existing node harness rather than only in a browser.

Issue #83's canon for what a flag is: **an event whose label is one of the five closed flag tokens**.

## Goal

<!-- BEGIN intent-block: T-1014 -->

Both halves of the rail's data path exist and meet in the middle. `skills/run/SKILL.md` instructs the orchestrator to put the board flag it just set onto the `handoff` event's `--label` as a bare verbatim token — still optional, still best-effort. `templates/loop-replay.html` derives a `flag` property in `adaptRow()` by byte-exact whole-label equality against the five `FLAG_STOPS` tokens, so `flagEvents` is non-empty for a run that carries them, the rail lights, the current stop advances, the reached trace persists through a rework, and seeking backward un-reaches the stops the playhead has not yet passed. A run with no flag-bearing rows — every run recorded before this task, and every adopter run whose orchestrator omits the label — still renders the ratified empty-state caption unchanged. Two committed fixtures prove both directions at once: a new `flag-rail` fixture where the rail lights, and the existing `mixed` fixture, untouched, where it stays empty. Nothing under `bin/` changes, and T-1011's row schema gains no field.

### Settled decisions

Each decision below is resolved. Nothing here is left to implementation judgment.

- **D1 — every `kind:"event"` row derives `flag`, uniformly; there is no per-event-id branch.** The derivation runs inside `adaptRow()`'s `kind === "event"` branch and applies to the row's `label` regardless of which of the five event ids the row carries. This is issue #83's canon read literally ("an event whose label is one of the five closed flag tokens" — a property of the label, not of the event id).
  - **Rejected — deriving `flag` only on `handoff` rows.** It adds a branch the canon does not have, and it is wrong in a reachable case: `human` is the one event id whose `--label` `bin/log-run.sh` *requires* to be non-empty, its vocabulary is free-form by T-1011 D3, and a human settling the board flag directly ("the maintainer set `READY_FOR_MERGE` at the gate") is exactly the kind of row an operator writes. Under a handoff-only rule that row is silently not a flag. Uniformity also keeps the match rule in exactly one place, which is what makes D2's symmetry table checkable at all.
  - The other four ids' own frozen label vocabularies are disjoint from the five tokens by their own instructions (`gate` carries a verdict, `rework` carries the causing verdict, `release` carries none), so uniformity costs nothing in practice and only ever adds a flag where an operator deliberately wrote a token.
- **D2 — the match rule is byte-exact whole-label equality against a `FLAG_STOPS` member. No trimming, no case folding, no substring or prefix search, no regular expression, no Unicode normalization.** The derivation is a single named function, frozen as `flagFromLabel(label)`, which returns the matching token or a null-ish value; a `null`, absent or non-string label returns null-ish and is never an error.
  - `FLAG_STOPS` stays the **single source** of the five-token list: exactly one occurrence of `READY_FOR_ARCH` exists in the template, in that array literal. Rejected — a second literal list inside the derivation: two lists is how a sixth token gets added to one of them.
  - **The emission wording must state that the label is the bare token, no surrounding prose.** Without that one sentence, the convention and the implementation go asymmetric: an orchestrator writing a helpful sentence around the token produces a row that looks flag-bearing to a human reader and is not one to the page, and nothing in the repository says which side is wrong. The frozen phrase **`the bare token, no surrounding prose`** must appear in `skills/run/SKILL.md`, and the frozen phrase **`byte-exact whole-label equality`** must appear there too, so the consumer contract is stated at the producer site rather than only in this spec.
  - **Three-way symmetry, frozen.** Every property below holds on all three surfaces at once. This table is the correspondence the task is judged against; AC15 is its machine anchor.

    | property | emission wording (`skills/run/SKILL.md`) | match rule (`templates/loop-replay.html`) | fixture rows (`flag-rail/shell-team.jsonl`) |
    |---|---|---|---|
    | the label is the bare token | the frozen phrase `the bare token, no surrounding prose` | `flagFromLabel` compares the whole label for equality; no substring search | a row whose label is `now READY_FOR_QA` derives **no** flag |
    | case is significant | the tokens are written verbatim, uppercase | no case-folding primitive is introduced | a row whose label is `ready_for_qa` derives **no** flag |
    | surrounding whitespace is significant | `no surrounding prose` covers whitespace | no trimming primitive is introduced | a row whose label is `READY_FOR_QA` followed by one space derives **no** flag |
    | exactly five tokens are rail stops | all five named in the Telemetry section | `FLAG_STOPS`, one occurrence of the list | all five appear as bare labels, in order |
    | `--label` stays optional | the existing sentence ending `is optional here` is preserved | a `null`/absent label derives no flag and the row is never dropped | ≥1 `handoff` row with `"label":null` |
    | uniform across event kinds (D1) | the rule is stated for the label, not per event id | the derivation sits in the `kind === "event"` branch, not in a per-id case | a `human` row whose bare label is a flag token **does** derive a flag |
- **D3 — the reached trace is re-derived per `updateRailB(simMs)` call; this is in scope, not deferred.** Today `flagStopsReached` is a module-level object that `updateRailB` writes into and never clears, so it accumulates monotonically across calls. That is invisible while `flagEvents` is always empty and becomes a real defect the moment the rail lights: seeking backward leaves stale `reached` dots behind the playhead, and the same `simMs` renders differently depending on how the operator got there — which breaks replay determinism, the property the page exists to provide.
  - Frozen: the module-level accumulator is **removed** (the identifier `flagStopsReached` occurs zero times in the template) and replaced by a function, frozen as `railReachedAt(simMs)`, that returns a fresh reached-set derived from `flagEvents` with `_tStart <= simMs`. `updateRailB(simMs)` calls it on every invocation, so the same `simMs` always renders the same rail.
  - **The ratified rework step-back behaviour is preserved by this derivation, not lost to it.** A later stop reached before a rework stays `reached` while `current` moves back to the re-emitted earlier stop, because both facts follow from "the events at or before `simMs`". What changes is only that seeking to a `simMs` *before* a stop was first reached no longer shows it as reached.
  - Rejected — leaving the accumulator in place and filing a follow-up issue. The rewind defect is unobservable today for exactly the reason this task exists (the rail never lights), so shipping the derivation without the rewind fix means shipping a known-broken behaviour into visibility and then asking a second review round to notice it. The two changes are one line apart in the same function.
- **D4 — a new fixture directory; `mixed` is not touched.** `tests/gen-loop-replay/fixtures/flag-rail/shell-team.jsonl`, run id `20260801T000000Z-flagrail`, joins the suite's `run_harness` list. `mixed` stays byte-identical and keeps proving the other direction: it contains no `READY_FOR` string at the base ref, so it is the standing proof that a flag-less run keeps the ratified empty state. The two fixtures together prove both directions; neither alone does.
  - Every row is written by `bin/log-run.sh` (never hand-authored), so the fixture is provably in T-1011's frozen shape and `bin/check-run.sh` accepts it.
  - Rejected — extending `mixed` with flag labels. It would convert the repository's only full-fidelity flag-less fixture into a flag-bearing one, deleting the empty-state proof in the same commit that makes the empty state newly reachable-but-untested. It would also change a fixture whose row counts T-1012's own frozen criteria assert.
- **D5 — the change surface is three files plus one fixture; `bin/` is untouched.** Emission: `skills/run/SKILL.md`'s Telemetry section, the `handoff` bullet. Template: `adaptRow()`'s derivation, `FLAG_STOPS`' declaration position, and `updateRailB`'s reached derivation. Harness: `tests/gen-loop-replay/run.sh`. Nothing else.
  - **The emission edit is purely additive**: zero deleted lines in `skills/run/SKILL.md`. That file is a `contain`-mode consumer of four prompt blocks (`templates/prompt-blocks/registry.txt`), so a deleted line is how prompt-sync breaks; and the existing sentence that keeps `--label` optional lives on the line being extended, so additivity is also what keeps the fail-soft guarantee from being edited away. The new material is an indented sub-bullet beneath the existing `handoff` bullet.
  - **`skills/run/SKILL.md` carries two zero-match regex locks** held by `tests/codex-skeleton-hygiene/run.sh`: `NEW_AC3` (an interpreter-prefixed invocation of a checker) and `NEW_AC15` (a stateful-gate sentinel, and a route-back-through-loop-guard phrase). The new wording must match neither, and that suite must be run and must stay byte-identical.
  - **`templates/loop-replay.html` is not registered anywhere new.** It is already a `tests/machine-tokens/run.sh` consumer (T-1012 D7) and that registration is unchanged. `skills/` is deliberately **not** registered there: that suite's mutation self-check copies only `bin agents templates` into its scratch root, so a `skills/` consumer would make it exit 2 rather than fail red.
  - The row schema is not re-opened: no `flag` key is written to a telemetry row, no writer-side validation is added, `bin/log-run.sh` and `bin/check-run.sh` are byte-identical. `flag` exists only as an adapted, in-page property.
- **D6 — the behavioural proof runs in the existing node harness, upgraded to observe class state; the static anchors are all red at the base ref.** T-1012's harness already extracts and executes a verbatim slice of the real page's script that includes `buildRailB`/`updateRailB`, but its `makeFakeElement()` `classList` stub is a no-op triple, so dot state is invisible. It becomes a **recording** stub: `add`/`remove`/`toggle` mutate a per-element set and `contains(name)` reads it, with `toggle(name, force)` honouring the optional second argument exactly as the DOM does (truthy adds, falsy removes, absent flips). Without the `force` semantics the rewind assertion cannot work at all, since `updateRailB` clears a dot by `toggle("reached", false)`.
  - The harness exports `flagEvents`, `FLAG_STOPS`, `updateRailB`, `railStopsB` and `flagFromLabel` alongside its existing return object.
  - **Every static anchor this task adds is one that fails at the base ref** — `flagFromLabel`, `railReachedAt`, the zero-count of `flagStopsReached`, the two frozen emission phrases, the new fixture's own existence. No anchor is a token that already exists (`FLAG_STOPS`, `flagEvents`, `bNowFlag` and the rail CSS are all present today and are asserted only as *preservation* locks, never as proof of the fix). This is the direct lesson of the intervention that produced this task.
  - **Paired positive controls make the rewind assertion non-vacuous.** A recording stub that silently failed to record would make "no dot is reached after seeking to 0" pass for the wrong reason, so the same fixture asserts the positive half first: after seeking to the end of playback, **all five** dots are reached and exactly one is current. Both halves must hold.

## Non-goals

- **Any change under `bin/`.** Measured, not assumed: the fix needs no generator change, because the generator ships rows verbatim (T-1012 D3) and the adaptation is the template's job. `bin/log-run.sh`, `bin/check-run.sh` and `bin/gen-loop-replay.sh` are locked byte-identical.
- **Re-opening T-1011's frozen row schema.** No `flag` key on the wire, no new event id, no change to the closed `handoff|rework|gate|human|release` vocabulary, no writer-side validation that a label is a flag token. A label is free-form and stays free-form; `--label` stays optional on `handoff`.
- **Part 3 of issue #77** — `README.md`, `README.ja.md`, `docs/**`. That is T-1013. The consequence is accepted for one more task: this repository ships a replay generator no README mentions.
- **`CHANGELOG.md` / `CHANGELOG.ja.md` and any version bump.**
- **New visual design, new dictionary keys, or new i18n strings.** The rail's treatment — dot geometry, the `reached`/`current`/`flash` classes, the `rail-empty` dashed state, the `railEmptyNote` caption and its `flagRailEmpty` dictionary entry in both languages — is ratified by `design-note-T-1012.md` and reused as-is. Nothing on the page gets a new caption, and the five tokens render verbatim English in both languages (T-1010's operator/machine-token boundary).
- **Changing the `mixed` fixture's contents**, or any other existing fixture directory.
- **Making the stop list configurable, data-driven, or extensible.** `FLAG_STOPS` is the frozen five. `BLOCKED` and `REWORK` are board flags and are deliberately not rail stops; a rework is drawn by the existing `flash` treatment, not by a sixth stop.
- **A tolerant match rule.** No trimming, case folding, substring search or normalization is added "to be helpful". A near-miss label is not a flag, by design, and the emission wording is the fix for a near-miss — not the parser.
- **Registering `skills/` as a machine-token consumer** (D5), and any change to `templates/prompt-blocks/registry.txt` or the workflow's suite lists (no new script or suite file is created).
- **A browser-automation harness in CI.** The node harness is upgraded to observe class state; it is not turned into a headless-browser runner, and the pixel-level confirmation stays a human/QA judgment (AC21).

## Input space

**Reachable input classes** — what real usage produces, and the implementation must handle correctly:

- **Runs with zero flag-bearing rows — the dominant class, permanently.** Every run recorded before this task (measured at the base ref: no `READY_FOR` string exists in any committed fixture, and the repository's own telemetry carries none), plus every adopter run whose orchestrator omits the label, which stays legal because `--label` stays optional. The ratified empty-state caption path must keep working unchanged.
- Runs where a `handoff` row's `label` is exactly one of the five tokens — the class this task creates — including all five present in one run, and only some of them present (an interrupted run that never reached `READY_FOR_MERGE`).
- Runs where the same token appears more than once, and where a later stop is reached before an earlier one is re-emitted: the rework step-back. A rework round re-emitting `READY_FOR_QA` after `READY_FOR_REVIEW` was already reached is the ordinary shape of this loop, not an edge case.
- Runs where a non-`handoff` event carries a bare flag token. Reachable because `bin/log-run.sh` *requires* a non-empty `--label` on `human` and its vocabulary is free-form (T-1011 D3), so an operator recording "the maintainer set the flag at the gate" writes a token there.
- Near-miss labels, all of which must derive **no** flag: a lowercased token, a token with leading or trailing whitespace, a token embedded in an operator sentence in any language, and the two board flags that are not rail stops (`BLOCKED`, `REWORK`).
- `label` explicitly `null` (what `bin/log-run.sh`'s `jstr` writes when the flag is omitted) and `label` absent from the object entirely. Neither is an error and neither drops the row.
- Out-of-vocabulary labels that already exist in real telemetry: the four verdict tokens, the interventions class slugs, a bare `GO`, a `STOP:` reason, free prose in the operator's language, and the HTML/JS metacharacter payloads T-1012's `hostile` class covers. None derives a flag, and the derivation must not disturb the escaping path those values already travel.
- Seeking: any `simMs` in `[0, TOTAL_MS]`, in any order — forward playback, a backward jump, a jump to `0` before any flag event, and repeated calls with the same value. The same `simMs` always renders the same rail.
- Runs where two or more flag events share an identical `_tStart`, which happens whenever two hand-offs occur with no work span between them (event `_tStart` accumulates only from span durations). The rail must still be deterministic: last-wins in `seq` order.
- Adopter-shaped runs: a `loop_id` other than `shell-team`, `from`/`to` values that are not this loop's phase names, `span` values that are not its agent names — with flag tokens still on the labels.
- Up to a few dozen flag-bearing events in one run (a long rework history), and up to a few thousand rows overall.

**Out-of-scope synthetic extremes** — declined deliberately; a finding grounded only in one of these is out of contract:

- A sixth flag token, a renamed token, or an adopter-configurable stop list. `FLAG_STOPS` is the frozen five; making it data-driven is a different task with its own layout question.
- Unicode confusables of a token: a homoglyph or full-width spelling, a zero-width character inside a token, a combining-mark variant, or any normalization form other than the bytes `bin/log-run.sh` wrote. The rule is byte equality by decision (D2), and an ever-more-exotic near-miss is not an escalating finding class — the three committed near-misses (case, whitespace, prose) are the protected boundary.
- A hand-forged row that fakes JSON escaping to smuggle a token past a boundary-anchored scan. T-1011 D7's declared residual, inherited rather than re-litigated: `bin/log-run.sh` is the single canonical writer and cannot produce one.
- Pathological scale: thousands of flag-bearing events, hundreds of rework rounds, a multi-megabyte payload. No performance bound is promised and no rail layout guarantee holds at that scale.
- Rail **pixel** fidelity: dot geometry at arbitrary viewport sizes, zoom levels or print media; the exact frame timing of the `flash` animation; the reduced-motion path's frame-by-frame behaviour. The treatment is ratified; only the data path changes.
- Browsers other than a current Chromium-, WebKit- or Gecko-based release; any legacy engine; the page with JavaScript disabled.
- Any behavioural change in `bin/`: generator flags, row validation, a writer-side check that a label is a flag token. The wire schema is unchanged (Non-goals), so no writer-side input class is in scope.
- Localizing, translating or abbreviating the tokens on the rail. They render verbatim English in both languages.
- Concurrent writers appending to a runs file while a generated page is open, live updating, and cross-run comparison of rails.
