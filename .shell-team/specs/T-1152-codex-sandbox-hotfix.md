# Shipped `codex exec` blocks become single bare commands so Claude Code 2.1.278 and later run them outside the sandbox, and `codex-capture.sh --publish --thread-id` refuses a review that did not run

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1152

**Branch**: `feature/T-1152-codex-sandbox-hotfix`, cut from `develop` at `30d71fcb`. **No predecessor pull request is open**, so the branch point is `develop` itself. Every criterion below that reads a base-side blob names that commit directly, resolved by `git rev-parse --verify 30d71fcb^{commit}` and spelled byte-identically in each, so a checkout that does not carry the object fails closed instead of resolving something else. The literal is written on purpose rather than resolved through `git merge-base develop HEAD`: `develop` moves when later work merges, and a criterion resolving it at read time would silently re-point at a commit that is not this branch's base.

**Revision note (v2, pre-freeze).** This spec was revised before any intent hash was recorded, to carry the orchestrator's rulings v2. The first version dropped the `.jsonl` raw because it assumed the Codex event stream could only be obtained through a shell redirection on the `codex exec` line. That assumption is false: Codex keeps its own per-thread record. The first version's `--alloc --out-only`, its optional `--publish-jsonl`, and every criterion built on them are gone.

## Problem

Claude Code 2.1.278 changed `sandbox.excludedCommands` so that a Bash command is exempted only when **every part** of it matches, not just its leading command. Every shipped `codex exec` block in this plugin ends in a shell redirection (`> "<RAW_JSONL>" 2>&1`, some also `< /dev/null`), and the alternate-executor recipe also passes its prompt as a `"$(cat …)"` command substitution. Measured on this host (Claude Code 2.1.281), each of those counts as a separate, non-matching part, so the whole call runs **inside** the outer sandbox. Codex then cannot reach its backend or run its own tools. The cross-provider review either fails loudly (`workspace routing discovery failed` → `turn.failed`, exit 1, no `-o` written) or, as measured on 2.1.278, "succeeds" with exit 0 and a final message of `Unable to determine.` that `codex-capture.sh --publish` accepts as a verdict. The same bare call without any redirection runs outside the sandbox and completes normally. `docs/distribution.md` still says the exclusion matches on a command line's first token, which is no longer true.
