## Problem

`docs/distribution.md` and `docs/distribution.ja.md` are the shipped install / update / version reference, and every host-specific section in them — `## Install`, `## Adopt in a target repo`, `## Update`, `## Version line`, `## Air-gapped / locked CI fallback (vendoring)` and their Japanese counterparts — is written for a Claude Code host only. The files' opening line goes further than "Claude Code first": it states that one install per machine makes everything available in every repo with no per-repo copying, which is false on a Codex CLI host, where the generated custom agents are produced per adopted repository from that repository's own root. `docs/workflow.md` and `docs/workflow.ja.md` describe the phase flow, the status flags and the two gates without saying that the same flow runs from a Codex CLI session at all; their `## Codex CLI quick-reference` section is about the *reviewer's* Codex invocations on a Claude Code host, which is the opposite direction and is easy to mistake for the host path. The Codex CLI host's own install and update commands exist only inside `docs/adopting.md`'s runbook, so a reader who starts from the distribution guide never learns the second host exists — and T-1148's review deferred the README's own "the full update path" pointer to this file on the understanding that this task makes it cover both hosts.
