## Problem

`bin/check-refreeze-class.sh` shipped at mode `100644`. Under this repository's own bare-name PATH convention — the way `skills/run/SKILL.md` tells the loop to invoke it — it failed with `permission denied`, and not one machine check noticed: the spec's acceptance criteria called it as `bash "$SCRIPT"`, and all 30 fixtures called it as `bash "$CLASSIFIER"`. A cross-provider reviewer found it by hand. The gap is not the one missing bit; it is that "is this artifact actually executable the way its documented callers invoke it" was nobody's measured property.

The same review deferred four hardening items on that classifier's failure paths and two suite-strengthening fixtures. All six were correctly deferred — each was grounded against the spec's own declared out-of-scope input class, and none blocked the merge — but three of the four failure-path items were independently corroborated by two review passes, one was empirically reproduced under `ulimit -f 0`, and one of them is explicitly shared, byte for byte, with `bin/check-intent.sh`, the ledger script the whole frozen-intent mechanism rests on. Fixing that one in the classifier alone would leave the pair divergent, which is the failure mode the classifier's own "one definition, not two" premise exists to prevent.

## Goal

<!-- BEGIN intent-block: T-1034 -->

A machine rule, not a memory, holds every tracked file under `bin/` at index mode `100755`, and that rule is wired into CI. `bin/check-refreeze-class.sh` no longer leaks a temp file when its extraction write fails, no longer reads a `cmp` I/O error as a comparison result, and refuses to classify a partially-read intent block. Both `bin/check-refreeze-class.sh` and `bin/check-intent.sh` preserve their real exit status through their `EXIT` trap, carry byte-identical `HUP`/`INT`/`TERM` handlers, and derive their `--help` text from their own header dynamically, so documenting the new signal exits cannot truncate it. `tests/check-refreeze-class/run.sh` carries 35 cases: the 30 T-1028 froze, plus five that pin how an indent or internal-whitespace change to a `- check:` line is classified and that only the line-count clause rejects an addition at the block's tail. `.shell-team/lessons.md`, `agents/`, `skills/`, `docs/`, `templates/`, every adopter-facing document, and every other `bin/` script and `tests/` suite are byte-identical to the base ref.

### Settled decisions

Every decision below is resolved. Nothing structural is left to implementation judgment, and every text this task ships into a script is frozen byte for byte in this section, so an acceptance criterion reads its expected bytes out of this file rather than restating them.

**DP1 — The exec-bit rule ships as this repository's own lock suite, never as adopter-facing loop machinery.** It lives at `tests/bin-exec-bit/run.sh`, structurally mirroring `tests/gitignore-raw-dumps/run.sh` (a lock over a property that already holds, with its own non-vacuity controls), and reaches CI through one new pure-bash step in `.github/workflows/check-handoff.yml`. **`bin/close-out.sh` was considered and rejected as the venue**: close-out runs inside adopter repositories, which have no `bin/` of ours at all, so a fail-closed gate there would break every adopter for a property that is ours to hold. No new `bin/` script is created; the rule has no adopter-facing surface.

**DP2 — The rule is judged by `git ls-files -s` (index mode), never by a filesystem `test -x`.** A working-tree probe lies under `core.fileMode=false`, and the index is what actually ships. Empty or unavailable `git` output is a **failure**, never a clean pass.

**DP3 — Coverage is a rule over a measured population, not an enumeration, and the population is derived without a glob.** The rule is: *every tracked entry under `bin/` reports mode `100755`.* It is derived from `git ls-files -s -- bin/`, which recurses into any future subdirectory and does not depend on a filename extension. A `bin/*.sh` glob would silently miss **`bin/install`**, 1 of the 36 tracked entries, so `bin/install` is named as an explicit positive control: the measured population must contain it, at `100755`, by name. Any mode other than `100755` fails — including a symlink (`120000`) or a gitlink (`160000`), which are classified as failures rather than accommodated, because introducing one is a design decision that belongs in a spec.

**DP4 — The narrow rule (`bin/` only) is chosen over the wide rule (every tracked file beginning `#!`), on a stated discriminator, and no exception ledger is built.** The discriminator is *silence*: a `bin/` script's missing exec bit is invisible, because every mechanical caller in this repository invokes it as `bash bin/…` while the documented human/loop caller uses the bare name. Every other executable-shaped tracked file fails **loudly** instead — a `tests/*/run.sh` is always invoked as `bash tests/…/run.sh`, and a PATH shim fixture (`tests/discover-work/fixtures/gh`, `tests/retro-inputs/fixtures/{gh,git}`) that lost its exec bit makes its own suite fail in CI on the next run. `docs/interventions-reminder-hook.sample.sh` is a sample an operator copies, not something this repository executes. The wide rule would therefore buy no new detection while requiring a content-anchored exception ledger with reverse-staleness checking — machinery whose own staleness is a maintenance surface this task declines to open.

**DP5 — The lock carries its own non-vacuity controls, inside the suite, printed under two frozen labels.** Following `tests/errexit-safe/run.sh`'s inline-mutation idiom rather than adding a CLI surface: the suite applies its rule to two synthetic mode listings it builds itself and prints, verbatim, `control: a 100644 member is rejected` and `control: an empty population is rejected`. A rule that cannot go red, and a zero-subject population that reads "clean", are the two ways this lock could ship as decoration.

**DP6 — At least one criterion exercises the mode the way the defect's real caller does.** `check-refreeze-class.sh --help` and `check-intent.sh --help` are invoked **by bare name with `bin/` prepended to `PATH`**, and again as `./bin/…`, with no `bash` prefix — the two shapes that failed in T-1028's round 1. This is deliberately not extended to all 36 entries: most have no `--help` and would do work, so the index-mode rule of DP3 is what covers them.

**DP7 — Both scripts' `print_help` is replaced by the T-101 dynamic header derivation, and the two bodies become byte-identical.** `bin/check-refreeze-class.sh` currently slices `sed -n '2,66p'` and `bin/check-intent.sh` slices `sed -n '2,95p'`. Documenting the new signal exits in either header would shift those boundaries and break `--help` by truncation or source leakage — the exact defect `bin/check-board-headings.sh`'s `usage()` already fixed under T-101 and `tests/check-board-headings/run.sh` already locks with a counterfactual. Renumbering the two ranges would re-arm the same trap for the next header edit, so both are replaced by this frozen body, identical in both files (both already define `SELF` and `fail_usage`):

<!-- frozen-begin: PH -->
```
print_help() {
  awk 'NR==1{next} /^#/{sub(/^# ?/,""); print; next}{exit}' "$SELF" \
    || fail_usage "failed to read this script's own header comment (--help) from: $SELF"
}
```
<!-- frozen-end: PH -->

**DP8 — `extract_region()`'s leak is closed structurally, by deleting the command substitution, not by moving the registration a third time.** The parent shell creates the temp file with `mktemp`, appends it to `TMP_FILES` **before** any write, and passes the path to `extract_region` as an argument; the function only writes into it and prints nothing. The `$( )` around the call — the actual root cause, since a subshell's `TMP_FILES+=()` never reaches the parent — is removed. This same function drew a defect in two consecutive T-1028 rounds; a third registration-position patch is precisely what the playbook says not to attempt.

**DP9 — A `cmp` exit status greater than 1 is classified `usage` (exit 2), matching this file's existing convention that every external-command failure is `fail_usage`** (`readlink`, `dirname`, `cd`/`pwd`, `basename`, `mktemp`, `awk`, `git hash-object` all already route there). Introducing a third convention for one command would be the drift. The status is captured explicitly, never read from a later `$?`:

<!-- frozen-begin: CMP -->
```
cmp_rc=0
cmp -s "$OLD_REGION" "$NEW_REGION" || cmp_rc=$?
if [ "$cmp_rc" -eq 0 ]; then
  fail_structural "old-spec and new-spec intent blocks are byte-identical after normalization (no delta) for $TASK_ID — a re-freeze with no change is a bookkeeping error, never a pass"
elif [ "$cmp_rc" -gt 1 ]; then
  fail_usage "cmp failed while comparing the two extracted intent blocks ($OLD_REGION, $NEW_REGION) — an I/O error is not a comparison result and is never read as 'the blocks differ'"
fi
```
<!-- frozen-end: CMP -->

**DP10 — "Symmetric", for the two-script change, means behaviour-identical with one byte-identical literal fragment, and the fragment is the signal half.** The two scripts' cleanup structures genuinely differ — `check-refreeze-class.sh` holds a `TMP_FILES` array cleaned by a named function, `check-intent.sh` holds a single `tmp_region` cleaned by a string-form trap installed after that variable exists — so a byte-identical whole-trap is not available without rewriting one of them, which is out of scope. The signal handler and its three installations **are** byte-identical in both, giving the cheap AC5-style machine check (one definition, two consumers). `self_name` is used rather than a hard-coded script name precisely so the fragment can be identical; both scripts already define it in their symlink-resolution bootstrap.

<!-- frozen-begin: SIG -->
```
on_signal() {  # $1 = signal name, $2 = the conventional 128+N exit code
  printf '%s: interrupted by SIG%s (a signal, not a classification)\n' "$self_name" "$1" >&2 || true
  exit "$2"
}
trap 'on_signal HUP 129' HUP
trap 'on_signal INT 130' INT
trap 'on_signal TERM 143' TERM
```
<!-- frozen-end: SIG -->

The seven lines are contiguous and are installed **immediately after the `SELF=` assignment** in both scripts, and not before it: `$self_name` is set in that bootstrap, and under `set -u` a handler firing before it exists would die on an unbound variable instead of exiting cleanly. A signal arriving during the bootstrap itself keeps its default disposition; that is stated rather than hidden.

**DP11 — `128+N` is adopted as an out-of-contract exit code, documented in both headers, and does not collide with the classification contract.** Both scripts keep `0`/`1`/`2` as their only *classification* exits — their `die()` functions are byte-identical to the base ref after this task — and each header gains a line stating that `129`/`130`/`143` mean SIGHUP/SIGINT/SIGTERM terminated the run and carry no classification. DP7 is what makes adding those header lines safe.

**DP12 — The `EXIT` trap captures the real status first and restores it last, and its own `rm` is guarded.** Under `set -e` a failing statement inside an `EXIT` trap aborts the handler and the script lands on 1, so capturing `$?` is not sufficient on its own — the `rm` must carry `|| true` as well, or the restore line is never reached. The status variable is named `_exit_rc` to avoid colliding with any `rc` either script may use. `check-intent.sh`'s trap installation **stays exactly where it is**, after `tmp_region` is assigned; only its form changes from a string to this named function, because a handler referencing `$tmp_region` installed any earlier would be unbound under `set -u`.

<!-- frozen-begin: EXC -->
```
cleanup_tmp_files() {
  _exit_rc=$?
  if [ "${#TMP_FILES[@]}" -gt 0 ]; then
    rm -f "${TMP_FILES[@]}" || true
  fi
  exit "$_exit_rc"
}
```
<!-- frozen-end: EXC -->

<!-- frozen-begin: EXI -->
```
cleanup_tmp_region() {
  _exit_rc=$?
  rm -f "$tmp_region" || true
  exit "$_exit_rc"
}
```
<!-- frozen-end: EXI -->

## Input space

**Reachable input classes** — what this task's artifacts really read and must handle correctly:

- **This repository's own git index, as `git ls-files -s -- bin/` reports it**: 36 tracked entries today (35 with a `.sh` extension, plus the extension-less `bin/install`), each at mode `100644` or `100755`. Also reachable, and classified as failures rather than accommodated: a future `bin/` subdirectory (the derivation recurses), a symlink entry (`120000`), a gitlink (`160000`), and an empty or unavailable `git` output (fails closed).
- **The classifier's two spec-file arguments**, unchanged from T-1028: UTF-8 markdown, LF or CRLF, one `**Task ID**: T-NNNN` line, exactly one marker pair, an intent block of tens to a few hundred lines, `- check:` sub-bullets indented by two spaces carrying both quote kinds, `$( )`, em-dashes and backticks mid-line.
- **`- check:` lines whose leading indent or internal whitespace differs between the two sides** — two spaces versus four, a tab, an extra space after the colon. Real: every spec in `.shell-team/specs/` is hand-edited, and an editor's re-indent produces exactly this.
- **An intent block whose new side has one more line at its very tail**, appended after the last content line and before the END marker. Real: a criterion or an Input-space bullet added at the end of a rework.
- **Four failure classes T-1028 declared out of scope and this task deliberately takes in**, each named because a review reproduced or corroborated it: (1) an extraction **write failure after `mktemp` already succeeded** — reproduced under `ulimit -f 0`; (2) **`cmp` returning greater than 1** (an I/O error rather than a comparison result); (3) **`SIGHUP`/`SIGINT`/`SIGTERM` delivered to a running invocation** — reachable by an operator pressing Ctrl-C or a CI job cancelling; (4) **an `rm` that fails inside the `EXIT` trap**, which is the only way the exit-code clobber actually fires.
- **Both documented invocation shapes of a `bin/` script**: bare name resolved through `PATH` with the plugin loaded, and `./bin/…` from the checkout root.

**Out-of-scope synthetic extremes** — inputs this spec explicitly declines to protect:

- **A hostile `$TMPDIR`**: an attacker-controlled temp directory, a symlink race against `mktemp`, or a permission flip between `mktemp` and the write. `mktemp`'s own guarantees are the boundary; T-1028 adjudicated this class and only the four members listed above are taken in.
- **Signals other than `HUP`/`INT`/`TERM`.** `KILL` and `STOP` cannot be trapped at all; `QUIT`, `USR1`, `USR2` and the rest keep their default disposition, deliberately, so the handler stays a six-line fragment two scripts can share verbatim.
- **A `git`, `awk`, `sed` or `cmp` that hangs rather than fails.** The time/liveness axis stays where T-1028's QA recorded it: environmentally-unverified, not protected. The `SIGTERM` probe uses a blocking `git` shim to *reach* the handler; it does not make hang-tolerance a property this task promises.
- **Concurrent invocations racing on the same temp files**, and any TOCTOU race on a spec file between validation and read. AC12's guards narrow the consequence; they do not close the race, and AC12 says so.
- **A filesystem or configuration where the working tree's exec bit is not preserved** (`core.fileMode=false`, a mount without exec-bit support). The index is the authority per DP2; AC4's working-tree clause assumes a mode-preserving checkout and is expected to be the first thing that fails on one that is not.
- **Ever-larger populations**: an arbitrarily deep `bin/` tree, thousands of entries, or a data file deliberately placed in `bin/`. The last of these fails the rule on purpose — introducing it is a design decision that needs a spec, not an input class to accommodate.
- **Adopter repositories.** Nothing here runs outside this checkout; the rule has no adopter-facing surface by DP1.
