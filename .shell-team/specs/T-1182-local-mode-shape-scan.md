# In `local` record mode the hand-off shape scan reads the ignored records: `check-pii-shapes.sh --paths` and the `record-shape-scan` block's `local` branch

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1182

## Problem

#711 task A (T-1180) declared the record mode. Task B (T-1181) told the roles and run skills that in `local` mode record files under the base dir are written and never committed. The hand-off shape scan still cannot see those records. The engineer, QA, the scrum-master and the cross-provider reviewer run `PII_CHECK_TRACKER_KEY=1 bash "<plugin root>/bin/check-pii-shapes.sh" --all` on the records they wrote. `--all` enumerates tracked files and untracked files that are not ignored. The default mode reads committed blobs. Neither mode reads an ignored file, so in a `local`-mode clone, where the base dir is ignored, every scan reports clean without having read one record. This task is #711 task C1. The coordinating session split task C into two tasks: this one adds an explicit-path mode to the checker, the `local` branch to the `record-shape-scan` block and the PII-controls docs; T-1183 carries setup, init, the remaining shipped docs, the live two-gate run and issue #714's follow-ups.

**Decisions frozen here** (each is promoted to a criterion):

- **D1 — the `--paths` mode.** Grammar: `check-pii-shapes.sh --paths <path> [<path>...]`. `--paths` is the last option, and every argument after it is a path. At least one path is required. An argument after `--paths` that begins with `-` is a usage error, so a path beginning with `-` is written `./-name`. `--paths` together with `--all` or `--base`, in either order, is a usage error. Each path is resolved against the invoking directory. A named file is scanned. A named directory is walked recursively, and a `.git` entry (directory or file) met inside a walk is neither descended into nor scanned. A symlink, whether named or met in a walk, is scanned by its stored target string and never followed, including a symlink to a directory. This matches `--all`. A file carrying a NUL byte is skipped with the existing `skip: binary` stderr notice. Ignore rules are never consulted: every named path is read whatever its ignore status. The known-shapes list applies to the repo-root-relative path, and `PII_CHECK_TRACKER_KEY` applies unchanged. Findings use the existing `FINDING pattern=<id> path=<path> line=<n>` grammar. `<path>` is relative to the repository root with no leading `./`, and a finding never echoes the matched bytes. A clean run prints the existing clean line and exits `0`. Exit `2`, without the clean line on either stream, results when a named path does not exist, when a named file or a file met in a walk cannot be read, or when the run scanned no regular text file: an empty directory, a directory holding only binary files, or only symlinks. The header comment, and so `--help`, gains a `--paths` Usage line and names `--paths` in the exit-code text. (**AC1**, **AC2**, **AC3**, **AC5**)
- **D2 — tracked behaviour byte-identical.** With `--paths` absent, the default mode, `--base`, `--all`, their usage errors and the tracker-key opt-in produce the same exit status, stdout and stderr as the base commit's script on the same input. (**AC4**)
