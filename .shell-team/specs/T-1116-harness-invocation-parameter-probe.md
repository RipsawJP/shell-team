**Grading, fixed as a mechanical rule over one recorded line, and that line is itself recorded.** The grading target is the **reply's final non-empty line**, and that line is transcribed verbatim onto the outcome record as its terminal field `final-line=`, with control characters stripped and nothing else altered — where a reply carries no non-empty line at all, the field is present and empty. The three graded fields are then **derived from that recorded line** rather than reported alongside it: `final-shape=conforming` iff the recorded `final-line` begins with the literal `answer=`; `integers=<digits>` is the count of maximal `-?[0-9]+` runs on it; `value=<integer|none>` is that single run where `integers` is `1` and the literal `none` otherwise. The verdict is then **derived, not chosen**: `na` where `final-shape` is `non-conforming` **or** `integers` is not `1`; otherwise `pass` where `value` equals the item in force's declared answer and `fail` where it does not. An `na` rep is **void** and is never counted as a `fail`, so format-following can never masquerade as capability and non-compliance can never masquerade as incapacity. **AC8** recomputes all three fields, and then the verdict, from the recorded `final-line` alone, so a mistranscribed or invented primitive fails there instead of sailing through a chain that recomputes only the last step. What this closes and what it does not is stated rather than left to a reader: `final-line` is the coordinating session's **transcription of the tool result**, exactly the same trust boundary every other evidence field on the page stands on, so the property gained is that each grade is **recomputable from a recorded observable** — not that the observable is authenticated. ## Decision points

Every design point below was settled by `tech-lead`'s Routing Map for this redo and by the coordinating session's review of it; this section records where each is encoded, so a later reader does not reopen a closed question.

- **DP-1 — the differential is the only routing evidence.** Encoded in the Goal's licensing paragraph, in the closed vocabulary's reachability (only `undetermined` and `instrument-inadmissible` are reachable without it), and mechanically in **AC10**(ii)(iv)'s pinned channel roles and self-report lock.
- **DP-2 — subject role `shell-team:tech-lead`.** Settled on the measured absence of `Bash` from its frontmatter, which makes the item uncomputable with a tool; `qa-verifier`'s `Bash` would have flattened the differential into a measurement of tool access. The map's own draft claimed the `model: opus` pin "sits outside the two override tiers"; the coordinating session corrected that — `opus` **is** one of the two tiers. Round 1 then found the corrected argument itself imprecise (R1-9), and the reworded version is what this spec now encodes: **separability follows from `model` being the arms' only difference** and holds whatever the pin's identity, while the pin being a *tested* tier buys the narrower thing of making `plug-base`'s behaviour under override-honored predictable from the calibration. The design decision is unchanged; only the justification's width moved. **Three** costs are disclosed rather than argued away: the long system prompt's effect on conformance, which can only produce a null; the calibration's cross-role scope (R1-4), whose only reachable direction is Branch B; and the loss of continuity with T-1111's subject role.

## Assumptions

Rows **A-1** through **A-12** are `**relayed**`: the primary confirmation is held by the coordinating session, which read the Agent tool's own schema and description text first-hand in its own context. This role has no path to that surface — it cannot see a tool schema, invoke a sub-agent or read a tool result — so each row names the holder, states the premise as the holder states it, and names what the freeze run must re-read and report beside it. Twelve relayed rows is also the measured `cost-input: t1092-domain-premise-count` for this task, and it is the concrete ground for the `spec-review — cross-provider` election: this spec's soundness rests on a domain premise this repository cannot itself measure.

- **A-1 — relayed — the `model` parameter's enum is closed at `sonnet`, `opus`, `haiku`, `fable`.** Holder: the coordinating session (Agent tool JSON schema, `"enum"`). This is the premise behind the two override tiers and behind row A-5's consequence. The freeze run re-reads the schema and records the enum beside this row.
- **A-2 — relayed — the precedence sentence and its `fork` exception.** Holder: the coordinating session, quoting the parameter description: the override "takes precedence over the agent definition's model frontmatter and the configured default subagent model", and is "ignored for `subagent_type: \"fork\"`". This is a **declaration**, not an observation of routing, and the whole point of this task is that the declaration's being honored for a plugin role with a pinned model is exactly what has never been measured. The freeze run re-reads and records it.
- **A-3 — relayed — the parameter list is exactly `description`, `prompt`, `subagent_type`, `model`, `isolation`, with no effort field and no cwd field.** Holder: the coordinating session. Two consequences this spec depends on: the effort verdict's primary evidence is this closed list, and the venue is an instruction plus an after-the-fact measurement rather than an enforcement, because no cwd parameter exists to point a launch anywhere. What this spec does **not** do is rest on the premise being true: `falsify-effort-key` exists to falsify it, and where it does, the effort branch **re-routes** — schema read `present`, a real launch-side attempt, an observed-effect reading — rather than stopping the task, because the model question's instrument reads none of this row. - **A-4 — relayed — the result's `<usage>` block carries exactly `subagent_tokens`, `tool_uses`, `duration_ms`, and no model field.** Holder: the coordinating session, observed on every sub-agent return in its own session.
