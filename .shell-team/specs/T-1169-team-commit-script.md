## Problem

On the Codex CLI host the sandbox refuses every write under `.git/`, so a role's own commit fails. The run skill's Codex dispatch paragraph says the run "neither asks for nor adds that grant", which a Codex CLI clean-install run (v2.8.1) read as forbidding even a per-command approval request, and the loop stopped `BLOCKED` before `READY_FOR_QA`. T-1168 then tried to state the allowed request in prose and in the refused-command lesson; four review rounds showed that any prose naming "the commands a commit needs" can be stretched to a removal, a `-A`/`-a`/`--amend` form, another command or the other host. The approved fix replaces the open-ended class with one closed, mechanically checked invocation: a script that stages exactly the named paths, commits them with a message file, refuses everything else, and verifies afterwards that the commit holds exactly those paths and no deletion. The canon is issue #662 (Expected relayed verbatim in T-1168's spec): the run never requests a grant that widens the session's sandbox, trust or writable roots; asking the operator to approve a role's own commit one concrete command at a time through the host's ordinary per-command approval prompt is allowed; the approval covers only the command shown.

**Goal (one sentence).** A new `bin/team-commit.sh`, invoked as `bash "<plugin root>/bin/team-commit.sh" --message-file '<file>' -- '<path>' …`, stages exactly the named paths with `git add --` and commits them with `git commit -F`, refuses every input outside a closed allowlist before writing anything, never resets, amends or bypasses hooks, and after committing verifies that the commit holds exactly the requested paths, each added or modified, with no deletion; on the Codex CLI host every commit the run makes goes through one such invocation, and when the sandbox refuses it the committing party first requests the host's ordinary per-command approval for that identical invocation, unchanged, and otherwise stops `BLOCKED` with the exact refusal and the exact command for the operator to run; every other command, every other git command and every deletion stays stop-and-report `BLOCKED`, the approval is never extended to a push, the run never requests a grant that widens the session's sandbox, trust or writable roots, and the Claude Code host is unchanged.

**Decisions frozen here** (each is promoted to a criterion):

1. **Interface.** `bin/team-commit.sh --message-file <file> -- <path>...`, plus `--help`/`-h`. Any other argument, and any of `-a`, `-A`, `--all`, `--amend`, `--no-verify`, `-n`, `--force`, is refused. Exit codes: `0` committed and verified (stdout: the new commit's full SHA, one line); `1` a `git add` or `git commit` it ran failed (stderr names the failing step and the staged paths; nothing is reset); `2` refused before any write (usage, environment, repository state, message file, path); `3` the commit was made but post-commit verification found a mismatch (stderr lists requested and actual paths; the commit is kept, never reset, undone or amended — D4). (**AC1**–**AC4**, **AC6**)
2. **Preconditions, all checked before any write; any failure is exit `2`.** Run from the top level of a git work tree (`git rev-parse --show-toplevel` equals the physical cwd); HEAD is a branch with at least one commit (unborn HEAD refused — this role's D-call: a first commit is repository setup, not a role's own commit, and post-commit verification needs a parent); not detached; no merge, cherry-pick, revert or rebase in progress; the index holds no staged change relative to HEAD (D1, strict-empty, no tolerance mode); none of `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_COMMON_DIR`, `GIT_NAMESPACE`, `GIT_LITERAL_PATHSPECS`, `GIT_GLOB_PATHSPECS`, `GIT_NOGLOB_PATHSPECS`, `GIT_ICASE_PATHSPECS`, `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_COUNT` is set in the environment (refused, never unset). `HOME`, `XDG_CONFIG_HOME`, `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM`, `GIT_CONFIG_NOSYSTEM` and the author/committer identity variables are not refused: they select the operator's own configuration and identity rather than redirect the repository, index or pathspec semantics (this role's reading of the briefing's "etc."). **Reachable input classes** (each with its **AC6** fixture case id):

1. **Successful commits.** A modified tracked file (`ok-modified`); a new untracked file (`ok-new-file`); several paths at once (`ok-multi`); a new executable file (`ok-new-exec`); a repository with its own `pre-commit` hook, which runs (`ok-hook-runs`); a multi-line message committed verbatim (`ok-message-verbatim`).
