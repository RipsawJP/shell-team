# Codex host, slice 2: the cross-provider review gate runs on the Codex CLI host, so a documented runbook alone carries a Codex-hosted run to `READY_FOR_MERGE`

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1135

## Problem

Slice 1 (T-1134) got a Codex CLI host as far as `READY_FOR_REVIEW` and then stopped, by design: `codex-reviewer`'s `APPROVE` still runs on the Claude Code host, so a Codex-only operator reaches one green gate and has to change hosts for the other. Two further gaps were disclosed there and tracked — a spawned role's `bin/*.sh` calls have no in-band resolution (#486), and the shipped "`bin/` is on `PATH`" claim is false for an installed plugin (#485). The measured way to close the review gate is to make the reviewer **the provider the host is not**: on a Codex host, the cross-provider second opinion comes from Claude. The hazard this task has to avoid is the same one slice 1 avoided — a second, Codex-shaped copy of the reviewer's prose — and the hazard slice 1 actually hit: eleven of its twelve findings were adopter-documentation omissions discovered one per review round, because completeness of a runbook was verified by reading it rather than by walking it.

## Input space

**Reachable input classes** — what a real role file, a real binding, a real Claude Code CLI result and a real adopter repository produce, all of which the implementation must handle correctly:

1. `agents/codex-reviewer.md` as it stands: a four-field frontmatter, a `description:` carrying neither a double quote nor a backslash, a body with no `'''` run, a trailing newline, and multi-byte UTF-8 in places. Generated normally, body byte-identical.
2. The same file after an ordinary future edit that adds prose. It must keep satisfying the generator's input class; a future edit that does not is the generator's own fail-closed refusal, not a silent partial generation.
3. A resolved binding row for `codex-reviewer` on `codex-cli` whose model token is the `provider-configured` placeholder and whose effort column is `-` — the shipped default. Neither `model` nor `model_reasoning_effort` is emitted.
4. An adopter's own `binding.conf` rebinding `codex-reviewer` to a Codex adapter with a real model token and a non-`-` effort. Both keys are emitted, by the branch the fixture suite already exercises.
5. An adopter's own `binding.conf` rebinding `codex-reviewer` to `claude-cli`. Neither key is emitted, and the loop's own documented consequence — cross-provider review is no longer guaranteed on a Claude host — is the repository's existing, unchanged disclosure.
6. A `claude -p --output-format stream-json` capture of the ordinary successful shape: one complete JSON object per line, each carrying a `"type"` key, ending with a `result` event whose fields include `usage`, `duration_ms` and `total_cost_usd`. Published through the unmodified capture helper.
7. The same stream with interleaved non-JSON noise on some lines. Tolerated by the helper's validation as long as one complete typed event line is present.
8. A `claude -p` run that produces no typed event at all — the network-refused `Not logged in` case, and any other non-zero exit. The recipe stops and reports `BLOCKED` with the exact error; the capture is refused rather than published, and the runbook names this case as branch 7 of the state space.
9. A `claude -p` run that succeeds but whose review finds nothing to change. An ordinary `APPROVE`, published and recorded like any other verdict.
10. An out-dir already holding slice 1's four generated files and no fifth. The generator overwrites its own files and adds the fifth; the checker reports the missing fifth as a violation and never repairs it.
11. An out-dir also holding the adopter's own Codex agent TOMLs, whose names do not begin `shell-team-`. Left untouched by the generator — including by whatever staged-write shape **D6** rules — and ignored by the checker.
12. A repository whose Codex trust has not been granted. Project-level agents are not discovered; the runbook states the precondition and no criterion claims the generator can work around it.
13. A shell that has not exported `<plugin root>/bin` onto `PATH` before starting `codex`. A spawned role's bare-name `bin/*.sh` calls do not resolve; the runbook states the export as a step rather than leaving it to chance, which is how #486 closes.
14. Either supported layout — the `.shell-team/` default and the legacy `tasks/` one — and a `$TEAM_RUN_BASE` override. The out-dir is a Codex host-configuration directory rather than a shell-team operating path; the binding read goes through the existing resolver, which honours the override as it already does.
15. A `--roles` override naming a legitimate subset of the shipped roles. Generates exactly that subset. A token outside a safe role-identifier shape is refused rather than turned into a path.

**Out-of-scope synthetic extremes** — named concretely, and declined:

- Claude Code CLI versions other than 2.1.268 and Codex CLI versions other than 0.154.0. Every flag, output shape, discovery rule and sandbox behaviour this design rests on was measured on those two versions on one macOS host, named in `## Assumptions`. A future version that renames a flag, reshapes an output format or changes a sandbox default is a re-measurement, not a defect these criteria can anticipate. No criterion asserts forward compatibility.
- Hosts other than the one measured, and operating systems other than macOS. The sandbox's protected-directory set, the plugin-root layout and the `PATH` inheritance were all measured in one place.
- A hand-crafted adversarial `agents/codex-reviewer.md` — a body engineered against the generator's awk extraction, a frontmatter engineered against its `description:` parse. A role file is a trusted instruction channel under this repository's own security invariant, authored prose reviewed by these same gates, not untrusted input.
- A hand-crafted adversarial Claude capture — a JSONL engineered to satisfy the helper's `"type"` check while carrying no review, an enormous single line, a stream with embedded NULs. The capture's producer is the CLI the recipe itself invoked in the same command, not a third party.
- Concurrent runs: two generator runs racing on one out-dir, a generator interleaved with a checker on the same directory, or two reviewer invocations sharing one capture stem. No locking is added; the documented use is one adopter running one loop.
- An agent-name collision between a generated `shell-team-codex-reviewer` and an identically named agent in the adopter's home-level Codex agents directory. The `shell-team-` prefix is the mitigation; precedence between the two namespaces is unmeasured and no resolution order is claimed.
- Any claim that a generated `sandbox_mode` bounds what a spawned agent can write, the reviewer's included. Measured false in slice 1; declined outright, and the generated file and both documentation sections say so rather than leaving a reader to discover it.
- Any claim that the `--tools` / `--disallowedTools` isolation on the `claude -p` invocation is a security boundary against a hostile model. It is a configuration that keeps an ordinary review read-only and keeps the adopter's own settings out of the run; it is not a sandbox, and no criterion asserts it as one.
- Cost bounds for the reviewer pass. The measured trivial-call figure is a property of one host's loaded global configuration at one moment, recorded in `## Assumptions` as context; no criterion asserts a budget.
