# A run's telemetry renders as a self-contained replay page

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1012
**Source**: GitHub issue #77 — **Part 2 only** (Part 1 = event rows, shipped as T-1011; Part 3 = README/`docs/` wiring, which is T-1013)
**Base**: `develop` @ `d08393b`
**Branch**: `feature/77-part2-gen-loop-replay`

## Problem

T-1011 gave a run a total order: span rows and event rows share one monotonic `seq` in one `<loop_id>.jsonl`, so a run can now be read back as a sequence of what the loop did. Nothing reads it back that way. `rollup-runs.sh` aggregates, `cluster-failures.sh` groups failures — both answer "how much" and "what went wrong across runs", neither answers "what happened, in order, in this one run". A reviewer, a retro, or anyone trying to explain the loop to someone else still has to read JSONL by hand.

A prototype replay page already exists and its interaction design is ratified: a ground ring of agents, an orchestrator/human layer above it, a single serial ball that is only ever in one place, a concurrent beam channel for the organizational routing the ball does not draw, a flag rail carrying the verbatim machine tokens, camera controls, level-of-detail mini-cards, an idle UI-designer caption, a JA/EN toggle driven from one dictionary, `prefers-reduced-motion` support, and a playback transport. It is hardcoded to one sample run in a bespoke event shape. What is missing is the part that makes it a tool rather than a demo: a generator that takes a real run id, reads the real telemetry, and produces that page.

The verbatim Part 2 scope from issue #77, canon for this task: *`bin/gen-loop-replay.sh <run-id>` — reads the resolved runs file (`team-paths.sh --get runs`; never a hardcoded layout), filters the run's rows, injects them as JSON into the shipped HTML template, writes a self-contained HTML file (no network, CSP-safe, works from `file://`). Pure bash, zero-dependency, shellcheck-clean, fail-closed: unknown run-id, malformed rows, or an unreadable template are errors, never an empty page.*

## Goal

<!-- BEGIN intent-block: T-1012 -->

`bin/gen-loop-replay.sh <run-id>` resolves the runs directory through `bin/team-paths.sh`, selects every telemetry row of that run across the directory's `*.jsonl` files, validates them with the sibling `bin/check-run.sh`, and writes one self-contained HTML file whose only difference from the shipped `templates/loop-replay.html` is a single injected data line. The page needs no network, no external asset and no build step; it opens from `file://`. Every failure path — an unknown run id, a malformed row anywhere in the scanned files, an unreadable or placeholder-less template, an unwritable or non-regular output path, a malformed argument — exits non-zero with a reason and leaves **no output file at all**. A span-only run (which is what every run recorded before T-1011 is, and what 11 of the 12 runs in this repository's own telemetry are at the base ref) renders as a real, honestly-degraded page that says what it is missing, never as a blank one. The prototype's ratified interaction design survives intact; what changes inside the template is the data-adaptation layer that turns T-1011's frozen row shapes into the scene model, and the removal of the sample run baked into it.

### Settled decisions

Each decision below is resolved. Nothing here is left to implementation judgment; the visual treatment of the degraded states is the one thing routed elsewhere, and it is routed explicitly (D3).

- **D1 — input resolution: the runs directory only, resolved, never hardcoded; T-1011's schema is consumed, never re-opened.** Precedence, mirroring `bin/log-run.sh:294-297`: `--runs-dir DIR` > `$TEAM_RUNS_DIR` > `$RUNS_DIR` > `bash team-paths.sh --get runs`. One deliberate divergence from `log-run.sh`, taken from `bin/close-out.sh:23-27`: there is **no guessed literal fallback**. `log-run.sh` falls back to the string `.shell-team/runs` because dropping a telemetry row is worse than writing it to a slightly wrong place; here, reading a guessed path would silently produce a replay of the wrong repository, so a resolver failure is exit 2.
  - **Every `*.jsonl` file in the resolved directory is scanned**, in `LC_ALL=C` sorted filename order, and rows are selected by exact `run_id` match. Rejected — reading only `<runs>/shell-team.jsonl`: that hardcodes this loop's own `loop_id`, which is exactly the class of assumption `team-paths.sh` exists to remove, and it is measurably wrong already — this repository's runs dir holds `shell-team.jsonl` *and* `close-out.jsonl` (`bin/close-out.sh` logs its own span under its own `loop_id`).
  - **Non-`.jsonl` files in the directory are ignored, not parsed.** Measured reachability, not hypothetical: `skills/loop-triage/SKILL.md:43` writes `triage-<date>.md` there, `skills/goal/SKILL.md:16` writes `goal-<task-id>.state` there, `bin/consolidate-proposals.sh:134` defaults its output there, `bin/team-init.sh:227` puts a `.gitkeep` there — and D4 puts this task's own `replay-*.html` there.
  - **Row ordering is `seq` ascending, ties broken by (filename, line number), stable.** T-1011 D3 froze `seq` as one monotonic counter per run shared across both shapes precisely so this ordering exists; the tie-break exists because nothing in T-1011 forbids a duplicate `seq` (its Non-goals explicitly decline cross-line validation) and a replay must still be deterministic when one occurs.
  - The frozen shapes are consumed as T-1011 froze them: span rows are 17 keys with **no** `kind`, event rows are 9 keys with `"kind":"event"` and the closed vocabulary `handoff|rework|gate|human|release`. `kind` absent or `"span"` means span. This task adds no key, renames none, and re-opens no part of that schema.
- **D2 — the injection is one line, one site, and escapes `<`, `>`, `&` — the measured top risk.** `bin/log-run.sh:234`'s `jesc()` escapes only `\` and `"`; `<`, `>` and `&` pass through verbatim, and `label` is free-form by T-1011 D3. A row whose label contains `</script>` is therefore a **reachable** input, not a synthetic one, and raw injection into an inline script block would terminate the block and kill the page — the same class as the `*/` incident of 2026-08-01.
  - The template carries exactly one injection site, this line, at column 1, frozen verbatim:

    ```
    <script type="application/json" id="loop-replay-data">__LOOP_REPLAY_DATA__</script>
    ```

    It sits immediately before the template's main `<script>` block. The generator replaces the token `__LOOP_REPLAY_DATA__` with the payload and changes **nothing else**: a generated file, with that line normalized back to the placeholder, is byte-identical to the template. Every other run-specific string on the page — the document title, the masthead heading, the header chips — is written by the template's own JavaScript from the parsed payload at runtime. Rejected — injecting the run id into the `<title>` and the `<h1>` as well: three injection sites in two different escaping contexts (HTML text vs. JSON-in-script) instead of one, for a value JavaScript can set itself.
  - **The payload is `application/json` consumed by `JSON.parse`, not a JavaScript object literal.** Rejected — keeping the prototype's `var DATA = {…}` and substituting the literal: injected telemetry would then be *code*. Under `JSON.parse` the operator's own free-form label text can never reach the JavaScript parser, and a payload the page cannot parse throws a catchable error, which is what makes D3's "never an empty page" implementable as an explicit banner rather than a hope. The parse is wrapped in `try`/`catch`; the catch renders the error state.
  - **The escape rule, frozen**: after the payload is assembled, every `<` is replaced by a backslash followed by `u003c`, every `>` by a backslash followed by `u003e`, and every `&` by a backslash followed by `u0026` — the JSON unicode string escape — applied as a blanket substitution over the whole payload string. `JSON.parse` decodes them back to the original characters, so a label is displayed exactly as the operator wrote it; the escaped form exists only in the file's bytes. A `label` of `</script>` therefore appears in the file's bytes as 19 characters: a backslash, `u003c`, `/script`, a backslash, `u003e`. This is provably equivalent to escaping them inside every string value and needs no parser, because none of those three characters can occur in JSON outside a string literal. It is a *second* layer: `JSON.parse` already prevents code execution, and this prevents the HTML tokenizer from ever seeing a tag-open inside the block.
  - **The payload is a single line of compact JSON** (no embedded newline), so the data block occupies exactly one line of the output. Rejected — pretty-printing: a machine-generated blob nobody reads by eye, in exchange for making every structural lock on the file multi-line.
  - **Payload envelope, frozen — exactly these four keys, in this order**: `{"run_id":…,"generated_at":…,"source":[…],"rows":[…]}`. `run_id` is the argument, echoed back; `generated_at` is an ISO-8601 UTC timestamp; `source` is the list of scanned filenames (basenames only — never absolute paths, which are a PII shape); `rows` is the selected rows **verbatim**, each one the exact JSON object `log-run.sh` wrote, in D1's order.
- **D3 — the bash side injects, the template's JavaScript adapts; degraded fidelity is a rendering contract, with its visual treatment routed to the design note.** The generator performs no field-level transformation: it filters, orders, wraps and escapes. Rejected — transforming rows into the prototype's bespoke `{type, agent, …}` shape in bash: that requires parsing JSON in bash, which the zero-dependency `bin/` contract forbids doing properly, and it would put the schema in two languages at once. Shipping rows verbatim also means a reader can diff the page's payload against the telemetry file and see they agree.
  - **The adaptation mapping, frozen at the level of which affordance each row shape gets.** The design note may rename internals; it may not reassign these.

    | frozen row | affordance in the ratified design |
    |---|---|
    | span row (`kind` absent or `"span"`) | a work step by the agent named in `span`, carrying `phase`, `model`, `tokens`, `tool_uses`, `duration_ms`, `verdict` into the detail panel and the LOD mini-card |
    | span row with `status` other than `success` | still a work step, visibly marked as not-success — **never dropped** |
    | event `handoff` | a ball move `from` → `to` |
    | event `rework` | a ball move `from` → `to` in the rework treatment, `label` as the cause |
    | event `gate` | a gate signal at `from`, `label` as the verdict |
    | event `human` | a human-layer settle, `label` as the action |
    | event `release` | the release settle |
  - **The roster is derived from the data, unioned with this loop's known roles.** Ring membership = the six known ids (`tech-lead`, `pm-spec`, `engineer`, `qa-verifier`, `codex-reviewer`, `ui-designer`) ∪ every distinct `span` value in the payload; `orchestrator` and `human` remain structural nodes, since they are the loop's topology and emit no spans. A `span` value the template does not recognise gets a neutral style and is **never dropped** — an adopter's agent names are not this loop's, exactly as T-1011 D3 reasoned about `from`/`to`.
  - **A run's operator-authored text is displayed verbatim in both languages.** The prototype's per-`seq` English override table is removed. Grounding: T-1010 settled that per-cycle artifacts are written in the operator's language and are not translated after the fact; a `label` is operator-authored text, and the JA/EN toggle localizes the page's own chrome, never the operator's words. Machine tokens (`READY_FOR_*`, `PASS`, `FAIL`, `APPROVE`, `REQUEST_CHANGES`, `REWORK`) stay verbatim English in both languages, as they already do.
  - **Degraded fidelity, as a contract.** Three degraded shapes are reachable and each must produce a real page: (i) **span-only** — no event rows at all, the dominant case; (ii) **event-only** — events but no work spans, reachable when a run is interrupted; (iii) **partial** — some event ids present, others absent. In every case the page must load, render the rows it has, and **state its own degradation** through a dictionary-backed caption naming what is missing, rather than silently showing a sparser scene. The dictionary key `degradedNoEvents` is frozen (it must exist in both the `ja` and `en` dictionaries) so the contract has a machine-checkable anchor. A run with zero rows cannot occur: that is an unknown run id, which is D5's exit 1.
  - **What the visual treatment is — banner vs. badge vs. dimmed rail, and how an empty flag rail draws — is the ui-designer's call**, delivered as `design-note-T-1012.md` before implementation. This spec fixes the contract; the note fixes the pixels.
- **D4 — the output goes inside the resolved runs directory, and generation is manual-only.** Default output path: `<resolved runs dir>/replay-<run-id>.html`. Measured basis: `templates/shell-team.gitignore:4` and this repository's own `.shell-team/.gitignore:4` already ignore `runs/` **entirely**, so the artifact is git-ignored with **zero new ignore patterns**, and an `.html` suffix dodges both consumers of that directory that use a suffix filter — `agents/triage-orchestrator.md:33,52,76`'s `<runs>/*.jsonl` glob and `bin/retro-inputs.sh:455`'s `.jsonl` file count. The directory already holds non-`.jsonl` generated files (D1), so this is a precedent followed rather than one set.
  - Rejected — a sibling `<base>/replays/` directory: it requires editing **both** `templates/shell-team.gitignore` and this repository's `.shell-team/.gitignore`, which are locked by `tests/gitignore-raw-dumps/run.sh`, and it makes every adopter who scaffolded before this task carry an un-ignored directory until they re-run `team-init.sh`. The benefit — a tidier directory — does not pay for a migration.
  - `--out PATH` overrides the destination. Writing over an existing **regular** file is allowed and expected (regeneration is idempotent). Any other occupied target is refused: a directory, a FIFO, and a symlink **including a dangling one** (`[ -e ]` alone reports a dangling symlink as absent, so the check is `[ -e … ] || [ -L … ]`). The run id is validated against `^[A-Za-z0-9._-]+$` before it is ever used in a path, so a `/` or `..` in the argument cannot escape the directory.
  - **No PII/secret content gate is added to the generator.** The playbook's guard applies to scripts producing **git-tracked** artifacts; this output is git-ignored by measurement above, and it is a rendering of a file that already sits in the same ignored directory, so it opens no new disclosure surface. Rejected — scanning the assembled payload and refusing to write on a PII-shaped hit: it would need heuristics over free-form operator prose in any language, and refusing to render an operator their own telemetry is the coercion this project has already ruled out.
  - **Generation is invoked by hand; nothing in the loop calls it.** `bin/close-out.sh` is untouched. Rejected for now, not dropped: printing an offer at close-out. It changes a committed flow with its own suite, and whether the loop should advertise the command at all is a documentation question that belongs to Part 3 / T-1013, which is where README and `docs/` are allowed to change.
- **D5 — fail-closed, with the exit codes pinned.** `0` success. `1` a data condition: no row matches the run id, or a scanned file fails `bin/check-run.sh`. `2` usage, resolution or I/O: a malformed argument, an unresolvable or unreadable runs directory, an unreadable template, a template whose placeholder count is not exactly 1, an occupied non-regular output path. This mirrors `check-run.sh`'s own 0/1/2 contract rather than inventing a third convention.
  - **On every non-zero path, no output file exists.** The page is built into a temp file in the destination directory and moved into place as the last action, so a mid-write failure also leaves nothing — "an error, never an empty page" is enforced by there being no page at all, not by a page saying "error".
  - **Validation runs over every scanned file, before selection, not after.** Rejected — filter first, then validate only the selected rows: a structurally broken line may have no extractable `run_id`, so it belongs to no run and would be skipped unexamined. That is fail-open at exactly the spot the issue names. Validating first costs an unrelated corrupt file blocking an unrelated replay; that is the correct direction to fail, since the runs dir is machine-written by a writer that self-checks every row, so a malformed line means corruption or a hand edit.
  - Delegating validation to the sibling `bin/check-run.sh` — rather than re-implementing a row check — is what keeps T-1011's frozen contract single-sourced. An unknown `kind` value is rejected there (T-1011 D4) and therefore never reaches the template.
- **D6 — inline-JS syntax coverage: a CI-only `node --check`, hosted in the new suite, fail-closed in CI and skipped locally.** The playbook's two questions were answered before the mechanism was chosen.
  - *Can CI verify this without duplicating production logic?* Yes. The artifact under test is the **real generator's real output** for a committed fixture; the suite extracts the main script block and runs `node --check` on it. The extraction is a few lines of `awk` in the test; no production behaviour is re-implemented.
  - *What is the blast radius of running the real script in CI?* Bounded and measured: invoked with `--runs-dir <committed fixture>` and `--out <temp path>`, the generator reads two files and writes one file under `$TMPDIR`. It never writes into the repository, never touches git, never networks. There is no cross-PR side effect to weigh.
  - The zero-dependency contract binds **shipped scripts**, not CI jobs — the workflow already `curl`-pins shellcheck 0.11.0 — and `ubuntu-latest` bundles node, so this adds no runtime dependency for any adopter. Rejected — shipping a JavaScript linter as a dependency of `bin/`: that would break the contract for real.
  - **Fail-closed rule**: the suite resolves the interpreter as `${NODE_BIN:-node}`. If it is unavailable and `$CI` is non-empty, the suite **fails** (the runner is supposed to have node; its absence means the assumption broke). If it is unavailable and `$CI` is empty, the suite prints a `SKIP:` line and continues. A silent pass is not an option in either branch.
  - **Rejected — banning `/* */` block comments in the template's JavaScript plus a `*/` grep lock.** The prototype carries 33 legitimate block comments that document the ratified design; converting them to `//` would churn ~33 hunks of pure documentation through review and bury the actual change. The incident class it guards is also not reachable here: injected data never lands inside a comment, and D2 confines it twice over.
  - **Adopted alongside it — a pure-bash structural lock that needs no interpreter**: injection must not change the file's script-tag arity (the counts of `<script` and `</script` in the output equal those in the template), and the injected payload must contain no raw `<` or `>` at all. That is the breakout class, caught everywhere bash runs.
- **D7 — a new test directory, and therefore both coupled CI lists change in the same commit.** `tests/gen-loop-replay/` is new, so `.github/workflows/check-handoff.yml` needs **two** edits: `bin/gen-loop-replay.sh` and `tests/gen-loop-replay/run.sh` appended to the single-line shellcheck argument list, **and** a `run: bash tests/gen-loop-replay/run.sh` step. This is the two-coupled-lists hazard T-1011 D8 was able to avoid and this task cannot; it is called out here and locked by an acceptance criterion so it is not discovered in review.
  - Fixtures are one directory per scenario — `mixed/`, `span-only/`, `event-only/`, `adopter/`, `hostile/`, `malformed/`, `multi-run/` — because the generator scans a whole directory, so a malformed fixture sharing a directory with a valid one would poison it (D5).
  - The rendered UI carries machine tokens (`READY_FOR_*` on the flag rail; `PASS`, `FAIL`, `APPROVE`, `REQUEST_CHANGES` as verdicts), so `templates/loop-replay.html` is registered as a consumer in `tests/machine-tokens/run.sh`, the same way every other token group there is. That suite's mutation self-check copies `bin agents templates` into a scratch root, so a `templates/` consumer is compatible with it unchanged.

## Non-goals

- **Part 3 of issue #77 in any form** — `README.md`, `README.ja.md`, `docs/**`, and any user-facing documentation of this command. That is T-1013. Two known consequences are accepted for one task: this repository ships a `bin/` script that no README mentions, and `README.md:172`'s telemetry description stays as T-1011 left it. A reviewer must not read either as a defect of this task; the scope lock forbids fixing them here.
- **Re-opening T-1011's schema.** No key added, removed, renamed or re-meant on either row shape; no change to the event vocabulary; no change to `bin/log-run.sh` or `bin/check-run.sh`. This task is a consumer.
- **`skills/run/SKILL.md`'s Telemetry section.** Verified complete at the base ref, not assumed: lines 101–113 already instruct all five `--event <id>` forms, the three payload flags, the shared-`seq` rule and the `|| true` discipline. Nothing about generating a replay belongs in the orchestrator's per-run instructions (D4: manual-only), so the file is untouched and locked as an invariant.
- **Changing the span schema, or migrating history.** No retroactive event rows, no rewriting of anything already under a runs dir.
- **`CHANGELOG.md` / `CHANGELOG.ja.md` and any version bump.** Release entries land through this project's release process.
- **A language configuration surface** (issue #20 D2). The JA/EN toggle is runtime state: it follows the browser locale, remembers the operator's choice in `localStorage`, and no file or environment variable configures it.
- **Redesigning the prototype's aesthetics or interactions.** The ground ring, the single serial ball, the beam channel, the flag rail, the camera controls, the LOD mini-cards, the idle UI-designer caption, the transport and the reduced-motion path are a ratified contract. This includes **not** introducing a `<!DOCTYPE>`: the prototype was ratified as it renders today, and switching the document into standards mode is a rendering-mode change with layout consequences, not a tidy-up. If a later task wants it, it comes with its own layout verification.
- **Analytics, live updating, multi-run comparison, export, or any external asset.** No aggregation across runs, no watch mode, no fonts/scripts/styles loaded from anywhere.
- **Serving the page over HTTP, or supporting a host-imposed Content-Security-Policy that forbids inline script.** The artifact is a single self-contained file opened from `file://` by design; "CSP-safe" here means it needs no `eval`, no `new Function`, no remote origin and no inline event-handler attributes — not that it survives an arbitrary policy.
- **Wiring generation into `bin/close-out.sh` or any loop step** (D4).

## Input space

**Reachable input classes** — what real usage produces, and the implementation must handle correctly:

- **Span-only runs — the dominant case, measured.** At the base ref this repository's own runs dir holds 12 distinct run ids across two `.jsonl` files, and 11 of them contain zero event rows (2 event rows exist in total, from the run that shipped T-1011). Every run recorded by any adopter before T-1011 is in this class, permanently.
- Mixed runs: span rows and event rows interleaved in one file under one shared ascending `seq`, all five event ids present, written across many separate process invocations.
- Event-only runs and partial-vocabulary runs, both reachable when a run is interrupted or when an orchestrator emits only some of the event ids.
- Every field shape T-1011's writer can produce: nullable `from`/`to`/`label` as explicit `null`; `model`, `verdict`, `usd`, `error`, `parent_span_id` null on a span; `status` values other than `success` (`error`, `timeout`, `skipped`, `stopped`); `tokens`/`tool_uses`/`duration_ms` absent.
- Free-form `label`, `from` and `to` text: machine tokens verbatim, interventions class slugs, prose in the operator's language (any language), embedded double quotes and backslashes as `jesc` escapes them, and **HTML/JS metacharacters that `jesc` does not touch** — `<`, `>`, `&`, and therefore `</script>`, `<!--`, `-->`, `*/`, `${`, a backtick. Length up to a few hundred characters.
- Adopter-shaped runs: a `loop_id` other than `shell-team`, `span` values that are not this loop's six agent names, `from`/`to` values that are not this loop's phase names.
- A runs directory holding several `.jsonl` files, a run id present in more than one of them, and non-`.jsonl` neighbours — `triage-<date>.md`, `goal-<task-id>.state`, a consolidated proposal file, `.gitkeep`, and a previously generated `replay-*.html`.
- Files with CRLF line endings, trailing whitespace, blank lines and no final newline (T-1011 D4 tolerates all four; the generator inherits that tolerance).
- Corrupt or hand-edited files, which is why validation exists: a truncated row, an unknown `kind`, an unknown event id, a shape-mixed row, and a structurally broken line carrying no extractable `run_id`.
- Argument-level hostility that reaches a filesystem path: a run id containing `/`, `..`, a shell metacharacter, or nothing at all; an `--out` target that is a directory, a FIFO, or a symlink whose target does not exist.
- Run sizes up to a few thousand rows in one run and a few dozen files in the directory.

**Out-of-scope synthetic extremes** — declined deliberately; a finding grounded only in one of these is out of contract:

- Pathological scale: hundreds of thousands of rows, a multi-megabyte single line, thousands of run ids in one directory. No performance bound is promised, and ever-larger inputs are not an escalating finding class.
- Ever-longer `label` values. One bounded case (a few hundred characters, including every metacharacter above) is protected; a 100 KB label is not, and neither is any successor to it.
- A deliberately hand-forged row that fakes JSON escaping to smuggle a key token past a boundary-anchored scan. This is T-1011 D7's declared residual, inherited here rather than re-litigated: `log-run.sh` is the single canonical writer and cannot produce one.
- Full JSON-grammar conformance beyond `check-run.sh`'s structural lint — nested objects or arrays as values, `\uXXXX` decoding, exponent-form numbers, duplicate keys. The generator ships rows verbatim and validates them with the sibling checker; it is not a parser and does not become one.
- Non-UTF-8 or binary content in a `.jsonl` file. Bytes are read and a structural violation is reported; a correct diagnosis is not protected.
- U+2028 / U+2029 line separators and bidi control characters inside a label. `jesc` does not strip them and `JSON.parse` accepts them, so the page loads; exact glyph rendering and text directionality are not protected.
- Browsers other than a current Chromium-, WebKit- or Gecko-based release; any legacy engine; the page with JavaScript disabled.
- A host-imposed Content-Security-Policy that forbids inline script, and any HTTP deployment. The artifact is a single self-contained file opened from `file://` by design (see Non-goals).
- Concurrent writers appending to a runs file while the generator reads it, and any file-locking guarantee.
- Rendering fidelity at arbitrary viewport sizes, zoom levels or print media, and screen-reader completeness beyond the ARIA attributes the prototype already carries.
- Cross-run properties: comparing two runs, aggregating across runs, or validating that a run's `seq` values are unique or gapless (T-1011 explicitly declines cross-line validation; D1's tie-break is the whole of this task's answer).

## Notes from engineer

**AC17's `check:` is mechanically unsatisfiable for any non-empty `seq` list — a bug in the check line itself, not in the generator.** The check computes `got=$(printf '%s' "$s" | tr '\n' ' ')` and `want=$(printf '%s' "$s" | sort -n | tr '\n' ' ')` and asserts `got = want`. `sort` unconditionally appends a trailing newline to non-empty output even when its input lacks one (verified directly: `printf '1\n2\n3\n4' | sort -n` ends in a `0a` byte, and `printf '' | sort -n` is exactly zero bytes) — `tr '\n' ' '` then turns that synthetic trailing newline into a trailing space in `want` that `got` never acquires (since `got` skips `sort` entirely and `$s` itself, from a command substitution, never carries a trailing newline to convert). Reproduced on this host, this exact repo tree, cnt=4: `got=[1 2 3 4]` (len 7) vs `want=[1 2 3 4 ]` (len 8) — a one-byte, structural mismatch, not a data-dependent one. Because `sort` always adds that trailing newline for any non-empty input regardless of order or content, `got` can never equal `want` whenever `cnt >= 1` — which AC17 itself also requires (`test "$cnt" -ge 4`). There is no fixture, ordering, or generator behavior that can make both hold at once; this is inherent to the check's own two-branch string construction, not fixable from the producer side.
