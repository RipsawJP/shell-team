# The canonical two-arm sweep procedure stages a frozen snapshot of the untracked telemetry corpus into its base arm, so corpus-reading criteria stop producing base-arm false FAILs

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1108

## Problem

The canonical procedure for a downstream-impact sweep lives in exactly one prescribing place: the `- **Downstream-impact inventory method (forward-only)**:` bullet at `agents/pm-spec.md:86`. It tells the sweeper to run every merged spec's criteria at the base ref and again at HEAD and to difference the verdict sets. It says **nothing** about the untracked, gitignored telemetry corpus those criteria read, and that omission is what produces a recurring, entirely mechanical false signal.

The mechanism is measured rather than inferred. `bin/check-acs.sh:374` executes a criterion's body with `cd "$ROOT"`, where `$ROOT` is the `--root` argument — for the base arm, a `git worktree add --detach` scratch tree. A corpus-reading criterion resolves the corpus path at run time (`RD=$(bash bin/team-paths.sh --get runs)`) and hard-exits when the file is absent (`.shell-team/specs/T-1066-effort-time-telemetry.md:92` is the shape: `R="$RD/shell-team.jsonl"; test -r "$R" || exit 1`). `bin/team-paths.sh:160` computes `RUNS="$BASE/runs"` — a repo-relative path — so in a scratch worktree the criterion reads that worktree's own `.shell-team/runs/`, and `.shell-team/.gitignore:4` (`runs/`) is exactly why the live corpus does not travel there. The criterion therefore reads FAIL at the base arm and PASS at HEAD, in the favourable direction, for reasons that have nothing to do with the diff under measurement.

The cost is not the FAIL; it is that **every** sweep must re-classify the same five criteria by hand, from scratch, and a sweep that classifies them wrongly reports a delta the diff never caused. The class has **one** primary-source measurement — T-1106's full 111-spec two-arm sweep, recorded at `.shell-team/todo.md:342`, naming T-1066 **AC5**/**AC7**, T-1072 **AC6**, T-1076 **AC15** and T-1082 **AC6**, all `base: FAIL → head: PASS`, root cause "a `git worktree add --detach` base arm does not carry over untracked files". Beside that single measurement sit two facts that are not further instances of it and are not counted as such: the standing disclosure in `.shell-team/test-recipe.md:1409-1418` (T-1078's entry, the first statement of the artefact, which itself records that T-1075 had already documented it once), and the classification burden the class imposes on every future mechanism-class sweep, which is a forward cost rather than a past occurrence. **This spec's justification is one measured instance plus a standing disclosure plus a recurring forward burden — never "three times".**

Issue **#321** filed the procedure gap and proposed pointing `TEAM_RUNS_DIR` at a per-ref scratch copy. **That proposal is measured non-working for the read side, and this spec records the correction against the issue's own text**: `bin/team-paths.sh` never reads an incoming `TEAM_RUNS_DIR`. It only *emits* one (`:174`, inside the `export` mode's `printf` list), and `RUNS` is computed from `TEAM_RUN_BASE` alone (`:143-160`) with `--get runs` returning `"$RUNS"` at `:187`. The variable is honoured on the **write** side — `bin/log-run.sh:490-491` reads it — so the issue's proposal is correct for a telemetry *writer* and inert for every criterion that *reads* the corpus through the resolver.
