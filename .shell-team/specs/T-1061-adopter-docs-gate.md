## Problem

Issue #244 shipped as two halves. T-1060 delivered the missing adopter documentation for the v2.0.0 executor binding; requirement 4 — the process half — is this task. The gap it names is that a spec for a user-visible capability can reach `READY_FOR_ARCH` with no adopter-facing-documentation acceptance criterion and nothing anywhere notices: the deliverable that realizes the release's value gets deferred to a fast-follow, and the only thing standing between that and the release is whether the spec's author happened to remember. The repository already carries the rule — `agents/pm-spec.md`'s `## Spec completion self-check` gained an adopter-docs bullet in the promotion commit at this branch's point of divergence — but a checklist bullet is author memory with a paper trail, not a gate. Nothing reads it, nothing refuses on it, and no artifact of a frozen spec records whether the question was even asked. Text inference cannot substitute for the missing signal either: measured across `.shell-team/specs/`, the string `user-visible` occurs **0** times and `adopter-facing` occurs **70** times across **34** files, including specs whose whole deliverable is internal loop mechanics — a heuristic over that corpus under-fires and over-fires at once.

## Goal

<!-- BEGIN intent-block: T-1061 -->

- user-visible: yes — an adopter running this loop in their own repository gains a new freeze-time refusal and a new line their specs must carry; both change what the loop does to an adopter's work rather than only how this repository is maintained.

Every spec frozen from this task onward declares, on one machine-readable line inside its own frozen intent block, whether its deliverable is a **user-visible capability**, and the freeze refuses when that line is absent or when a `yes` declaration is not discharged. The declaration is a top-level bullet `- user-visible: yes — <rationale>` or `- user-visible: no — <rationale>`, written between the intent block's `BEGIN` marker and the `## Non-goals` heading, ignored wherever it appears inside a fenced code block so that a spec may quote the grammar it is governed by. That inertness is uniform: **every** line a reader of this declaration consults is fence-aware, the intent-block markers included — so a spec that quotes a marker inside a fenced example, as this one does, carries exactly one declaration and one region, and `bin/check-intent.sh` remains the sole owner of the marker pair's task-id scoping. A `yes` declaration is discharged in exactly one of two ways, never both at once: an acceptance criterion carries an indented `- adopter-surface: <surface>` line naming where the adopter-facing documentation lands, or the spec carries a top-level `- adopter-docs-waiver: <reason>` line stating why this user-visible capability has no adopter-docs surface — a first-class outcome, so a repository with nothing an adopter reads passes without fabricating a surface. A `no` declaration passes on its own and carries neither marker; carrying one beside it is refused, on the same footing as this repository's existing rule that a "nothing here, deliberately" sentinel and a real entry cannot coexist in either direction. The gate is a duty the coordinating session performs at the **bootstrap freeze only** — a task's first freeze, never a re-freeze of an already-recorded hash — reading the declaration region itself and refusing the freeze on anything the grammar above does not admit. **No mechanical checker ships in this task**: the standalone checker, its fixture suite and its CI wiring were carved out to a fast-follow issue when this task's own pre-commitment trigger fired, so this duty is a read a role performs rather than an exit code it consults, and it is honest about that wherever it is documented. It never judges **content**: the sweep does not open, resolve or validate the surface a spec names, because a path allowlist would coerce every adopter's repository into this one's layout; the declaration's honesty is a matter for the reviewing gates, and only its presence and internal consistency are checked. The change is **forward-only in the strongest sense**: no spec that exists at this branch's point of divergence gains a declaration line, no merged criterion is repaired, widened or annotated, and nothing sweeps the corpus. This task dogfoods its own rule — its spec declares `yes`, names its adopter surface, and its own criteria verify that declaration inline rather than trusting it.

An allowlist of blessed paths would coerce an adopter's repository into this one's layout, which is the opposite of what the gate is for.

## Input space

**Reachable input classes** — what this task's deliverables really face:

- **Spec files this loop produces, in either supported layout.** A spec with a well-formed single intent-block marker pair; a spec with no marker pair at all (every one of the files present at this branch's point of divergence, and any pre-freeze draft); a spec whose declaration is present, absent, or written twice; values `yes` and `no`; a rationale that is present, absent, or whitespace-only; an `- adopter-surface:` line present or absent under a criterion; an `- adopter-docs-waiver:` line present or absent; both markers present at once; either marker present beside a `no`. The base directory is resolved rather than assumed, so both the `.shell-team/` and the legacy `tasks/` layout are in scope.
- **Near-miss declaration spellings a real author produces**: a capitalised or otherwise non-canonical value; a missing separator; an indented copy of the line; a trailing carriage return from an editor or a CRLF checkout; a copy sitting before `## Goal` or after `## Input space`; the token appearing inside ordinary prose mid-line.
- **A spec that quotes the grammar it is governed by.** This is not hypothetical — this spec, `agents/pm-spec.md` and `skills/run/SKILL.md` all spell the three tokens, and the two documentation sections spell them for adopters. A fenced occurrence must therefore be inert to whoever reads the declaration, and this class is reachable in the very first artifact the duty is performed against — this spec, whose own inline verification in AC10 depends on that inertness.
- **Both freeze branches of the run loop**: a task's bootstrap freeze (no `- intent-hash` recorded yet), where the gate applies, and a re-freeze of an already-recorded hash, where it does not.

**Out-of-scope synthetic extremes** — inputs this spec explicitly declines to protect:

- **Whether a named surface is really adopter-facing.** Nothing this task ships opens, stats, resolves or pattern-matches an `- adopter-surface:` value beyond non-emptiness. A value naming a file that does not exist, or naming nothing an adopter would ever read, satisfies the grammar — deliberately. Content honesty is what the reviewing gates and the human are for; a mechanical judgment here would need a path allowlist, and an allowlist would coerce every adopter's repository into this one's layout.
- **A spec engineered to defeat the region extraction**: more than one `<!-- BEGIN intent-block -->` / `<!-- END intent-block -->` pair in one file, a marker pair whose ids differ from each other, a marker line inside a fenced block, an unterminated fence at end of file, nested fences. `bin/check-intent.sh` already owns the marker pair's well-formedness and this task neither extends nor duplicates that judgment; where a reader of this declaration cannot resolve exactly one region, the answer is to refuse and say so, never to guess which region was meant.
- **A hostile spec author.** The threat model is accidents — a forgotten line, a wrong value, a marker in the wrong place, a copy-paste from a quoted example. A spec deliberately constructed to declare `no` while shipping a user-visible capability defeats this gate by design, and no grammar closes that; the reviewing gates and the frozen record are what make the lie legible afterwards.
- **A third natural language.** The two documentation sections are written for exactly the two language pairs this repository ships; nothing here generalises to *n* copies, and the parity clauses are written for two.
- **Retro-fitting the corpus.** No behaviour is specified for what would happen if this duty were applied to all sixty-odd existing specs at once, because nothing this task ships does that, and the forward-only lock measures that it does not.
- **Adversarial markdown in the two edited documentation files**: extremely long single lines, deliberately unbalanced fences, mixed line endings, heading text colliding with another section's. ## Pre-commitment

This task **writes a verification mechanism**, the category this repository measures as running long, so the escalation contract is fixed here, before round 1.

- **Trigger, factual condition**: the same component draws **two consecutive rounds** of independent new defects (the repository's default threshold, not loosened).
- **Trigger, contextual condition**: before a third round of rework on that component begins.
- **Priority when the two disagree**: the factual condition governs. Two consecutive rounds fires the disposition even if the contextual boundary has not been reached.
- **Disposition, decided now rather than at the moment it fires**: the **droppable** component is the standalone checker together with its fixture suite and its CI wiring — `bin/check-adopter-docs.sh`, `tests/check-adopter-docs/run.sh`, and the three workflow edits. It goes to a fast-follow issue, and **the rounds' findings travel with it as its requirement list** rather than being re-derived there. Dropping it leaves a coherent task: the declaration grammar, the pm-spec self-check, the run-skill sweep item and the adopter documentation all still ship, and the gate still moves the trigger off author memory onto the shell side.
- **Never-dropped**: the **declaration-line grammar** and the **freeze-sweep item**. These have no carve-out to execute. If either is defeated across two consecutive rounds, the task **stops and returns to planning** — the same mechanism defeated across consecutive design generations is evidence about the design premise, not about the implementation's craft.
- **Re-read step**: whoever reaches a trigger re-reads this section before acting, because at the moment a trigger fires one more patch is always the cheapest move available and a trigger with no pre-decided disposition reopens the design question exactly where nobody is placed to settle it.

### 5. The alternative, priced honestly

A third targeted patch is genuinely cheap: the fence branch at `bin/check-adopter-docs.sh:387-391` needs the scope transition to run before the content skip — mechanically a few lines, and the reviewer has already supplied the fence/no-fence control pair that would prove it. Three independent defects in one scan across two consecutive rounds — a whole-file scan with no scope notion, an order-dependent value aggregation, and a fence that hides the scope-close event the second fix introduced — is evidence about the design premise, not about the care taken on any one round: each fix was correct for the defect it addressed and the next round found a new hole in the fix itself. The frozen pre-commitment names this exact trap ("at the moment a trigger fires, one more patch is always the cheapest move available") and states the threshold is the repository's default, "not loosened" on severity grounds. **What the operator would be accepting by overriding the discipline and taking the patch anyway**, stated so the choice is informed rather than discouraged: (i) a fourth round on the same component becomes the expected case rather than a surprise, and the trigger will have been shown to be advisory, which weakens every future pre-commitment in this repository including ones written for riskier work; (ii) the shipped artifact would be a fail-closed gate with a demonstrated false-pass class and no evidence its transition space has been enumerated — a gate that passes a spec it should refuse is worse than no gate, because the sweep stops reading once an exit code says `0`; (iii) the three-round findings would stay as review-record prose instead of becoming a requirement list with an owner, which is how they get re-derived by whoever touches this next; and (iv) it is reversible in one direction only — accepting the patch now does not prevent a later redesign, but it does ship the scan into adopters' loops in the meantime, and an adopter's freeze passing on a spec with no real adopter-docs criterion is the exact failure issue #244 opened to close. Against that, the drop's cost is one class-B re-freeze of 37 frozen lines, five fewer check lines, and a documented interval during which this gate is prose plus this spec's own inline anchors. **The operator decides; this package presents both and presumes neither.**
