## Problem

Issue #244 shipped as two halves. T-1060 delivered the missing adopter documentation for the v2.0.0 executor binding; requirement 4 — the process half — is this task. The gap it names is that a spec for a user-visible capability can reach `READY_FOR_ARCH` with no adopter-facing-documentation acceptance criterion and nothing anywhere notices: the deliverable that realizes the release's value gets deferred to a fast-follow, and the only thing standing between that and the release is whether the spec's author happened to remember. The repository already carries the rule — `agents/pm-spec.md`'s `## Spec completion self-check` gained an adopter-docs bullet in the promotion commit at this branch's point of divergence — but a checklist bullet is author memory with a paper trail, not a gate. Nothing reads it, nothing refuses on it, and no artifact of a frozen spec records whether the question was even asked. Text inference cannot substitute for the missing signal either: measured across `.shell-team/specs/`, the string `user-visible` occurs **0** times and `adopter-facing` occurs **70** times across **34** files, including specs whose whole deliverable is internal loop mechanics — a heuristic over that corpus under-fires and over-fires at once.

## Goal

<!-- BEGIN intent-block: T-1061 -->

- user-visible: yes — an adopter running this loop in their own repository gains a new freeze-time refusal, a new line their specs must carry, and a new shipped checker they can run themselves; all three change what the loop does to an adopter's work rather than only how this repository is maintained.

Every spec frozen from this task onward declares, on one machine-readable line inside its own frozen intent block, whether its deliverable is a **user-visible capability**, and the freeze refuses when that line is absent or when a `yes` declaration is not discharged. The declaration is a top-level bullet `- user-visible: yes — <rationale>` or `- user-visible: no — <rationale>`, written between the intent block's `BEGIN` marker and the `## Non-goals` heading, ignored wherever it appears inside a fenced code block so that a spec may quote the grammar it is governed by. That inertness is uniform: **every** line the checker reads is fence-aware, the intent-block markers included, and the region is located by the unfenced marker pair alone with no task-id derivation of its own — so a spec that quotes a marker inside a fenced example, as this one does, is read as having exactly one region rather than two, and `bin/check-intent.sh` remains the sole owner of the marker pair's task-id scoping. A `yes` declaration is discharged in exactly one of two ways, never both at once: an acceptance criterion carries an indented `- adopter-surface: <surface>` line naming where the adopter-facing documentation lands, or the spec carries a top-level `- adopter-docs-waiver: <reason>` line stating why this user-visible capability has no adopter-docs surface — a first-class outcome, so a repository with nothing an adopter reads passes without fabricating a surface. A `no` declaration passes on its own and carries neither marker; carrying one beside it is refused, on the same footing as this repository's existing rule that a "nothing here, deliberately" sentinel and a real entry cannot coexist in either direction. The gate is a shipped, pure-bash, zero-dependency, fail-closed checker whose refusals are one token on stderr from a closed set with zero bytes on stdout, wired into the loop at the **bootstrap freeze only** — a task's first freeze, never a re-freeze of an already-recorded hash — and into CI against fixtures and this task's own spec. It never judges **content**: it does not open, resolve or validate the surface a spec names, because a path allowlist would coerce every adopter's repository into this one's layout; the declaration's honesty is a matter for the reviewing gates, and only its presence and internal consistency are mechanical. The change is **forward-only in the strongest sense**: no spec that exists at this branch's point of divergence gains a declaration line, no merged criterion is repaired, widened or annotated, and no checker sweeps the corpus. This task dogfoods its own gate — its spec declares `yes`, names its adopter surface, and passes the checker it ships.

## Non-goals

- **No content judgment, and no path allowlist.** Whether a surface a spec names is *really* adopter-facing is never decided mechanically by anything this task ships. The checker does not open, stat, resolve or pattern-match the value of an `- adopter-surface:` line beyond requiring it to be non-empty. An allowlist of blessed paths would coerce an adopter's repository into this one's layout, which is the opposite of what the gate is for.
- **No retro-fit of any existing spec *by this task*.** No spec file present at this branch's point of divergence gains a declaration line, a surface line or a waiver line. Adding one to an already-frozen intent block would be a class-B amendment of merged frozen intent, and this gate never manufactures one.
- **No repair, widening or annotation *by this task* of any merged criterion**, including the ones this task's diff reddens. Every red is disclosed in `## Blast radius` and differenced against the branch point; none is fixed, and no other spec gains a `- stale-at:` line from this task.
- **No corpus sweep in CI or anywhere else.** No step this task adds runs the checker over `.shell-team/specs/*.md` as a set. The CI dogfood target is this task's own spec, by name, plus the fixture suite.
- **No goal-side mirror.** `skills/goal/SKILL.md` is byte-identical to the branch point. It has no Specify or freeze-authoring phase to attach the gate to — measured, not assumed — and a duty written into a loop with no carrier for it is a duty nobody performs.
- **No edit *by this task* to the freeze pipeline's existing scripts** — `bin/check-intent.sh`, `bin/check-acs.sh`, `bin/check-refreeze-class.sh`, `bin/check-handoff.sh`, `bin/team-paths.sh`. The gate is a separate checker invoked beside them; none of their grammars, exit codes or parsing rules moves. In particular the declaration and marker lines are ordinary non-`check:` lines, so `check-acs.sh` continues to recognize only `- check:` as a criterion's command and `check-refreeze-class.sh` continues to classify a change to any of them as class B.
- **No edit *by this task* to the generated prompt-block regions of any consumer**, and no edit to the lessons corpus. `agents/pm-spec.md`'s `<!-- BEGIN/END prompt-block: playbook-pm-spec -->` region is byte-identical to the branch point; the grammar lands in the hand-written `## Spec completion self-check` section outside it.
- **No `README.md` or `README.ja.md` edit *by this task*.** The adopter surface for this mechanism is the two adopter-workflow pages, which the READMEs already delegate detail to; a README section would add a second place for the same grammar to drift.
- **No edit *by this task* to `CONTRIBUTING.md`, `docs/tuning-oversight.md`, `CHANGELOG.md`, `CHANGELOG.ja.md`, `.claude-plugin/plugin.json`**, and no version bump or badge move. Who may re-freeze, and under which class, is unchanged by this task.
- **No new status flag, verdict label, board field, telemetry key, event id or refusal token outside this checker's own closed set.** The declaration is read from the spec file; nothing about it reaches the board, a span row or a hand-off line.
- **No change *by this task* to what `check-intent.sh` hashes.** The declaration sits inside the existing marker pair, so it is frozen by the mechanism that already exists; no new marker, no second hashed region, no change to the normalization.
- **No stateful retry, no bounded auto-retry, and no new human gate.** A refusal routes back to `pm-spec` for a meaning-preserving correction exactly as a broken or vacuous `- check:` line already does.

## Input space

**Reachable input classes** — what this task's deliverables really face:

- **Spec files this loop produces, in either supported layout.** A spec with a well-formed single intent-block marker pair; a spec with no marker pair at all (every one of the files present at this branch's point of divergence, and any pre-freeze draft); a spec whose declaration is present, absent, or written twice; values `yes` and `no`; a rationale that is present, absent, or whitespace-only; an `- adopter-surface:` line present or absent under a criterion; an `- adopter-docs-waiver:` line present or absent; both markers present at once; either marker present beside a `no`. The base directory is resolved rather than assumed, so both the `.shell-team/` and the legacy `tasks/` layout are in scope.
- **Near-miss declaration spellings a real author produces**: a capitalised or otherwise non-canonical value; a missing separator; an indented copy of the line; a trailing carriage return from an editor or a CRLF checkout; a copy sitting before `## Goal` or after `## Input space`; the token appearing inside ordinary prose mid-line.
- **A spec that quotes the grammar it is governed by.** This is not hypothetical — this spec, `agents/pm-spec.md` and `skills/run/SKILL.md` all spell the three tokens, and the two documentation sections spell them for adopters. A fenced occurrence must therefore be inert, and this class is reachable in the first artifact the gate ever runs against.
- **Unusable input paths**: a path that does not exist, a directory, an unreadable file, a dangling symlink. Each is an exit-`2` outcome, never a silent pass.
- **Two execution contexts for every documented command**: this repository's own checkout root without the plugin on `PATH`, and an adopter-shaped repository with the plugin loaded where `bin/` scripts are reached by bare name from a different working directory.
- **Both freeze branches of the run loop**: a task's bootstrap freeze (no `- intent-hash` recorded yet), where the gate applies, and a re-freeze of an already-recorded hash, where it does not.

**Out-of-scope synthetic extremes** — inputs this spec explicitly declines to protect:

- **Whether a named surface is really adopter-facing.** The checker never opens, stats, resolves or pattern-matches an `- adopter-surface:` value beyond non-emptiness. A value naming a file that does not exist, or naming nothing an adopter would ever read, satisfies the grammar — deliberately. Content honesty is what the reviewing gates and the human are for; a mechanical judgment here would need a path allowlist, and an allowlist would coerce every adopter's repository into this one's layout.
- **A spec engineered to defeat the region extraction**: more than one `<!-- BEGIN intent-block -->` / `<!-- END intent-block -->` pair in one file, a marker pair whose ids differ from each other, a marker line inside a fenced block, an unterminated fence at end of file, nested fences. `bin/check-intent.sh` already owns the marker pair's well-formedness and this task neither extends nor duplicates that judgment; this checker's contract for anything it cannot resolve into exactly one region is exit `2`, not a guess.

- **A third natural language.** The two documentation sections are written for exactly the two language pairs this repository ships; nothing here generalises to *n* copies, and the parity clauses are written for two.
- **Retro-fitting the corpus.** No behaviour is specified for what would happen if the checker were pointed at all sixty-odd existing specs at once, because nothing this task ships does that, and the forward-only lock measures that it does not.
- **Adversarial markdown in the two edited documentation files**: extremely long single lines, deliberately unbalanced fences, mixed line endings, heading text colliding with another section's. These files are authored in this repository under review, and the extraction commands the criteria use are written for the shapes a contributor produces.

## Pre-commitment

This task **writes a verification mechanism**, the category this repository measures as running long, so the escalation contract is fixed here, before round 1.

- **Trigger, factual condition**: the same component draws **two consecutive rounds** of independent new defects (the repository's default threshold, not loosened).
- **Trigger, contextual condition**: before a third round of rework on that component begins.
- **Priority when the two disagree**: the factual condition governs. Two consecutive rounds fires the disposition even if the contextual boundary has not been reached.
- **Disposition, decided now rather than at the moment it fires**: the **droppable** component is the standalone checker together with its fixture suite and its CI wiring — `bin/check-adopter-docs.sh`, `tests/check-adopter-docs/run.sh`, and the three workflow edits. It goes to a fast-follow issue, and **the rounds' findings travel with it as its requirement list** rather than being re-derived there. Dropping it leaves a coherent task: the declaration grammar, the pm-spec self-check, the run-skill sweep item and the adopter documentation all still ship, and the gate still moves the trigger off author memory onto the shell side.
- **Never-dropped**: the **declaration-line grammar** and the **freeze-sweep item**. These have no carve-out to execute. If either is defeated across two consecutive rounds, the task **stops and returns to planning** — the same mechanism defeated across consecutive design generations is evidence about the design premise, not about the implementation's craft.
- **Re-read step**: whoever reaches a trigger re-reads this section before acting, because at the moment a trigger fires one more patch is always the cheapest move available and a trigger with no pre-decided disposition reopens the design question exactly where nobody is placed to settle it.
