## Problem

The loop runs exactly one agent at a time: PM → Engineer → QA → Reviewer execute strictly sequentially, so a task's wall clock is the *sum* of every phase and at any moment every team member but one is idle. The operator's goal state (issue #252) is that all agents are asynchronously and concurrently active, and the fresh data point behind the filing is that a four-line docs repair still spent 3h+ end to end because the per-task process cost is roughly fixed and is paid serially. Nobody can currently say which phase pairs may safely overlap, because the answers live in scattered measured facts that have never been put in one place: which shared files two concurrent tasks would collide on, which of this repository's seam guards are structurally incompatible with two writers in one checkout, what the harness already provides versus what a scheduler would need, and what a saving would actually be worth once the reconcile-at-join cost is subtracted. This task answers that question and commits to no mechanism.

### Verdict scope (operator-ratified)

**Authorship: operator-ratified.** The primary record is the `- intervention: human-correction` entry dated 2026-08-14 in `.shell-team/interventions/T-1066.md`. This section restates that ruling for the gates that read this spec; it is not this spec's self-discipline and it is not re-litigated here.

For this deliverable — an internal feasibility investigation whose purpose is to inform a decision about restructuring how the loop spends machine time — **deliverable correctness means two things**, and a finding against either is verdict-gating: (1) the **computed values** are correct, meaning each figure names the source it was read from and reproduces when the command quoted beside it is re-run; and (2) the **conclusions' direction** is right, meaning what the note says its numbers support is what they support — a candidate's disposition, a contention verdict, a serialization verdict, the recommendation.

**Connective prose is not verdict-gating.** A finding about a sentence that joins, summarises or characterises values that are themselves correct — a totality word whose domain is wider than its command's, a label mismatch, a stale count in a narrative aside, an imprecise summary — is recorded as a **note** in the review record and does not on its own produce `REQUEST_CHANGES` or `FAIL`, provided every computed value it touches is correct and no conclusion's direction moves. **No escalation ratchet is created over prose classes**: repeated findings of a connective-prose class do not raise a gate's severity, do not create a halt condition, and do not on their own trigger a rework round; they accumulate as notes and are dispositioned at close-out.

**An external citation is a computed value.** Per the operator's 2026-08-14 scope addendum, a citation in `## Prior art (external)` that misrepresents its source is a **computed-value-class defect** — the cited claim is the value — and is verdict-gating exactly as a wrong number is. A citation the reading gate cannot reach from its own sandbox (general web is typically unreachable; some vendor documentation endpoints may be) is reported as **environmentally-unverified** rather than failed, and the note labels which of its citations it expects to be unreachable so that the report is a shared expectation rather than a surprise.

This is a statement about what gates the verdict, not permission to be careless. A prose finding is still reported, and the engineer may still fix one — it simply does not stop the task.
