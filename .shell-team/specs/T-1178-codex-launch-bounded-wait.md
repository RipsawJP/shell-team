# A Codex pass launched by `code-reviewer` or `drift-evaluator` stops `BLOCKED` within a bounded time when Codex never starts, instead of waiting on stdin forever

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1178

## Problem

`codex exec` appends piped stdin to its prompt and waits for EOF even when a prompt argument is given (issue #695). In a Claude Code sub-agent's Bash tool, stdin was intermittently an open pipe that never closed, so the shipped bare `codex exec` line printed only `Reading additional input from stdin...` and never emitted `thread.started`; a foreground launch with a 600 s timeout and two background launches all hung, and a fresh reviewer instance hung the same way. Closing stdin with `< /dev/null` makes the line a multi-part command, which Claude Code 2.1.278+ runs inside the sandbox, where Codex fails. The shipped `agents/code-reviewer.md` (`:46`) mandates a foreground synchronous call and forbids `run_in_background`, and its only fallback polls for the `-o` capture, which appears only at the end of a pass — so nothing in the shipped recipe can notice an early hang. When it happens, the second gate cannot run and the loop cannot reach `READY_FOR_MERGE`, for every adopter on a sandbox-enabled Claude Code host.
