# One canonical board-entry boundary, and a stranded continuation line that fails closed

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1016
**Source**: GitHub issue #89 — both fix directions it asks for. Backlog item 1 of the v1.3.0 sprint goal ("mechanize unenforced loop invariants").
**Base**: `develop` @ `a3ee283`
**Branch**: `fix/89-close-out-stranding`

## Problem

`T-1013`'s board entry accumulated internal blank lines and a markdown table inside a rework hand-off sub-bullet. `bin/close-out.sh`'s pass-1 awk moves "the task's top-level line plus its contiguous sub-bullets", and its continuation predicate is `^[[:space:]]+-` — indented **and** dash-led. The first line of the entry that was neither (a blank line, then indented table rows) ended the capture, so the move stopped mid-entry and left 15 lines stranded in `## Active` with no top-level entry above them.

Nothing failed loudly. `bin/check-handoff.sh` skips every indented line before it validates anything, so the strand was invisible to the board linter — including the copy of it that `bin/close-out.sh:229` runs against its own temp board as a pre-write gate, which is exactly the place that should have refused. `bin/check-intent.sh` treats an indented line outside an open scope as a no-op, so the strand was out of scope there too. The board was repaired by hand (`develop` commit `6750dcf`); nothing in the repository would have caught it, and nothing would catch the next one.

The defect is wider than "the mover stops at a blank line". The same predicate is written four times, in three different forms, and an indented **non-dash** line — a table row `  | … |` — breaks contiguity under the dash-led form with no blank line present at all. This is a verification-mechanism task by the repository's own classification: it changes the parsers that decide what a board entry *is*. `bin/check-intent.sh`'s own header records that this exact class of question — "which line shapes close an entry's scope" — produced four consecutive rounds of independent defects when it was answered by enumerating tolerated shapes, and was only settled by inverting the definition. That precedent is binding here.

## Goal

<!-- BEGIN intent-block: T-1016 -->

One canonical entry-continuation predicate, defined by inversion, is applied at every site in `bin/` that decides where a board entry ends, and a continuation line that belongs to no entry is a hand-off-lint violation rather than an invisible one. `bin/close-out.sh` moves a whole entry — internal blank lines, indented table rows, tab indentation, CRLF, the last entry of a section, the last entry in the file — and, because it already gates its temp board through `bin/check-handoff.sh`, it now refuses fail-closed to write a board that carries a strand and says why. `bin/check-intent.sh` stops treating a blank line as a scope terminator, so the intent ledger and the mover agree about what belongs to an entry. The shipped board template states the grammar the checkers enforce, and CI lints this repository's own live board for the first time. Exit-code taxonomies, existing violation classes and every currently-green board — `templates/todo-template.md` and `.shell-team/todo.md` — are unchanged.

### Terms, fixed before anything is implemented

`indented`, `blank`, `boundary` and `entry` each have more than one plausible referent in this codebase's existing comments, and the four sites disagree partly because of that. These definitions are normative for this task; every site's implementation and every fixture is read against them. All character-class judgments are POSIX `[[:space:]]` under the C locale.

| term | definition | notes |
|---|---|---|
| **indented line** | first character is whitespace — matches `^[[:space:]]` | space or tab; both are in scope |
| **blank line** | no non-whitespace character anywhere — empty, or whitespace only | CR is whitespace, so a CRLF-terminated empty line is blank |
| **continuation line** | an indented, non-blank line — matches `^[[:space:]]+[^[:space:]]` | shape after the indent is irrelevant: `-`, `|`, `>`, a digit, prose |
| **boundary line** | a non-indented, non-blank line — first character is non-whitespace | *any* shape: `- [ ]`, `- [x]`, `* `, `+ `, `1.`, `#`/`##`/`###`, `_(none)_`, bare prose |
| **section** | the lines between a `^## ` heading and the next `^## ` heading (or EOF) | `### ` does **not** open a section; it is an ordinary boundary line |
| **task line** | a boundary line matching `^- \[[x ]\] ` | the shape `bin/close-out.sh`'s pass-1 and `bin/check-board-headings.sh` already use |
| **entry** | a task line plus every following line up to, but not including, the first boundary line or EOF | blank lines inside do not end it |
| **entry extent** | the entry, with trailing blank lines removed — it ends at the last continuation line | what a move carries |
| **strand** | a continuation line that is inside no entry: no task line precedes it since the start of its section | the defect this task makes visible |

### Settled decisions

Each decision below is resolved. Nothing here is left to implementation judgment.

- **D1 — the predicate is canonicalized by inversion, at every site, and is never an enumeration of tolerated shapes.** The canon is: *a boundary is any non-indented non-blank line, or EOF; a blank line is neutral and ends nothing; everything else — every indented non-blank line, whatever its first character — continues the entry.* A `^## ` heading needs no clause of its own: it is a non-indented non-blank line and is therefore already a boundary, which is the point of inverting the definition rather than listing shapes.
  - **Rejected — patching the dash-led predicate to also tolerate `|`, or to also tolerate a blank line.** That is a shape enumeration, and `bin/check-intent.sh`'s header records what shape enumeration cost this repository: rounds 1, 2 and 3 each fixed one more shape, and round 3's Blocker was a CommonMark `* [ ]` bullet falling through the list. A fifth shape (a `>` blockquote continuation, an indented HTML comment, an indented image) is always one hand-off note away. The inverted definition has no list to be short.
  - Every changed site carries the frozen marker string **`board-entry continuation canon (T-1016)`** exactly once, in a comment adjacent to its predicate, so the next reader finds the canon instead of re-deriving one. AC1 is the completeness anchor; AC2 is the anchor that the superseded form is gone rather than merely joined by a new one.
- **D2 — the design tension is resolved by option ③: `bin/check-intent.sh` adopts the same canonical predicate. A blank line becomes neutral there too.** Concretely: a blank (or whitespace-only) line is a no-op that leaves `in_entry` untouched; rules 1 and 2/3 of the existing state machine are otherwise unchanged, so all four of its earlier rounds' fixes survive intact — every non-indented non-blank line, of every bullet form, still closes any open scope before anything else happens.
  - **Why this is behaviour-preserving on every well-formed board, and therefore low-risk**: entries are separated by a blank line followed by the next top-level line, and that top-level line is a boundary that closes the scope anyway. A section's last entry is followed by a heading, also a boundary. The verdict changes only for a board that has a blank line *inside* an entry — the incident class. AC10 asserts exactly this as an invariance property, and AC12 requires the whole existing `check-intent` suite to stay green.
  - `bin/check-intent.sh`'s comment block explicitly grounds its blank-line semantics in `bin/close-out.sh`'s behaviour (the phrase **`blank line ends the continuous block`**). That fact is what this task changes, so the comment changes with it — a stale grounding citation in a parser is how the next divergence gets justified. AC10 asserts the phrase is gone and the canon marker is present.
  - **Rejected — option ①, a new rule that forbids internal blank lines inside an Active entry.** It answers only half the incident (a table row breaks contiguity with no blank line anywhere), it is a restriction on adopters' markdown rather than a fix to our parsers, and it makes `close-out`'s widened predicate unreachable in the very section it was widened for — an untested widening is a widening that regresses.
  - **Rejected — option ②, `close-out` folding internal blank lines while it moves.** It turns a mover into a normalizer, so the board's committed bytes stop being what the agent wrote, and it leaves the asymmetry standing where it actually bites: a live `## Active` entry whose intent-hash sub-bullet sits after a blank line stays invisible to `bin/check-intent.sh`. The silent case is two hash sub-bullets split by a blank line — the ledger holds a structural error and the checker sees one well-formed record and reports alignment.
- **D3 — the strand check is added to `bin/check-handoff.sh`. No new script is created.** The decisive property is the interlock: `bin/close-out.sh:229` already runs `check-handoff.sh` against its temp board as a fail-closed pre-write gate, so putting the check there makes `close-out` refuse its own truncated output without `close-out` gaining a single new dependency. The two halves issue #89 asks for stop being two independent hopes.
  - This does **not** violate `bin/check-board-headings.sh`'s DP-A (T-079), which says `check-handoff.sh` must not gain *base-ref comparison* — because `close-out` gates a git-untracked temp file for which no base ref exists. The strand check is base-independent and single-file; it reads nothing but the board handed to it, so the temp-board gate keeps working. AC8 proves it on the temp-board path itself.
  - **Rejected — a new `bin/check-board-strand.sh`.** It would need its own shellcheck argument, its own CI step and its own fixture suite; `close-out` would have to call it, adding an install-completeness failure mode that `check-handoff.sh` (already a hard dependency of `close-out`) does not have; and a board-grammar violation would be reported by two different linters depending on which shape it is. AC14 locks the negative: no such file exists and the workflow's shellcheck argument list is byte-identical to the base ref.
  - **The compat cost is real and accepted, in a bounded form.** Strengthening a shipped checker can newly fail an adopter's board. It is bounded by scoping the strand check to the section `check-handoff.sh` already reads (`## Active` — D4), by the shape being a genuine corruption rather than a style preference, and by the violation message naming the line and the reason so the remedy is obvious. `templates/todo-template.md` and this repository's live board are asserted still green (AC4, AC13, AC17).
- **D4 — a strand is a continuation line with no *task line* above it in the same section, and the check runs over `## Active` only.** "Owner" means a task line (`^- \[[x ]\] `), not merely any boundary line: the board grammar in `templates/todo-template.md` defines exactly two kinds of line inside a section — a task line and its continuation lines — plus the documented `_(none)_` placeholder, so a continuation line hanging off a placeholder or off bare prose is already outside the grammar and is worth reporting.
  - A malformed top-level line still opens an entry. A line beginning `- [ ]` that fails `LINE_RE` is reported once, as a format mismatch, and does **not** additionally produce a strand violation for each of its sub-bullets. One defect, one message.
  - **`## Done` is out of scope, deliberately.** `check-handoff.sh`'s stated contract is the `## Active` section; widening its section scope is a change of contract with its own compat surface and its own argument. The incident class is fully covered without it: `close-out` reads its source entry from `## Active`, so a truncated move strands lines in `## Active`, and the `## Done` entry `close-out` builds is constructed top-level-line-first and cannot strand by construction. Recorded as a fast-follow candidate, not filed from this role.
  - The frozen violation reason string is **`stranded continuation line (no task entry above it in this section)`**, emitted through the existing `emit()` helper so the message shape stays `<file>:<lineno>: <reason>: <line>` and the exit code stays `1`. No new exit code is introduced; `2` remains "cannot evaluate the input".
- **D5 — the change surface is four `bin/` scripts, one template, one workflow step and four existing test suites.** No new script, no new suite file, no new shellcheck argument.
  - `bin/close-out.sh` — pass-1 awk adopts the canon and captures the **entry extent** (trailing blank lines trimmed, so the moved entry's shape in `## Done` is byte-for-byte what it is today for every entry that has no internal blanks). The header comment's "contiguous sub-bullets" wording is re-grounded in the canon, staying inside the `sed -n '2,40p'` range that `--help` prints.
  - `bin/check-handoff.sh` — the sub-bullet skip becomes the canonical continuation test, and the strand check rides on the same pass.
  - `bin/check-intent.sh` — D2's blank-line neutrality plus the re-grounded comment.
  - `bin/check-board-headings.sh` — predicate alignment **only**; this is a provably behaviour-preserving edit, not a fix. Its line filter never captures a range: an indented non-dash line and a blank line both already fail its `^- \[[x ]\]` heading match, so widening the skip from `^[[:space:]]+-` to the canonical form changes no verdict. It is changed anyway so the canon has no fourth dialect, and its header comment's now-stale cross-reference to "check-handoff.sh's sub-bullet skip (`^[[:space:]]+-`)" is re-grounded in the same edit — the prose and the code are one canonical pair. AC12 (its suite green) plus its new fixture is the proof of behaviour preservation.
  - `templates/todo-template.md` — the grammar is written down where adopters read it, since a checker that newly rejects a shape must say what the accepted shape is. Two frozen phrases, each on one physical line: **`blank lines and indented lines of any shape belong to the entry`** and **`an indented line with no task entry above it in the section is an error`**.
  - `.github/workflows/check-handoff.yml` — **one new run step**: lint this repository's own live board, resolved through `bin/team-paths.sh --get todo`. CI has never linted the live board; it lints only the shipped template. The incident happened on the live board, and the sprint goal is mechanizing unenforced invariants — this is the dogfooding half, and it is what makes the strand check self-referential rather than fixture-only.
- **D6 — `bin/close-out.sh` names the reason when its pre-write gate refuses.** Today the gate runs `check-handoff.sh` with both streams discarded and prints only "rewritten board would fail check-handoff.sh — board left untouched", so an operator sees a refusal with no cause. That is the same failure mode this whole task is about, one layer up. The gate captures the checker's stderr and prints it before failing. The exit code (`1`), the no-write guarantee and the ordering are unchanged.
- **D7 — the mechanism is specified per site, not just per outcome, and every site is proved.** This is a cross-cutting-discipline change: one predicate applied across four parallel sites. The inventory below is the correspondence the task is judged against; every row is either changed-and-proved or exempt-with-a-reason, and no row is absent.

## Non-goals

- **Re-repairing the board content fixed in `6750dcf`.** That repair is merged and is this task's base, not its subject.
- **`bin/close-out.sh`'s other features** — telemetry emission, the printed issue-close procedure, `project_status` regeneration, the fast-follow-disposition gate, `--note` validation, the flag rewrite. The disposition gate's *reach* grows as a side effect of the widened range (it now scans the whole entry extent), which is correct and needs no change of its own.
- **Extending the board grammar.** Tables inside sub-bullets are *carried* and *tolerated*; they are not blessed, documented as supported, or given a shape of their own. No new sub-bullet kind is defined.
- **Widening the strand check to `## Done`** (D4), or to any other section.
- **Adding base-ref comparison, fence tracking or ATX-closing tolerance to `bin/check-handoff.sh`.** T-079's DP-A and T-095's DECISION 2 make those a deliberate asymmetry between `check-handoff.sh` and `check-board-headings.sh`; this task does not reopen either, and no fence-state machine is added to any parser.
- **Changing any exit-code taxonomy**, adding a new violation class beyond the one frozen reason string, or changing `check-intent.sh`'s three judgments, its hash normalization, or the carved-out ledger tamper-evidence subsystem.
- **A new script under `bin/`, a new file under `tests/*/run.sh`, or a new entry on the workflow's shellcheck argument list.**
- **`README.md` / `README.ja.md` / `docs/**` / `CHANGELOG*` / `agents/**` / `skills/**` / `templates/prompt-blocks/**`, and any version bump.** The grammar sentence lands in the board template only.
- **Any repair of, or change to, `.shell-team/todo.md`'s existing `## Done` entries.** This task adds its own `## Active` entry and nothing else on that file.

## Input space

**Reachable input classes** — what real boards produced by this loop contain, and the implementation must handle correctly:

- Entries whose continuation lines are all dash-led sub-bullets, one indent level, two spaces. The dominant class: every entry on this repository's board and in the shipped template.
- Entries carrying **indented non-dash lines**: markdown table rows (`  | … |`), and their separator rows. Reachable because agents write hand-off narratives into sub-bullets — this is the incident.
- Entries carrying **internal blank lines** between continuation lines, and a run of two or more trailing blank lines before the next entry. Also the incident.
- Entries that are the last in their section (next line is a `## ` heading), the last in the file (EOF), and entries in a board where `## Done` precedes `## Active`.
- Sections that are empty, and sections carrying the documented `_(none)_` placeholder — the shipped template's shape.
- Tab-indented continuation lines, and lines that are whitespace-only (an editor's trailing spaces). Both already have fixtures in this repository.
- CRLF line endings throughout a board. `bin/check-handoff.sh` and `bin/check-intent.sh` already strip CR; `bin/close-out.sh`'s awk must treat a CR-only line as blank.
- Continuation lines of multi-kilobyte length, and boards of several hundred lines and several hundred kilobytes. This repository's own board is both.
- Boards in **both layouts** — `.shell-team/todo.md` and the legacy `tasks/todo.md` — resolved through `bin/team-paths.sh`, plus the `$TEAM_TODO` override.
- Boundary lines that are not task lines: bare prose, a `### ` sub-heading, and CommonMark `* `/`+ `/numbered bullets. The last of these is not hypothetical: it is `bin/check-intent.sh`'s round-3 Blocker.
- A malformed top-level line (a `- [ ]` line that fails `LINE_RE`) followed by its own continuation lines.
- A board where a task's `- intent-hash` and `- intent-ratified` sub-bullets are separated from the task line by other continuation lines, including a blank one.

**Out-of-scope synthetic extremes** — declined deliberately; a finding grounded only in one of these is out of contract:

- **A fenced code block inside `## Active` whose content lines are indented and which is not preceded by a task line.** Its lines are reported as strands. `bin/check-handoff.sh` is deliberately fence-unaware (T-095 DECISION 2 keeps that asymmetry against `bin/check-board-headings.sh`), this task does not reopen it, the documented board grammar puts the only fence in `## Format`, and the remedy the message points at is to move the block. Declared, not discovered.
- **ATX-closing heading notation** (`## Active ##`) in `bin/check-handoff.sh` or `bin/close-out.sh` — the same T-095-declared asymmetry, unchanged here.
- A literal `## Active` or `## Done` line embedded in a continuation line's prose, or an HTML comment spanning several lines inside a section.
- Indentation by characters that are whitespace in Unicode but not in POSIX `[[:space:]]` under the C locale — a non-breaking space, an ideographic space, a zero-width space. Such a line is a boundary line by definition (the table above), and no support for treating it as indentation is promised.
- Nesting depth as a distinct concept: a four-space or eight-space continuation line is the same class as a two-space one. No sub-entry, sub-sub-bullet or ownership hierarchy is introduced.
- Pathological scale: multi-megabyte boards, tens of thousands of entries, a single line of megabyte length. No performance bound is promised.
- Markdown documents that are not this loop's board, renamed to `todo.md`, and boards hand-authored outside the agents' grammar.
- Concurrent writers appending to the board while `bin/close-out.sh` runs; the existing temp-file-then-copy write is unchanged and no locking is added.
- Ever-more-exotic near-miss shapes for the strand detector beyond the four boundary classes AC5 pins (placeholder, prose, sub-heading, CommonMark bullet). Those four are the protected boundary; a fifth invented shape is not an escalating finding class.
