## Problem

Two defect classes this cycle surfaced have a corpus half that already shipped and a pm-spec authoring half that does not exist yet. The first: a document that labels a result "measured at `<ref>`" while the command printed beside it reads the working tree — two independent sites in one task, plus a third found by the same-class sweep. The corpus entry for it landed in the previous car; nothing yet requires the **spec** covering such a document to carry a criterion aimed at the printed command's *reading target*, so the rule reaches the roles that type and verify the command but not the role that writes the criterion. The second: an acceptance criterion whose subject is a population count is frozen once and then silently drifts as the population grows, with no statement anywhere of when it should be looked at again.

This repository already carries a live instance of both at once. `docs/loop-engineering/check-line-mktemp-guard-audit.md` declares a population of 214 lines over 26 files, names `1e31600` as its base ref in its header, and states that the same values are re-run **against the working tree** by T-1024's AC2 — so the label names one thing and the pinned command reads another, and six cycles of corpus growth have moved the working tree well past the declared pair. The divergence was measured and disclosed by a later audit task rather than closed, because nothing in the frozen criterion said when to re-measure. Fixing the values alone would re-stale on the very next spec added, and would contradict the first discipline in the act of applying the second.

```markdown
- **Population-count staleness trigger (forward-only)**: an acceptance criterion whose subject is a **population count** — a `grep`/`find`/`ls` count over a set that grows as the repository grows, compared against a declared value, an expected total or a floor — carries an explicit re-measurement trigger, written as an indented `- stale-at: <the observable event that invalidates this count>` sub-bullet placed immediately after that criterion's own `- check:` line, or immediately after the criterion's bullet where it has none. One per criterion, and its value names an **event**, never a date.
```
