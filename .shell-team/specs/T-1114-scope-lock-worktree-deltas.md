# T-1114 — A scope-lock criterion measures the whole base-to-worktree chain, so a staged change to an already-tracked path stops being invisible to it

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1114

## Problem

The scope-lock shape every spec in this corpus shares measures the changed-and-added set as a committed range unioned with untracked files. A change *staged* against an already-tracked path — the issue's headline case is a rename of a governed file to a disallowed path, staged at verification time — appears in neither measured set, so the lock reports green while the tree it is guarding violates it. The gap is one authoring convention rather than dozens of defects: the convention lives in exactly one file, and every spec's scope lock is a copy of what that file teaches. The corpus currently *assumes* a clean tree away in dozens of frozen check lines instead of measuring the states it assumes away, and the loop's own seam gate asserts cleanliness once at a seam and never inside the locks — so nothing between the seam and the lock closes the window.

- A path that is **gitignored**, which must stay invisible to all four reads so a build artifact or a local cache cannot fail a lock.
- Real git configurations reachable in an ordinary checkout: `diff.renames` at its default-on setting or explicitly off; `core.excludesFile` set or unset; and a branch carrying no commits of its own beyond the base ref, which is this branch's own state at authoring time.

**Out-of-scope synthetic extremes** — named concretely, and declined:

- A path whose name contains a newline, a literal tab, or a byte requiring `core.quotePath` quoting. All four reads are newline-delimited streams and every scope lock in this corpus already assumes newline-safe paths; defending against a path that breaks the delimiter is a different task from closing the staged-delta gap.
- A submodule, or a nested `git worktree` inside the repository, whose own index and `HEAD` are separate from the outer repository's — the union is defined over one index and one worktree.
- A path carrying the `skip-worktree` or `assume-unchanged` bit, or a sparse-checkout cone that deliberately hides a working-tree delta from `git diff`. - A repository whose `.git` is a file pointing elsewhere rather than a directory.

- An adopter who has aliased, wrapped or shadowed `git` itself, or set `diff.external`.
