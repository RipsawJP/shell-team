## Problem

Every quality gate in this loop treats the spec as ground truth. `qa-verifier` verifies the implementation *against* the spec; `codex-reviewer` verifies the delivered change (it reads the spec, but only once an implementation exists to read it against); `drift-evaluator` verifies drift *from* the frozen intent. The freeze sweep verifies the spec's **mechanical** truth — satisfiability, broken or vacuous check lines, measured premises against the repository and the live trackers. Nothing in the loop verifies the spec against **domain reality**: a wrong deployment-order assumption, a rollback precondition that does not hold in production, a blast-radius claim about a system this repository cannot measure. A spec wrong about the world sails through faithfully implemented, tests green, review APPROVE — and for accuracy-critical work that makes the spec the loop's one unverified single point of failure.

Issue #332 records the field observation and the workaround its author reached for: hand-assembling exactly the missing gate outside the loop (orchestrator writes the spec, Codex cross-reviews the spec *document*, a human approves, and only then does implementation enter the loop). This task ships that shape as a mode, so an accuracy-critical spec gets an independent cross-provider read of its *premises* without anyone leaving the loop to get one. It pairs with T-1091's `specify` axis: #331 gave such a task a spec author who holds the facts, and this gives the same task an independent check on those facts.

**Goal (one sentence).** A spec's **domain premises** become reviewable inside the loop: a fourth dispatch axis `spec-review`, closed over `none|cross-provider` and defined and priced in a new note of its own, elects whether a task pays for one extra cross-provider pass; `agents/codex-reviewer.md` gains a **spec-review mode** whose input is the spec document — the frozen intent block plus its declaration region — rather than a branch diff, whose mandate is whether the domain premises are sound and whether the acceptance criteria test the right thing rather than merely testable things, and whose verdict is a `### Codex Spec-Review verdict: APPROVE | REQUEST_CHANGES` block recorded as a `## Spec review` section in the task's existing review record and routed back to the spec's author resolved through the `specify` decision; `skills/run/SKILL.md` gains a **Specify-seam spec-review gate** as a fourth sub-bullet beside the three existing first-freeze declaration-region gates, positioned after the freeze sweep and **before** the `- intent-hash (v1)` record so a finding is answered while nothing is frozen; `bin/close-out.sh` gains one `DISPATCH_AXIS_TABLE` row plus a second fail-closed refusal class that, at close-out, refuses a task whose entry recorded `spec-review — cross-provider` unless its review record carries an APPROVE; and an adopter reading the shipped documentation can tell when to elect the extra round and what it does and does not guarantee.

**The gate's condition source, frozen as a design and not as an implementation detail.** The election's **primary condition source is `pm-spec`'s own `- spec-review:` hand-off field**, which exists before the freeze sweep *by construction of the phase order* — the sweep is a step the coordinating session takes on what `pm-spec` handed back — so there is no sequence, textually compliant or otherwise, in which the condition is not yet readable. That value is **cross-checked against the `spec-review` decision `tech-lead`'s Routing Map printed at Plan** — the printed decision itself, never the board's transcription of it, for the same timing-independence reason the primary source is not the board — and a mismatch in **either** direction refuses the freeze rather than selecting a branch, routing to whichever side the mismatch's source demands and **escalating to the human where the two texts alone cannot say which of them is wrong**. The read **fails closed**: a missing, duplicated or out-of-vocabulary value refuses and routes back, and an unreadable election is never assumed to be `none`. The board's `- dispatch: spec-review — …` record stays the durable audit trail of the routing decision and is **never** the firing condition; `bin/close-out.sh`'s teeth read that board record at **close-out**, where transcription has demonstrably already happened, which makes them a backstop rather than a second firing condition. Four residuals are disclosed rather than claimed closed, and belong to a follow-up issue in the same pattern `skills/run/SKILL.md`'s existing declaration-region gates already cite: **(i)** both condition texts are agent-produced and unauthenticated, so the cross-check raises the cost of a mistake and not of a deliberate misstatement by the one party that writes both; **(ii)** the read itself is verified by nothing — the teeth verify only that an *elected* review reached APPROVE, never that the gate ran; **(iii)** "the domain premises are sound" is a reading judgment, not a machine-checkable state; **(iv)** the election is not inside the frozen intent block, so a post-freeze de-election is not `drift-detected` and is visible only as a Routing-Map-versus-board divergence.

**Why the gate sits before the intent hash rather than after it.** Reviewing *after* the hash is recorded makes every Goal-level or criterion-level finding a class-B re-freeze requiring a human ratification (`skills/run/SKILL.md:54–55`, `agents/pm-spec.md:101`). Reviewing after the sweep but before the hash means a finding is answered while nothing is frozen — no drift, no re-freeze, no ratification cycle spent on prose nobody disputes — and still satisfies #332's own "after the freeze sweep, before Implement". The board therefore stays at `READY_FOR_ARCH` across a spec review's rounds: **no new seam, no new phase and no new status flag**, the same shape the Design phase already uses.
