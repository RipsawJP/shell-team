# A freeze is refused unless the board attests that every check: line ran live

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1018
**Source**: GitHub issue #96 — the tooling half of the corpus lesson `## 2026-07-26 — Run a spec's `check:` lines live and reconcile them before recording an intent hash`, whose own text (as extended 2026-08-02) says the rule must become "a gating step with an owner and a moment, not a standing reminder". Backlog item 3/5 of the v1.3.0 sprint goal (mechanize unenforced loop invariants).
**Base**: `develop` @ `87daf74` (post T-1017 and its close-out; confirmed as this branch's real fork point)
**Branch**: `feature/96-freeze-attestation-gate`

## Problem

The rule is already written, already promoted, and already bound into the role that authors specs: before an intent block is frozen, whoever holds execution capability runs every `check:` line live, catches the two-then-three known failure classes (mechanically broken, vacuously passing, structurally unsatisfiable), corrects them meaning-preservingly, and only then records the hash. Verify, then correct, then freeze.

It keeps not happening at the moment it matters. T-1011 and T-1012 each discovered a broken frozen `check:` line mid-implementation and each cost a human-ratified re-freeze. T-1016 applied the discipline, wrote a free-form disclosure sub-bullet on the board, and still shipped an AC10 whose inline fixture lacked the `**Task ID**` line `bin/check-intent.sh` structurally requires — the compound `check:` line was never decomposed into the clauses it asserts, so its single exit code hid a criterion that measured nothing; that too cost a v1→v2 ratification. T-1017 ran the same discipline with the decomposition done up front and needed zero corrections. Two data points, one difference: whether the run was decomposed and recorded, or merely intended.

The lesson's own diagnosis is the design brief: *a written rule with no owner and no moment mechanically attached to the freeze did not change what happened at the freeze.* Nothing in this repository can tell an attested freeze from an unattested one. `bin/check-intent.sh` already judges the ledger the freeze writes — the board's `- intent-hash (vN)` record — and already parses the task's own board sub-bullets through a single shared parser whose four review rounds bought exactly this capability. The gate belongs there, at the one board state that can only exist before a freeze.

## Goal

<!-- BEGIN intent-block: T-1018 -->

`bin/check-intent.sh` refuses a freeze that no attestation vouches for. When the task's board entry carries no well-formed `- intent-hash` record — the freeze moment — the checker requires a conformant `- freeze-attestation` sub-bullet for the version about to be recorded, and refuses fail-closed with a new, distinct `attestation` classification on stderr when one is absent, malformed, internally inconsistent, or disagrees with the number of `- check:` lines in the spec's own intent block. A task that has adopted the convention keeps pace with it: once any conformant attestation exists, one is required for every version through the board's declared version, so a ratified re-freeze is gated too. A task frozen before this gate existed — a record with a hash and no attestation at all — is never asked for one retroactively, and its verdict is byte-for-byte what it is today. The exit taxonomy stays `0`/`1`/`2` with the new condition landing on `2` under its own token, so neither the run skill's bootstrap-record branch nor its drift-escalation branch can misfire; `skills/run/SKILL.md` reads the token and never records a hash on the attestation branch, and `skills/goal/SKILL.md` translates the fourth outcome into its own reserved signature sentinel. No git-history walk is reintroduced, no new script is added under `bin/`, and no adopter is asked to backfill a record.

### Terms

| term | definition |
|---|---|
| **the freeze** | the act of writing a `- intent-hash (vN): <40-hex>` sub-bullet onto the task's own top-level board entry — whether the first (v1) or a human-ratified re-freeze (vN, N≥2) |
| **the freeze moment** | the board state in which the task's entry carries **zero** well-formed `- intent-hash` records. It is the only state that can exist solely before a first freeze, and it is where the gate bites |
| **the attestation** / **the record** | one board sub-bullet, under the task's own top-level entry, matching the frozen grammar in D4 |
| **the freeze-runner** | whoever holds execution capability at the freeze (in this loop: the coordinating session, or `tech-lead`). The grammar validates the `owner=` field's *shape*, never a role enum — see D5 |
| **the counted total** | the number of physical lines **inside the spec's intent-block marker region** matching `^[[:space:]]+- check:` (marker lines excluded, exactly the region the hash is taken over) |
| **the declared version N** | the version in the board's single well-formed `- intent-hash` record; at the freeze moment, where there is none, **N = 1** |
| **the legacy carve-out** | a task whose entry carries a well-formed `- intent-hash` record and **zero** attestation-shaped lines. Never gated |
| **the classification token** | the first field `bin/check-intent.sh` prints on stderr on every rejection path — today `usage`, `structural`, `drift-detected`; this task adds `attestation`. Matched by callers on the line-anchored prefix `check-intent: <token>: `, never on message prose |

### Settled decisions

Each decision below is resolved. Nothing here is left to implementation judgment.

- **D1 — the attestation is a board sub-bullet under the task's own top-level entry. Not the spec file, and not a new artifact.**
  - **Why the board.** `bin/check-intent.sh` already parses this exact scope through `extract_task_records()`, the single shared board parser whose rounds 1–4 refinement (the inverted continuation predicate, the exact task-id capture compare, T-1016's blank-line neutrality) is the asset being reused rather than re-earned. The ledger the attestation belongs to — `- intent-hash`, `- intent-ratified` — already lives there, and the existing free-form convention (T-1016's and T-1017's `- pre-freeze live run (…)` sub-bullets) is already there too. Authorship also stays clean: the frozen text is pm-spec's, the attestation is the executor's, and they sit in different files.
  - **Why not the spec file — the decisive reason is circularity.** An attestation placed inside the intent block would change the hash it attests. Placed outside it, in the spec's mutable region, it is neither hashed nor parsed by anything, so it would be a comment with a grammar. Neither position is a gate.
  - **Why not a new artifact** (`.shell-team/attestations/<task>.md`, a sibling of the provenance/interventions records). It would need a new checker, a new CI step, a new close-out gate and a new adopter obligation, to hold one line that the checker already reading the board can read for free. Rejected on cost, and on the "no new `bin/` script" constraint below.
- **D2 — "a new freeze" is decided mechanically by the absence of a hash record, plus a pace rule for tasks that have adopted the convention. No git history is consulted, and no existing frozen record is judged retroactively.** Three rules, in this order:
  1. **Malformed first.** Any line in scope matching the loose anchor `^[[:space:]]+- freeze-attestation` but not the full grammar is a refusal (`attestation`), whatever else is true. A record the checker cannot parse is never treated as absent, and never as present.
  2. **The legacy carve-out.** Exactly one well-formed `- intent-hash` record **and** zero attestation-shaped lines in scope ⇒ the attestation judgment is skipped entirely and the checker proceeds to the version-chain and hash-match judgments unchanged. This is the whole backward-compatibility answer, and it is keyed on something already in the record rather than on when it was written.
  3. **Otherwise the pace rule.** With N = the declared version (1 at the freeze moment), there must be **exactly one** well-formed attestation for each version `1..N` and none outside that range. A missing, duplicated or out-of-range version is a refusal (`attestation`).
  - **Why a board-git-history walk is rejected, explicitly.** Deciding "was this hash newly written" from the board file's own git log is precisely the ledger-tamper-evidence subsystem that T-071 implemented in rework3/rework4 and carved back **out** in rework5, after five independent defects across rounds 3–5 all concentrated in that one subsystem, under the user's pre-committed disposition. Its tombstone is in `bin/check-intent.sh`'s header. Reintroducing it here would re-buy that history for a judgment the record itself can answer.
  - **Why a full-board backfill is rejected, with the cost measured rather than estimated.** This repository's board carries **21** well-formed `- intent-hash` records and **20** `- intent-ratified` records; exactly **2** entries carry any live-run disclosure at all (T-1016, T-1017, both free-form). Backfilling would mean writing 19 records for runs nobody performed, several of them against intent blocks that have since been superseded — fabricated provenance, which is the opposite of what the channel is for. Adopter repositories carry their own such records and would be broken by a retroactive demand.
  - **Why this is not fail-open for a genuinely new freeze.** The carve-out requires a hash record to exist. At the freeze moment there is none, so a first freeze is *always* gated; and once v1 is attested, rule 3 gates every later version. The residual hole is a hash bullet written by hand without ever invoking the checker — the same trust boundary the rework5 tombstone already documents, and the same posture `bin/check-acs.sh`'s TRUST BOUNDARY note takes. It is stated in the Input space, not papered over.
  - **The one shipped-behaviour change this causes, named rather than discovered later:** a board with no hash record and no attestation reports `attestation` where it reports `structural` today. That is the gate biting, and it is the bootstrap condition by construction. `tests/check-intent/run.sh` case (v-a) asserts the old token and is updated in this task; the compat cost for an adopter mid-task is one board line, whose exact shape the refusal prints.
- **D3 — the exit taxonomy stays `0`/`1`/`2`, total, with one new classification token; status is read first and the token only within it.** `attestation` refusals are exit `2` — never `1` — so the drift channel stays exclusively about bytes and ledger bookkeeping. The complete table, every reachable condition:

  | # | condition | exit | stderr classification |
  |---|---|---|---|
  | (0) | every judgment passes | **0** | `aligned` (stdout, unchanged) |
  | (1) | bad flag, missing/extra argument, non-regular or unreadable file, or an internal `readlink`/`dirname`/`mktemp`/`awk`/`git hash-object` failure | **2** | `usage` |
  | (2) | no `**Task ID**: T-NNN` line; marker count ≠ 1 for either marker; BEGIN not strictly before END | **2** | `structural` |
  | (3) | zero or ≥2 top-level board entries for the task; any malformed `- intent-ratified` line | **2** | `structural` |
  | (4) | ≥2 well-formed `- intent-hash` records, or any malformed `- intent-hash` line | **2** | `structural` |
  | (5) | a line matches the loose attestation anchor but not the full grammar (D2 rule 1) | **2** | **`attestation`** |
  | (6) | no conformant attestation for a required version `1..N` — including the freeze moment, where N = 1 (D2 rule 3) | **2** | **`attestation`** |
  | (7) | two or more attestations for the same version, or an attestation for a version outside `1..N` | **2** | **`attestation`** |
  | (8) | the version-N attestation's arithmetic fails: `ran ≠ total`, `P + F ≠ ran`, or `total ≠` the counted total | **2** | **`attestation`** |
  | (9) | any well-formed attestation's internal arithmetic fails (`ran ≠ total`, `P + F ≠ ran`) for a version other than N | **2** | **`attestation`** |
  | (10) | zero well-formed `- intent-hash` records **and** the attestation judgment passed — the bootstrap case | **2** | `structural` (message unchanged) |
  | (11) | version-chain count mismatch or broken chain | **1** | `drift-detected` |
  | (12) | recorded hash ≠ the current intent block's normalized hash | **1** | `drift-detected` |

  - **Judgment order is fixed:** (1) → (2) → extract+hash → (3) → (4) → **(5)…(9)** → (10) → (11) → (12). The attestation judgment therefore precedes both drift judgments: a board that is simultaneously unattested and drifted refuses as `attestation`, and drift becomes reachable again the moment the attestation is written.
  - **Why a new token rather than reusing `structural`.** `skills/run/SKILL.md` step 2 records the hash when the checker reports exit `2` in the bootstrap shape. Every condition in rows (5)–(9) must **not** record a hash, so folding them into `structural` would create exactly the misroute this task exists to prevent. One new token covers the whole subsystem, so `structural`'s condition set stays byte-identical to today's and no existing consumer changes meaning.
  - **Why not exit `1`.** Rows (11)–(12) route to human ratification. An unattested freeze is not a ratification question; sending it there would ask a human to ratify a change nobody has verified.
  - **Rows (5)–(9) are the fail-closed floor.** An attestation the checker cannot parse, cannot reconcile, or cannot match to the version being recorded is never treated as satisfying the gate.
  - **The pre-existing looseness of `structural` is deliberately left alone**: today it covers both the bootstrap shape and genuine structural defects, and `skills/run/SKILL.md` distinguishes them by the message. This task adds no `structural` condition, so it neither fixes nor worsens that; recorded as a fast-follow candidate (the same disposition T-1017's D6 took for the sibling asymmetry), not filed from this role.
  - **Two frozen header phrases**, each on one physical line of `bin/check-intent.sh`'s header comment and therefore in `--help`: **`a freeze is refused unless the board carries a conformant freeze-attestation record for the version being recorded`** and **`an unattested, malformed or miscounted freeze-attestation is exit 2 with the attestation classification, and the hash is never recorded`**. `print_help`'s `sed -n '2,64p'` self-reference is re-derived so `--help` prints the whole header comment and no script code — the same repair T-1017 made to `bin/close-out.sh`, for the same reason: the header is the surface an operator reads at refusal time.
- **D4 — the grammar is one strict, fixed-order line, and it is the executor's own hand-written record. `bin/check-acs.sh` gains nothing.**

  ```
    - freeze-attestation (v1, 2026-08-03): lines=21/21 sweep=mutual-satisfiability verdict=4P/17F owner=coordinating session
  ```

  - **Fields, in this exact order, single spaces between them:** `(v<N≥1>, <YYYY-MM-DD>): ` then `lines=<ran>/<total>` then `sweep=mutual-satisfiability` (a fixed literal) then `verdict=<P>P/<F>F` then `owner=<value>` last, running to end of line. `owner=`'s first character must be a non-space, and its value is validated for non-emptiness only. Every count is `[0-9]+`. A trailing CR is stripped, as everywhere else in this checker.
  - **Cross-checks that make the record more than a claim.** `ran == total`; `P + F == ran`; and, **for the version-N record only**, `total ==` the counted total. Internal arithmetic is checked for every well-formed record; the spec-derived count is not, because a record for an older version was measured against an intent block that has since been ratified away and the checker can only measure the current one. This split is exactly what AC9 pins.
  - **Why the counted total is defined over the intent block, not the whole spec file.** A count over the whole file would go stale on any edit to *mutable* prose (a Notes-for-engineer example that happens to start with `- check:`), producing a refusal with no ratifiable cause. Over the marker region it can only change when the frozen region changes, which already requires ratification. Where the two disagree — a non-canonical spec with criteria outside the block, or two `check:` sub-bullets under one AC (where `check-acs.sh` silently runs only the first) — the refusal **prints the counted number**, so the freeze-runner never has to guess, and the disagreement itself surfaces a real defect.
  - **`sweep=mutual-satisfiability` is a fixed literal and its substance is not verifiable.** The checker verifies that the claim was made, by whom, on what date, over how many criteria, with what measured outcome. Whether the sweep was substantive is outside any checker's reach: this is the same trust boundary `bin/check-interventions.sh` declares (a discipline aid over a committed, reviewed artifact, not a security boundary against an adversarial author) and it is inherited verbatim rather than pretended away.
  - **Fixed field order, rejecting order-free `key=value` parsing.** Order-free parsing needs a tokenizer, duplicate-key handling and an unknown-key policy — three new boundary surfaces on the very subsystem this task must keep small. One regex, one order, printed in full on refusal.
  - **A commit sha or base ref in the record is rejected.** The pre-freeze run happens on a working tree with uncommitted spec edits; a sha would name something that never existed.
  - **The keyword is new (`freeze-attestation`), not the existing prose phrase, and that is deliberate.** T-1016's and T-1017's committed `- pre-freeze live run (…)` lines do not match the loose anchor `^[[:space:]]+- freeze-attestation`, so they are invisible to the gate rather than "malformed" — the two conventions provably cannot collide, and those two entries fall under the carve-out with their verdicts unchanged. The free-form narrative sub-bullet remains permitted and unparsed; it is where the SKIP count, the corrections made, and the decomposition notes keep living.
  - **`bin/check-acs.sh` gains no `--attest` skeleton-emitting mode.** Re-measured, not assumed: `tests/errexit-safe/run.sh`'s NOT_APPLY registry pins `check-acs.sh:234`, `:260` and `:294` by exact `file:line:content`, so any line added above them drags that suite into this task's allow-list; and it would turn a read-only runner into a writer. The convenience it would buy — typing one line — is delivered instead by the refusal printing the exact shape with the counted total already substituted, from the checker that has to compute that number anyway.
  - **The printed shape is deliberately not a valid record.** It carries `YYYY-MM-DD` and `<P>`/`<F>`/`<who ran them>` placeholders, so pasting it verbatim is refused again rather than silently accepted.
- **D5 — owner vocabulary is neutral.** `coordinating session` and `tech-lead` are this loop's names for the capability, not a vocabulary the grammar may enforce. The field is validated for shape (non-empty, no leading space) and nothing else: no enum, no allow-list, no case rule, no language rule, and multi-word values in any human language are conformant. The one thing the value must not be is a personal identifier — an email-shaped or home-directory-shaped value in a git-tracked file is what `bin/check-pii-shapes.sh` already refuses on the diff, and that guard is not duplicated here.
- **D6 — both consumers of the exit code are updated in this task, and they are the only ones.** The inventory is in the correspondence table below, with an origin/contamination column.
  - `skills/run/SKILL.md` step 2 reads the classification token and branches: `attestation` ⇒ **do not record or overwrite any `- intent-hash` sub-bullet**; run every `check:` line live and in full, decompose each compound line into the clauses it asserts, sweep for mutual satisfiability, route a mechanically-broken / vacuous / unsatisfiable line back to pm-spec for a meaning-preserving correction, append the attestation, re-check. `structural`, `usage`, `drift-detected` and an unrecognized shape keep exactly the behaviour they have today, with unrecognized failing closed. This file is adopter-shipped, so its text is the operative instruction, not a note.
  - `skills/goal/SKILL.md`'s signature-translation table gains a fourth check-intent row: `attestation` ⇒ `check-intent: FAIL AC900007`. Without it, an `attestation` tick and a `structural` tick collapse onto one signature (`AC900001`) and `loop-guard.sh` fires a false `no_progress` — the precise incident shape the 2026-07-26 completion-gate lesson records. `AC900007` is the next free reserved sentinel: `AC900001`–`AC900006` are taken (check-intent ×2, check-provenance ×2, check-interventions ×2), measured. The SIG text carries the translated token only, never the checker's raw stdout or stderr, which is the rule that line already states for every other gate.
- **D7 — the change surface is one `bin/` script, two test suites and two skills. No new script under `bin/`, no new `tests/*/run.sh`, no new `shellcheck` argument, and no change to `.github/**` at all.**
  - `bin/check-intent.sh` — the attestation judgment, the new token, the header grammar and exit table, the re-derived `--help` range.
  - `tests/check-intent/run.sh` — case (v-a)'s token update plus this task's own assertions (AC19's ids). Its fixtures are built inline per case, so no `fixtures/` file is added.
  - `tests/machine-tokens/run.sh` — the intent-block token group is the registry of this vocabulary; `freeze-attestation` joins `intent-hash` / `intent-ratified` there or the registry is silently incomplete.
  - `skills/run/SKILL.md`, `skills/goal/SKILL.md` — D6.
  - **No new `bin/` script, for a stated reason.** A separate checker would need its own CI step and its own suite, and would either duplicate `extract_task_records()` or write a second board parser — the exact defect class rework3 closed by inverting the predicate instead of enumerating shapes. The judgment also has to happen at the same moment, against the same two files, as the hash judgment it gates.
  - **`tests/errexit-safe/run.sh` is *not* in scope, re-measured rather than assumed:** its NOT_APPLY registry pins lines in `check-handoff.sh`, `check-acs.sh`, `check-contract.sh`, `check-board-headings.sh`, `close-out.sh` and `gen-playbook-blocks.sh` — **no `check-intent.sh` line is pinned**, so this task's edits shift nothing. ## Non-goals

- **Verifying that the attested run actually happened, or that the sweep was substantive.** The record is the executor's claim; the checker verifies its shape, its arithmetic, and its agreement with the spec's own criteria count. A fabricated record with correct numbers passes, by design and by inherited trust boundary.
- **Detecting a hash bullet written without invoking the checker at all.** That needs the first-seen-wins history walk carved out in T-071 rework5. Not reintroduced, in any form, including a narrower one.
- **Backfilling, migrating or retroactively judging any of the 21 existing frozen records**, here or in an adopter repository. The carve-out is permanent for a record that never adopted the convention.
- **Gating a re-freeze on a task that never carried an attestation.** Rule 3 only engages once one exists. Stated, not hidden.
- **Changing `structural`'s condition set, or fixing its pre-existing bootstrap/defect conflation** (D3).
- **Any change to `bin/check-acs.sh`** — no `--attest` mode, no new output, not a line (D4).
- **A new script under `bin/`, a new `tests/*/run.sh`, a new `shellcheck` argument, or any change to `.github/**`.**
- **`CONTRIBUTING.md`, `docs/**`, `README*`, `CHANGELOG*`, `templates/**`, `agents/**`, `.shell-team/lessons.md`, and any version bump** (D8, D9).
- **`bin/check-intent.sh`'s other judgments** — normalization, marker matching, the board parser's continuation canon, the version chain, the hash comparison, the symlink-resolving bootstrap. Consumed as they stand.
- **A richer version algebra** (`v1.2`, ranges, a version-less attestation) or a second attestation per version.
- **Localizing the field keywords or the classification token.** English literals, like every other message in `bin/`.
- **Any change to `.shell-team/todo.md` beyond this task's own entry.**

## Acceptance criteria

Base ref for every `git` anchor is `87daf74`. Every check runs from the repository root, uses an explicit `mktemp` template under `$TMPDIR`, names every file it reads literally or through a positional/loop variable (never a filename list in a string variable), asserts readability or non-emptiness before any negative judgment, counts with `awk` rather than a `grep -c` whose exit code would have to be swallowed, and pairs every refusal assertion with a positive control on the same fixture. No `check:` value begins or ends with a backtick. Fixture task ids are `T-902`–`T-908`. Run this spec with `CHECK_ACS_TIMEOUT=180`.

## Input space

**Reachable input classes** — what real freezes in this loop and in an adopter repository produce, and the gate must handle correctly:

- **A task at its first freeze**: exactly one marker pair, a top-level board entry, zero `- intent-hash` records — with an attestation (must pass through to the bootstrap `structural`) and without one (must refuse).
- **The 21 already-frozen entries on this repository's own board** (measured, not estimated), carrying 20 ratification records between them and zero attestation records, plus every adopter's equivalent. These are the carve-out and their verdicts must not move.
- **The 2 entries carrying a free-form `- pre-freeze live run (…)` narrative sub-bullet** (T-1016, T-1017). Prose, not records; invisible to the loose anchor.
- **A task frozen under the gate and then ratified**: hash `vN`, `N-1` ratification records, `N` attestations — including the intermediate state where the hash has moved to `vN` and the `vN` attestation is not yet written.
- **Near-miss attestation shapes**: the ten in AC4 plus the four arithmetic shapes in AC5. A misspelled fixed literal, a reordered field list, an empty owner and a non-ISO date are all things a hand-written line produces on a first attempt.
- **Prose sub-bullets in the same entry quoting the grammar mid-sentence.** This task's own board entry will carry several; so will every review record that describes the gate.
- **Multi-word owner values in any human language** (`coordinating session`, `tech-lead`, an operator's own word for the capability).
- **A spec whose intent block carries zero `- check:` lines** (all-runtime criteria): `lines=0/0 verdict=0P/0F` is the truthful, conformant record.
- **A spec where the intent-block count and `check-acs.sh`'s executed count disagree** — two `check:` sub-bullets under one AC (where only the first is ever run), or criteria placed outside the marker region. Reachable through ordinary authoring; the refusal prints the counted number so the freeze-runner is never left guessing, and the disagreement itself is a defect worth surfacing.
- **CRLF-terminated boards and specs**, and board sub-bullets separated from the task line by blank lines (T-1016's continuation canon).
- **An entry that has moved to `## Done`** by close-out: the attestation travels with it and stays in scope.
- **Both layouts and a `TEAM_RUN_BASE` override**, since both paths arrive as explicit arguments from a caller that resolved them through `bin/team-paths.sh`.
- **The pre-existing structural and drift classes** — absent/duplicated entries, malformed hash or ratification lines, marker problems, a broken chain, a mismatched hash — all of which must keep their current exit and token.

**Out-of-scope synthetic extremes** — declined deliberately; a finding grounded only in one of these is out of contract:

- **Whether the attested run really happened, or whether the sweep was substantive.** A fabricated record with internally correct numbers passes. The checker's reach is shape, arithmetic and agreement with the spec's own criteria count; the trust boundary is inherited verbatim from `bin/check-interventions.sh` and `bin/check-acs.sh` (a discipline aid over a committed, reviewed artifact, never a security boundary against an adversarial author).
- **A hash bullet written by hand without invoking the checker**, and any judgment of *when* a hash was written. Detecting it needs the first-seen-wins history walk T-071 rework5 carved out after five consecutive defects; it is not reintroduced, not even in a narrower form.
- **A re-freeze on a task that never carried an attestation.** Permanently ungated by the carve-out, by design.
- **Ever-more-exotic malformed shapes beyond the enumerated near-miss classes and the field grammar**: unicode look-alikes for `=` or `/`, zero-width characters inside a keyword, a 10 000-digit count, a megabyte-long owner value, a version like `v1.2` or `v01`, embedded control characters. The grammar is a single-line regex; a shape it rejects is a refusal, and inventing a new one is not a new defect.
- **A second attestation for one version, or a richer version algebra** (ranges, decimals, an unversioned record). Refused as malformed or as a cardinality violation; no algebra is promised.
- **Cross-checking the date** against a clock, a commit date or the ratification record's date. A checker that consulted a clock would stop being deterministic.
- **Localizing the field keywords, the fixed sweep literal or the classification token.**
- **TOCTOU between the checker's read and the hash write**, and concurrent edits to the board. No locking is added.
- **Pathological board or spec scale**: a megabyte board, thousands of entries, tens of thousands of criteria. No performance bound is promised.
- **Any task other than the one the spec's `**Task ID**` line names**, including `## Done` history for other ids and the fixture range.
- **Enforcing an owner vocabulary, or judging whether the named owner *could* have run the checks.** D5 forbids the first; the second is unmeasurable.

## Pre-commitment on rework rounds

Set before the first round, so the disposition is not decided while under pressure. **Factual trigger**: the attestation grammar or the board-parser judgment draws independent Blocker/Major findings in **two consecutive** review rounds. **Contextual trigger**: a third round of rework on that subsystem is about to start. The default threshold is this repository's standing "two consecutive rounds"; it is not loosened. When the two conditions disagree, the factual one decides.

On trigger, the third round does **not** open with another patch. It presents the human with a redesign-or-split choice, each option carrying its actual content rather than a label: (a) drop the pace rule (D2 rule 3) and ship only the freeze-moment gate, leaving re-freezes ungated and stated as such; (b) drop the count cross-check (D4) and validate shape and internal arithmetic only, which removes the spec-reading half of the judgment; (c) keep the design and route back to pm-spec to re-derive the grammar. This mirrors the T-071 rework5 precedent, where a subsystem that drew five independent defects across three rounds was carved out under a pre-committed disposition rather than patched a sixth time.
