# An optional budget.extension_ratifier field declares who may rule on a loop-guard max_iterations extension, defaulting to the operator

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1130

## Problem

`bin/loop-guard.sh` emits `STOP:max_iterations_reached` and the run skill escalates
it to the user. The only party that can grant an extension is the operator typing
into the run session. In a hub-and-spoke run — an operator-authored spec relayed
from an authoring session to a separate run session cwd'd at the target repo — the
authoring session holds the judgment context but has no path to rule on the
extension.

The requester's canon is GitHub issue #458, reproduced verbatim below. It was
**relayed into this role in the task brief**, not opened by it.

> ## Problem
> `bin/loop-guard.sh` emits `STOP:max_iterations_reached` and `skills/run/SKILL.md` (step at line ~81) escalates it to the user. The only party that can grant an extension is the operator typing into the run session.
> In a hub-and-spoke run — an operator-authored spec relayed from an authoring session to a separate run session cwd'd at the target repo — the authoring session holds the judgment context but has no path to rule on the extension. Measured in the sprint `b-first-run` retro (`.shell-team/retros/2026-09-07-b-first-run.md`, Problem 3 / Try 2): the STOP fired twice and the operator had to type "extend" twice by hand, even though the question was a budget question the authoring session could have answered.
> ## Proposal
> Add one optional field to the loop contract's `budget:` block (`templates/loop-contract-template.yaml`, `templates/shell-team.contract.yaml`, `templates/goal.contract.yaml`), for example:
> ```yaml
> budget:
>   max_iterations: 3
>   extension_ratifier: operator   # default; or: authoring-session
> ```
> - Default `operator` preserves the shipped behaviour byte-for-byte: no field, or `operator`, means the STOP escalates to the user exactly as today.
> - `authoring-session` is read only when `STOP:max_iterations_reached` fires and only for a task whose board entry carries `- entry-mode: operator-authored`; the run skill then addresses the extension request to the declared authoring session instead of the operator, and records on the board who granted the extension and by how much.
> - Any other value → `STOP:guard_error` (fail closed, same shape as the existing per-field validation in `loop-guard.sh`).
> ## Acceptance sketch
> - Unset field: `tests/loop-guard/run.sh` fixture output unchanged (byte diff against base).
> - `extension_ratifier: authoring-session` on a `pm-authored` task → guard_error or ignored with a stderr note (decide at spec time; must not silently widen who may extend).
> - Run skill text names the ratifier from the contract in the STOP escalation, per the 2026-08-13 lesson (declare whose authority a disposition belongs to).

Two spec-time decisions the sketch defers are settled below and stated in the
frozen region: the acceptance sketch's second bullet is answered as **ignored with
the fallback and its reason stated in the escalation message** rather than
`guard_error` — a valid vocabulary word applied to a task it does not match is a
condition the run skill evaluates, not a corrupt contract — and the guard's
*vocabulary validation* runs on **every** invocation rather than only when the STOP
fires, so a typo'd value fails closed instead of sitting latent until the cap is hit.

A **single optional field**, `extension_ratifier`, is added to the `budget:` block of
the three shipped loop-contract templates, declaring who may rule on an extension
when `bin/loop-guard.sh` emits `STOP:max_iterations_reached`. Its vocabulary is
closed to exactly two words, `operator` and `authoring-session`. Duties are split:

**`bin/loop-guard.sh` validates the vocabulary and nothing else.** Absent, empty,
`operator` and `authoring-session` are accepted; any other value fails closed to
`STOP:guard_error` on exit 2, in the same shape as the existing `budget.max_usd`
guard, and that validation is evaluated **before** the four enforcement blocks so a
corrupt value yields `guard_error` rather than `max_iterations_reached`. The guard
gains no new flag, takes no board argument, reads no board, and reaches no new
decision: with the field absent or set to either accepted word, every decision it
prints and every exit code it returns is exactly what the base ref's guard prints
and returns for the same input. The field's extraction inherits
`contract_value()`'s shipped normalization unchanged — section scoping, inline
`#`-comment stripping, trailing-whitespace stripping, first-occurrence-wins — and
an **empty value is treated as absent**, because the shipped extractor cannot
distinguish the two and changing it would move the four existing budget reads.

**The run and goal skills apply the board condition.** Their STOP escalation
bullets name the ratifier read from the contract, state that `authoring-session`
takes effect only for a task whose board entry carries `- entry-mode:
operator-authored`, and state that on a `pm-authored` task — or one carrying no
`- entry-mode:` at all — the loop **falls back to the operator with the reason
stated** in the escalation message, never silently. They declare that a
contract-declared ratifier is an **operator-ratified** disposition rather than AI
self-discipline, and they name the board sub-bullet that records a granted
extension, `- extension-granted`.

**Both adopter-facing oversight documents gain a section**, `## Who may grant a
loop extension` and its Japanese mirror, explaining the field, its default, its
condition and its fallback.

Nothing here delivers a request anywhere: what changes is who the escalation
message names, what it says when the declaration does not apply, and what the
board records afterwards. The loop's fixed layer is untouched — both gates still
required, merge still a human action.

## Non-goals

- **No second field, and no widening of the vocabulary.** The scope is **one optional field** with exactly two accepted words. No `extension_ratifier_contact`, no free-form session identifier, no per-STOP-reason variant, no list value.
- **No transport, no delivery, and no authentication.** Nothing is sent to an authoring session, no channel is opened, no identity is verified, and no session is addressed programmatically. The field is a declaration in a file the adopter controls, not an authorization mechanism.
- **`authoring-session` is never reachable by default.** The three shipped templates ship `operator`; a scaffolded repository and every existing adopter contract reach only the absent or `operator` state without a human editing the file.
- **No new STOP reason, no new exit code, no new flag, and no board argument to the guard.** The outcomes stay `CONTINUE` (0), `STOP:` on one of the four existing reasons (3), and `STOP:guard_error` (2); the guard's input surface stays one contract path plus the five existing flags.
- **No change to `contract_value()`'s extraction semantics**, and therefore no attempt to distinguish an empty value from an absent key. Changing the extractor would move the four existing budget reads that **AC1** locks.
- **No change to `bin/check-contract.sh`.** An extra `budget:` key is already accepted; making the new field a *required* key would break every existing adopter contract.
- **No new checked-in fixtures** under `tests/loop-guard/fixtures/` — they would defeat **AC1**'s byte-identity arm. New suite arms build scratch contracts under the suite's existing `$TMP` root, the pattern the T-1021 arms already use.
- **No new checker, no new `bin/` script, no new test suite, and no CI change.** In particular the new `- extension-granted` board sub-bullet gets no machine gate in this task.
- **No edit to `.shell-team/loops/shell-team.contract.yaml`.** Issue #458 names the three shipped templates and this task's diff stays inside them; the ground for leaving this repository's own live contract alone is recorded in the mutable `## Symmetry table`.
- **Scope is `STOP:max_iterations_reached` only.** `budget_exhausted`, `no_progress` and `guard_error` escalate exactly as they do today; the field is not consulted for them.
- **No version bump and no CHANGELOG entry** — the sprint's release step owns those — and **no release-tier re-derivation in this spec**.

## Input space

**Reachable input classes** — what real adopter usage, the shipped templates and this repository's own fixtures produce, all of which the implementation must handle correctly:

1. A contract with **no** `extension_ratifier` key at all — every contract in existence today, including every adopter's already-scaffolded one and all five checked-in guard fixtures. The decision must be identical to the base ref's in every case.
2. `extension_ratifier: operator` — what the three shipped templates ship, in the trailing inline-comment spelling.
3. `extension_ratifier: authoring-session` — the opt-in state, reachable only by a human editing the file.
4. An accepted value carrying surrounding whitespace and/or a trailing `#` comment. The shipped extractor normalizes both, and class 2's own spelling is an instance of it.
5. The key present with an **empty** value. The shipped extractor yields the same empty string here as for an absent key, so this spec fixes the two as equivalent.
6. Two or more `extension_ratifier` records inside one `budget:` block. The shipped extractor's first-occurrence-wins rule decides; a valid first record is accepted whatever follows it.
7. The key spelled at column 0, inside another section such as `stop:`, or after the `budget:` section has been closed by a column-0 non-comment line — not read at all, so the field is absent. A column-0 **comment** does not close the section, which is the shape `tests/loop-guard/fixtures/guard-contract.yaml`:16 already exercises for the four existing keys.
8. A hand-edited wrong value: a case variant (`Operator`), an underscore variant (`authoring_session`), a prefix or suffix of an accepted word, a boolean or numeric literal, a two-word value, and a quoted `"operator"`. All fail closed.
9. All three of the board states the skills' condition distinguishes: an entry carrying `- entry-mode: operator-authored`, one carrying `- entry-mode: pm-authored`, and one carrying no `- entry-mode:` sub-bullet at all (every entry predating T-1096). The last two take the stated fallback.
10. Readers of the two `docs/tuning-oversight` sections: a GitHub markdown renderer and a plain-text reader.

**Out-of-scope synthetic extremes** — declined explicitly, so a finding escalating one of these is answerable rather than open-ended:

- **YAML shapes the shipped line-oriented extractor has never supported for the four existing budget keys**: a flow mapping (`budget: {extension_ratifier: operator}`), anchors and aliases, merge keys, multi-line block scalars, tab-indented keys, and a quoted value. The new field inherits exactly the support the existing four have and no more; a quoted `"operator"` is therefore a rejected value rather than a defect.
- **Adversarial encodings of the value**: zero-width or homoglyph substitutes for either accepted word, CRLF line endings, a non-UTF-8 re-encoded contract, an embedded NUL, and an arbitrarily long value. The vocabulary match is an exact byte comparison against two ASCII words; anything else is rejected, which is the safe direction.
- **Scale**: ever-larger contract files, ever-deeper indentation, thousands of duplicate `extension_ratifier` records, and a contract with thousands of sections.
- **Every environment-injection and configuration-scope channel** — `GIT_CONFIG_*`, `XDG_CONFIG_HOME`, a shadowing shell function or hostile `PATH`. The guard runs no git and this field launches no process, so none of them has a target in this diff.
- **Authentication and impersonation.** Whether the party that answers an extension request is genuinely the declared authoring session, whether an authoring session may be spoofed, and whether a hostile contract could redirect a grant. The field is a declaration in a file the adopter already fully controls; anyone who can edit it can already edit `max_iterations` itself.
- **Concurrency.** Two sessions answering the same STOP firing simultaneously, or a grant arriving after the run has already stopped.
- **Terminal rendering and localization of the escalation message**: width, wrapping, ANSI handling. `bin/` output stays English; only the two oversight documents carry a Japanese mirror.
- **A repository where the branch point is unreachable** (a shallow or `--single-branch` clone). **AC1** and **AC4** read the branch point and would fail there; that is a checkout defect to fix by fetching, not an input class this spec protects.
