# The shipped `<base>/.gitignore` template ignores the raw review captures `codex-capture.sh --publish` writes, so an adopter who tracks the base dir stops committing them

**Scope class**: operator-inserted **minimal stop-the-bleed** item. Only what closes the leak and the shipped text the change makes false is in scope; everything else is a filed issue.

## Problem

`bin/codex-capture.sh --publish` moves the raw Codex output into the resolved reviews dir as `<stem>.txt` and `<stem>.jsonl`. The template `bin/team-init.sh` installs as `<base>/.gitignore` ignores only `runs/` and the pre-publish temps `reviews/.codex-capture.*`, so in an adopter repository that tracks its base dir — a choice `README.md` explicitly supports — every published raw capture shows up as an untracked file and is committed by an ordinary `git add`. Raw captures can carry personal information, which is exactly why the pre-publish temps are already ignored. This repository never showed the leak because its own root `.gitignore` carries the three raw patterns, and that file's comment says the shipped template "deliberately leaves" them to the host repo — the one shipped layer adopters actually receive does not carry them.
