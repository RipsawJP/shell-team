## Problem

The cross-provider review gate is the only judge in this loop that comes from another model family, and nothing durable records which Codex CLI produced any given verdict. This repository repeatedly compares one verdict against another — verdict-hash no-progress detection, same-class round thresholds, intervention records, a re-run offered as a reproduction — and every one of those comparisons silently assumes the judge held still. `codex --version` is executed today only as a health check whose output is thrown away, so if the CLI or its default model moves under the loop, the meaning of a recorded `APPROVE` moves with it and nobody can see that it did.

The defect is narrower than "there is no place to record it": the review record's per-round verdict block **is** that place, and recent records already carry a version there. It is carried **optionally**, so the corpus is inconsistent — several rounds record a bare model name with no version at all, the version's spelling varies between records, and two records put it in body prose instead of the verdict block. An optional field is not a provenance record.

## Goal

<!-- BEGIN intent-block: T-1045 -->

Every Codex-produced verdict block records the CLI that produced it. `agents/codex-reviewer.md`'s `## Output` template carries a **mandatory** `- Codex CLI:` line immediately after its existing `- Codex model:` line, its Preconditions turn `codex --version` from a discarded health check into a transcribed provenance value, and its verbatim-English key list names the new key so no language mirror can translate it. `agents/drift-evaluator.md` — the other surface that runs `codex --version` and names a Codex model in a durable report — carries the same line and the same precondition sentence, byte-identical to codex-reviewer's by construction. `docs/workflow.md` and `docs/workflow.ja.md` stop describing the version check as something the reviewer runs "implicitly", in step with each other. Because one verdict block exists per round, per-round recording follows from the template rather than from anyone remembering, and this task's own review record demonstrates it. Nothing is pinned: no minimum version, no version comparison, no gate on the value. No file under `bin/` changes, `.shell-team/provenance/`'s schema and shape are untouched, no existing review record is retro-fitted, and `templates/`, `skills/`, `tests/`, `.github/` and every other agent are byte-identical to the base ref.

**DP-E — The drift-evaluator surface is mirrored now, not deferred.** The case for deferral is real and is recorded rather than dismissed: that role's verdict is advisory, flag-free, feeds no verdict-hash comparison and gates no board flag, so the specific harm #169 names (a re-run that is no longer a reproduction) is weaker there. It is mirrored anyway, for three reasons. Its report is a **durable file** (`<reviews>/<task-id>-drift.md`) written to be read later by a human deciding whether a diff still means what a frozen intent said — a judgment whose value depends on knowing which judge made it just as much as a merge verdict's does. It already carries **both** halves this task changes (a `codex --version` precondition and a `- Codex model:` field), so it is the same defect and not an analogous one. And the mirror costs one template line plus one appended sentence, both taken byte-for-byte from the same frozen blocks — against which a deferral would ship a known asymmetry across two parallel gate surfaces for the next reader to rediscover, which is precisely what the parallel-surface symmetry norm exists to prevent. One asymmetry is kept and is intentional: the frozen `CXL` line's failure clause is **inert** in the drift-evaluator, whose Rules (L146) say a failed `codex --version` means no advisory report is written at all, so there is no block for the clause to govern. Byte-identity across the pair is worth more than trimming a clause that can never fire there, and the inertness is stated here rather than left for a reviewer to find.

**DP-F — No backfill. Forward-only.** The 40-plus existing review records are not retro-fitted. The actually-executed CLI version for a past round is unmeasurable now, and a fabricated or inferred value in a provenance field is worse than an absent one — it would make the corpus look uniformly trustworthy at exactly the points where it is not. The version-less rounds named in `## Summarized sources` stay version-less, and a criterion measures that nothing under the reviews directory except this task's own record moved.

**DP-G — Nothing is pinned, and no `bin/` change ships.** No minimum version, no allowed-version list, no comparison of one round's value against another's, no gate on the value, and no new or extended checker. #169 excludes pinning explicitly, and a comparator would need a version-ordering rule this task has no grounds to write. The only machine assertions this task ships are over its own artefacts: the two templates, the two docs, and this task's own review record.

**DP-H — Task classification, stated so review rigour is calibrated rather than guessed: this is a pure addition following an existing pattern.** It adds one field beside an existing field, names it in the same key list a previous field was named in, and corrects a documentation pair. It writes no parser, no validator and no state tracker, and it changes no executable line anywhere. The lower review standard for that class applies — with one exception held at the higher standard: the criterion over this task's own review record (AC5) is a **new lock**, and it is self-hosting in a way that invites a false positive, since a review record discussing this very diff will quote the new key in its prose. AC5's own text and Input space say how that is handled, and AC10(b) requires it to be mutation-probed.

**DP-I — Pre-commitments, set before the first round.** **P1 (factual trigger)**: two consecutive rework rounds of independent new `Blocker`/`Major` findings against any one of the three subsystems (the codex-reviewer edits, the drift-evaluator mirror, the docs pair plus AC5's self-hosting lock); **(contextual trigger)**: a third round is about to start; **the factual trigger governs when they disagree**. A finding raised and fixed in an earlier round does not count toward it. **P2 — the split order is decided now**, droppable first: ① the drift-evaluator mirror (DP-E's deferral case is already written, so dropping it costs a one-line revert and a reason, not a redesign); ② the docs pair correction. **Never dropped**: the codex-reviewer template line, its precondition sentence, and its key-list entry — those three are the task. Dropping ① forfeits the symmetry claim and the hand-off must then say **codex-reviewer only, drift-evaluator deferred**, in those words. **P3 — verify, then correct, then freeze**: every `check:` line is run live and in full by the executing side before the hash is recorded, and anything mechanically broken or vacuously passing is repaired with a meaning-preserving fix first. **P4 — every new check ships with a mutation self-check or a positive control**; AC10(b) enumerates the probes, and AC5's self-hosting false-positive shape is one of them.

**DP-J — Re-litigating a settled decision is a re-freeze proposal, not an engineer fix.** An argument that the line belongs in `.shell-team/provenance/` after all (DP-A), that the version should be pinned or compared (DP-G), that `- Codex model:` should be constrained (DP-C), that the drift-evaluator should be deferred (DP-E), or that old records should be backfilled (DP-F) routes to pm-spec. So does any edit to `templates/prompt-blocks/`, to `bin/`, to another task's spec, or to `.shell-team/lessons.md`.

## Non-goals

- **Pinning the Codex CLI version, requiring a minimum version, or comparing one round's recorded version against another's.** #169 excludes it explicitly and names it a separate decision (DP-G).
- **Any `bin/` change** — no new checker, no extended checker, no script that greps the new key. Every `bin/` file is byte-identical to the base ref.
- **Any change to `.shell-team/provenance/`'s schema, shape, or checker**, and no `Codex CLI` line in any provenance file (DP-A).
- **Backfilling the existing review records** (DP-F). No file under the reviews directory other than this task's own moves.
- **Verifying that the recorded values are true.** The CLI's self-reported version and the model identifier it names are **trusted**: no channel exists to confirm either independently, and inventing one is not this task's scope. This is the same trust posture `- Codex model:` has always had.
- **Any change to `templates/prompt-blocks/` or `registry.txt`** (DP-B). The registry-owned Language bullet is not edited.
- **Any change to verdict-hash, no-progress, same-class or loop-guard logic**, and no feeding of the new value into any signature.
- **Recording provenance for the Claude-family roles** (engineer, qa-verifier, tech-lead, pm-spec). The same argument arguably applies to them; #169 does not ask, and extending it would need its own spec.
- **Any entry in `.shell-team/lessons.md`**, any other `.ja.md`, any CHANGELOG entry and any version bump. The sprint's release step owns the last two.
- **Goal-external discoveries.** Anything surfaced here that is not #169 is filed as an issue for the next planning input and not acted on.

## Input space

**Reachable input classes** — what this task's artefacts really read and must handle correctly:

- **The stdout of `codex --version` on an operator's machine**: a single short line naming the CLI and a semantic version, which is the shape every existing record's parenthetical implies (`codex-cli 0.145.0`); the same with a pre-release or build suffix; and a **multi-line** variant, which the frozen `CXL` line handles explicitly by requiring the lines be joined with a semicolon and a space rather than left to break the block's one-line `- key: value` shape.
- **A failed `codex --version`** — not installed, not on `PATH`, a non-zero exit, an auth-layer error printed to stderr. In the codex-reviewer this is reachable and its disposition is fixed: the line carries the word `unavailable` followed by the exact error, never a version value, and the round is `BLOCKED` per the role's existing Rules. In the drift-evaluator the same failure means **no report is written at all** (its L146), so the clause is inert there — recorded in DP-E rather than trimmed.
- **A review with one round, and a review with many rounds.** One verdict block exists per round in one record file, so AC5's per-header form scales without a declared count; `.shell-team/reviews/T-1044.md`'s three blocks and this task's own record are both in class.
- **A record that quotes the new key in prose or in a fenced excerpt** — including this task's own review record, which will discuss the diff that introduces the key. AC5 must stay green on such a record; this is the self-referential dogfooding shape, and it is why AC5 looks forward from each verdict header rather than counting occurrences.
- **A verdict block whose prose is written in a language other than English** while the keys stay English (`.shell-team/reviews/T-1025.md:174` is the existing instance). The key list bullet in each agent file is what keeps the new key out of the translated set.
- **A `- Codex model:` value carrying a free-form tail** — a config source, a reasoning-effort setting, a parenthetical version, backticks around any of it. Roughly twenty-five existing records do this, DP-C keeps it legal, and no criterion constrains it.
- **The two documentation halves read by a human, one per language**, each inside a fenced quick-reference block whose first line is a shell comment.
- **`.shell-team/reviews/T-1045.md` absent** — the state at freeze time and at QA's first pass. AC5 must report FAIL, never a vacuous pass.
- **Both edited agent files under the machinery that governs them**: `bin/check-prompt-sync.sh`'s `contain` obligations for codex-reviewer (and their absence for drift-evaluator), and `tests/codex-skeleton-hygiene/run.sh`'s skeleton-block assertions over both.

**Out-of-scope synthetic extremes** — inputs this spec explicitly declines to protect:

- **A hostile or lying `codex` binary**: a shimmed `PATH` entry, a `--version` that reports a version other than the one that reviews, a CLI whose output embeds a `### Codex Review verdict:` line or a NUL byte to forge structure, or a version that changes between the `--version` call and the review call in the same round. The Codex CLI is a tool the operator installed and this role already executes; recording what it reports is the whole scope, and **verifying** what it reports has no channel (Non-goals). Same trust posture as `- Codex model:`.
- **A `codex --version` output of unbounded length** — kilobytes of banner text, an arbitrarily deep multi-line dump. The joined form stays one line by construction; no criterion measures its length, and an ever-longer synthetic value is not a defect here.
- **A review record with hundreds of verdict blocks**, or one assembled by a tool other than the codex-reviewer.
- **Historical review records** (DP-F). Their version-less rounds stay version-less; no criterion reads them except to assert they did not move.
- **Any comparison between two recorded values** — ordering two versions, deciding whether a change was material, gating on either (DP-G). A finding whose only trigger is that the field is recorded but never compared is out of scope by construction: that is the issue's own boundary.
- **Provenance for the Claude-family roles**, and provenance for any provider other than Codex.
- **A `- Codex CLI:` line appearing in some *other* file's per-round structure** that this task did not create — a future skill, a future agent, an adopter's own template. The registry governs only the consumers listed in it, and nothing here widens that.
- **Adopter repositories' own review corpora.** The three criteria that read records (AC5, AC6, AC7) read this checkout's, and this task ships no checker that would run anywhere else.
