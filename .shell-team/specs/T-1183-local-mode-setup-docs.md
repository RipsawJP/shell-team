**Goal (one sentence).** In a clone that declares `shell-team.mode local`, `bin/team-setup.sh` reports an ignored base dir under `Already in place:`, prints for a base dir that is not ignored one `Required:` item carrying the `info/exclude` line, leaves a base dir already committed in HEAD to the operator, and never prints `git add` or a removal command or edits any ignore file, while in every other case its output is byte-identical with the base commit's; `bin/team-init.sh`'s closing summary adds lines naming `tracked`, `local` and `git config shell-team.mode local`; and a new CI-wired suite drives the whole mechanical `local` path in a fixture repository, ending with `git log --all -- <base>` empty and the code commit present.

**Definition.** A directory is **ignored** when `git check-ignore` reports the directory path itself, or one of its parent directories, as ignored by a rule that is not a `!` re-include, from any source (the clone's `info/exclude`, a `.gitignore`, the global excludes file). A rule that hides only some files under the directory (for example a `<base>/*.md` pattern) does not make the directory ignored.

**Decisions frozen here** (each is promoted to a criterion):

- **D1 — setup branches on the mode.** `bin/team-setup.sh` reads the mode once, before any write and in every mode, through its sibling `team-mode.sh` run in the repository root. If that read fails (exit 2, or the sibling is missing), setup prints a diagnostic on stderr, writes nothing at all (not even the scaffold) and exits `2`. When the mode is `tracked` (no key, `tracked`, or any value other than the exact `local`), the stdout, stderr and exit status are byte-identical with the base commit's script on the same input. When the mode is `local`, setup handles the base dir and, in the legacy layout, an outside specs dir, one directory at a time:
  - (a) Its anchor (the board; the specs dir's `.gitkeep`) is in HEAD. One item under `Remains the operator's decision:` says that the directory is tracked, that ignore rules do not apply to tracked files, and that whether to keep tracking it is the operator's decision. No `info/exclude` line is printed for that directory. This case takes precedence over (b) and (c).
  - (b) It is ignored. One item under `Already in place:` names the directory.
  - (c) Otherwise, one `Required:` item names the line to append to the clone's exclude file for the directory, written `` `/<dir>/` `` (for example `` `/.shell-team/` ``). ## Acceptance criteria

Every `check:` runs from the repository root under `bash`, reads the post-implementation tree, and writes only under `$TMPDIR`.

- **Timeouts.** Each line that runs a script goes through a `tmo` helper (120 s) or a `tms` helper (1200 s, for whole suites). The helper starts the script in its own process group under `ulimit -f`, kills the group on timeout, and captures output into files capped by that limit.
- **Environment.** Those lines export a temp `HOME`, `XDG_CONFIG_HOME` and `CODEX_HOME`, `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_NOSYSTEM=1`, and put stub `claude` and `codex` executables first on `PATH`.
- **Forbidden content.** No check line uses `ps`, a recursive deletion or `xargs`, and none expects a removal command. A suite or checker is scanned for a recursive-deletion pattern before it runs, and is not run if one matches.
- **Fixtures.** Fixture commits use `user.email=t`.
- **Base-side reads.** They use the chain in the `base-ref-discriminator` declaration, spelled byte-identically. Base scripts that need their siblings run from a `git archive` extraction of `B` under `$TMPDIR`.
- **Normalization.** Some values are spliced into a script's output: the fixture root, the plugin root and the temp root. They are replaced by `<F>`, `<P>` and `<T>` before two scripts' outputs are compared.
- **Staleness.** The criteria that read `B` are **merge-point-scoped and expected to go stale** once this task's changes reach `develop`.
