## Input space

**Reachable input classes** — what this task's criteria really read and must handle correctly:

- **This repository's own tracked markdown, at the base ref and at `HEAD`**: one skill file (UTF-8, LF, very long single-line numbered steps carrying backticks, em-dashes, `$( )` and both quote kinds), one agent prompt (hand-written bullet prose plus `<!-- BEGIN/END prompt-block: … -->` marker regions), this spec (frozen-block HTML comments, `- [ ] **ACn**` bullets, `- check:` sub-bullets), and the board (top-level `- [` entry lines with two-space-indented sub-bullets, several thousand lines, sub-bullet labels that collide across entries).

An unresolvable `develop`, an empty blob, an empty diff and a `git grep` that matches nothing are each reachable and each must fail closed rather than read as a clean result.
- **Frozen-block content carrying characters that are regex-significant**: em-dash (U+2014), backticks, `$`, `*`, `[`, `(`, `\`, and straight double quotes. Every criterion consumes these as fixed strings fed from a file (`grep -F -f`, `git grep -F -f`) and never interpolates them into a pattern.
- **A frozen block whose extraction yields zero lines or more than one** — reachable from a mistyped marker name or a hand edit — and asserted as a failure by every criterion that extracts one.
- **A spec corpus that grows between authoring and check time**: AC9 re-derives its population live, so a spec added or removed under `.shell-team/specs/` is a reachable input that reddens the criterion rather than silently narrowing it.
- **A file with zero prompt-block markers** (`skills/run/SKILL.md`) alongside one with several (`agents/pm-spec.md`): AC4 asserts the expected count per file rather than a shared floor, because a floor of one would be false for the first and a floor of zero vacuous for the second.
- **The task's own spec and records passing from untracked to tracked** between the freeze run and the QA run: AC6's allow-list is written so both states satisfy it, and the criteria are read against the post-implementation tree state per the very discipline this task ships.

**Out-of-scope synthetic extremes** — inputs this spec explicitly declines to protect against:

- **A tracked filename containing a newline, tab, or a byte `core.quotePath` would C-style-quote.** This corpus is hand-curated and commits none; the line-oriented reads of `git ls-files`, `git ls-tree` and `git grep -l` here are accepted as sufficient, exactly as the merged specs this one follows accepted them.
- **A NUL byte or invalid UTF-8 inside a tracked markdown file.** Committing one independently breaks that file as the markdown every existing gate already parses; it is a design decision needing a spec, not an input class to accommodate.
- **An adversarially planted marker** — a nested, duplicated or forged `<!-- frozen-begin: … -->` pair, or a `<!-- BEGIN intent-block: … -->` inside a fenced block — designed to defeat the `awk` extraction. Every extraction asserts an exact line count, which fails closed on it; no criterion is widened to detect a deliberate forgery.
- **A hostile `$TMPDIR`**: an attacker-controlled temp directory, a symlink race against `mktemp -d`, or a permission flip between creation and first write.
- **A concurrent writer mutating the working tree during a criterion run.** That is a run-discipline matter for the executing side, not an input class these criteria accommodate.

- **An agent prompt or skill file written in a language other than English**, or one whose headings are spelled differently. `CLAUDE.md`'s Language section fixes agent-facing files to English with no translated counterpart; a criterion is not widened to survive a hypothetical translation.
