# The duplicated `## Done` merged, its class closed inside the board-heading checker, and that checker CI-wired against this repository's own board

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1099

## Problem

This repository's live board carries **two** top-level `## Done` headings — measured first-hand at authoring time, before this task's own board entry was appended: `grep -n '^## ' .shell-team/todo.md` printed `7:## Status flags`, `12:## Active`, `2224:## Done`, `4418:## Done`, `5941:## Format`. Every line number in this spec's mutable prose is from that same reading and is **expected to drift**, because the board is append-only and this task's own entry landed above most of them; read them at the pinned base instead, with `git show "$B:.shell-team/todo.md" | grep -n '^## '` where `$B` is the discriminator declared in `## Goal`. The *count* — two — is what the criteria assert, and it is asserted against that committed blob rather than against any number typed here. Newer closed entries sit under the first and older ones under the second, so a reader and every human-facing convention ("newest at the top of Done") are answered by two different sections. Neither board checker can see it: `bin/check-handoff.sh` lints only `## Active` by its own declared contract, and `bin/check-board-headings.sh` diffs `T-NNN` heading **ids** against a base ref, so once both diff sides carry the duplicate it stays silent forever — which is exactly what happened. The second gap is that neither checker runs against *this* repository's own board in CI for the heading-identity half, so a defect of this class has no automated moment of detection at all.

**Goal (one sentence).** The live board's stray second `## Done` heading is deleted by a provably pure edit that moves no entry byte; `bin/check-board-headings.sh` gains a **base-independent, fail-closed** assertion that the board's structural top-level headings each occur the right number of times, proven non-vacuous against the heading-lookalike corpus its own suite already carries; and that checker runs against this repository's own board in CI, so the `#301` class has a moment of detection from now on.

**Where the class-check lands, and why there (decision (a)).** It is a new assertion **inside `bin/check-board-headings.sh`**, beside the duplicate-id check it already owns, not a new script and not an extension of `check-handoff.sh`. Three grounds, each measured: (i) the only fence-aware, ATX-aware CommonMark section parser in `bin/` is that file's own state machine, and a shared `bin/lib/` is explicitly foreclosed — so a new script *necessarily* means a **second parser**, which is the parser/consumer drift the checker's own header warns about and the class that drew a Blocker plus two Majors on the first cut of the same parser; (ii) the adversarial corpus this assertion needs already lives in that file's suite as fixtures, so the assertion is born with its lookalike coverage instead of acquiring it over review rounds; (iii) `check-handoff.sh` is ruled out twice over — by its own declared `## Done` non-scope and by DP-A, since `close-out.sh` gates a git-untracked temp board through it and a base-ref-comparing checker cannot serve that call site. The alternative considered and rejected is a new `bin/check-board-structure.sh`: it would satisfy arm A's structural form just as directly, but only by paying the second-parser cost that ground (i) names.

**How strict, and for which headings (decision (b)).** The assertion's subject is **level-2 (`##`) headings only**, and it splits: `## Active` and `## Done` must occur **exactly once** each; every other level-2 heading must occur **at most once**. The presence half is grounded, not stylistic — a board missing `## Active` makes `check-handoff.sh` pass **vacuously**, and `close-out.sh` already fail-closes on a board with no `## Done`, so the checker is asserting a precondition its two sibling consumers already depend on. The at-most-once half deliberately carries **no presence requirement**, so an adopter's own extra sections (`## Reserved`, `## Planned`, anything) are permitted and an adopter's layout is not coerced. Level 1 and level 3 are out of scope with a measured reason: no consumer keys on `# Tasks`, and this repository's own board legitimately carries 37 identical `### Local test result` headings inside entries, so an at-most-once rule at level 3 would be false on the very board it guards. Two identity rules complete the definition. For `Active` and `Done` the occurrence count is measured by the **same section-opening predicate the checker's existing parser uses**, so the count is of headings the consumers can actually see — a lookalike that satisfies a looser normalization while `check-handoff.sh`/`close-out.sh` cannot find it must never satisfy the presence half. For every other heading, identity is the line's text with the leading `##` removed, an optional ATX closing hash run **preceded by at least one space** removed, and the remainder's surrounding whitespace trimmed, with internal whitespace preserved literally — so `## Format ##` is `Format`, while `## Active Backlog` and `## Active###` stay distinct headings from `Active`. Heading-shaped lines inside a code fence and indented heading-shaped lines are not headings, by the parser this assertion reuses.

**Fixture-flip adjudication (decision (c)).** If any pre-existing case in `tests/check-board-headings/run.sh` changes its expected exit status, that flip is **adjudicated here as a decision** — a class-B re-freeze naming which fixture, which direction and why the new judgment is the right one. It is never resolved by editing a fixture to keep the suite green. Measured prediction, so the adjudication has a baseline: no flip is expected, because every existing head fixture's second `## Active` line sits inside a fence and every ATX/over-match lookalike is a distinct heading under the identity rule above.

**The pure edit (decision (d)).** The board change is a **deletion of two lines and nothing else**: the stray `## Done` heading and one adjacent blank line. Zero insertions, zero entry lines moved, zero entry bytes changed, no reordering — the seam is already newest-above-oldest, measured. It lands as its own commit so the board diff stays auditable, and the engineer re-measures the stray heading's line number at its own HEAD before editing rather than trusting any number written here.

**Arm A, and the trigger this promotion fires (decision (e)).** Under `tamper-arm-rule-v1` this obligation takes **arm A**, both conjuncts argued: its verdict will **gate a loop transition** — the CI step's exit status gates the pull request, and a board whose structural headings are broken is a board every later phase gate reads — and its judgment is **mechanically executable from committed bytes**, being a count of heading lines in one file. Arm A's structural form is satisfied by an existing script: a named `bin/` script, its own `tests/check-board-headings/run.sh` suite, and its own step in the workflow. This is the **third** obligation promoted into arm A, after #341 and #344, which is precisely the condition `record-tamper-resistance.md`'s own re-evaluation trigger names — so the trigger has **fired**, and this task records that firing where the next retro will find it: a line in that note and a sub-bullet on this task's board entry. The trigger counts obligations, not scripts; reusing an existing arm-A script makes the promotion cheap, not absent.

**Adopter-claim hygiene (decision (f)).** The **script** ships; the **CI step does not**. No prompt block, corpus entry, `README*`, `docs/adopting*`, `docs/workflow*`, `skills/*`, `agents/*` or template may claim CI runs board linting **for adopters** — that claim is exactly what T-1009 removed.
