## Problem

That is GitHub issue #167.

The second — **ship the question rather than an answer, as frozen documentation** — died at round 3, when the prescribed self-check was shown to report an all-clear in exactly the state #167 reports.

v4's `## Same-class-2 pre-commitment` named a **terminal** fallback for the documentation surface in advance, and cross-provider round 3 fired it. ## What this achieved and what it cost

Stated plainly, without euphemism, because a future planning cycle reading the board needs to see it in one pass.

**What it cost.** Before v5, this task consumed **four freezes** (v1–v4), **three cross-provider rounds**, **four QA rounds** (the board labels them 1, 2, 5 and 6) and **two full implementations** of a mechanism plus one of a documentation deliverable. Every file the plugin ships is exactly what it was at `d825293`.

**What it achieved.** One thing, and it is worth writing down precisely because it is not nothing: a grounded, reproduced account of **why two independent designs for asking git this question failed**, in a form the next attempt can start from instead of an empty page. Six defeat vectors, each live-reproduced by at least two parties:

**Against the mechanism — "ask git inside the plugin" (four vectors):**

1. **Injection by a named environment variable.** `GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_<n>`/`GIT_CONFIG_VALUE_<n>` inject a `core.excludesFile` into the probe's own git call and flip the verdict; the frozen twelve-name `env -u` blacklist did not list them. Round 1, finding 3, Major, `Acquisition layer: YES` — it fired the acquisition layer's one-round budget on the first cross-provider round the task ever had.
2. **Injection by an unnamed sibling of the enumerated list.** `GIT_CONFIG_PARAMETERS` (coordinating session), then `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM`, `GIT_DIR`+`GIT_WORK_TREE` redirection and `XDG_CONFIG_HOME` (QA) — the last **not a `GIT_*` name at all**, so no enumeration scoped to `GIT_*` could have closed it at any length. This vector is why v2 replaced the blacklist with an `env -i` allow-list rather than growing the list.
3. **Shell-function shadowing of the sanitizer itself.** An exported bash function named `env` — or, identically, `git` — intercepts the sanitizing call before `PATH` is ever consulted, so the allow-list never executes and the verdict flips through any variable the caller likes. Round 2 addendum, Finding A, **Blocker** (the only one in this task's history), at the same environment-variable-only privilege tier as vector 1.
4. **A file-based configuration scope the sanitizer cannot reach.** `env -i` clears the process environment but not git's system-scope configuration (`$(prefix)/etc/gitconfig`, read live under the exact allow-list on the machine it was measured on); a `core.excludesFile` there flips the verdict independently of all four allow-listed names. Round 2 addendum, Finding B, Major — downgraded from a normalized blocker in the review's own synthesis ledger, for a reason recorded there (it needs filesystem write access, a narrower privilege than vectors 1–3).

**Against the documentation — "ship the question, not the answer" (two vectors):**

5. **A notice promised for a state the implementation silences.** The v1 adoption paragraph told the adopter that `team-init` reports when git cannot give a documented answer (a corrupt or unreachable repository); the frozen table routed exactly that state to silence. Round 1, finding 2, Major. This is why the replacement blocks were frozen bytes rather than left to wording — and the class still recurred.
6. **A directory-form query blind to name- and extension-scoped ignore rules.** `DOC2`/`DOC2JA` told the adopter that "prints nothing" means the base dir is not ignored and there is nothing to do. With `.shell-team/*.md`, or an ordinary repo-wide `*.md`, that query stays silent while every record the loop writes is genuinely ignored and `git add .shell-team/todo.md` stages zero files — **#167's own failure occurring while the prescribed self-check reports an all-clear**, and every record the loop writes is markdown. Round 3, finding 1, Major.

Recorded so the count is honest rather than flattering: a **third** false claim on the documentation surface — v3's instruction to look for a `!`-prefixed line, an output shape that does not exist for a directory query — was measured false and repaired by the author before a review round, so it never became a defeat vector. Three false claims were written into this surface in total; two reached a review and one did not.

**The conclusion on the record.** The loop could not answer #167 by either available means at this quality bar. **#167 is left open as unanswered**, re-filed with `.shell-team/reviews/T-1042.md` and `.shell-team/reviews/T-1046.md` named as its evidence, so the next planning cycle decides what — if anything — to do about it. **Sprint v1.7.0's goal item for #167 is not met.** #67 is untouched and stays open for its own surfaces.
