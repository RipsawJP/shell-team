## Problem

`bin/resolve-executor.sh:506`–`:513` already refuses an effort value the bound adapter does not declare, so the **static** half of #203 design point 1 ships. The runtime half does not: no invocation path applies a resolved effort to anything, and four shipped adopter documents say so in words that are about to become false — `README.md:214` ("a declared effort is recorded but applied to no call"), `docs/adopting.md:283`–`:286` ("a declared **effort** is recorded on the span but applied to no call … declaring one is not applying it"), and both `.ja` mirrors. Since T-1118 there is exactly one invocation path in this repository whose per-invocation effort mechanism has been *measured* — `tech-lead` under `codex-cli`, whose recipe passes `--ignore-user-config` and therefore drops the operator's own `config.toml`, leaving `-c model_reasoning_effort=<value>` on the command line as the only way an effort value can reach that run at all. An adopter who wrote `effort: high` into a `binding.conf` today holds an inert value; #420 asks that it stop being inert on that one path, that a value the provider rejects fail closed rather than run at some other tier, and that every other path say per adapter that it is still recorded only.
