## Problem

Starting shell-team on the Codex CLI host takes manual runbook steps 3 through 9 per repository (`docs/adopting.md:456`–`:571`) plus step 11 after every upgrade, and the runbook itself says three of them (trust, writable roots, network) are `-c` flags on every `codex` invocation. An operator who forgets one of them gets a symptom far from its cause, such as `Not logged in` from a sandboxed network. Issue #628 asks for two commands that do these steps. The issue text, relayed verbatim by the coordinating session:

> Expected: "An operator on the Codex CLI host runs two commands from their own shell: 1. **Setup, once per repository and after each plugin upgrade** — e.g. `bash "<plugin root>/bin/codex-setup.sh"` from the repository root: runs the generator, adds `.codex/agents` to `.git/info/exclude` when no ignore rule already covers it (never editing a tracked file), runs `check-codex-agents.sh`, checks `command -v claude` and that the CLI answers, and reports each prerequisite it cannot satisfy itself (trust) with the exact remedy. Idempotent; writes nothing outside `.codex/agents` and `.git/info/exclude`. 2. **Launch** — e.g. `bash "<plugin root>/bin/codex-launch.sh"`: exports `<plugin root>/bin` onto `PATH` and execs `codex` with the per-invocation `-c` settings the runbook names (writable root `<repo>/.git`, network access, trust for this repository), passing any further arguments through. It only composes flags for that one invocation and never writes the operator's Codex `config.toml`. The runbook then describes these two commands first, and keeps the manual steps as the fallback."
>
> Notes: "`bin/` stays pure bash, zero-dependency and shellcheck-clean; both scripts run from the host shell, outside any Codex session."
>
> Out of scope: "changing Codex's own discovery, trust or sandbox model; writing the operator's global Codex configuration by default."
>
> Owner scope-addition comment (2026-09-30): "`codex-launch.sh` runs `check-codex-agents.sh` before exec and regenerates on drift, so the everyday operator step is the launch command alone; `codex-setup.sh` remains for first-time setup and for prerequisites it cannot fix itself."

**Goal (one sentence).** An operator on the Codex CLI host sets up a repository with `bash "<plugin root>/bin/codex-setup.sh"` and starts every session with `bash "<plugin root>/bin/codex-launch.sh" [codex args…]`. Setup generates the agents, adds one exclude line when nothing already ignores them, verifies them, and reports the Claude CLI and trust prerequisites with their remedies. Launch refuses before writing anything when it cannot proceed, regenerates drifted agents, and execs `codex` with exactly the runbook's three `-c` grants followed by the operator's own arguments. Neither command writes the operator's Codex configuration, and the runbook presents them first, with the manual steps kept as the fallback.

**Decisions frozen here** (each is promoted to a criterion):

1. `--help` or `-h` as the first argument prints the script's own usage and exits `0` before any repository check. Every other argument to launch passes through to `codex` verbatim, except that one leading `--` is consumed, so `codex-launch.sh -- --help` reaches Codex's own help. Setup takes no other arguments. (**AC1**)
2. The repository is `git rev-parse --show-toplevel`. The trust key and writable root are composed from absolute paths. A path containing `"`, `\` or a control character (newline included) is refused rather than escaped. Spaces and `.` are accepted. (**AC2**)
3. The writable root is the absolute path of git's common directory, which equals `<repo>/.git` in an ordinary repository. In a linked worktree `<repo>/.git` is a regular file, and the index, refs and objects a commit writes live under the common directory, so the runbook's literal `<repo>/.git` would name a file. (**AC2**)
4. Launch refuses, with no write and no `exec`, when it runs outside a git repository, when no ignore rule covers `.codex/agents` (pointing at setup rather than writing an exclude line itself), and when `codex` is not on `PATH`. (**AC3**)
5. Launch runs `check-codex-agents.sh` on `<repo>/.codex/agents`. Exit `1` regenerates the agents and re-checks, and only a clean re-check proceeds. Exit `2` refuses. (**AC4**)
6. Launch composes no `--sandbox` flag. The operator may pass one through. (**AC1**)
7. Launch does not change the working directory and writes nothing except `<repo>/.codex/agents`. Neither script writes anything under `$HOME` or `$CODEX_HOME`. (**AC1**, **AC3**, **AC5**)
8. Setup appends exactly the line `.codex/agents` to the file `git rev-parse --git-path info/exclude` names, only when `git check-ignore` reports the path not ignored and the line is not already there. It exits `0` when every check passes, `1` after completing everything it can when a prerequisite it cannot satisfy is unmet, and non-zero outside a git repository. The trust report is informational: it names the `-c` flag and the `config.toml` form, notes that launch supplies the flag, and never changes the exit status. (**AC5**, **AC6**, **AC7**)
9. "The Claude CLI answers" means `claude -p "reply with the single word ok"` run with stdin from `/dev/null` exits `0` with non-empty stdout. (**AC7**)
