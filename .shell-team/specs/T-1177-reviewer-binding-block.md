# Under a non-Codex `code-reviewer` binding, every reviewer mode and `review-response` stop `BLOCKED` instead of running Codex

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1177

## Problem

An operator who binds `code-reviewer` to a non-Codex provider in `<base>/binding.conf` — for example because repository content must not be sent to OpenAI — still gets a loop that sends it there (issue #700). `bin/resolve-executor.sh` resolves the row (`claude` is an in-process provider, `bin/resolve-executor.sh:226`), `bin/check-invocation-path.sh` admits the role and the orchestrator dispatches `code-reviewer` with the Agent tool, but `agents/code-reviewer.md` never reads the binding: it branches only on `CODEX_THREAD_ID` (`agents/code-reviewer.md:63`) and runs `codex exec` (`:45`, `:73`, `:193`). The board and telemetry then record a Claude review while the content goes to Codex, so the operator's prohibition is breached silently. The shipped docs say such a rebind changes which executor is resolved and what telemetry records; nothing says the review itself is unchanged.
