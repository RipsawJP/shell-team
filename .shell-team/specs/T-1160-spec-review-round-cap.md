## Problem

An elected `spec-review — cross-provider` round has no bound. The run skill's Specify-seam gate says a spec-review round is not a loop iteration, so `loop-guard.sh`'s `max_iterations` and `no_progress` never fire at this seam. The same paragraph promises that a repeated finding class fires the `same-class-2` early escalation, but that promise is prose addressed to the orchestrator's memory, and nothing mechanical counts rounds or classes. Relayed motivation only, not a premise any criterion rests on: an adopter run reportedly ran twelve consecutive `REQUEST_CHANGES` spec-review rounds on one criterion, with no escalation to the operator and no same-class record anywhere.
