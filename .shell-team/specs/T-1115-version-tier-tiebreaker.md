# Encode the version-tier tiebreaker in CONTRIBUTING.md

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1115

## Problem

`CONTRIBUTING.md`'s `## What a version number encodes` carries two clauses that can both apply to a single change with nothing saying which governs: the PATCH bullet assigns `performance work` to PATCH "regardless of diff size or how invasive the change was to make", while the MINOR bullet grants MINOR to an adopter-perceivable benefit that passes the headline test and the default-reachability test jointly. T-1112 hit the overlap exactly — a change whose felt benefit was wall-clock (reading as performance work) but which inverted a shipped README claim and changed what an adopter's default path observably does — and both readings were textually defensible, so the tier had to be settled by an operator ruling rather than derived. Two derivation sites read only this file's text (the freeze-time version-derivation gate T-1110 ships in `skills/run/SKILL.md`, and `pm-spec`'s own authoring-time reading), so without the ruling written into the file the next change of this shape derives PATCH honestly at both sites, the gate reports a match against a PATCH premise, no deviation notice fires, and a release that changes documented default behaviour ships unannounced.

## Goal

## Non-goals

- **The added line does not outrank the whole PATCH bullet.** It settles the collision with the `performance work` item only. The PATCH bullet's `capabilities that ship but stay latent behind an opt-in are PATCH` rule is left exactly as it stands — nobody ruled on that item, and rewriting it here would change a shipped rule under cover of encoding a ruling that did not mention it. The overlap between a claim-falsification and an opt-in-gated capability is a real open question and is filed as a fast-follow by the coordinating session; **AC3** locks the narrowness mechanically.
- **The two tests are not amended, relaxed or bypassed.** `## What a version number encodes`'s MINOR gate stays joint. The added line moves a change out of the performance-work grouping and then lets the two tests govern it; it does not grant MINOR to a change that fails the default-reachability test — a documented-claim falsification whose default path is unchanged still derives PATCH under this rule. **AC4** locks both test bullets byte-identical to the base blob and **AC3** refuses a categorical spelling on the new line.
- **No MAJOR-tier interaction is created.** A change that breaks the stable surface `## Cutting a release` defines is still MAJOR; the added line says nothing about it and is asserted not to name that tier.
- **No second copy of the rule anywhere.** No `README*`, no `docs/`, no `agents/*.md`, no `skills/`, no `templates/`, no `CHANGELOG*`. Both derivation sites already read `CONTRIBUTING.md` by name, so a mirror would be a second surface to keep in sync for no reader. Measured: `docs/adopting.md` and `docs/adopting.ja.md` restate the derivation *procedure* and not the tier rule, so no adopter-doc mirror is owed and **AC9** locks them byte-identical.
- **No checker, no test suite, no CI step, and no prompt-block edit.** The T-1110 gate already derives from this file's text; nothing needs to learn a new grammar.
- **No version assignment, no changelog entry, no release.** This task states a rule about tiers; it does not apply one to itself beyond the authoring-time reading recorded on the board.
- **No repair of any merged criterion this diff reddens.** Repairing another task's frozen criterion is a class-B re-freeze of someone else's intent. The reddening is disclosed in `## Blast radius` and left alone.
- **No full-population sweep, no whole CI-equivalent re-run, and no behaviour verification of any mechanism this task does not touch.** Stated explicitly because `verification-class: no-mechanism` requires it. Every criterion's verification shape is one of the four this class can honestly carry: a string presence-or-absence grep, a byte-scoped diff, a checker's exit code, and a records-line existence check.
- **No claim that the class is closed.** A derivation can still be performed carelessly, and the two derivation sites are agent-and-human readings this task cannot authenticate. What ships is text that makes the correct derivation reachable from the file alone; it does not make the derivation correct.
