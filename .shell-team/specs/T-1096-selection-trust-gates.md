### §1 — The mechanism decision (#336), binding on both gates

**The decision: (C), a criticality-scoped combination, recorded as `tamper-arm-rule-v1`.** Neither pure arm survives its own measurement. **(A) alone** — promote every recurring primitive into `bin/` and have every spec's check lines call them — is unbounded: a spec's inline check line is authored once against one artifact, the corpus already holds a spec population that grows every cycle, and there is no adopter value in a shared primitive for a judgment exactly one document ever makes. **(B) alone** — demote every check to a smoke test and let review confirm closure — discards the one control this repository has actually measured as holding: across five adversarial rounds the shipped `bin/` checkers were never defeated while the per-spec one-liners fell every round, so moving a gating verdict from the layer that holds to the layer that falls is the wrong direction. The measurements point at different arms for different obligations, which is what (C) means, and the operator's 2026-08-22 interim re-pricing has already been running arm B for dev-scaffold inline check lines — that ruling **stays in force and is not reopened here**.

**`tamper-arm-rule-v1` — the rule, as a decision procedure over observable properties, in this order:**

1. **Will the obligation's verdict gate a loop transition — a status-flag advance, a freeze, or a close-out — and is the judgment it makes mechanically executable from committed bytes by a script?** Both yes → the obligation is **tamper-relevant** and takes **arm A** (`arm-A-tested-primitive`): it lands as a named script under `bin/` with its own `tests/<name>/run.sh` suite and its own step in `.github/workflows/check-handoff.yml`, and every caller **invokes** it as a subprocess rather than re-implementing its judgment inline. No inline `- check:` line and no inline block inside a larger script may carry that judgment. **Both conjuncts are prescriptive tests on the obligation's own consequence and content, never observations of what happens to exist today**: where no shipped script executes an arm-A obligation yet, that is an **implementation gap to close, and never evidence for arm B**.
2. **Otherwise** — the verdict gates nothing beyond a single spec's own acceptance report, or the judgment is not mechanically executable from committed bytes — the obligation takes **arm B** (`arm-B-enumerated-instrument`): the check line or the read is an enumerated-case instrument, review reads it for computed values, conclusion direction and real instrument defects at the depth the artifact's consumer class earns, and adversarial guard-completeness is not a Major. This is the operator's 2026-08-22 ruling, unchanged.

**Why question 1 is phrased as a consequence test rather than as a look at the current tree.** An observational reading ("is it executed by a shipped script?") has no answer for an obligation nobody has built yet, so it would route every genuinely new obligation to the `otherwise` branch by default and the rule would only ever *label* arms that had already been chosen somewhere else — the "describes rather than decides" failure this task's own `## Verdict scope` names as the thing to probe. The second conjunct is what keeps the prescriptive reading from over-reaching in the other direction: an obligation whose judgment no script can make from committed bytes cannot be fixed by demanding a script for it.

**Three probe cases, run against the rule as worded above rather than against the two obligations it was written for**, because a rule tested only on its motivating cases is indistinguishable from a description of them:

- **An advisory-verdict checker** (the optional drift/alignment pass). Question 1's first conjunct fails — that pass "gates no board flag" and leaves the board exactly at `READY_FOR_MERGE` — so it takes **arm B**. Correct outcome: an advisory verdict earns instrument depth, not tamper-resistant depth.
- **An orchestrator prose duty** (a reflection or a confirmation read the coordinating session performs). The first conjunct can hold — such a read can precede a disposition — but the second fails: classifying a finding set is not executable from committed bytes. **Arm B**, and this is precisely the case the second conjunct exists for, since the first conjunct alone would have demanded a checker for a judgment no script can make.
- **A tamper-relevant arm-B instrument** (a spec's inline check line whose defeat would let a tamper-relevant verdict pass). Question 1's first conjunct fails on its face — the check line's verdict gates only that spec's own acceptance report — so question 2 sends it to **arm B**; the reclassification clause below then fires and moves it to **arm A**. Named as a probe deliberately: it is the one case where the two questions alone give the wrong answer, and it shows the reclassification clause carrying real weight rather than sitting there as decoration.

**Two clauses that keep the rule a decision rather than a description.** First, the arm is chosen by **what the obligation's verdict gates and whether its judgment is mechanically executable**, never by what the obligation is about, and never by which scripts happen to exist: a check line whose *subject* is a `bin/` script's behaviour still takes arm B for the check line itself, while that behaviour is covered by that script's own suite under arm A. Second, **reclassification is part of the rule**: an obligation sitting in arm B whose defeat would let a tamper-relevant verdict pass is reclassified to arm A, and that reclassification is exactly #336's own second pickup trigger ("immediately if a tamper-class defect is found in a shipped checker"). A **re-evaluation trigger** ships with the decision rather than leaving it unconditionally settled: the rule is re-read at the first retro following either a defeat of a shipped `bin/` checker — which would invalidate control observation 2 and with it arm A's whole justification — or the promotion of a third obligation into arm A, whichever comes first.

**Applying the rule to this task's two obligations.** #341's verdict gates a **freeze** and its judgment — do two committed board sub-bullets exist and agree, and does every gap id carry a resolution id — is executable from committed bytes; #344's verdict gates a **close-out** and its judgment — is the last conformant verdict line an approval — is likewise. Both conjuncts hold for both, so both take arm A, and the fact that neither script exists yet is the implementation gap this task closes rather than a reason to read either as arm B. In this repository's measured idiom that means two separate scripts invoked as subprocesses, not a shared library: `bin/` carries no sourcing pattern at all (siblings are invoked as `bash "$SCRIPT_DIR/…"`, four times in `close-out.sh` alone), so arm A's "primitive" is a callable script with its own suite and its own CI step, never an invented `bin/lib/` convention. Each gate's implementation cites the recorded decision in its own bytes (**AC3**), so a later reader finds the rule from the code rather than from memory.

### §2 — The close-out backstop (#344)

**The six defeat classes, verbatim, as the requirement floor.** Any implementation must refuse, or be structurally immune to, every one of these:

1. **Unanchored verdict match** — `### Codex Spec-Review verdict: APPROVE_WITH_CAVEATS`, or the unfilled template literal `APPROVE | REQUEST_CHANGES`, satisfied a prefix grep (review round 1).
2. **Unscoped scan** — an APPROVE from an *earlier* round satisfied a whole-file grep when the latest round said REQUEST_CHANGES (review round 1).
3. **Heading-match asymmetry** — an exact-match selector plus a loose boundary regex disagreed: a trailing-whitespace `## Spec review ` variant anchored the scan to a stale round (review round 2); an internal-double-space variant reproduced the same class after the trailing-only fix (QA round 3 probe).
4. **Boundary defeat, dangerous direction** — a later *unrelated* heading with leading whitespace was invisible to the boundary, leaking subsequent content (and a stray APPROVE) into the extracted "latest round": false PASS (QA round 4).
5. **CRLF fallback bypass** — `[ \t]` never matches `\r`, so a CRLF-terminated record defeated heading detection entirely and the whole-file fallback resurrected a stale APPROVE: false PASS (QA round 5). Root cause: the fallback could not distinguish "no heading exists" from "heading detection failed".
6. **Missing/non-ASCII separator** — `##Spec review` (zero space) and a U+00A0 separator are invisible to both judgments simultaneously, because a reductive whitespace normalization can collapse existing whitespace but can never *supply* a missing separator; rounds merge and a stale APPROVE false-PASSes (QA round 6).

**The design: consult no heading, and make every occurrence visible.** Classes 3, 4 and 6 are all heading-classification failures, so the design removes heading classification entirely; class 5's root cause is a fallback that could not tell a clean absence from a failed read, so the design has **no fallback**. Concretely: strip CR per line; collect **every** column-zero line matching the **stem** `^### Codex Spec-Review verdict:` — the stem alone, with **no assumption about what follows the colon**; refuse when there are none; otherwise take the **last** one and require its remainder to be exactly one ASCII space followed by one of the four closed forms, refusing anything else; pass only on an approval remainder. Append-only ordering replaces section scoping, which closes class 2, and the anchored full-line treatment of the remainder closes class 1.

**Why the collection net is the stem and not the stem-plus-separator, stated as the third correction to the candidate design.** Making the net `^### Codex Spec-Review verdict: ` — stem plus one literal ASCII space — relocates defect class 6 rather than closing it: a line reading `### Codex Spec-Review verdict:` followed by a non-breaking space and `REQUEST_CHANGES` fails that net, so it is **never collected at all** — not refused as an unrecognised tail, simply invisible — and if it is the true latest round sitting after a well-formed earlier `APPROVE`, the last collected line is the stale approval and the gate **passes** a task whose real latest verdict was a refusal. That is the identical dangerous direction as classes 1, 2 and 6, moved from the heading the redesign correctly stopped consulting onto the verdict line's own separator, which a stem-plus-space net would still implicitly trust. Widening the net to the stem and validating the separator as part of the remainder puts every near-miss in the **refusal** branch, which is the same refuse-unrecognised-never-skip discipline the last-line rule already uses.

**Classification of that finding, made explicitly because this spec's own §4 makes it consequential.** §4's never-dropped clause says a *new independent text-extraction defeat class* against §2 stops the task and returns it to planning rather than buying a patch round, so whether the separator finding is a new class or a restatement decides whether this round is a correction or a stop. It is a **restatement of defect class 6 at a second, untested location, not a new class** — and the ground is class 6's own verbatim wording, which names the root cause as a separator that is missing or non-ASCII defeating a match ("a reductive whitespace normalization can collapse existing whitespace but can never *supply* a missing separator") and is **not scoped to headings**; only its two illustrative examples were headings, because the heading was the only place T-1092's design looked. Same root cause, same failure direction, a location this spec had not tested. The pre-commitment's stop rule therefore does not fire, and this classification is recorded here rather than left to be assumed either way.

**Where the stem's own bytes stop being defended, declared rather than discovered.** The stem is a machine token whose bytes the producer contract fixes verbatim, so a mutilation *inside* the stem — a non-breaking space between `Spec-Review` and `verdict:`, say — is a producer-contract violation rather than an input class, and no widening of the net is attempted for it: that is the enumeration path `.shell-team/lessons.md:1325` forbids, and this boundary is declared once here instead of being rediscovered per round. One structural property bounds the consequence and is asserted rather than asserted-about: because the zero-collected case **refuses**, a record whose only verdict line carries a mangled stem refuses too, so the mutilation lands in the safe direction. The one case that does not is a mangled stem appended after a well-formed approval, which is named as a Non-input in `## Input space` on the same trusted-principal footing as the fenced-code-block case.

**One implementation constraint, stated in the spec because it is a correctness property rather than a style preference.** Whatever reads the record must be **EOF-safe for a final line carrying no trailing newline**. The common `while IFS= read -r line; do … done < "$RECORD"` idiom is not: `read` returns non-zero on a final partial line, and since that status is the loop's own continuation test the last line is silently dropped — so a record whose true final verdict line is the file's last byte with no terminating newline would be lost and an earlier stale approval resurrected. Read the whole file with `grep`/`awk`/`tail` shapes that treat a final unterminated line as a line, or handle the final read explicitly the same way as every other.

**Three corrections to the candidate design, each grounded in measurement rather than in taste — the first two here, the third in its own paragraph below.** First: the candidate matched "the last line matching anchored `^…: (APPROVE|REQUEST_CHANGES)$`", which **skips** a line whose tail is out of grammar and therefore lets a stale in-grammar APPROVE above it satisfy the scan — classes 1 and 2 in new dress. The shipped rule instead anchors on the **prefix**, takes the last such line whatever its tail, and refuses when that tail is unrecognised, so nothing is ever skipped over. Second: the closed grammar is **not** the bare verdict token. Measured first-hand, `.shell-team/reviews/T-1093.md:137`, `T-1094.md:210` and `T-1095.md:145` each carry `### Codex Spec-Review verdict: APPROVE (round N)`; a `$`-anchored bare-token pattern matches none of them, which would refuse every task whose review reached APPROVE past round 1 and — the dangerous direction — would silently pass a record whose round-1 bare APPROVE was later superseded by a suffixed `REQUEST_CHANGES (round 2)`. The grammar is therefore the four forms `APPROVE`, `APPROVE (round <digits>)`, `REQUEST_CHANGES`, `REQUEST_CHANGES (round <digits>)` and nothing else. **This is not a re-entry into the strategy the 2026-08-24 lesson forbids**: that lesson's `- Rule:` names ad-hoc normalization of free-form headings and verdict strings, whereas this is a closed four-form alternation measured off the real producer's output, applied to the one line the gate reads, with every unrecognised shape refused rather than normalized. Nothing here canonicalizes anything.

**The producer contract is pinned in the same task, because reader and producer must be one contract.** `agents/codex-reviewer.md:195` fixes the heading literal but says nothing about what may follow the verdict token, and the observed output adds ` (round N)` in three of three multi-round cases. That paragraph therefore states the closed suffix grammar explicitly, so the reader admits exactly what the producer is told to emit (**AC9**).

**The load-bearing assumption, verified at spec time across every shipped flow.** "Last = latest" requires the review record to be append-only. Verified: the spec-review mode appends its `## Spec review` section and creates the file when absent (`agents/codex-reviewer.md:195`, `:197`); the default mode writes the same `T-XXX.md` with no per-round filename variation (`:212`) and its real output shows successive rounds appended after the spec-review section (`.shell-team/reviews/T-1095.md:3`, `:187`, `:232`); the review-response mode returns per-finding fields and writes no review record at all (`:144–157`); the write boundary at `:206` closes the write list; and the rework and route-back paths in `skills/run/SKILL.md` and in `agents/codex-reviewer.md:197` instruct a route-back to the spec's author, never a rewrite of the record. **No shipped flow rewrites a review record in place, so the design stands.** What is *not* claimed: nothing mechanical enforces append-only-ness, so a hand edit could violate it. That is priced as a trusted-principal Non-input below, and **AC7** carries its negative control so the property is exercised rather than asserted.

**The fenced-code-block case, priced rather than merely repeated.** T-1092's frozen Input space names a verdict heading forged inside a fenced code block as not an input class but the trusted-principal case, and says pricing it belongs here. Priced: the gate deliberately does not learn markdown fences, and the consequence is directional. A quoted line-start verdict heading appearing **after** the real latest verdict becomes the last prefix match and, if its tail is out of grammar, refuses — a false refusal, in the safe direction. A quoted line-start `APPROVE` appearing after a real `REQUEST_CHANGES` is a **false PASS**, and it is reachable by any round whose prose quotes the heading at line start. **Election, and the one thing this gate cannot distinguish.** The gate fires only when the task's own Active entry carries `- dispatch: spec-review — cross-provider — …`; `none` or no `spec-review` record at all is a silent pass-through, because `tests/close-out/run.sh:1233` locks that forward-only property for every in-flight three-axis task. Making a missing election a refusal would break the locked property, so this residual is #341's ordering fix applied at a seam where it cannot be applied, and it is stated as a limit.

### §3 — The pre-freeze conformance-read gate (#341)

**Two condition sources, both committed files a script can read.** Source 1 is `- entry-mode: pm-authored|operator-authored`, transcribed as a sub-bullet on the task's Active entry by `pm-spec`, who owns that entry (`skills/run/SKILL.md:44`). Two parties, two writing moments, one file a script can read at any time.

**Source 1 needs a writer, and this task ships it — the reader alone would refuse every future freeze.** Measured at authoring: the shipped contract obliges `pm-spec` to emit `- entry-mode:` **in its hand-off** (`agents/pm-spec.md:121`), and `skills/run/SKILL.md:51` deliberately contrasts "that hand-off" against "the board's own `- dispatch:` record" as two different things — so under the current instructions the field is a conversational return value and **nothing writes it onto the board at all**. A gate reading source 1 off the board while nothing writes it there would, once wired as a real exit code, refuse **every** future task's freeze — including entirely legitimate `pm-authored` work — so this task ships the **producer duty in the same diff as the reader**: `agents/pm-spec.md` gains the obligation to transcribe `- entry-mode: <the mode that actually ran>` as a sub-bullet onto the board entry it already creates and updates, and `skills/run/SKILL.md`'s statement of `pm-spec`'s board duties says the same thing in the same place, so the duty is stated at both surfaces that describe it rather than at one. The hand-off field is **not** replaced: it keeps its existing role as the pre-freeze prose gate's condition source, and the board sub-bullet is its durable twin.

**What "forward-only" does and does not mean here, resolved rather than left to the seam.** It does **not** mean a missing source 1 passes silently — that is exactly the round-2 silently-false-condition class this design exists to kill, and the refusal-on-absence rule is what makes the verdict order-independent. It means instead that **no shipped path ever submits an entry the gate was not meant to judge**: the gate is invoked only at the pre-freeze seam for the one task being frozen, never from `bin/close-out.sh` and never as a whole-board sweep, so historical entries and an adopter's existing board are untouched by construction rather than by a leniency clause. For the one narrow window that remains — a task specced under an older version and frozen after the upgrade — the gate refuses and **prints the one-line remedy**, in the same shape `bin/close-out.sh:330–337` already prints a conformant interventions record: a refusal that names its own fix in one line is a migration prompt, not a regression, and it is the honest price of not weakening the gate permanently to accommodate a single hand-off's worth of exposure.

**The round-2 order-dependence class is killed by inverting the failure mode, and by fixing one order.** The gate's condition is not "source 2 says operator-authored" — a condition that reads false when the record is merely not transcribed yet. It is: **both sources present, and agreeing**; a missing source is a **refusal**, never a silently-false condition. That inversion alone makes the verdict order-independent in the sense the acceptance sketch demands — the same verdict whichever order the two sub-bullets were written in — but it would refuse every task if source 2 genuinely could not exist yet, so the second half of the fix is that `skills/run/SKILL.md` **fixes the order** that file currently leaves unfixed: the dispatch records are transcribed immediately after `pm-spec` creates the entry and **before** the freeze sweep runs (**AC13**). That is the answer to #341's own first design question — what durable artifact the Plan-time decision should be written to — and it is the board record with its ordering solved rather than inherited. **A new durable Plan-time artifact is rejected on a measurement**: `bin/team-paths.sh:68`'s closed key set has no `plans` key, so a new Plan file would be an adopter-visible layout change out of all proportion to the problem.

**What counts as answered — the decision, and its limit.** `pm-spec` writes each flagged gap as `- flagged-gap (<id>): <what was flagged> — <why it is author-only>` with `<id>` matching `[a-z0-9-]+`; the author writes, per gap, `- flagged-gap-resolution (<id>): <what the author decided>` with non-empty text. The gate requires the two **id sets to be equal in both directions**, each id appearing exactly once on each side, and every resolution text non-empty. An orphan resolution with no matching gap is a refusal too, because it is evidence the ids drifted rather than that a gap was answered. **The marker is recognised by its stem and a near-miss is refused, never silently ignored.** A strict extractor that only recognises the exact `- flagged-gap (<id>): ` shape would fail to recognise `- flagged-gap (g1) : x` (a stray space before the colon), or any other delimiter near-miss, as a gap **at all** — contributing to neither the gap set nor the resolution set, so a genuinely flagged and genuinely unanswered gap reads as "zero gaps, zero resolutions", which is the explicitly-permitted conformant nothing-to-answer case. That is the same absence-versus-failed-read shape defect class 5 names for the CRLF record, applied to the gap-marker grammar instead of to line endings, and it is closed the same way §2 closes its own: **scan for the stem, then refuse anything carrying the stem that does not parse**. Any line whose stem is `- flagged-gap-resolution` or `- flagged-gap` but whose remainder does not parse cleanly into `(<id>): <non-empty text>` is a refusal with its own message, distinct from both a missing resolution and an orphan. One ordering detail that is a defect generator if left implicit: `- flagged-gap` is a **prefix of** `- flagged-gap-resolution`, so the resolution stem is tested **first** and a line matching it is never also counted as a gap.

Stated plainly as the limit this buys: "answered" means *the author wrote a resolution against that id*, never that the resolution is adequate; and **the never-flagged case is undetectable** — a run that flags nothing yields zero gaps and zero resolutions, which is the conformant nothing-to-answer case and is indistinguishable from a conformance read that never happened. Note what the stem-scan does and does not change about that: it removes the *malformed-marker* route into the zero-gaps case, so the case is now reachable only by genuinely flagging nothing, which is the residual (iii) this spec discloses rather than a new hole.

**The three residual trust boundaries, disposed one by one rather than in one sentence.** **(i)** Neither source is authenticable by this gate: two parties write them, but both land on one file either party can write, so the cross-check raises the cost of a *mistake* and not of a *deliberate* misstatement. **Re-disclosed, not closed.** **(ii)** "The read itself is verified by nothing" is now **partially** closed and the split is stated exactly: the gate verifies that a conformant record of the read exists and agrees with the Plan-time decision, and it does not verify that the read happened. **(iii)** "Answered" stays a reading judgment; the gate makes id-level bookkeeping mechanical and nothing more. **Re-disclosed, not closed.**

**The no-live-firing residual, handled explicitly.** No arm of `specify — operator-authored` has fired end to end. The gate is therefore designed against the shipped hand-off and board grammar plus fixtures, and the unexercised mode is disclosed. **T-1096 deliberately does not self-exercise that arm**: this task's `specify` axis is `pm-authored`, because authoring this spec in `operator-authored` mode would make the coordinating session the author of the very document that audits author/attester collapse — the one independent read this task exists to mechanize would be the read it removed. The `operator-authored` arm ships fixture-exercised only, and that is said in the shipped prose rather than left to a reader to notice.

## Input space

**Reachable input classes** — what the two gates really meet, produced by real flows in this repository and in an adopter's:

- A review record created by the spec-review mode as the task's very first `codex-reviewer` activity, carrying one `## Spec review` section and one `### Codex Spec-Review verdict: REQUEST_CHANGES` line.
- The same record after two or three further spec-review rounds, whose verdict headings carry the ` (round N)` tail — measured in three of three multi-round records in this repository.
- The same record after the delivered-change review has appended its own `## Delivered-change review` sections with `### Codex Review verdict:` headings, before and after the spec-review section's own latest verdict.
- A review record that does not exist yet, for an elected task whose spec review has not run.
- A review record path that resolves to something other than a readable regular file: a directory, a dangling symlink, an unreadable file.
- A record whose line endings are CRLF, produced by an editor or a tool on a different platform.
- A record whose prose quotes a verdict heading — inside a fenced block, indented, or (the hazardous case) at column zero.
- A board entry electing `spec-review — cross-provider`, one electing `none`, and one carrying no `spec-review` dispatch record at all (every in-flight three-axis task).
- A board entry carrying both `- entry-mode:` and `- dispatch: specify — …` in either order, exactly one of them, neither, or two copies of one.
- A board entry whose two sources disagree, in either direction.
- A board entry carrying zero flagged gaps, one gap with a resolution, one gap without, several gaps partly resolved, a resolution whose id matches no gap, and a duplicated id on either side.
- An `- entry-mode:` value outside the closed pair — a typo, a translated word, an empty value.
- A whitespace variant on any of the sub-bullets: a tab indent, a doubled space after the bullet, a doubled space inside the ` — ` separator of a dispatch record.
- An invocation with a missing flag, an unknown flag, a `--task` value that is not `T-<digits>`, or an unresolvable reviews directory.
- A board file resolved under either supported layout (the default `.shell-team/` or the legacy `tasks/`), and a `$TEAM_REVIEWS_DIR` override pointing at a scratch directory.

**Out-of-scope synthetic extremes** — named concretely, so an adversarial gate has a declared boundary and the engineer has grounding to decline:

- **A forged verdict heading at column zero inside a fenced code block**, and any other way of making a review record read as approved when it is not. The party writing the record is the trusted principal; the gate deliberately does not learn markdown fences, and the false-PASS direction of this case is priced and disclosed in §2 rather than defended against.
- **A review record rewritten in place** so that a stale APPROVE is the only verdict left. Indistinguishable from a genuine single-round approval by construction; **AC7** exercises the outcome and records it as the disclosed limit.
- **A fabricated board sub-bullet** — an `- entry-mode:` or `- dispatch:` record naming a mode nobody decided, or a `- flagged-gap-resolution:` written by the same party that wrote the gap. Residual (i), re-disclosed and not closed.
- **A conformance read that flagged nothing because it never happened.** The never-flagged case is undetectable by design; residual (iii).
- **Ever-more-extreme malformed verdict tails** — a thousand-character tail, a tail carrying control characters or bidirectional-override codepoints, a verdict token in a non-Latin script, a heading repeated ten thousand times. The grammar is closed at four forms and every other tail is one refusal; no criterion here grows with the length or exoticism of a rejected tail.
- **A mutilation inside the verdict line's own stem** — a non-breaking space or a homoglyph within `### Codex Spec-Review verdict:` itself, as opposed to in the separator or the tail, which are both **in** scope and refused. The stem is a machine token the producer contract fixes verbatim, so a corrupted stem is a producer-contract violation rather than an input class, and widening the collection net to chase stem variants is the enumeration path `.shell-team/lessons.md:1325` forbids — declared here once so it is not reopened per round. The consequence is bounded rather than unbounded: because the zero-collected case refuses, a record whose only verdict line has a mangled stem refuses too, and the single unprotected shape is a mangled stem appended after a well-formed approval, which sits on the same trusted-principal footing as the fenced-code-block case above.
- **Ever-larger flagged-gap sets** — a hundred ids, nested ids, ids differing only by a homoglyph. The id grammar is `[a-z0-9-]+` and set equality is judged over it; a synthetic escalation of the count or the confusability of ids is not protected.
- **Concurrency** — two writers appending to one review record at the same instant, or a freeze sweep racing a transcription. Both gates read a committed file at one moment; no locking is designed and none is claimed.
- **A live `specify — operator-authored` run.** Deliberately not created by this task, for the author/attester reason in §3; the fixtures stand in and the residual is disclosed.
- **Any claim about either gate's *effect*** — how many silent skips it prevents, how often it fires. Unmeasurable at this task's scale and out of scope in both directions.
