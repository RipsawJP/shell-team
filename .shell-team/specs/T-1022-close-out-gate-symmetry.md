# Close-out validates the source line through the hand-off lint itself, and screens that sibling fail-closed

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1022
**Source**: GitHub issues **#98** (T-1016's Codex fast-follow: `bin/close-out.sh` accepts a looser top-level line shape than `bin/check-handoff.sh` validates, so a malformed line rides into `## Done`) and **#101** (T-1017's spec D6 deliberate non-goal: the pre-write `check-handoff.sh` interlock has no explicit missing-sibling screen). Batched into one task per the tech-lead's routing map: both are gate-symmetry defects in the same block of the same script, and both shift the same `tests/errexit-safe/run.sh` line pins.
**Base**: `develop` @ `fa05f29` (read from `.git/refs/heads/develop`: `fa05f29bf7a0c86c1fe762be3e1c62ea117c523d`)
**Branch**: `feature/98-close-out-gate-symmetry`

## Problem

`bin/close-out.sh` moves a task's entry from `## Active` to `## Done`, rewriting its status flag to `READY_FOR_MERGE`. Two independent asymmetries make that move less safe than the surrounding gates look.

**#98.** The flag rewrite matches the source line against its own regex — a greedy prefix, a backticked token, ` — spec: `, a non-space path ending `.md`, then *optional trailing whitespace*. `bin/check-handoff.sh`'s `LINE_RE` is stricter: the title slot must contain at least one non-whitespace character, the line must end exactly at `.md`, and the flag must be in the allowed vocabulary. Anything the rewrite accepts but the lint would reject rides into `## Done` — and `## Done` is deliberately outside every board check's scope (the format check, the strand check, and the pre-write interlock all look only at `## Active`), so nothing downstream ever catches it. An invalid flag is worse than unnoticed: it is silently rewritten to `READY_FOR_MERGE` and laundered into the record.

**#101.** The pre-write interlock shells out to the sibling `check-handoff.sh` with no `-f`/`-r` screen in front of it. T-1017 gave exactly that screen to its own sibling (`check-interventions.sh`) and recorded the asymmetry as a deliberate deferral, because fixing it changes a shipped refusal's exit class. Today a vendored or partial `bin/` install surfaces as "the rewritten board would fail the lint" at exit `1` — an install problem misattributed to board content, pointing the operator at the wrong file.

Neither is hypothetical in shape: this repository's own board is the input, and `bin/` is copied into adopter repositories as a directory an operator can partially vendor.

## Goal

<!-- BEGIN intent-block: T-1022 -->

`bin/close-out.sh` refuses, before any board write, to move a `## Active` source line that `bin/check-handoff.sh` would reject — and it decides that by feeding a synthesized single-entry board to the sibling checker itself rather than by carrying its own copy of the line grammar, so the flag vocabulary becomes enforced on the source line too. A missing or unreadable `check-handoff.sh` sibling is screened before either invocation and refuses with exit `2` and a named reason instead of surfacing as a lint failure at exit `1`. On every refusal the board file is byte-untouched. `bin/check-handoff.sh` itself is unchanged, no check is widened to `## Done`, and no existing `## Done` entry is repaired.

### Terms

Four gates now live in this script and three of them lint a board; naming them loosely is how a review round gets spent on the wrong one.

| term | definition |
|---|---|
| **the source line** | the single physical line at `A_START` in the real board — the task's top-level `- [ ] **T-NNN** …` line, as `sed -n "${A_START}p"` reads it (trailing CR included, trailing newline excluded). Its continuation lines are not part of it. |
| **the hand-off lint** | the sibling `bin/check-handoff.sh`, invoked as a subprocess. Its judgment (`LINE_RE` shape **and** `ALLOWED_FLAGS` vocabulary **and** the strand rule) is consumed as-is; this task adds no second copy of it |
| **the synthesized board** | the temporary file the source-line gate builds to ask the hand-off lint about one line: a `## Active` heading, one blank line, the source line verbatim, and no other `- [ ]` line anywhere in that section |
| **the source-line gate** | the block this task adds: synthesize, invoke the hand-off lint, classify its exit status, refuse. Runs before pass 2's rewrite |
| **the pre-write interlock** | the *existing* gate that lints the **rewritten** board (`rewritten board would fail check-handoff.sh`) immediately before the single write. Its own exit mapping is not changed by this task |
| **the sibling screen** | the `-f`/`-r` test this task adds ahead of the first `check-handoff.sh` invocation, modelled on the `check-interventions.sh` screen T-1017 shipped (`cannot verify the interventions record …`) |
| **an escaping input** | a source line that pass 1's `awk` locates as this task's entry, that the flag rewrite accepts, and that the hand-off lint rejects. The set of these is **measured** by this task, not transcribed |
| **laundering** | the current behaviour by which a source line's invalid status flag is replaced with `READY_FOR_MERGE` during the rewrite, so the defect leaves no trace in the record |

### Settled decisions

Each decision below is resolved. Nothing here is left to implementation judgment.

- **D1 — #98 is fixed by canon reuse (option C1), not by a local copy of the grammar.** The source-line gate writes the synthesized board to a temp file and runs `bash "$SCRIPT_DIR/check-handoff.sh" <synthesized>`; the checker's verdict is the gate's verdict.
  - **Why not a local `LINE_RE` copy (option A).** Two copies of a line grammar in one repository drift, and the drift is exactly the defect #98 reports — a second dialect of the same contract. The playbook's rule for a verification mechanism applies directly: this invariant is a grammar judgment, so a hand-rolled regex has a structural ceiling, and an existing grammar-aware tool should be used where one exists. Here the "existing tool" is the canonical checker itself, which is the strongest available form of that rule.
  - **Why not lint the whole real board pre-write (option C2).** Not for blast radius — see D2, where that ground is measured and found not to distinguish the options — but for **attribution**. C2 refuses a close-out of *this* task by reporting *another* task's line, and it cannot name which line is the reason this task will not close. C1 judges exactly the one line the task moves, which is the boundary of the task's own responsibility, and its refusal names that line's real board path and line number.
  - **Consequence, adopted deliberately rather than absorbed as a side effect: the flag vocabulary becomes enforced on the source line.** `flag_allowed()` runs inside the checker, so a source line carrying `ready_for_qa`, `READY`, `READY_FOR_MERGED` or any other token outside `ALLOWED_FLAGS` is now refused instead of being laundered into `READY_FOR_MERGE`. This is declared as an intended additional refusal class, documented in the script's own header (D7) and measured by AC5 in both directions (the refusal now, the laundering at the base ref).
- **D2 — the C2 blast-radius premise is measured, and it is the status quo, not a new cost.** The routing map rejected C2 because "an unrelated bad line would block every close-out". Read from the source at the base ref, that is already true today: the pre-write interlock lints the **rewritten** board, which still carries every other `## Active` line, so a malformed unrelated entry already refuses every close-out with exit `1`. The post-state's violation set is the pre-state's minus the moved line, so C1 and C2 accept and refuse the *same set of boards*; they differ only in attribution and timing. The decision for C1 stands on D1's attribution ground instead. **AC16 measures this** rather than asserting it, and is expected to pass before implementation — that pass *is* the evidence for the correction.
- **D3 — the source-line gate's exit mapping is total and fail-closed.** close-out's taxonomy is unchanged: `1` = a refusal about the state of the work, `2` = usage / validation / resolver / install error.

  | # | condition | close-out exit | reason |
  |---|---|---|---|
  | (0) | the hand-off lint exits `0` on the synthesized board | gate passes | — |
  | (i) | the hand-off lint exits `1` (any violation: format mismatch, unknown status flag) | **1** | F |
  | (ii) | the hand-off lint exits `2` (it could not read the synthesized board) | **2** | G |
  | (iii) | the hand-off lint exits with any other non-zero status | **2** | G |
  | (iv) | `bin/check-handoff.sh` is absent or not a readable regular file | **2** | E |

  - **Row (ii)/(iii) is the fail-closed floor.** An unusable checker is never read as a pass and never guessed into row (i): the synthesized board is a file this script just created, so "the checker cannot read it" is an environment failure, not a board defect, and telling the operator to fix their board would be a wrong instruction.
  - **Three frozen reason strings**, each on one physical line of `bin/close-out.sh` and in its refusal output: **E** = `cannot run the hand-off lint (check-handoff.sh missing or unreadable next to close-out.sh)`; **F** = `would be rejected by the hand-off lint — refusing to move a malformed line into ## Done`; **G** = `cannot verify the Active line (check-handoff.sh exited`. Reason F's line additionally carries the **real** board path and the **real** source-line number (`<BOARD>:<A_START>:`), never the temp file's.
- **D4 — the refusal output has three parts, in a frozen order: the synthesized-board note, then the checker's own stderr, then close-out's reason.** T-1016 D6 and T-1017 D5 established that a gate refuses by naming the cause first; this gate has one extra obligation, because the checker's `<file>:<lineno>:` prefix names a temp file rather than the board. So the gate prints, first, one line containing the frozen phrase **`the file:line below refers to a synthesized single-entry board, not the real board`**; then the checker's captured stderr verbatim; then reason F carrying the real `<BOARD>:<A_START>:`.
  - **The checker's stderr is not rewritten or filtered.** Editing another checker's output to look like this one's is a new dialect, which is what D1 exists to avoid. The note line is what resolves the ambiguity.
- **D5 — the sibling screen sits immediately ahead of the *first* `check-handoff.sh` invocation, and there is exactly one of it.** After this task the first invocation is the source-line gate, so the screen precedes it and covers the pre-write interlock too. It is not hoisted up next to the board resolution or the interventions gate: T-1017 D4's reasoning holds unchanged — an install error must not pre-empt board-state refusals that are more informative and far more likely (a task not in `## Active`, an unresolved pending disposition, a non-conformant interventions record).
  - **Shape mirrors T-1017's checker screen exactly**: an `[ ! -f … ] || [ ! -r … ]` test, `die` (exit `2`), a named reason (E), and no remedy block — the problem is the install.
- **D6 — the existing pre-write interlock's own mapping is untouched.** It continues to treat every non-zero status from the hand-off lint as exit `1` with its existing reason string. Normalizing *its* exit `2` would be a second change to a shipped refusal's exit class, with its own compat surface, and it is not what #101 asks for — the same reasoning T-1017 used to defer #101 itself. The resulting asymmetry between the two invocations is deliberate and recorded in Open questions.
- **D7 — the header's exit-contract prose is realigned, and `--help` stops being keyed to a hardcoded line number.** `--help` prints the header comment block through `sed -n '2,59p'` (measured at the base ref). This task lengthens the header, so a bare range-number bump is the vacuous fix the routing map warns against — T-1017 already had to bump this same number once, which is the recurrence that decides it. The extent is derived at run time from the file's own contiguous leading comment block starting at line 2, with no literal line number anywhere in the `--help` path.
  - **Three frozen header phrases**, each on one physical line: **H1** `a source line the hand-off lint would reject refuses the close-out before any board write`; **H2** `a missing or unreadable check-handoff.sh sibling is exit 2 (it was exit 1 before this change)`; **H3** `the Active line's status flag must be in the allowed vocabulary — an invalid flag is no longer silently rewritten`.
  - **AC12 asserts full equality** between `--help`'s output and the file's own `#`-stripped header block, plus the absence of any literal numeric range — not merely that a new phrase appears.
- **D8 — Compat surfaces. Two, both accepted, both documented in the script's own header and measured against the base ref.**
  - **(a) Previously-accepted malformed source lines are now refused with exit `1`.** Two sub-classes: a line the hand-off lint rejects on *shape* (a whitespace-only title, trailing whitespace after the `.md` path, and whatever else the D9 measurement surfaces), and a line carrying a **flag outside the vocabulary** (previously laundered to `READY_FOR_MERGE`). The remedy is always the same and always cheap: fix the line so the board's own lint passes — which CI already requires of every board in this repository, and which `bin/check-handoff.sh` already reports on any board an adopter lints. A board that carries such a line is already failing its own gate; close-out now declines to bury the evidence in `## Done`.
  - **(b) A missing or unreadable `check-handoff.sh` sibling changes exit class from `1` to `2`.** Recorded as deferred in `T-1017-close-out-interventions-gate.md` (D6, and its Open questions bullet "Whether `bin/close-out.sh`'s pre-write `check-handoff.sh` invocation should gain the same explicit missing-sibling test this gate has") precisely because it is a compat change; #101 is the decision to take it. AC3 measures both sides of it against the base ref.
  - **No adopter-facing document changes and no version bump.** The exit contract's operator-facing surface is the script's own header, which `--help` prints, and that is the surface a refusal points at. `CHANGELOG*` entries in this repository are written at release-cut time by `CONTRIBUTING.md`'s `## Cutting a release` procedure (T-1015), not per task; `CONTRIBUTING.md` states loop discipline, and neither compat surface changes any discipline it states.
- **D9 — the escaping-input set is enumerated mechanically, by differential testing, never transcribed from a reading of the two regexes.** The oracle is the real `bin/check-handoff.sh` run against a synthesized board; the subject is the real `bin/close-out.sh`; the corpus is generated in-suite over named axes (D10). The asserted property is a two-way implication over every corpus line: **the lint rejects ⇒ close-out exits non-zero and the board is byte-identical**, and **the lint accepts ⇒ close-out exits `0` and the line moves to `## Done`**.
  - **The routing map's reading is recorded as a hypothesis, not as fact.** It holds that pass 1's `awk` already requires `^- \[ \] \*\*T-NNN\*\* `, so the real escape surface is roughly whitespace-only titles, while trailing `.md` whitespace and invalid flags are normalized away by the rewrite. Two of those three are *not* what the spec author's own reading says (trailing whitespace is normalized away, so it escapes today as an accepted line; an invalid flag is laundered, which is a different harm from an escape). **The AC measures; neither reading is baked into a `check:` line as a count or a class list.** A disagreement between either reading and the measured corpus is a prose correction to this section, not a finding against the code.
  - **Why empirical and not static.** Two regexes in two languages (bash `[[ =~ ]]` and the checker's own `[[ =~ ]]`, plus an `awk` locator) cannot be intersected reliably by inspection, and a static scan cannot see the rewrite's normalizing effect at all. The completeness claim for the escape surface is therefore delegated to the differential harness and bounded by D10's axes — not claimed for arbitrary input.
- **D10 — the differential corpus's axes are named and closed; its summary is machine-readable.** Every corpus line begins `- [ ] **T-901** ` (so pass 1 locates it) except a small named set that deliberately does not. The axes: title shape (normal / padded / whitespace-only spaces / whitespace-only tab / empty); flag token (each of the seven allowed / lowercase / near-miss / a token with spaces); trailing whitespace after the path (none / space / tab); line terminator (LF / CRLF); title content (plain / containing a backticked token / containing a decoy ` — \`x\` — spec: y.md`); path shape (`x.md` / `docs/specs/x.md` / `.shell-team/specs/x.md` / no `.md`); separator shape (U+2014 with spaces / hyphen-minus / missing surrounding space); checkbox and id shape (`- [x]`, indented, double-spaced, mismatched id — the deliberately-not-located set).
  - The suite prints one summary line carrying the id `closeout-lineshape-differential` and five `key=<digits>` tokens: `corpus=`, `refused=`, `accepted=`, `notlocated=`, `mismatches=`. AC9 parses it and enforces floors plus `mismatches=0`; the floors exist so a shrunken corpus cannot satisfy the criterion.
- **D11 — trap discipline: no second `trap … EXIT`.** `trap` is not additive. The temp files the source-line gate needs are created in the **existing** `mktemp` block (the one creating `ENTRY_FILE` / `TMP_BOARD` / `GATE_ERR`) and added to that single `trap`'s removal list. The gate therefore sits **after** that block and before pass 2's `awk`. The screen (D5) needs no temp file and sits immediately above the gate.
- **D12 — the refusal invariant, measured with `cmp`: on every refusal this task can produce, the board file is byte-untouched.** Structurally guaranteed because every exit added here precedes the script's single write (`cat "$TMP_BOARD" > "$BOARD"`), and asserted anyway — the guarantee is the reason an operator can retry a close-out without inspecting the board first. A private `$TMPDIR` additionally proves the single trap actually cleans up on the refusal paths.
- **D13 — the change surface is one `bin/` script, two test suites, one recipe file, and this task's own records.** `bin/close-out.sh` (screen, gate, header prose, `--help` extent); `tests/close-out/run.sh` (the new assertion ids and the differential harness); `tests/errexit-safe/run.sh` (its `file:line:content` pin over `close-out.sh` shifts); `.shell-team/test-recipe.md` (append the differential-harness procedure). No new script under `bin/`, no new `tests/*/run.sh`, no `.github/**` change, no adopter document, no version bump.
  - **`tests/errexit-safe/run.sh`'s pin is re-measured, never arithmetic-shifted.** Measured at the base ref, the pin `close-out.sh:382` appears in **six lines and seven occurrences**: the `NOT_APPLY` heredoc entry (L312), the explanatory comment above the mutation self-check (L371 — a fifth site beyond the four the routing map named, disclosed rather than absorbed), the mutation `sed` pattern (L377, twice: the escaped pattern and its replacement), the `grep -qF` (L381), and the `ok`/`bad` messages (L382, L384). AC11 does not enumerate them: it requires every `close-out.sh:<N>` occurrence in that file to carry the **same** number, requires at least six occurrences, and requires the `NOT_APPLY` entry's quoted content to be byte-identical to `sed -n "${N}p" bin/close-out.sh` — so a missed site or a wrong number fails, whatever the true site count turns out to be.

## Non-goals

- **`bin/check-handoff.sh` — not a line.** It is `tests/errexit-safe/run.sh`'s single **(a) inviolable, byte-unchanged** designation, and it is the contract this task consumes; adjusting the consumed contract to make the consumer easier to write is the failure mode C1 exists to prevent. AC15 asserts byte-identity with the base ref.
- **Widening the format or strand checks to `## Done`.** Issue #98 excludes it explicitly, and it is a contract change of its own: `bin/check-handoff.sh`'s header states `## Done` is deliberately out of scope, this repository's `## Done` carries older looser entries, and every adopter's would too. AC17 fixes that boundary in place.
- **Retroactive repair of any existing `## Done` entry**, here or in an adopter repo. Forward-only, the same way T-1017 declined to backfill the T-1010 interventions hole.
- **Redesigning `tests/errexit-safe/run.sh`'s line-number keying.** Its `file:line:content` pins shift on every edit above them; that has now cost T-1006, T-1007, T-1008, T-1016, T-1017 and this task one re-measurement each. Recorded as an **issue candidate for the next planning input, deliberately not filed from this role**.
- **The pre-write interlock's own exit mapping** (D6), and **`bin/close-out.sh`'s other features**: telemetry, the printed issue-close procedure, `project_status` regeneration, `--note` validation, the T-068 disposition gate, the T-1017 interventions gate.
- **The telemetry and `project_status` exit contracts.** Both remain best-effort and can never fail a close-out; both run after the write and are therefore unreachable from every refusal this task adds.
- **UI.** There is none: `bin/close-out.sh` is a non-interactive script whose entire interface is its arguments, its exit code, its stdout procedure text and its stderr refusals.
- **Any escape hatch** — no flag, no environment variable, no warn-instead-of-refuse mode for either the screen or the source-line gate. An opt-out on a fail-closed gate makes it advisory, and D8's remedy is to fix a line that already fails the board's own lint.
- **A new `bin/` script, a new `tests/*/run.sh`, a new `shellcheck` argument, any `.github/**` change, any adopter-facing document, any version bump.**
- **Any change to `.shell-team/todo.md` beyond this task's own entry.**

## Input space

**Reachable input classes** — what real boards in this loop and in an adopter repository produce, and what this task must handle correctly:

- Well-formed top-level lines as this loop's own agents write them: `- [ ] **T-NNNN** <title> — \`FLAG\` — spec: .shell-team/specs/<slug>.md`, with titles of a few hundred characters carrying em-dashes, backticked tokens, parentheses, and non-ASCII prose (this repository's own board has all of these).
- The legacy form: a `tasks/todo.md` board in a legacy-layout root, with `docs/specs/<slug>.md` paths.
- All seven flags in `ALLOWED_FLAGS`, at any phase of the loop — a task is closed out from `READY_FOR_MERGE` in the normal case, but the board's own history shows entries closed from other flags.
- **A flag outside the vocabulary** — a lowercase or near-miss token from a hand edit. Reachable between edits by construction: `bin/check-handoff.sh` ships a dedicated `unknown status flag` message because this happens.
- A title padded with leading or trailing spaces (`LINE_RE` tolerates it), and a **whitespace-only** title (it does not) — #98's originating class.
- **Trailing whitespace after the `.md` path**, from an editor that does not strip line ends.
- CRLF-terminated boards. `bin/check-handoff.sh` strips a trailing CR per line deliberately; the source line reaches the synthesized board with its CR intact and must still be judged the same way.
- Entries with continuation lines of any shape — sub-bullets, tables, tab-indented prose — per T-1016's board-entry continuation canon. They are copied verbatim and are not part of the source line.
- Boards with several `## Active` entries, including one that is itself malformed and belongs to a different task (AC16's shape).
- A `## Done` section carrying older, looser entries with no bold id and no spec path. Real in this repository and, by inheritance, in adopter boards.
- Both layouts resolved through `bin/team-paths.sh`, plus a `$TEAM_TODO` board override and a `$TEAM_INTERVENTIONS_DIR` override in use at the same time — the exact combination `tests/close-out/run.sh` already uses.
- An incomplete install: `check-handoff.sh` absent, non-regular, a dangling symlink, or unreadable next to `close-out.sh`, including a hand-vendored subset of `bin/` — #101's originating class.
- A `$TMPDIR` that is set and writable, and the case where it is unset (`mktemp` falls back to `/tmp`).

**Out-of-scope synthetic extremes** — declined deliberately; a finding grounded only in one of these is out of contract:

- **Ever-more-exotic separator glyphs** beyond the U+2014 em-dash the grammar names — en-dash, horizontal bar, fullwidth hyphen, a homoglyph from another script. Both predicates reject all of them identically, so no asymmetry can exist there; a finding that demands one be *accepted* is a change to `bin/check-handoff.sh`, which this task must not touch.
- **New corpus axes invented beyond D10's closed list.** The completeness claim for the escape surface is bounded by those axes; a proposed new axis is in scope for a *finding* only if real board content can produce it, and the axis list is where that argument has to be made.
- **A source line crafted to break the synthesized board's structure** — one containing an embedded newline, or a `## Active` / `## Done` heading at line start. Structurally unreachable: the line comes from `sed -n "${A_START}p"`, which cannot yield an embedded newline, and every source line begins `- [ ] `, so no substring of it can start a line in the synthesized board.
- **Pathological scale**: a multi-megabyte board line, a board with tens of thousands of `## Active` entries, a title of megabyte length, a corpus of thousands of generated lines. No performance bound is promised, and the differential harness's corpus is bounded by D10's axes rather than by exhaustion.
- **Boards that are not this loop's boards**: two `## Active` headings, no `# Tasks` heading, a board whose `## Active` section is absent entirely. `bin/check-handoff.sh`'s first-`## Active` semantics are consumed exactly as they stand, and the synthesized board always has exactly one.
- **TOCTOU between any gate and the write** — a board or a sibling script replaced in the milliseconds after it verified. No locking is added and the existing temp-file-then-copy write path is unchanged.
- **Hostile `$TMPDIR` or `$TEAM_TODO` values** — a path outside the repository, a FIFO, a value carrying newlines or shell metacharacters. Both are operator-supplied and consumed exactly as they already are; a `mktemp` failure is fail-closed (AC8's non-vacuity control) and no new validation is promised for either.
- **Adversarial board authorship.** The board is a trusted, committed, reviewed artifact in this repository's security model; this task adds a shape gate, not a truth gate, and asserts nothing about whether a well-formed line is *correct*.
- **Localization of any frozen reason string or header phrase.** English literals, as every other message in `bin/` is.
- **`bin/close-out.sh` invoked without `--task`, or with a `--task` absent from `## Active`.** Both are validated and refused upstream of everything this task adds.
