## Problem

Issue #277's first adoption precondition asks for the `per-instance-telemetry-discriminator` invariant — the seventh of the closed set `docs/loop-engineering/phase-multiplexing.md` locks — to be designed so that a merged hand-off record produced by an N-instance fan-out stays attributable to the role instance that produced each of its parts. Half of that already shipped: T-1072 added the nullable `instance` field to the span row with a validated grammar, T-1076 made concurrent appends safe with `--seq auto`, and T-1074 gave `bin/aggregate-verdicts.sh` a per-unit `- attribution:` line naming the part that produced each unit. Nothing ties the two halves together. No mechanism anywhere in this repository verifies that a fan-out run's span rows actually carry discriminators, that an id is not silently reused across roles, that the telemetry's instance set and the merged record's part set agree, or that an id read back off a row conforms to the grammar the writer enforces — and the same invariant is consequently declared `implemented` at three shipped sites while a fourth still records it as a follow-up nobody has discharged.

**Goal (one sentence).** A new fail-closed checker, `bin/check-fanout-instances.sh`, reads one fan-out's own telemetry rows and the merged verdict record `bin/aggregate-verdicts.sh` produced for it, and refuses — with a classified exit code and empty stdout — unless four properties hold together: every span row in the declared scope carries a discriminator (**presence**), every discriminator conforms to the writer's own grammar when read back (**grammar**), no single id is claimed by rows of two different roles inside that scope (**uniqueness**), and the scope's instance set and the merged record's declared part set are equal in both directions (**consistency**) — with the canon contradiction the invariant currently carries reconciled in a note as a layer distinction rather than by rewording any frozen record.

**What this task is, given that half of it already shipped.** The writer-side design issue #277's first precondition asks for is already in the tree: `--instance` with its grammar (T-1072), `--seq auto` for concurrent appends (T-1076), and the per-unit `- attribution:` line on the merged record (T-1074). This task is therefore **not** a re-design of the span schema and not a second opinion on the grammar; it is the reading side that was never built. The scope decision is settled here and stated as a decision rather than left to the implementer: this is a **mechanism** task that ships a checker, because a design-only deliverable would restate T-1072's already-frozen design and would unblock nothing for T-1083, which needs something that can actually refuse a mis-attributed fan-out.

**Where each of the four properties is enforced, and why not in the existing linter.** All four are enforced in the new checker and in no existing one. `bin/check-run.sh` stays structural: T-1072 settled that `instance` "is validated by the **writer only**" and that the linter does not charset-check it, exactly as it does not charset-check `provider` or `adapter`, and its own header says so at lines 24–26. That decision is **not reopened** — it is honoured by placing the reading-side grammar check in a fan-out-context checker that only ever runs against a scope a caller declares to be a fan-out, so a span row carrying an arbitrary `instance` string stays valid under the general linter exactly as it is today. Enforcing presence in the general linter would be worse than useless: the overwhelming majority of rows in every corpus carry `"instance":null` legitimately, and the orchestrator's own convention emits gate cost as `--span orchestrator --phase gate` with no instance at all.

**How the scope is declared, and why a scope selector exists at all.** The checker verifies one fan-out, named by the caller: `--telemetry <file> --run-id <id> --phase <phase> --aggregation <file> --label <label>`, with optional `--iteration <n>` and `--attempt <n>` narrowers that further restrict the row set. A run's telemetry legitimately mixes rows that were never part of any fan-out — event rows, orchestrator gate spans in another phase, and a serially-executed earlier round of the same phase — so a file-wide rule would be wrong rather than strict. The selector is AND-composed and boundary-anchored per key. A scope that spans both a serial round and a fanned round of one phase is a **caller** error, not a checker limitation: it refuses `missing-instance` and the remedy is to narrow with `--iteration`/`--attempt`, which is stated in the help text rather than papered over. `--aggregation` and `--label` are **required**, with no degraded telemetry-only mode: the consistency property is the entire reason this checker exists, and a mode that skipped it would let a caller obtain a pass without it.

**Why no third `is_span_row()` copy is written.** T-1011 hazard H4 — two deliberately duplicated `is_span_row()` implementations kept honest by `tests/is-span-row-parity/` — is not extended to a third site. Selection is by the required span-only keys the scope already names: an event row carries no `phase` key at all, so it is never selected, and a selected row carrying `"kind":"event"` is refused as `malformed-row` rather than silently skipped. The parity suite and both existing copies are untouched.

**The refusal contract, aligned with the sibling tool rather than colliding with it.** Exit codes carry `bin/aggregate-verdicts.sh`'s meanings unchanged: `0` success, `1` a refusal about the **content** of the rows or the block, `2` a **usage** error about the invocation, `3` a refusal because the fan-out is **incomplete** — the case whose remedy is to re-run or re-emit rather than to re-read. On every non-zero exit stdout is empty and exactly one classified line `check-fanout-instances: <class>: <detail>` reaches stderr, with `<class>` drawn from a closed vocabulary the script's own header enumerates and from no other. On success exactly one line reaches stdout and stderr is empty. The check order is fixed so a fixture carrying two defects reports deterministically: block parse first, then per-row shape, presence, grammar, uniqueness, unattributed ids, and the exit-3 coverage check last — the same reason `bin/aggregate-verdicts.sh` puts its own exit-3 check last, that the class whose remedy differs from every other refusal's is the one reserved for last.

**What the canon reconciliation does and does not touch.** The invariant is declared `implemented` at three shipped sites and `named as a follow-up only` at one. Both are true at different layers, and the reconciliation says so in a note rather than rewording either: the three shipped sites describe **writer-side usage**, which genuinely is implemented and was deliberately worded that way (`.shell-team/provenance/T-1074.md` lines 19–21), while `docs/loop-engineering/phase-multiplexing.md` line 351 is T-1069's historical record of what that task itself did under its own `no-mechanism` class. ## Pre-commitment (AI self-discipline, self-imposed at freeze; **not** operator-ratified)

- **Factual trigger**: two consecutive review rounds of independent new defects against the same component. **Contextual condition**: executed before a third round starts. Where the two disagree, the factual trigger governs.
- **Droppable, in this order**: (1) the **consistency half** — the `--aggregation`/`--label` block reader and the classes `unattributed-instance`, `uncovered-part`, `malformed-block`, `duplicate-block`, `block-not-found`. Dropping it leaves a checker that still enforces presence, grammar and uniqueness over a declared scope, with the block reader and its five classes carried to a new fast-follow issue together with **both rounds' findings as its re-landing requirement list**, not re-derived there. (2) the **prompt-block wire-in and its adopter clause**, dropped to the same issue, leaving the checker shipped but invoked manually.
- **Never dropped**: the telemetry-side half (presence, grammar, uniqueness) and the fail-closed exit contract (classified codes, empty stdout on refusal). Their defeat across consecutive rounds stops the task and returns it to planning, because a discriminator checker that cannot hold those is evidence about the design premise rather than about the implementation's craft.
