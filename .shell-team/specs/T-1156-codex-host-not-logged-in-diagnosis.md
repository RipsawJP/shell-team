## Problem

On a Codex CLI host, the cross-provider review runs the shipped `claude -p` line from `templates/prompt-blocks/host-dispatch.md`. Run inside the Codex sandbox, that line exits `Not logged in`, even though the host's own Claude Code CLI is logged in. In the adopter run behind issue #593, the session had to work out for itself that this was a sandbox problem rather than a logout, and improvised the recovery (re-running the same line outside the sandbox, which worked). The recipe is the Codex host's only cross-provider review path, so every Codex-host run pays one failed pass plus a diagnosis the session has to invent. The mirror case on the Claude Code host (`codex exec` inside the Claude Code sandbox, issue #586 / T-1152) already ships its diagnosis. The Codex-host side has no matching sentence.
