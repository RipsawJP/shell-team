## Problem

On a Codex CLI host, `code-reviewer`'s review pass runs `claude -p` inside the Codex session's sandbox. At that sandbox's default network setting the call fails with `Not logged in · Please run /login` — a network refusal that reads exactly like an authentication failure. The diagnosis that separates the two already ships in `docs/adopting.md` steps 7–8, but the text the running reviewer and orchestrator actually read at that moment (`templates/prompt-blocks/host-dispatch.md`, spliced into `skills/run/SKILL.md`) only names the symptom and says "handle it like a `codex` failure". In an adopter run this produced a report that read the symptom as a login problem, and the operator had to correct the diagnosis by hand (relayed). There is also a sequencing trap: `codex-capture.sh --publish` never sees the `claude` exit status, refuses silently (exit `3`) on a capture with no typed event or an empty `.out`, and its EXIT trap deletes both raw files — so the exact error must be read from the raw capture before cleanup or publish, or it is gone.

## Input space

**Reachable input classes** — what a real Codex-host review pass can leave in `<RAW_JSONL>` and in its exit status:

1. The network-refused failure at the sandbox's default `network_access = false`: `Not logged in · Please run /login` in the raw, with a non-zero exit, **or** an exit `0` and no typed result event, **or** an exit `0` and a typed `result` event marked `is_error` (which shape occurs is unmeasured; the rule treats all three identically, and the third is the one that would otherwise pass `--publish`).
2. A genuine authentication failure of an installed but unauthenticated CLI: the identical `Not logged in` text, inside or outside the sandbox — the isolation call is what tells it apart from class 1.
3. A missing `claude` binary: `command not found` in the raw, non-zero exit, no `Not logged in` — the rule's general half (read the raw, report the exact error) applies; the `Not logged in` guidance does not.
4. Any other non-zero failure whose text carries no `Not logged in` (a rate limit, a transport error, a CLI crash) — same as class 3.
5. A raw that holds only non-result typed events (for example a `system` init line) and no `"type":"result"` line — "no typed result event", handled as in class 1 when its text carries `Not logged in`, as in class 3 otherwise.
6. A successful pass: exit `0` and a typed result event not marked `is_error` — the rule does not fire; alloc/run/publish proceeds unchanged.
7. The readers of the rule: the spawned `shell-team-code-reviewer` on a Codex CLI host, and the orchestrator reading `skills/run/SKILL.md`; an adopter reading `docs/adopting.md` / `.ja.md` step 8.

**Out-of-scope synthetic extremes** — declined explicitly:

1. A future Claude Code CLI that changes or localizes the `Not logged in` wording, or a Codex CLI that renames `sandbox_workspace_write.network_access`.
2. An unreadable, symlinked, truncated-mid-write or binary `<RAW_JSONL>`.
3. The Claude Code host's own review path (`codex exec`), which this rule does not govern.
4. A sandbox mode other than `workspace-write` (for example `danger-full-access`, where no network refusal occurs).
