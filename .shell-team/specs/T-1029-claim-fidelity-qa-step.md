## Problem

Two v1.4.0 tasks shipped frozen prose that flattened a distinction its source document drew — a scored population and its excluded remainder collapsed into one total, and a per-case requiredness contract restated as uniformly optional. QA passed both, because nothing in the pipeline named the source document or required anyone to open it; the criterion walkthrough compared the implementation against the spec's own paraphrase, which is exactly where the distinction had already been lost. Both were caught only by the cross-provider round, where the source itself was opened. The 2026-08-04 retro's adjudication promoted the discipline into the lessons corpus (entry `2026-08-04 — A summary of another document preserves the source's own distinctions…`, shipped by T-1027), but only its `Rule` field is transcribed into the generated playbook blocks — `bin/gen-playbook-blocks.sh` never transcribes `How to apply`, by design, and `How to apply` is where this entry's mechanism lives. So both roles now carry the exhortation and neither carries the step.

### Settled decisions

Each decision below is resolved; nothing here is left to implementation judgment. The three texts this task ships are frozen byte for byte, and every acceptance criterion reads its expected bytes **out of this file** rather than restating them in a shell quote — every one of them contains apostrophes, backticks and em-dashes that no single shell quoting style survives intact.

**Term definition, settled before the mechanism (a term with more than one plausible referent).** "Source" already has three referents in this repository's specs, and the new slot claims exactly one of them.

| Candidate referent | Existing carrier | In scope for `## Summarized sources`? |
|---|---|---|
| The task's originating tracker item or retro | the ad-hoc `**Source**:` metadata line (e.g. `.shell-team/specs/T-1027-promote-retro-2026-08-04.md`) | **only when the spec restates its facts** — origin alone does not put it in the slot |
| A document whose facts the spec restates (a count and its breakdown, a contract's per-case requiredness, which outcomes a mechanism can reach) | nothing — this is the gap | **yes; this is the slot's referent** |
| Files read while drafting, with no fact carried into frozen prose | the ad-hoc `**Authoring sources**` line | **no** — a reading list is not a summary, and requiring one would make the slot noise |

- **D1 — the slot sits OUTSIDE the intent block, immediately after `## Problem` and before `## Goal`.** Inside would change the frozen region's 4-part composition (Goal + Non-goals + Acceptance criteria + Input space), whose description is scattered across many files including the class-M surfaces T-1028 has just shipped; a fifth part would owe all of them an edit, for a task that is deliberately narrow. Outside also gives the right mutability: naming a further source part-way through a rework is then an ordinary edit rather than a re-freeze, which is what keeps the declaration honest instead of expensive. And it works for adopters who do not use intent blocks at all — the slot coerces no one into freezing. "Visible at freeze time" is satisfied by adjacency: the section is the last thing above the `## Goal` heading where the freeze region begins.
- **D2 — the slot is a heading section (`## Summarized sources`), REQUIRED, with an explicit sentinel `not applicable — <reason>` when a spec summarizes nothing.** Shape: the `## Input space` precedent, not a single grep-able key line — a spec can summarize more than one document, so a key line forces cramming or silently caps the declaration at one; a heading is exactly grep-able anyway (`grep -qxF '## Summarized sources'`), so the key-line form's supposed mechanical advantage is not real; and a second declaration shape would fragment a vocabulary that already has one. Requiredness with a sentinel, rather than "write it when it applies": the defect class survived **precisely because omission was silent** — an absent section is indistinguishable from "nothing to declare", so the author who never considered the question and the author who considered it and found nothing produce identical bytes. **What the one line costs and buys**: it costs one line in every spec that summarizes nothing, written by the role that is already writing the spec; it buys a falsifiable declaration — a reviewer, a QA round, or a later reader can point at the sentinel and disagree with it, which is impossible with an absence.
- **D3 — the QA item takes the shape of the existing mandatory items** (`agents/qa-verifier.md`'s intent / provenance / interventions bullets), with six properties, each of which is a directive and each of which is machine-visible in the frozen text (AC4): **(i)** it fires only when the section is present *and* not the sentinel — a spec with no such section keeps the prior behavior unchanged, so the rule is forward-only and backward compatible, exactly as the `## Input space` consumers are; **(ii)** its **scope is every site in the frozen region that restates, quotes or summarizes** a named source's facts — the Goal sentence, a Non-goal, a criterion's prose, an Input-space clause, a settled-decision paragraph inside the marker pair — **plus the `## Summarized sources` declaration line, which D1 deliberately places outside that region and which is therefore an additional checked site rather than a member of it, and never a substitute for the sites above**; for a spec with no intent-block markers the same reading runs over its `## Goal`, `## Non-goals` and `## Acceptance criteria` sections, so an adopter who does not freeze is still covered. This is the load-bearing property: **the two incidents this task comes from flattened a count and a per-case requiredness contract inside frozen criteria, not inside a declaration** — neither spec even had a declaration — so an item that checks only the declared one-liner would certify the one sentence that was never wrong. **(iii)** it is **not** subject to the `out-of-input-space` exemption, like the other three mandatory items; **(iv)** the verdict carries one line per named source — the path or locator, the sites checked, the distinction claimed, and the result — because a single blanket "sources checked" sentence is the same flattening this task exists to close, one level up; **(v)** a source that cannot be opened from the session is recorded with the **existing** `environmentally-unverified` vocabulary (`agents/qa-verifier.md`'s Adversarial fixture synthesis checklist; `agents/codex-reviewer.md`'s issue-canon rule already reuses it for the identical reason) — **no new token is invented**, and an unreachable source does not by itself force a FAIL; **(vi)** an explicit prohibition — re-reading the spec's own paraphrase, or re-deriving the claim from the spec's wording, verifies nothing, which is the precise failure mode the two incidents took. A flattening found inside the frozen region is reported as a finding like any other, with its location stated, because the repair is a class-B re-freeze routed through pm-spec rather than an engineer edit to hashed bytes — the generic route-back already exists for every other mandatory item and F3 names it here only so the verdict says *where* the defect sits.
- **D4 — the parallel-surface symmetry audit covers five roles and only two of them move.** The table is in the body below, outside the frozen region, with each cell marked present / mirrored-now / not-applicable-with-a-measured-reason. `agents/codex-reviewer.md` is **not-applicable**: it receives no playbook injection by design (its own Rules state the evaluator-independence design), and it is the surface that already caught both incidents by opening the source — mirroring the item there would add an obligation to the one gate that demonstrably performs it. `agents/engineer.md` and `agents/tech-lead.md` are **not-applicable** on the corpus entry's own adjudication: E1's `Applies-to` is `pm-spec, qa-verifier`, because in both incidents the engineer's transcription from a frozen block was byte-exact and correct — the defect was authored upstream and missed downstream. AC8 is the machine half of all three not-applies (those files are byte-identical to the base ref); AC10 pins E1's `Applies-to` line so the ground itself is measured rather than asserted.
- **D5 — instruction-only: no new `bin/` script, and no change to `bin/check-acs.sh`, `bin/check-intent.sh` or `bin/check-refreeze-class.sh`.** Three grounds. (1) The `## Input space` precedent is exactly this: no checker enforces that section's presence either, and its three consumers (pm-spec's self-check, qa-verifier's grounding Rule, codex-reviewer's severity rule) are prose that falls back to prior behavior when the section is absent. (2) The property that matters — *was the source actually opened and matched clause by clause* — is not observable by any command; a checker could only assert that a section exists, which would buy the appearance of enforcement over the part that already works. (3) A checker demanding the section in every spec would retroactively fail every spec merged before this task (measured by pm-spec with a repository-wide search of the **working tree at the branch point, before this task's own files were written**: zero occurrences of the string `Summarized sources`; the freeze run re-measures it against the base ref itself), so a fail-closed gate here would be a backward-incompatible gate over frozen artifacts. What a spec *may* do is exemplified in F2 rather than built: where a named source is a file in this repository, a criterion may carry a `check:` clause asserting the file is readable and its cited anchor still present — and F2 states the limit of that clause in the same breath, so it is never mistaken for verification of the reading.
