## Problem

The corpus's verification protocol — a full-population blast-radius diff over every merged spec at two refs, the full CI-equivalent step list, a fixed mutation-probe matrix, an open-ended adversarial review scope — was designed for tasks that change executable behaviour. Editorial and prose tasks inherit it whole and unpriced, through two orchestrator-controlled channels: pm-spec writes the corpus-standard runtime criterion into a prose task's spec and the freeze attests it without asking what the marginal information is worth, and the review briefing invites the cross-provider reviewer to police process completeness at `Major` severity, which compels more of the same. The cost is measured, not theorised: a four-line template fix (T-1062) spent its whole engineer phase on it and drew four review rounds and an operator STOP escalation; an editorial batch (T-1063) was heading into multi-hour fixture re-runs to confirm that specs reading none of the six edited files had not changed, and was stopped mid-sweep at 16 of 67 specs; the pricing established by hand for T-1064 converged in one round each. Nothing in the shipped norms carries that pricing, so the next prose task re-invents it or pays the code-task price again.

**DP2 — the read-set form inherits the blind spot the full-population method exists to close, so it carries that blind spot explicitly instead of silently.** The existing item's ground is that a criterion reaching its target through indirection — a path built at run time from `bin/team-paths.sh --get todo`, a file named only through a variable — matches no search for that path's literal bytes and is invisible to a string-search method **in principle**. The tier therefore requires, for a `no-mechanism` task, that the indirection class be **named** and discharged in one of exactly two ways: by running those criteria too, or by disclosing in the spec precisely what stays unmeasured.
