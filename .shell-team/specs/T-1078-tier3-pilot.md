**Base ref / branch point — one discriminator for the whole spec.** Every base-side blob read in this spec reads **the branch point**, resolved at check time by one two-arm expression that every criterion spells identically: try the predecessor branch `feature/1077-worktree-reconcile` first, and fall back to `develop` only when that branch no longer resolves. The choice is stated once and applied uniformly, because two refs in one document is exactly the inconsistency a sibling-clause cross-check exists to catch.

The two arms exist because the correct ref has two eras, both measured rather than assumed — the same reasoning shape `.shell-team/specs/T-1077-worktree-reconcile.md` (lines 7–11) states for its own stack, re-anchored one car forward. **Today**, this task's branch is stacked on PR #303 (`feature/1077-worktree-reconcile`), which is **open and unmerged**, and PR #296 (`chore/lesson-promotion-2026-08-16`) is open below it, so `develop`'s tip contains neither: a bare `develop` spelling would put both open cars' files permanently inside every `<base>...HEAD` range, making this spec's byte-identity and scope-lock criteria structurally unsatisfiable rather than merely red. **After the batch GO**, both cars merge and their branches are deleted; `git merge-base develop HEAD` then resolves the same commit the first arm resolves today, because `develop` has come to contain it. The two-arm form is therefore not a hedge between two candidate refs — **both arms resolve the same commit, each in the era where it is the one that can**. The first arm is written as `git merge-base "$BR" HEAD` rather than as a `rev-parse` of the branch tip on purpose: a rework round that advances `feature/1077-worktree-reconcile` after this branch was cut moves that branch's tip but not the common ancestor, and the common ancestor is what "branch point" means here.

The fallback is written as an explicit branch-existence test rather than as a `2>/dev/null ||` chain on purpose: a `||` chain cannot distinguish "the predecessor branch is gone" (the expected era change, which must fall back) from "`git merge-base` failed for some other reason" (which must fail closed), and collapsing the two would let a broken read silently resolve a different, earlier commit. Each arm's own failure still exits non-zero. One residual case is disclosed rather than engineered away: if the predecessor branch were deleted **without** merging — an abandoned car — the second arm would resolve `develop`'s tip, which is not this branch's point; that scenario invalidates the whole stack this task sits on, and is a route-back rather than something a criterion should paper over. No 40-hex literal is written into any criterion: every criterion resolves the ref itself and fails closed when it does not resolve. The one 40-hex value this task's deliverable does carry — the raw-evidence commit — is read out of the note's own text at check time (**AC11**), never typed into a check.

## Problem

`docs/loop-engineering/phase-multiplexing.md` prices Tier-3 work-splitting — partitioning one feature's implementation across N engineers each owning a disjoint file set — as `not-yet`, with a break-even model that is explicitly symbolic: its `- break-even: partition-overhead` parameter reads `undetermined`, and its `- break-even-condition:` says in as many words that the condition "cannot be evaluated numerically today." Two things have changed. First, the named blocker is gone: T-1077 shipped `bin/land-worktree.sh`, so N-way landing is now a mechanism rather than a sketch. Second, the model as written carries two defects that survive independently of the blocker — issue #277's recorded erratum (the stated inequality omits the `partition-overhead` and `rework-amplification-input` terms while citing the first as the reason the model is unevaluable), and a second mismatch: the `- break-even: reconcile-cost` parameter is modeled on a rebase-and-re-verify-per-pending-worktree shape that the shipped mechanism does not have. Until a pilot actually runs, the tier's disposition rests on a model nobody can evaluate and on a cost term describing a mechanism that was never built that way.

### Verdict scope (operator-ratified)

**Authorship: operator-ratified.** The primary record is the `- intervention: human-correction` entry dated 2026-08-14 in `.shell-team/interventions/T-1066.md`. This section restates that ruling for the gates that read this spec; it is not this spec's self-discipline and it is not re-litigated here.

For this deliverable — a quantitative research note whose purpose is to inform a decision about restructuring how the loop spends machine time — **deliverable correctness means two things**, and a finding against either is verdict-gating: (1) the **computed values** are correct, meaning each figure names the source it was read from and reproduces when the command quoted beside it is re-run; and (2) the **conclusions' direction** is right, meaning what the note says its numbers support is what they support — the two prices, the corrected inequality's terms, the saving's confidence word and the tier's recommendation.

**Connective prose is not verdict-gating.** A finding about a sentence that joins, summarises or characterises values that are themselves correct — a totality word whose domain is wider than its command's, a label mismatch, a stale count in a narrative aside, an imprecise summary — is recorded as a **note** in the review record and does not on its own produce `REQUEST_CHANGES` or `FAIL`, provided every computed value it touches is correct and no conclusion's direction moves. **No escalation ratchet is created over prose classes**: repeated findings of a connective-prose class do not raise a gate's severity, do not create a halt condition, and do not on their own trigger a rework round; they accumulate as notes and are dispositioned at close-out.

**D1 — the pilot's subject is real-shaped and lives in a throwaway clone, and the two rejected alternatives are named with their reasons.** The subject is a partitionable implementation task authored for this pilot and executed entirely inside a throwaway clone under `$TMPDIR`. **(a) A real backlog task was rejected**: it confounds the measurement with its own QA and review gates, whose rounds this pilot does not control, and it writes to the real repository, which puts a live task's deliverable inside a measurement's blast radius. **(b) A replay of a past task was rejected**: a replay cannot produce a live rework round, and rework amplification is one of the two prices this task exists to measure. What (a) costs is stated rather than hidden: a purpose-authored subject is one task of one class on one day, so nothing here generalises to "features" in the plural, and the Limits say so. The licence rule inherited from T-1069's DP-D(a) governs throughout: `measured` is available **only** for what this pilot's own arms actually ran, and for nothing else.

**D2 — the venue, and the one line that must never be crossed.** `git worktree add` runs **only inside the throwaway clone**, never in the real checkout: registering worktrees against the real checkout makes teardown a destructive operation, which is the precedent T-1069 and T-1073 both set and neither crossed. The coordinator branch is never checked out in the clone, because `bin/land-worktree.sh` refuses (`structural`, exit 2) an `--onto` that is checked out in any worktree of the repository. After every arm, the **real checkout** is measured clean on both halves — `git status --short` and `git ls-files --others --exclude-standard` each read empty — and the outcome is recorded either way rather than assumed. Teardown removes the throwaway clone directory itself; no `git worktree remove`, no `rm`, and no git verb of any kind is aimed at the real checkout. Every agent instance the pilot launches has a liveness check started at the same moment it is launched, through a harness-tracked background launch — a watchdog started with a bare shell `&` inside a foreground call dies with that call, which `docs/loop-engineering/harness-agent-concurrency.md` measured directly.

**D3 — the arms, the frozen wall-clock definition, and the fairness conditions.** The **serial arm** (`serial-n1`) is one engineer instance implementing the whole subject task from the same start tree the parallel arm's workers start from. The **parallel arm** (`parallel-n2`, and `parallel-n3` where budget allows) is N engineer instances, each owning a file set fixed as disjoint **before any of them launches**, whose committed work is landed one at a time through `bin/land-worktree.sh` onto one coordinator branch. Wall clock is defined once, frozen, and applied identically to every arm: **t0 is the orchestrator's own launch call for that arm**, and **the arm ends at the last completion notification plus that arm's own landing spans** — so the parallel arm pays for its landings and the serial arm does not, which is the honest comparison rather than the flattering one. Launch latency is disclosed rather than subtracted: `docs/loop-engineering/harness-agent-concurrency.md` measured ≈14.3 s to ≈32.8 s across ten launches, mean ≈20.7 s, and that note is cited as the source rather than re-measured here. Reps run as the budget allows; spread is disclosed descriptively per arm and **no inferential statistic** — no significance test, no confidence interval, no regression — is computed or implied anywhere.

**D4 — what licenses the word `measured`, mechanically rather than rhetorically.** A closed set of six legitimacy ids, each recorded `met` or `not-met` with its own evidence: `production-unit` (the units are real Agent-tool engineer instances invoked through the harness, not a shell-process proxy), `real-mechanism` (every landing ran through the shipped, unmodified `bin/land-worktree.sh`, never a hand-rolled merge), `same-machine-session` (every arm ran on one host in one continuous session), `disjoint-partition-fixed-before-launch` (the partition manifest was written and fixed before any arm launched and never re-partitioned after an outcome was seen), `arm-completion` (every arm this note prices ran to completion; a dropped or aborted arm is `not-met`), and `repetition-variance` (every priced arm ran at least two reps and its spread is disclosed). **If any one of the six reads `not-met`, no `- saving:` line anywhere in the note may carry `measured`** — the coupling is mechanized in **AC5** rather than left to a reader's discipline, and the honest outcome it produces (a `modeled` or `undetermined` saving and a `not-yet` recommendation with the failing condition named) is an acceptable result of this task, not a failure of it.

**D5 — the two prices, and exactly how far each one's measurement reaches.** **`partition-overhead`** is the sum of two components measured separately and reported separately: the **partition-authoring cost** — the wall clock spent producing the disjoint file set and the interface agreement the workers are held to — and the **serialization cost** — the landings' own wall clock, read off the landing spans rather than estimated. **`rework-amplification`** is measured by seeding **one** cross-partition defect deliberately and observing how many owners a single rework round forces: whether a finding that spans the partition boundary reworks one owner or N. That measurement licenses `measured` **for the seeded class only**; real-gate-driven rework rates stay `modeled` against the canonical `rounds-to-approve` series the note already cites, and the note must say so in the same place it reports the seeded result. Where an arm is dropped, its parameter is recorded `undetermined` with the reason — **never** a guess, an interpolation or a figure carried over from a different arm.

**D6 — the inequality correction, which is this task's core deliverable and is owed even if every arm is dropped.** Two defects are fixed together in the one `- break-even-condition:` line the note carries. **(i)** Issue #277's recorded erratum: the stated inequality omits `partition-overhead` and `rework-amplification-input` from its sum while its trailing clause cites the first by name as the reason the model is unevaluable — an internal inconsistency in the symbolic model's own presentation. The corrected line states every term it depends on inside the inequality. **(ii)** A second, independently measured mismatch: `- break-even: reconcile-cost — modeled —` prices a rebase of each pending worktree plus a re-run of the verification gate plus a `--ff-only` merge, but the mechanism that shipped never rebases — `bin/land-worktree.sh` composes trees and writes two-parent commits, and `skills/run/SKILL.md`'s reconcile step freezes the gate policy as mechanical verification per landing with the two agent gates run once against the final composed tip. The corrected parameter prices the mechanism that exists: a per-landing composition and mechanical verification, plus exactly one pair of agent gates for the whole composition rather than one pair per pending worktree. Both halves are base-relative and demonstrable: the branch point's own blob carries the uncorrected forms, and **AC2** and **AC3** compare against it rather than asserting the corrected text in isolation.

**D7 — the note's existing label vocabulary is closed against this task, and new content gets new labels.** Every labelled line already defined in the note's Terms section belongs to T-1069's measurements and to criteria that count them: `- pilot-arm:`, `- measured-label:` and `- pilot-safety:` are each closed by a merged criterion over a fixed id set with a total-count equality, and `- population:`, `- cores:`, `- liveness:`, `- tier:`, `- saving:`, `- recommendation:`, `- dividing-line:`, `- aggregation-check:`, `- invariant-lock:` and `- break-even-condition:` each have a fixed cardinality a merged criterion asserts. ## Input space

**Reachable input classes** — what this pilot, its analysis and its criteria really encounter, and which this task must handle correctly:

1. **A real Agent-tool engineer instance that stalls, returns partial work, or returns work outside its declared file set.** All three are reachable from the harness this loop runs on; each is recorded as an arm outcome (`arm-completion` `not-met` where the arm cannot be priced) rather than smoothed over, and the out-of-partition case is exactly what `bin/land-worktree.sh` refuses on.
2. **Every refusal class the shipped coordinator can return** — `overlap`, `diverged`, `empty-landing`, `ref-moved` (exit 1), `usage` and `structural` (exit 2), `lock` (exit 3). A landing that refuses is a measurement, not an accident: the exit class and its stderr line are recorded verbatim in the evidence region.
3. **A launch latency between roughly 14 and 33 seconds per instance**, already measured on this host class, which is a material fraction of a short arm's wall clock and is therefore disclosed beside every arm rather than netted out.
4. **A host on which `timeout` does not resolve.** This project's own development host is macOS, where neither `timeout` nor `gtimeout` is present by default; the liveness control actually used is recorded rather than assumed.
5. **A seeded cross-partition defect that the mechanical verification happens to catch.** The seeded defect is chosen to span the partition boundary, but whether the per-landing mechanical verification sees it is an outcome, not an input — and if it does, the rework-amplification arm measures a different thing than intended and says so.
6. **A partition whose two file sets turn out to be interface-coupled in practice.** Path-disjointness is textual; a signature one worker changes and another calls is reachable and is precisely the class the shipped mechanism does not guard, so it is a possible pilot finding rather than a pilot failure.
7. **The real checkout being non-clean for a reason unrelated to the pilot** — an editor's scratch file, a concurrent process. The cleanliness reading is taken and recorded either way; a dirty reading is investigated and disclosed, never overwritten by a second, cleaner reading.
8. **The merged spec corpus growing while this task runs.** Every criterion above is presence-, structure- or delta-shaped for exactly this reason; none compares a declared population figure against a live re-derivation.
9. **A note line carrying an em dash, a backtick-quoted grammar, or a path with a dot** — the note's own line grammars are the parsed surface here, and both this task's criteria and four merged specs' criteria read them.
10. **A budget that permits fewer reps than the legitimacy set requires.** Reachable and expected; its consequence is a `not-met` on `repetition-variance` and a saving that may not read `measured`, which the coupling in **AC5** enforces rather than leaving to judgment.

**Out-of-scope synthetic extremes** — inputs this spec explicitly declines to protect, named concretely so the boundary is falsifiable:

- **Concurrency degrees beyond three.** The arms are `n=1`, `n=2` and, budget permitting, `n=3`; escalating that ladder to four, eight or an arbitrary N is not a defect this spec accepts, and no claim here is made about degrees the pilot did not run.
- **Statistical power.** Two reps per arm on one host on one day supports a descriptive spread and nothing more. A demand for significance testing, confidence intervals, a regression or a repeated-measures design is declined outright, and the Limits say so.
- **Generalisation to arbitrary task classes.** One purpose-authored subject task of one shape is measured. Any escalation of the form "but a larger / different / more coupled feature would behave differently" is correct and is exactly why the recommendation is scoped, not a finding against the pilot.
- **Adversarial or misbehaving agent instances** — an instance that deliberately writes outside its partition, edits another instance's worktree, or tampers with the coordinator branch. The shipped mechanism's refusals are the whole of the defence and no threat model beyond them is built here.
- **Cross-host, network-filesystem or multi-machine execution.** Everything runs on one host, on a local filesystem, in one session.
- **A general spec-partition grammar's cost.** The pilot measures the cost of authoring **one** partition for **one** subject. What it would cost to make partition-authoring a standing discipline across a corpus of specs is not measured, not modelled and not estimated.
- **Token cost and dollar cost.** No vendor price model, no token accounting per instance, no monetary figure appears anywhere; the recorded telemetry does not isolate a partitioned engineer sub-task's own token cost from a phase total, and inventing one would be an estimate rather than a measurement.
- **Reproducibility of the wall-clock figures on another machine.** The measured numbers are properties of this host, this harness version and this day, exactly as the Tier-1 pilot's knee already is.
