## Problem

A frozen intent block is the record the loop is judged against, so it must not move while the party being judged holds the pen. Today that protection is absolute: **every** re-freeze needs a per-instance human GO, whatever moved. T-1004's BLOCKED escalation (2026-07-30) is the cost — a frozen `check:` line contradicted another frozen criterion (one criterion's check forbade any `agents/` diff while another mandated one), the only repair was a one-line, meaning-preserving check-line fix, and the loop had to stop and wait for a human whose contribution to that decision was a signature, not a judgment.

Issue #47 verbalized what in that GO actually needs a human. Fact-finding is already machine territory. Meaning-preservation is a reading judgment the loop's own reviewers can make. What the human genuinely supplies is **independence from the implementing interest** — and independence can be supplied structurally: a mechanical boundary on *what* may change, plus the cross-provider reviewer as a second key. The gap this task closes is that the boundary exists only as prose in an issue: there is no checker that can say "this delta is confined to `- check:` lines", no record shape that makes a delegated re-freeze auditable after the fact, no mandatory review item that can revert one, and no shipped documentation telling an adopter that the knob exists or where their answer goes. A second, quieter gap: the board retains exactly one intent-hash record per task (a superseded hash is discarded), so once a re-freeze lands, nothing on the board can even name the bytes that were replaced.

## Goal

<!-- BEGIN intent-block: T-1028 -->

The loop can repair a mechanically broken frozen `check:` line without a per-instance human GO — but only when a machine says the delta is confined to `- check:` lines, only when an operator has granted that authority in their own checkout, only with an auditable record naming the class, the trigger, the superseded hash and every replaced line with its replacement, verbatim, and only with a mandatory cross-provider review item that reverts it by restoring the superseded block as a new ratified version. Everything else — a Goal sentence, a Non-goal, a criterion's prose, an Input-space line — stays a human's to amend, and the shipped default with no grant stays exactly what it is today: a per-instance human GO. `bin/check-intent.sh` is byte-identical to the base ref, its exit contract and its consumers are untouched, and the board's one-hash retention rule is unchanged.

### Settled decisions

Each decision below is resolved. Nothing here is left to implementation judgment. Every measurement attributed to the tech-lead was taken from a live reading of the real files; the engineer re-verifies rather than inherits.

- **D1 — M1's machine check ships as a NEW standalone script, `bin/check-refreeze-class.sh`; `bin/check-intent.sh` is not touched (issue #47's option (b)).** The old block it compares against is supplied by the caller, because that is where the old bytes actually live: at the moment of a re-freeze the spec's working-tree copy still holds the vK block, and the `aligned` run immediately before the edit is what makes capturing it authentic. Options (a), (c) and (d) are refused, each for a measured reason. **(a) a new mode on `check-intent.sh`** multiplies the argument space and the classification vocabulary of a script whose confirmed consumers are the run skill, the goal skill and `qa-verifier`, each of which branches on its exit contract `0/1/2 × {usage, structural, attestation, drift-detected}`; the highest-risk surface in this task would then be the one file that must not move. **(c) retaining the superseded vK hash in the ratified-record grammar** changes the ledger's shape for every existing record and still cannot classify a delta — a bare hash answers "did it change", never "did only check lines change" — unless a second, check-stripped hash is stored too, doubling the record surface. **(d) records plus a review item with no machine check** is precisely the interim state issue #47 describes as "until it exists"; this task is the "it". Forbidden in the chosen option as in every other: **no git-history walk inside the classifier** — the only `git` subcommand it may invoke is `hash-object` (`bin/check-intent.sh`'s rework5 tombstone, its header comment's "never reintroduces a board-git-history walk, in any form, for any judgment"; the same reasoning binds a sibling checker built for the same ledger).
- **D2 — the classifier carries its own exit contract, and no existing contract or sentinel changes.** `bin/check-refreeze-class.sh` exits **0** with `check-refreeze-class: mechanics:` on stdout, **1** with `check-refreeze-class: class-b:` on stderr, and **2** with `check-refreeze-class: usage:` or `check-refreeze-class: structural:` on stderr. `bin/check-intent.sh`'s exit codes, classification tokens and stderr messages are byte-unchanged, so **`skills/goal/SKILL.md` needs no new reserved sentinel and gains no condition**: the goal loop's completion gate keeps exactly the conditions it has today, because a re-freeze is an orchestrator step in the run skill's Specify branch, never a completion condition. That non-change is locked by AC14 rather than merely asserted — a change to a completion gate's condition count would drag a contamination and sentinel-distinctness audit behind it, and the cheapest way to owe none is to provably change nothing.
- **D3 — the mechanics rule is positional and strict, and its blind spot is declared rather than papered over.** Two normalized intent blocks are `mechanics` when (i) they have the **same line count**, (ii) at least one line differs, and (iii) at every differing index **both** lines match `^[[:space:]]+- check:` — the same regex `bin/check-intent.sh` counts `- check:` lines with, so the two scripts can never disagree about what a check line is. Any insertion or deletion shifts positions and fails (i); any prose change fails (iii). The consequence, stated because it is real: a pure **swap** of two check lines between two criteria classifies as `mechanics` even though it changes meaning. That is exactly the residual risk issue #47 assigns to a named human, it is pinned as a test case (`crc-blindspot-swapped-checks`) instead of being discovered later, and it is disclosed in the classifier's own header and in both `docs/tuning-oversight` files. Two blocks that are byte-identical after normalization are **structural(2)**, not `mechanics`: a re-freeze with no delta is a bookkeeping error, and treating "nothing changed" as a pass would make the classifier vacuous on exactly the input a careless caller produces.
- **D4 — M3's record is a pair of board sub-bullets, and T-1018's pace rule is not loosened.** The existing `- intent-ratified (YYYY-MM-DD): vK→vK+1 — <human GO> — <reason>` line stays the ledger record — `bin/check-intent.sh`'s version-chain judgment must keep passing untouched — and under class M its `<human GO>` field reads `class=mechanics; standing grant: <where the grant is recorded>`, so a reader of the ledger alone can see which authority was used. The bulky elements go on a companion sub-bullet, `- refreeze-class (vK→vK+1): mechanics — trigger=<broken-as-command|vacuous|contradictory> — old-hash=<40-hex> — lines=<n> — old[1]: <the superseded line> — new[1]: <the replacement line> — evidence: <the live run that showed the defect>`, where `<n>` is the number of `- check:` lines that differ — the classifier's own `mechanics` line prints `differing=<n>`, so the number is read off the tool rather than counted by hand — and the record carries **exactly `<n>`** `old[i]:`/`new[i]:` pairs, numbered from 1 in the order the lines appear in the block and all sitting between `lines=` and `evidence:`. A repair that replaced three check lines writes `lines=3` and three pairs: D3's rule permits a multi-line mechanics repair (`crc-mechanics-two-lines` pins one), so a single pair standing in for several would break the audit promise that every replaced line is recorded verbatim. That shape is inert to the existing parser by construction: it matches none of `HASH_LINE_RE` / `RATIFIED_LINE_RE` / `ATTEST_LINE_RE`, so it is a no-op indented line inside the entry's scope. **The pace rule is unchanged for class M**: a conformant `- freeze-attestation (vK+1, …)` record still precedes the vK+1 hash, and the vK+1 attestation's own live sweep is what produces M2's evidence. `old-hash=` is the record-level answer to the board's one-hash retention: the superseded hash is quoted in the record that supersedes it, which is retention without a grammar change.
- **D5 — M4 is wired in two places, and its revert is a real operation.** `skills/run/SKILL.md` step 6 gains the orchestrator's obligation to tell `codex-reviewer` that a class-M re-freeze happened and to name both versions (F4); `agents/codex-reviewer.md`'s `## Rules` gains the reviewer's own mandatory item (F1). Both are needed and neither substitutes for the other: the reviewer cannot know a re-freeze happened unless it is told, and the orchestrator cannot make the judgment for it. `agents/codex-reviewer.md` carries **no** prompt-block marker regions (measured), so the Rules edit is a hand edit with no regeneration. **"REQUEST_CHANGES reverts the re-freeze" means**, concretely, against an append-only ledger: restore the superseded intent block **byte-for-byte** as a new ratified version vK+2, then verify the restoration mechanically by running the classifier over **two spec files** — a captured copy of the spec as it stood at the rejected vK+1, and the restored spec — with `--new-hash` set to the superseded version's 40-hex, which is the value the vK→vK+1 mechanics record retained in its `old-hash=` field and the reason that field exists; the classifier takes two positional arguments in every mode, so a `--new-hash` invocation without them is a `usage` error rather than a verification. A pass there proves the restored block is hash-identical to the superseded one under the ledger's established normalization (the same normalization every intent-hash has always been taken over), which is the strongest restoration claim this ledger can make. Then record the vK+1→vK+2 ratification plus a `- refreeze-class (vK+1→vK+2): reverted — trigger=review-rejected — …` record in the same `lines=<n>` plus numbered-pair shape, carrying `grant-status=suspended-pending-human-review`, attest and record the vK+2 hash, and surface the suspension to the human. The revert itself needs **no** new per-instance GO — it restores content the human's own last ratified record already covers and its correctness is machine-proven by `--new-hash` — while the grant's fate stays the human's, which is issue #47's own revocation trigger. A label-only revert (leaving the bytes and noting the objection) is not a revert.
- **D6 — the enforcement claim is stated at the strength it actually has.** `bin/check-refreeze-class.sh` proves a delta is confined to `- check:` lines. It never proves the replacement line means what its criterion's prose says, and it never proves the loop consulted it: whether the class-M path is taken at all is carried by an operator instruction file, which is context, not enforcement. Both documentation files say so in the register `docs/tuning-oversight.md` already established for its capture-fidelity asymmetry — a paragraph that names what is mechanically true, what is instruction-strength, and what neither proves. The three items that stay human are named there and here: **the grant itself** (transferring authority is the holder's act), **the residual-risk acceptance** (a meaning change hidden inside a check line that both the orchestrator and the cross-provider key miss — the swap case being the concrete instance), and **the revocation trigger**.
- **D7 — documentation splits by audience.** `docs/tuning-oversight.md` **and** `docs/tuning-oversight.ja.md` (a measured pair that must move together) carry the **policy and the knob**: the class-M/class-B split, that the shipped default is a per-instance human GO, that the standing grant is an operator-side line in `CLAUDE.local.md` (the file that document already names as read-last and gitignored), the byte-identical sample grant block F5, the three human-owned items, and D6's honesty paragraph. `CONTRIBUTING.md` (English only — measured: no `CONTRIBUTING.ja.md` exists) carries **this repository's mechanics**: the two board record shapes including the `lines=<n>` plus numbered-`old[i]:`/`new[i]:`-pair rule, the closed trigger vocabulary, the checker invocation with both of its positional arguments, and a pointer back to `docs/tuning-oversight.md` for the policy. This is where the retro's Try item 1 lands: the freeze-GO scope becomes findable in shipped documentation instead of only in an operator's private file.
- **D8 — this task does not dogfood its own mechanism.** T-1028's spec freezes under the pre-change rules, and any mid-task re-freeze of **this** spec uses the pre-change per-instance procedure. A mechanism may not certify the artifact that defines it: a class-M record produced by the very code under review would make a defect in that code unfalsifiable, since the record and the classifier would fail together and agree. AC14 holds the machine half — this board carries zero `- refreeze-class` records.

## Non-goals

- **Changing the shipped default away from a per-instance human GO.** With no operator grant the behavior is byte-for-byte what it is today. This project does not decide an adopter's oversight preference for them, and the class-M path is a knob, never a new default.
- **Any change to `bin/check-intent.sh`.** Not one byte (AC14). Its exit codes, its classification tokens, its stderr messages, its board parser and its consumers stay exactly as they are; a proposal to extend it is out of contract (R3).
- **Reviving ledger tamper-evidence, or any board git-history walk, in `bin/check-intent.sh` or in the new classifier.** The rework5 tombstone stands. The classifier's only `git` subcommand is `hash-object` (AC1).
- **Changing the board's one-hash retention rule**, the `- intent-hash` / `- intent-ratified` / `- freeze-attestation` grammars, or T-1018's pace rule. The superseded hash is retained *inside the new record's own text*, which is why no grammar moves.
- **Semantic drift judgment.** Whether a replacement check line still *means* what its criterion says is a reading judgment for the cross-provider reviewer and, at the loop level, S4's territory. The classifier is deliberately blind to it and says so.
- **Transcribing any private operator file's contents into a shipped file.** The documentation describes the grant's *location and format* generically and ships F5, a text written for this spec; a shipped file must not quote a checkout's own `CLAUDE.local.md`.
- **Any change to `skills/goal/SKILL.md`, its completion-gate condition count, its reserved `AC9000NN` sentinels, or `bin/goal-state.sh`.** Byte-identical (AC14).
- **Any change to other `bin/` scripts, other `tests/` suites, `templates/`, or the other agent files** (`qa-verifier`, `engineer`, `tech-lead`, `drift-evaluator`, `scrum-master`, `ui-designer`). Byte-identical (AC14).
- **A CHANGELOG entry or a version bump.** The sprint's release step owns both; this task ships the mechanism.
- **Automating the grant, revoking it, or detecting its presence from a shipped script.** The grant lives in a gitignored operator file that no shipped script reads; pretending otherwise would be the enforcement claim D6 exists to refuse.
- **Goal-external discoveries.** Anything surfaced while doing this work that is not issue #47 is filed as an issue for the next planning input and not acted on here.

## Acceptance criteria

Base ref for every `git` anchor is the literal `27f1db9`. Every check runs from the repository root, names every file it reads explicitly, asserts readability before any negative grep (so an unreadable file can never read as a clean pass), guards every `mktemp` with an immediate non-zero exit, and writes nothing outside `$TMPDIR`.

- [ ] **AC1** The classifier exists and honors the repository's shell contract: `bin/check-refreeze-class.sh` is a readable regular file, is shellcheck-clean at the pinned version, prints its own usage on `--help` and exits 0, and its source carries all four classification tokens (`check-refreeze-class: mechanics:`, `: class-b:`, `: structural:`, `: usage:`). Two negatives, both grounded: it contains no `eval`, and — the tombstone clause — the set of `git` subcommands it invokes, derived from its non-comment lines only, is **exactly** `git hash-object` (a comment-line exclusion is required because the header comment names `git log` and `git show` in the course of forbidding them; a whole-file grep would false-positive on the very sentence that documents the rule).
  - check: rc=0; S=bin/check-refreeze-class.sh; test -r "$S" || exit 1; shellcheck "$S" || rc=1; h=$(bash "$S" --help 2>&1) || rc=1; printf '%s\n' "$h" | grep -qF -- 'check-refreeze-class.sh' || rc=1; for t in 'check-refreeze-class: mechanics:' 'check-refreeze-class: class-b:' 'check-refreeze-class: structural:' 'check-refreeze-class: usage:'; do grep -qF -- "$t" "$S" || rc=1; done; if grep -qE '(^|[^[:alnum:]_])eval([^[:alnum:]_]|$)' "$S"; then rc=1; fi; g=$(grep -v '^[[:space:]]*#' "$S" | grep -oE 'git [a-z][a-z-]*' | sort -u); test "$g" = "git hash-object" || rc=1; test "$rc" -eq 0

## Input space

**Reachable input classes** — what the new classifier and the criteria above really read, and must handle correctly:

- **Spec files as this repository writes them**: UTF-8 markdown with LF endings (occasionally CRLF from an editor — normalization strips it), one `**Task ID**: T-NNNN` line anchored at end of line, exactly one `<!-- BEGIN/END intent-block: T-NNNN -->` pair, and an intent block of tens to a few hundred lines.
- **Intent blocks whose `- check:` sub-bullets are indented by two spaces** and hold a single-line shell command containing both quote kinds, `$( )`, em-dashes, angle brackets and backticks mid-line — the shape every spec in `.shell-team/specs/` already carries.
- **Intent blocks with zero `- check:` lines** (a spec whose criteria are all runtime/`SKIP`): a legitimate 0, never an error. Such a pair can only ever classify as `class-b` or `structural`, never `mechanics`, and that is correct.
- **An old-side file produced by the caller**, either a copy of the working-tree spec taken before the edit or a `git show <ref>:<path>` redirect — possibly without a trailing newline, which the normalization already tolerates.
- **Boards as this repository's board**: one top-level `- [ ] **T-NNNN**` entry per task, indented sub-bullets, blank lines inside an entry, and sub-bullets whose prose quotes record shapes mid-sentence (the self-referential dogfooding class — this task's own board entry is an instance, which is why AC14's negative grep is anchored on the record shape rather than on the word).
- **Version numbers and hashes already bounded by the existing grammars**: `v1`–`v9999` and 40-character lowercase hex, unchanged by this task.
- **Operator instruction files** (`CLAUDE.local.md`): read by a human or an agent, never parsed by any shipped script — which is the whole of D6's honesty claim.

**Out-of-scope synthetic extremes** — declined deliberately; a finding grounded only in one of these is out of contract:

- **A pure swap of two `- check:` lines between criteria.** In scope as a *pinned known behavior* (`mechanics`, `crc-blindspot-swapped-checks`), out of scope as a defect: it is the concrete instance of the residual risk issue #47 assigns to a named human, and closing it would require parsing which criterion a check line belongs to — a second, AC-structure-aware parser this task does not build.
- **A fabricated old-side file** supplied without `--old-hash` by an operator who already holds the grant. Declared residual risk, human-owned, not a defect class; the `--old-hash` form exists so the honest caller can prove authenticity, not so the classifier can police a caller who is the trust boundary.
- **Intent blocks with thousands of lines or thousands of `- check:` lines**, and version/count values beyond the four-digit bound T-1021 already fixed.
- **Adversarial `$TMPDIR` behavior** — a hostile temp directory, a symlink race, a quota-exhausted filesystem beyond the classified fail-closed write guard. T-1024 adjudicated that class for the whole spec corpus.
- **Non-UTF-8, binary or NUL-bearing spec files**, and marker literals that appear inside fenced code blocks (`bin/check-intent.sh`'s exact-full-line compare already treats those as real markers; the new classifier inherits that behavior verbatim rather than diverging from it, and re-litigating it is a T-071 argument).
- **Concurrent re-freezes of the same task from two sessions**, and any locking or transaction semantics over the board.
- **Whether a replacement `- check:` line is semantically equivalent to the one it replaces.** Named as a Non-goal; no criterion here asserts it and none can.
- **Enforcing, detecting or validating the operator's grant from a shipped script.** The grant is instruction-strength by construction; a finding that "nothing stops an agent from taking the class-M path without a grant" is a restatement of D6, not a defect.
- **Unbounded paraphrase of the documentation.** AC12 and AC13 pin headings, anchors and one byte-exact block; a prose rewrite that keeps all of them but changes emphasis is the review's judgment, not an open finding class.
