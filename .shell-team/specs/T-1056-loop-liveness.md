## Problem

Every instrument that observes a shell-team loop today runs inside it. `bin/loop-guard.sh` prints `CONTINUE` or `STOP:<reason>` only when the loop calls it; `bin/goal-state.sh` advances `iteration` only when a tick executes; `bin/gen-project-status.sh` summarises the board and git deterministically and deliberately carries no wall-clock value at all. A loop that stops ticking — wedged on a permission prompt, holding a dead sub-agent, running in a session that died — therefore emits nothing. Nothing is also exactly what a healthy loop emits while it waits at the human GO before a merge. The two states are the same silence, and no artifact on disk distinguishes them.

The smaller half of the problem is the missing one: **nothing records that the loop is blocked on a human.** Once a wait is declared, silence *without* a declaration becomes diagnosable, and a process the loop does not control can read already-persisted state and say which silence it is looking at.

### Settled decisions

Every decision below is resolved. Where a decision departs from the most obvious reading of the issue, its reason is stated at the decision, not deferred to review.

**DP1 — the name is `bin/check-liveness.sh`, and the verdict travels on stdout *and* the exit code, with exit `1` reserved for nothing.** The `check-*` prefix is this repository's convention for a fail-closed classifier, and the dual carrier is `bin/loop-guard.sh`'s measured shape: one decision always printed, and an exit code a caller can branch on without parsing. Stdout is **exactly one line, exactly one bare verdict token, nothing else** — every reason, diagnostic and context line goes to stderr — so a timer can compare it with byte equality rather than a substring search. Exit codes: `0` `RUNNING`, `3` `WAITING`, `4` `STALLED`, `5` `DEAD`, `2` `OBSERVE_ERROR` (which includes every usage error, since a caller that cannot classify must alarm either way). Exit `1` is assigned to **no** verdict, deliberately: bash's own `errexit` failure fallback is exit 1, so a contract that assigned a verdict to 1 could not distinguish "the classifier decided this" from "the classifier crashed before deciding", and a behavioural assertion over that code would be structurally vacuous. Arguments are explicit and never inferred, copying `bin/check-durability.sh`'s `--ref` idiom: either `--task <T-NNN>` (which composes both artifact paths under `bin/team-paths.sh --get runs`) or **both** `--state <path>` and `--declaration <path>`; supplying one of the pair alone, or mixing `--task` with either, is a usage error rather than a partial default.

**DP2 — the four values' discriminants, and what actually separates `STALLED` from `DEAD`.** `WAITING` is discriminated by a fresh, valid declaration — a categorical signal, not a threshold. The other three are discriminated by two quantities: `A_state`, the seconds between `now` and the state file's mtime, and `A_git`, the seconds between `now` and `HEAD`'s committer epoch. `RUNNING` is `A_state ≤ T_stall`. `STALLED` and `DEAD` are **not** separated by a distinction of kind: no observable in already-persisted state, read read-only, reports whether a process is alive, and the issue rules out the loop writing its own heartbeat, which is the only thing that would supply one. That is stated here rather than glossed. What separates them is a **second threshold plus a second quantity**: `DEAD` requires `A_state > T_dead` **and** `A_git > T_dead` — the loop has neither ticked nor landed a commit for that long — while `A_state > T_dead` with a recent `HEAD` is still `STALLED`, because something did land. `DEAD` is therefore strictly stronger than a larger number on one clock, and both values are reachable and testable without `sleep` (DP5). If that second threshold draws defects, droppable item (a) of the pre-commitment collapses the vocabulary to three values rather than shipping a value nothing can generate.

**DP2a — the tick-freshness observable exists for the `/goal` loop only, and this is a scope boundary rather than an omission.** The state file the classifier reads is `/goal`'s; `/shell-team:run` mints no per-tick state file. So for a `/shell-team:run` pass the classifier's reachable answers are `WAITING` (a fresh declaration) and `OBSERVE_ERROR` reason `state-missing` (no run state to read) — which is the honest fail-closed answer, not a silent pass. The run skill still writes declarations, for two reasons: the declaration is the half issue #227 names as *the* missing primitive, and its gates are where a human wait is most likely. Minting a run-loop state file is loop integration and belongs to T-1057.

**DP3 — the declaration is volatile, lives beside the state file it references, and its staleness is closed structurally rather than by discipline.** Path `<runs>/gate-<task-id>.decl`: the runs dir is gitignored and documented as per-run state never meant to be committed, which is what makes it the right home; the non-markdown extension keeps it out of every `<base>/*.md` sweep this repository runs, the reason T-1054's DP1 gave for `.conf`. The tracked alternative is priced and rejected: it would need a row in `templates/durability-records.txt` and a commit at every gate, and `bin/check-durability.sh` would then fail on a record that is by definition mid-run and about to be deleted. Format: `gate-declaration 1` as the first non-comment line (a version line that is absent, duplicated, unsupported or not first is a refusal), exactly one each of `task`, `reason`, `run-epoch`, `declared-epoch`, and a `gate-declaration-end` terminator so a killed redirect leaves a detectable truncation rather than a plausible file. **Clearing is symmetric with writing**: the same choke point that writes the declaration removes it, before it acts on the human's answer. That discipline is backed by two mechanisms so a missed deletion cannot pin `WAITING` forever — the failure mode that would make this artifact worse than nothing. First, `run-epoch` must equal the state file's `start_epoch`; a declaration from an earlier run is refused `declaration-foreign-run` rather than believed. Second, a declaration whose `declared-epoch` is **not later than the state file's mtime** is `superseded`: the loop has demonstrably ticked since the wait was declared, so the wait is over whether or not the file was removed, and the classifier ignores the declaration and runs the ladder. A superseded declaration is therefore not an error — it is an uncleaned file whose wait provably ended — and the fall-through is not fail-open, because the ladder's `RUNNING` cell independently requires a recent state-file mtime, which is the same evidence.

**DP4 — the write sites are closed by a mechanism, not by a sweep.** Seventeen points across the two skills hand control to a human; they are enumerated with line numbers in `## Declaration write-site inventory`. Editing seventeen paragraphs is exactly the omission class a sweep cannot close, so the design is **one choke point per skill plus one closed reason vocabulary**: a single canonical paragraph, authored once as `templates/prompt-blocks/liveness-declaration.md` and registered in `contain` mode against both skills, stating the write duty, the clear duty and the reason-selection rule for *every* such point, with each skill's own site list living outside the canonical core as the registry's `contain` mode is documented to allow. Two things then hold mechanically rather than by inspection: `bin/check-prompt-sync.sh` fails if either surface drifts from the canonical text, and the union of reason tokens the two skills spell must equal the shipped registry exactly in both directions, so a skill cannot invent a reason the classifier will refuse and a registry row cannot exist with no writer. The norm text is written for a plural governed set — it says "at each point", never "the point" or "the only gate" — because it is authored once and read on two surfaces that between them carry seventeen instances.

**DP5 — mtime, the clock, and why a negative age is an error here when `goal-state.sh` floors one.** mtime is read as `stat -c %Y <f>` (GNU) falling back to `stat -f %m <f>` (BSD), the one form already measured in this repository, plus a **third arm this repository does not yet have**: neither form yielding a bounded decimal is `state-unreadable`, never a substituted zero. `now` is `date +%s`, overridable with `$LIVENESS_NOW` in the same shape `$GOAL_NOW` already has, so every threshold boundary is testable in both directions with no `sleep`. Every epoch is width-bounded `^[0-9]{1,11}$` and every threshold and age `^[0-9]{1,9}$`, each normalized with `10#` immediately after its bound proves it a bounded digit string — the discipline `bin/loop-guard.sh` records as the close for a leading-zero value aborting arithmetic inside an `if` condition, a position `set -e` does not cover. **A negative age is `clock-skew` at exit 2, not floored to zero.** `bin/goal-state.sh` floors one, correctly, because a negative elapsed value would make `loop-guard` raise `guard_error`; here the inversion is the whole point, since flooring a broken clock's negative age to zero would make it `A_state = 0` and therefore `RUNNING` — a wedged loop reported healthy by a broken clock is the exact failure this artifact exists to prevent.

**DP6 — threshold defaults, their reasons, and their re-evaluation trigger.** `T_stall` defaults to **900 seconds** and `T_dead` to **3600 seconds**, both overridable with `--stall-after` and `--dead-after`. The grounds are measured, not guessed: the state file is written only by `init`, `bump` and `set-sig`, so its mtime advances **once per tick**, and one tick is an engineer pass plus a six-layer completion gate including one synchronous cross-provider review call. 900 seconds is chosen to sit above a normal tick and below a human's patience; 3600 is chosen because an hour with neither a tick nor a commit exceeds any single tick this repository has produced, and `DEAD`'s second conjunct means a slow-but-live run cannot reach it. These are defaults, not measurements of tick duration, and the issue's rejection of stillness-alone-as-alarm is what the declaration answers, not the numbers. **Re-evaluation trigger, stated because a settled default is conditional on a fixed environment**: re-derive both values if a tick in this repository is measured above 900 seconds, if the completion gate gains a seventh layer, or if the cross-provider review call's synchronous duration changes materially. A non-numeric or out-of-range threshold is `threshold-invalid`; `--dead-after` less than or equal to `--stall-after` is `threshold-order` rather than a silent reordering.

**DP7 — the fail-closed matrix is complete over three dimensions, and the board's active flags are declined as a fourth with a stated reason.** The matrix in `## Fail-closed verdict matrix` assigns exactly one verdict to each of the 48 cells of (declaration state: `absent` / `fresh` / `superseded` / `invalid`) × (state file: `S0` recent / `S1` stalled band / `S2` dead band / `SX` absent-unreadable-malformed-skewed) × (git: `G0` recent / `G1` beyond `T_dead` / `GX` unresolvable). `RUNNING` occupies exactly 4 of those 48 cells and is emitted from exactly one site in the script. **The board's active flags are read by nothing in this task.** They are not a discriminant: a flag names which phase a task is in, never whether anything is executing, and every flag value is compatible with both a live and a dead loop — a task sitting at `READY_FOR_QA` looks identical whether QA is running or the session died. Classifying on it would repeat, one level up, the stillness-as-alarm error the issue rejects. Reading an input that feeds no verdict would add a failure mode for no benefit, so the classifier does not resolve the board path, does not read the board, and reports nothing from it.

**DP8 — evaluation order is fixed, and it is what makes each cell single-valued.** (1) arguments, mode exclusivity and thresholds; (2) `now`; (3) the state file — existence, readability, `start_epoch`/`iteration` shape, mtime, non-negative age; (4) the declaration, if the file exists — shape, terminator, reason membership, run identity, ordering — with `fresh` emitting `WAITING` here and going no further; (5) `HEAD`'s committer epoch and its non-negative age; (6) the ladder, emitting `RUNNING`, `STALLED` or `DEAD`; (7) the `--out` write, **before** stdout is emitted, so a failed write replaces the verdict with `OBSERVE_ERROR` reason `out-unwritable` rather than letting a timer read a stale file while stdout claims health; (8) an explicit unclassified-error emit as the script's last statement. Step 4 is why `WAITING` does not require git to be readable — a declared human wait is the best-evidenced state there is, and erroring on it because `HEAD` will not resolve would defeat the artifact's purpose — and step 5's position is why `RUNNING` always requires every input positively evidenced.

**DP9 — the classifier's only write is an explicit, replace-semantics `--out` file, and a symlink at that target is refused.** With no `--out`, stdout is the only channel and the classifier creates nothing at all. With `--out <path>`, the verdict is written as a self-describing line-oriented document with a `liveness-verdict 1` version line and a `liveness-verdict-end` terminator, composed in a guarded `mktemp` sibling and moved into place, so a killed invocation cannot leave a half-written verdict a timer would read. Replace is the intended semantics — a timer overwrites each tick — but a **symlink at the target, dangling or not, counts as occupied and is refused** `out-unwritable` without following it, because following it writes through to a path the caller did not name.

## Non-goals

- **No transport.** Nothing delivers the verdict anywhere: no comment, webhook, notification, push, mail, terminal bell or exec of any messenger. Issue #227 names delivery a separate follow-up concern explicitly, and the stated reason — not debugging the judgement logic and the transport at once — is the reason it is honoured here.
- **No extension of `bin/gen-project-status.sh`.** Its determinism contract is byte-identical output for identical board/git state; liveness needs wall-clock. That file is byte-identical to the base ref.
- **No shipped daemon, timer unit, `launchd` plist, `cron` entry or supervisor.** The invoking timer is a process outside this repository. What ships is the invocation recipe in the script's own `--help`, and nothing else.
- **No liveness as a loop gate.** The verdict is never passed to `bin/loop-guard.sh` or `bin/goal-state.sh`, never folded into a failure signature, gates no phase transition, adds no status flag, and is never written to the board. `bin/loop-guard.sh` and `bin/goal-state.sh` are byte-identical to the base ref.
- **No integration with the out-of-repo watchdog.** That tool observes a sub-agent's transcript one level down; nothing here reads it, invokes it, or is invoked by it.
- **No board read.** The classifier resolves no board path and reads no board (DP7).
- **No binding config, adapter registry or executor read.** Nothing here reads `<base>/binding.conf`, `templates/binding-adapters.txt`, `templates/task-envelope.txt` or any adapter definition, invokes any executor, or composes any argv. ## Input space

**Reachable input classes** — what this task's deliverables really read and must handle correctly:

- **A `/goal` run state file as `bin/goal-state.sh` writes it**: exactly three `key=value` lines, `start_epoch` a 10- or 11-digit epoch, `iteration` up to nine digits, `prev_sig` empty or a `;`-joined token list, with or without a trailing newline.
- **A run state file that is wrong in exactly one way** — the real failure mode of a file an interrupted `bump` left behind: truncated mid-write, a key absent, a value emptied, a leading-zero integer, or a file present but unreadable because a permission changed.
- **A declaration this loop's own choke points wrote**, and a declaration wrong in exactly one plausible way: an interrupted redirect leaving no terminator, a hand edit, a reason token guessed rather than copied, a declaration left behind by a previous run of the same task, and a declaration written before the run whose state file names a later `start_epoch`.
- **A declaration whose wait has provably ended** because the loop ticked after it was written and nobody removed the file. This is expected, not exceptional, and has a defined non-error outcome.
- **All three layouts the resolver supports**: the default `.shell-team` base, the legacy `tasks` base, and an explicit `TEAM_RUN_BASE` override — both artifact paths are derived in each, never assumed.
- **Wall-clock conditions a real host produces**: a clock that jumped backwards after an NTP correction or a suspend/resume, a state file whose mtime is ahead of `now`, a `HEAD` commit whose committer date is ahead of `now`, and a file system with one-second mtime granularity.
- **A repository whose `HEAD` does not resolve** — a checkout with no commits yet, or an invocation whose working directory is not inside a git repository at all. Both are reachable when an adopter wires the timer before the first commit, and each fails closed.
- **The plugin-shipped reason registry as installed**, plus a decoy file of the same name in the working directory — reachable whenever the timer runs in a repository that happens to carry a `templates/` directory, which every adopter of this plugin's own conventions might.
- **An `--out` target that already exists** (the normal case for a repeating timer), that is a symlink, that sits in a directory the caller cannot write, and that a previous killed invocation left half-written.
- **Absent inputs**: no state file at the resolved path, no declaration file (the common case), an unreadable reason registry. Each is reachable and each has one defined outcome.
- **A timer invoking the classifier repeatedly, including twice within one second**, and an invocation that overlaps a tick's own write to the state file.

**Out-of-scope synthetic extremes** — inputs this spec explicitly declines to protect against:

- **A hostile operator.** Hand-forging a declaration whose `run-epoch` and `declared-epoch` are chosen to pin `WAITING` over a genuinely dead loop, replacing the shipped reason registry inside the plugin's own installation, or overriding a shell builtin to defeat the parser. `CLAUDE.md`'s security invariant makes the operator and the working directory trusted, and `bin/check-durability.sh` scopes its own threat model identically; the guarantee here is detection of accidents, and a finding whose only trigger is deliberate forgery is `out-of-input-space`.
- **Environment-variable neutralization, `GIT_*` enumeration, `GIT_DIR` redirection, replace refs, clean filters or LFS.** Named explicitly because a sibling checker names them, and for the same reason: they belong to a separate hardening issue.
- **Ever-larger or ever-longer synthetic input**: declarations with thousands of lines, a reason token longer than 64 characters, a registry with thousands of rows, a state file with thousands of keys, an epoch beyond eleven digits or a threshold beyond nine. The width bounds are declared boundaries and a finding that only fires past them is `out-of-input-space`.
- **Non-ASCII or homoglyph reason tokens, task ids or field values.** The reason set is closed and ASCII by construction; a homoglyph simply is not the token and is refused as unknown.
- **A NUL byte or invalid UTF-8 inside a state file, declaration, registry or verdict file.** Authoring one independently breaks the file for every text tool in this repository.
- **Filenames containing a newline, a tab, or a byte `core.quotePath` would C-style-quote**, in any path this task reads or any path a criterion enumerates. This corpus commits none, exactly as the merged specs this one follows accepted.
- **A hostile `$TMPDIR`**: an attacker-controlled temp directory, a symlink race against `mktemp -d`, or a permission flip between creation and first write.
- **A `sleep`-based or duration-sensitive test.** Every threshold boundary is exercised through `$LIVENESS_NOW`; a finding that only reproduces by waiting real seconds is `out-of-input-space`.
- **Any question about whether a run exists at all.** The caller names the run; "is anything running in this repository" is not a question this classifier answers, and a finding that it cannot discover an unnamed run is `out-of-input-space`.
- **Concurrency between two classifier invocations writing the same `--out` path.** The write is atomic per invocation; serialising two timers is the operator's arrangement, not an input class this deliverable accommodates.
- **A `/shell-team:run` pass's tick freshness.** That loop mints no per-tick state file (DP2a), so `RUNNING`/`STALLED`/`DEAD` are not reachable for it in this cut and a finding that they are absent there is `out-of-input-space` — it is T-1057's.

## Fail-closed verdict matrix

Every cell of the three declared dimensions, each assigned exactly one verdict. The board's active flags are **not** a dimension (DP7): they are read by nothing here, because a flag names which phase a task is in rather than whether anything is executing, and every flag value is compatible with both a live and a dead loop.

- dimensions: 4 x 4 x 3
- cells: 48

Declaration states: `absent` (no file at the resolved path) · `fresh` (valid, `declared-epoch` later than the state file's mtime) · `superseded` (valid, `declared-epoch` not later than that mtime) · `invalid` (any refusal in DP8 step 4). Git bands: `G0` `HEAD` resolves and age ≤ `T_dead` · `G1` `HEAD` resolves and age > `T_dead` · `GX` `HEAD` does not resolve or its age is negative.

## Pre-commitment

Written before round 1, so a trigger executes a decision rather than opening one. This **is** verification-mechanism work — a new classifier, a new grammar, a closed vocabulary and a completeness mechanism across two prompt surfaces — so several rework rounds are budgeted for rather than treated as a surprise.

**Factual trigger**: two consecutive rework rounds of new, independent `Blocker`/`Major` findings against one component. **Contextual trigger**: a third round about to start. **The factual trigger governs when they disagree.** This is the repository's default threshold and it is not loosened.

**Never dropped** — the four-value classification core (`RUNNING`, `WAITING`, `STALLED`, `DEAD` each reachable, each generated by real observation) and the fail-closed matrix (every cell assigned exactly one verdict, `RUNNING` reachable only on positive evidence and never as a fallthrough default). If a round's findings would require **weakening** either, the task **stops and returns to sprint planning** rather than being patched: the same mechanism defeated across consecutive design generations is evidence about the design premise, not about the implementation's craft. It is not silently dropped, and no third droppable is invented to avoid the stop.

**Droppable, in order:**

1. **The second threshold separating `DEAD` from `STALLED`** — collapse the vocabulary to three values (`RUNNING`, `WAITING`, `STALLED`), delete `T_dead`, `--dead-after`, the `A_git` conjunct, exit code `5` and the `DEAD` cells, and fold the matrix's git dimension down to "resolvable / not". What is retained is strictly better than nothing: the declared-wait distinction and the stall detection, which are the two halves issue #227 actually names. What is lost, stated rather than argued away: an operator cannot tell a wedged run from an abandoned one, only that neither is ticking. The rounds' findings travel to a new issue as its requirement list, together with DP2's own reasoning about why no kind-distinction is observable, so the successor does not re-derive it.
2. **The state-file half of the output** — delete `--out`, the verdict document, the atomic-write machinery and the `out-unwritable` token, leaving stdout as the only channel. Retained: the whole classification, which is the part a timer branches on. Lost: a timer that wants to diff consecutive verdicts must keep its own record. The rounds' findings travel with it in the same way.
