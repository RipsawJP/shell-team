# One invocation policy: the shipped tree stops claiming the plugin puts `bin/` on `PATH` and documents `bash "<plugin root>/bin/<script>"` instead, in both languages

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1136

## Problem

Every adopter-facing and agent-facing file in this tree tells its reader that loading the plugin puts `bin/` on `PATH`, and the claim is false: on a Codex CLI host the plugin cache directory is not on `PATH` at all (`bash bin/gen-codex-agents.sh` exits 127), and on a Claude Code host a session started without `--plugin-dir` loads the plugin's skills while `command -v check-handoff.sh` resolves nothing and `CLAUDE_PLUGIN_ROOT` is unset — both measured by the maintainer and recorded in issue #485. The documented fallback is no better: `else bin/<script>` assumes a checkout, which an adopter does not have either. T-1134 already shipped the honest form in its own two runbook sections — `bash "<plugin root>/bin/<script>"`, with the plugin root read from what the host itself reports — so this task applies that one policy across the rest of the tree rather than inventing a second one, and lands the three fast-follows T-1135's review round 2 filed as #494 in the same branch.
