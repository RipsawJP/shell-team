## Problem

Three defects in this repository's own test infrastructure, all measured, none adopter-facing.

`tests/bin-exec-bit/run.sh` holds every tracked `bin/` file at index mode `100755`, and one task after it shipped, an `awk`-redirect-plus-`mv` splice silently dropped the exec bit on `tests/check-handoff/run.sh` — the same defect class, one directory over, outside the lock. The reason the lock was drawn narrowly was that a `tests/` exec-bit drop was believed to fail loudly; it does not. Separately, twenty tracked test files build their scratch roots at fixed, guessable paths, so two concurrent runs of the same suite collide — a real collision that surfaced during a QA double-run and left the team with an operating constraint ("run those suites strictly sequentially") instead of a fix. And a signal-blocking bracket added to two `bin/` checkers is inherited across `exec` into the `mktemp` child, making a narrow window uninterruptible; every remedy proposed for it is either infeasible on this host, a regression, or a re-freeze of another task's frozen intent.

And the `mktemp` exclusion is what lets the compliant two-arm idiom, whose `$HERE` fallback still names `$HERE/tmp…`, pass. **The lock's declared reach**: it is a shape lint over the two styles this corpus actually uses, not a dataflow analysis; a fixed root written in some third style would not be caught, and that limit is stated in Input space rather than hidden. - `control: a fixed ${TMPDIR} scratch root is rejected`
- `control: an mktemp XXXXXX assignment is accepted`
- `control: an empty tests/ population is rejected`
