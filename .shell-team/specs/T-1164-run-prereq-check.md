## Problem

A run started in a repository that is not set up for the host it runs on fails late and without a pointer. On the Codex CLI host, with no `.codex/agents/`, an adopter run stopped at Plan `BLOCKED` with nothing naming the missing prerequisite or its fix (relayed from issue #640's Problem). T-1163 shipped the fix for the plugin's part (the prompts `set up shell-team` / `update shell-team`), but nothing at run time tells the operator to use it. Separately, the review pass sends repository content to the other provider, and on the Codex CLI host an automatic approval reviewer denied that transfer because nothing named the payload and the destination (relayed measurement, see Assumptions). The canon text, relayed verbatim by the coordinating session from issue #640:

> **At run time (absorbed from #625).** On both hosts, before the first dispatch of a run, the run skill checks — read-only — that setup is present and current for this host and that the prerequisites it can observe hold. When one does not, it stops the task `BLOCKED` with the check's own output, names the setup prompt as the remedy for the plugin's part, and states any host-side condition as the operator's decision to make; it never substitutes another dispatch path or executor, and never changes the host's configuration.

Also relayed from #640's Problem: "Observed in an adopter run on the Codex CLI host: with no `.codex/agents/` present, the orchestrator stopped at Plan `BLOCKED` with no pointer to the missing prerequisite or its fix."
