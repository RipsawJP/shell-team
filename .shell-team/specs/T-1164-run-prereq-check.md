## Problem

A run started in a repository that is not set up for the host it runs on fails late and without a pointer. On the Codex CLI host, with no `.codex/agents/`, an adopter run stopped at Plan `BLOCKED` with nothing naming the missing prerequisite or its fix (relayed from issue #640's Problem). T-1163 shipped the fix for the plugin's part (the prompts `set up shell-team` / `update shell-team`), but nothing at run time tells the operator to use it. Separately, the review pass sends repository content to the other provider, and on the Codex CLI host an automatic approval reviewer denied that transfer because nothing named the payload and the destination (relayed measurement, see Assumptions). v3: that second part left this task with the pre-commitment's D2 and is issue #650's; this spec now addresses the first part only. The canon text, relayed verbatim by the coordinating session from issue #640:

> **At run time (absorbed from #625).** On both hosts, before the first dispatch of a run, the run skill checks — read-only — that setup is present and current for this host and that the prerequisites it can observe hold. When one does not, it stops the task `BLOCKED` with the check's own output, names the setup prompt as the remedy for the plugin's part, and states any host-side condition as the operator's decision to make; it never substitutes another dispatch path or executor, and never changes the host's configuration.

Also relayed from #640's Problem: "Observed in an adopter run on the Codex CLI host: with no `.codex/agents/` present, the orchestrator stopped at Plan `BLOCKED` with no pointer to the missing prerequisite or its fix."

## Acceptance criteria

Every `check:` runs from the repository root under `bash`, reads the post-implementation tree, writes only under `$TMPDIR` (temp directories are left in place, never removed), and contains no recursive delete. Fixtures export a temp `HOME`, `CODEX_HOME` and `XDG_CONFIG_HOME`, set `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_NOSYSTEM=1`, unset `TEAM_RUN_BASE` and `CODEX_THREAD_ID`, and put stub `claude` and `codex` executables that exit `0` first on `PATH`. `sr <repo> <host>` prepares a repository with the shipped `bin/team-setup.sh`; `ck <dir> <args>` runs the checker and prints its exit status.

## Input space

**Reachable input classes**:

1. **Host.** A Claude Code session; a Codex CLI session (`CODEX_THREAD_ID` set); an explicit `--host` value; an invalid `--host` value or a bare `--host`.
2. **Invocation.** From the repository root, from a subdirectory; from a read-only (mode `555`) repository root or subdirectory; outside any git work tree; with an unknown argument; with `--help` or `-h`; with `TMPDIR` absolute, relative or unset (the checker uses no scratch).
3. **Repository state.** Fresh (no base dir); set up by this version on either host; set up for Claude Code only and then run on the Codex CLI host; scaffold partially missing (board or loop contract removed); `.codex/agents` missing a role file; `.codex/agents` whose role files differ in content (from an older plugin version or a hand edit) — present, so not reported at Step 0 (D3); an edited base `.gitignore`, board or test recipe; a host `binding.conf` under the resolved base or none (not read by the checker); a legacy `tasks/` layout, a `TEAM_RUN_BASE` override resolved by `team-paths.sh`, or one it refuses.
4. **`PATH`.** `claude` or `codex` present or absent.
5. **Plugin root.** An installed plugin cache on either host, or a checkout; a plugin root with no `agents/` (the checker does not regenerate agents, so this does not affect it).
6. **Shells.** bash 3.2 (macOS) and bash 5 (Linux CI).

**Out-of-scope synthetic extremes**, declined explicitly:

1. Repository or plugin-root paths carrying a single quote, a control character or non-UTF-8 bytes (`bin/team-setup.sh` already refuses the first two before a repository is set up).
2. A symlinked base dir, `.codex` or `.codex/agents` (setup refuses them, T-1163).
3. Concurrent setup and checker runs in the same repository.
4. A tampered plugin root (hand-edited scripts or templates) other than the missing-`agents/` shape **AC4** models.
5. A bare repository.
6. A host that rebinds `code-reviewer` to a same-family executor and has no other-provider CLI installed (see Open questions; the checker still reports the CLI absent).
