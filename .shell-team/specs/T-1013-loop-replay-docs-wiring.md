## Problem

Issue #77's Part 1 (T-1011, event rows) and Part 2 (T-1012, the generator; plus T-1014, the flag rail's data path) shipped a real feature that **no adopter-facing document mentions**. Measured at the base ref, not assumed: the string `replay` occurs in zero of `README.md`, `README.ja.md` and `docs/**`, and `gen-loop-replay` occurs in zero of them. This repository ships a `bin/` script, a shipped HTML template, a fixture suite and a CI job for a feature whose only description lives in specs and in the script's own `--help`.

Two documentation lines were additionally *left stale on purpose*, with the obligation recorded in a frozen spec rather than in conversation. `.shell-team/specs/T-1011-telemetry-event-rows.md`'s Non-goals says it in as many words: `README.md:172` ("emits one span row per phase") and `docs/loop-engineering/goal-loop.md:45` / `.ja.md:47` ("one span per sub-agent call") *"become incomplete — not false — after this change. T-1012 closes them."* T-1012 then re-deferred them to Part 3, and its own Non-goals accepted the consequence explicitly: *"this repository ships a replay generator no README mentions."* This task is where that debt is paid, and it is the **last feature task before the v1.2.0 release**.

The scope was narrowed by measurement rather than by inheritance. The Track B routing this task was planned against listed the run skill's emission instructions as possibly incomplete; reading `skills/run/SKILL.md:101-114` shows all five event ids **and** T-1014's flag-label convention on the `handoff` bullet are already there. So the producer side is done and **this task is documentation only** — six markdown files, no executable surface.

## Goal

<!-- BEGIN intent-block: T-1013 -->

A reader who has never opened a spec can learn from the shipped documentation that a run replays as a page, how to generate one, where it lands, and what it will and will not show them. Concretely: both READMEs' Telemetry bullet describes span rows **and** event rows instead of spans alone; both `goal-loop` telemetry rows say what the goal loop actually emits and name the replay generator; both READMEs' layout tree lists `gen-loop-replay.sh`; both READMEs carry a new short section giving the command, the output location, the flag-label caveat and a fixture-driven demo; and both `workflow.md` files place the generated page in the per-cycle-artifact class alongside a retro. The four documentation lines that T-1011 knowingly left incomplete are closed, and every criterion anchors on the **new** wording rather than on wording that is already green. Nothing outside `README.md`, `README.ja.md`, `docs/loop-engineering/goal-loop.md`, `docs/loop-engineering/goal-loop.ja.md`, `docs/workflow.md` and `docs/workflow.ja.md` changes — no `bin/`, no `templates/`, no `skills/**`, no `tests/`, no workflow, no version bump.

### Settled decisions

Each decision below is resolved. Nothing here is left to implementation judgment.

- **D1 — the `goal-loop` telemetry row is closed by stating what the goal loop actually emits: spans only.** Measured, not assumed: `skills/goal/SKILL.md:241-250` emits `--span` rows only and carries no `--event` instruction, and the standing disposition keeps that file untouched. So the row's existing text is not *false*; it is incomplete only in that it no longer tells the reader where event rows come from or that these rows are replayable. Frozen wording requirement: that single table row must name `/shell-team:run` as the source of event rows, keep `loop_id=goal`, and name `bin/gen-loop-replay.sh` as the reader of either kind.
  - **Rejected — writing that the goal loop emits event rows.** It would be false at this base ref and would only become true by editing `skills/goal/SKILL.md`, which is out of scope by standing disposition.
  - **Rejected — leaving the row alone as "already accurate".** T-1011's frozen Non-goals named this exact line as a closure obligation on Part 3. Declining it now would retire the obligation silently, in the task that closes the issue.
  - The row **stays one line**. The two `goal-loop` files each contain exactly one occurrence of `bin/log-run.sh` today, and the criteria use that single line as their scope; splitting the cell across lines defeats the anchor.
- **D2 — the new README material is one top-level section per language, with frozen headings.** English: `## Replaying a run`. Japanese: `## run のリプレイ`. Placement: between `## Operating loop` and `## Design choices` (English) and between the corresponding two sections in the Japanese file. The headings are frozen because they are what makes a *section-scoped* criterion possible in a file whose surrounding prose is in two different languages — the alternative anchors are all either language-specific or whole-file (and therefore satisfiable by text written somewhere else in the file).
  - **Rejected — a `###` subsection under `## Operating loop`.** That section's body is a bullet list; a heading inside it reads as part of the list.
  - **Rejected — a new `docs/loop-replay.md` page (plus `.ja.md`).** The debt being paid is that the README does not mention the feature; a new page moves the mention one hop away, and adds two files, two entries in the layout tree, and a cross-link pair — more surface than a short section, for a feature whose whole interface is one command.
  - **Rejected — a committed sample page or screenshot.** The generated page is git-ignored by measurement (T-1012 D4), a committed one would become a tracked artifact needing its own content gate, and an image adds a binary asset to a repository that has none.
- **D3 — the section states the flag rail's precondition as a caveat, not as a promise.** The rail lights only when the orchestrator put the board flag it just set onto the same `handoff` event's `--label` as the bare token (T-1014's convention, which is optional and best-effort); a run without those labels renders the ratified empty-state caption instead. This is not a nicety: **flag-less runs are the dominant class permanently** — every run recorded before T-1014, and every adopter run whose orchestrator omits the label. A section that promised a lit rail unconditionally would document a page most readers will not see.
  - The caveat is a **pointer**, not a copy: it names the convention and where it is produced, and does not restate `skills/run/SKILL.md`'s frozen phrases. Restating them creates a second copy of a contract that already has exactly one home.
- **D4 — the demo is the committed `flag-rail` fixture, driven through `--runs-dir`, writing outside the repository via `--out`.** Frozen: run id `20260801T000000Z-flagrail`, directory `tests/gen-loop-replay/fixtures/flag-rail`. This is the fixture whose rail actually lights, so it demonstrates the affordance D3 describes rather than the empty state, and it works for a reader who has no run of their own yet.
  - `--out` is **required in the documented demo command**. Without it the page defaults into the fixture directory and leaves an untracked file inside `tests/`, which is a bad thing to teach and a nuisance for the next person who runs a scope-lock check.
  - The default output location is documented as `<runs>/replay-<run-id>.html`, with the runs directory named by its **resolver** (`bin/team-paths.sh --get runs`) rather than by a literal path: a literal is correct in at most one of the two supported layouts. The section also states the page is already `git-ignore`d, so a reader does not go looking for an ignore rule to add.
- **D5 — `workflow.md` / `.ja.md` place the generated page in the existing per-cycle-artifact paragraph, and draw the two-sided line explicitly.** The paragraph that already covers retros (`**Per-cycle artifacts**`, the one anchored on `bin/check-retro.sh` and the `retro-section:` markers) gains the replay page: the **generated page's content** follows the operator's language — the operator-authored `label` text renders verbatim and the page's own UI dictionary carries both languages — while machine tokens (the rail's five `READY_FOR_*` stops, the verdict labels) stay verbatim English, and the **shipped `templates/loop-replay.html` itself is shipped surface**, written in English like every other shipped file.
  - **Rejected — a new `## ` section in `workflow.md`.** The distinction being documented is a language-boundary distinction, and the language boundary already has exactly one home in that file. A second home is where the two copies start to disagree.
  - **Rejected — extending any checker** (a `check-retro.sh`-style structural validator for the page, a new suite, a workflow step). This task changes no executable surface.
- **D6 — the change surface is exactly six markdown files.** `README.md`, `README.ja.md`, `docs/loop-engineering/goal-loop.md`, `docs/loop-engineering/goal-loop.ja.md`, `docs/workflow.md`, `docs/workflow.ja.md` — plus this spec, the board entry, and the task's own records. Every one of the six is edited (an unedited one is a criterion failure, not an acceptable outcome), and the edits are **bounded**: existing paragraphs are extended or replaced in place, not reflowed. A whole-file rewrap of a Japanese document produces a diff no reviewer can read and hides the actual change inside it.
- **D7 — EN/JA symmetry is asserted as a projection, not as a translation.** The two language variants must carry the **same set of language-neutral anchors** (paths, flags, machine tokens, the frozen fixture id); they are *not* required to have matching sentence counts, matching line wrapping, or a one-to-one translation-unit correspondence. The projection is machine-checked; whether the Japanese sentences *mean* the same thing as the English ones is a human read, and is named as such rather than left implied.
