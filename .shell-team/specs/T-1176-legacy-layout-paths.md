# Legacy-layout specs resolve to `tasks/specs` when that is where they live, and the contract templates name no layout path

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1176

## Problem

In the legacy layout, `bin/team-paths.sh` fixes the specs directory to `docs/specs` whatever the repository holds (`bin/team-paths.sh:148-151`). An adopter that keeps its specs in `tasks/specs/` and has no `docs/` is stopped by the run's Step-0 check (`bin/check-setup.sh:182-183`: `docs/specs (the specs dir) is missing`), a regression since v2.8.0 (issue #693); every sub-agent prompt had to override the resolved path by hand (issue #589). `set up shell-team` then clears the check by creating an empty `docs/specs/.gitkeep` outside the base directory (`bin/team-init.sh:353`), which the operator had to hide by hand in `.git/info/exclude` — so that adopter now has both directories, the real one and a dummy. Separately, the three shipped contract templates name legacy paths (`tasks/todo.md`, `docs/specs/*`, `tasks/reviews/*`) in their free text, which a default-layout adopter receives verbatim (issue #696). Changing a template naively turns every existing adopter's untouched copy into a new `Remains the operator's decision:` drift line (`bin/team-setup.sh:483-498`), which is the opposite of this sprint's goal.
