## Problem

An adopter run (issue #591) reviewed the same commit range three times with the same bare `codex exec` shape, changing only the request text. The coarse request returned `VERDICT: APPROVE` with one line, "no findings", after 19 commands; a request naming six perspectives and demanding `file:line` evidence per perspective returned `REQUEST_CHANGES` with a Major, a Minor and an Info after 18. The difference was what the request asked Codex to verify, not how much it read. The shipped `agents/code-reviewer.md` has the coarse shape: its primary pass is Codex's built-in `review --base` subcommand, which has no prompt channel at all (measured, see `## Assumptions` M1); its free-form second pass asks generically for "a JSON array" of findings, so an empty array is contractually fine; and that second pass fires only on a blocker/major, so a shallow zero-finding `APPROVE` never triggers it. T-1152's round 2 shows the same shape in this repository: no second pass, `briefing-fidelity (primary-r2): not-applicable`, and an `APPROVE` resting on the reviewer's own static trace. `bin/codex-capture.sh --publish --thread-id` (T-1152) now proves a review *ran*; nothing proves it looked at what the spec asked.

Rounds: the first round of a task; a later round whose previous round carried rejected or downgraded synthesis-ledger rows and fast-follow dispositions; a later round whose previous round was `BLOCKED — review not established`; a round inside a declared `concurrent-review-window` (pinned scratch worktree for `<repo>`, the perspectives file still under `$TMPDIR`).

6. The perspectives file's own path: under `$TMPDIR`, outside `--cd <repo>`, with hyphens in it (the issue's rewritten-path observation), on a host whose `$TMPDIR` is a per-session directory.
7. Adopter state at upgrade: a generated `.codex/agents/shell-team-code-reviewer.toml` produced before this change (stale until regenerated); a task in flight whose earlier rounds were recorded under the old contract.
8. Review records: a record whose earlier rounds use the old verdict shape (no ledger), with a new round appended; a record carrying a heading-less `BLOCKED — review not established` round between verdict rounds.

**Out-of-scope synthetic extremes** — declined explicitly:

1. Fabricated or wrong evidence: a ledger whose anchors name lines that do not exist, or exist but do not show what the row claims. No mechanical anchor validation is built (C1); the reviewer's own judgment and the next gates stay the defence.
2. A Codex evidence pass whose ledger is well-formed and anchored but whose `holds` judgments are simply wrong.
3. Spec text crafted to instruct Codex through the perspectives file (a prompt-injection payload placed in a spec's criteria or `## Review depth` by the reviewed diff). This is data the reviewer quotes, not a boundary this task defends; a security finding is never downgraded on this ground.
4. A Codex CLI release that lifts the `review --base` / `[PROMPT]` exclusivity, or that stops reading files outside `--cd` under `--sandbox read-only` (see the stale-ats in `## Assumptions`).
5. Specs so large that the perspectives file exceeds a model's prompt budget, and ledgers with hundreds of rows.
6. Markdown pathologies inside ledger cells: literal `|` characters, multi-line cells, a table Codex renders without the header row.
7. A `$TMPDIR` that is unset, unwritable, or points inside the repository.
