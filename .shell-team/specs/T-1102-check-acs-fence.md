# A fenced acceptance-criterion line is inert to the acceptance-criteria parser

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1102

## Problem

`bin/check-acs.sh` scans a spec line by line with no notion of fenced code blocks, so a column-0 `- [ ] **ACn**` line printed *inside* a fence — as an illustration of the grammar a spec is governed by — is parsed as a real acceptance criterion, and the `- check:` line beneath it is executed. `.shell-team/specs/T-1061-adopter-docs-gate.md` carries exactly that shape: its `## Notes for engineer` prints a passing-spec skeleton inside a fence, and the parser reports a criterion that does not exist and runs a value (`...`) that is not a command. The same blindness reaches three sibling line classes in the same scan — the unrecognized-label accumulator, the `## ` section reset and the `- check:` capture — so the reported symptom is one face of a single missing state machine rather than one line to patch. Separately, `skills/run/SKILL.md:12` cites an issue number for a visual-output churn example whose real subject is a different norm entirely, a stale citation the loop's own review record already identified and deferred.

`bin/check-acs.sh` tracks backtick fence state across its criterion/check scan, so a line inside a fenced code block contributes nothing to the parse. The suppression is **uniform across all four line classes** the one scan chain contains — the `**ACn**`/`**AC-N**` label match, the broader unrecognized-label candidate match, the `## ` section reset and the `- check:` capture — because they are branches of a single chain over a single line and a per-branch guard is the defect class a sibling checker's own review history already recorded. The state machine is the hardened one `bin/check-board-headings.sh` already ships, copied rather than re-invented: an opener is 0–3 literal space characters followed by a backtick run of at least three, its run length is recorded, and only a likewise-indented run of at least that length with nothing but whitespace after it closes it — so a four-backtick outer fence is not closed by a three-backtick inner one, a closer carrying trailing text does not close, a four-space or single-tab indent opens nothing, and the strip of a trailing carriage return still precedes every fence test. Tilde (`~~~`) fences are **not** tracked, on the same ground the sibling records, and the boundary is stated in the shipped text rather than left for a reader to discover. An unterminated fence suppresses every line to end of file, which is what CommonMark says those bytes are; where that swallows a spec's whole criteria section the existing zero-criteria refusal reports exit `2`, so the direction of that failure is closed. ## Non-goals

- **No change to the exit-code contract, and no new exit class.** `0`/`1`/`2` keep their current meanings and their current triggers. An unterminated fence is not made into a new refusal of its own: the zero-criteria path already exists and already exits `2` when it matters, and a new refusal class would change what an adopter's gate rejects for a reason unrelated to the reported defect.
- **No new stderr write site in `bin/check-acs.sh`.** Measured ground rather than taste: `tests/errexit-safe/run.sh`'s completeness self-audit accounts for every errexit-unsafe write site in `bin/` by exact content key and declared count, so a new diagnostic would have to be registered there in the same commit, widening this task from a parser fix into an audit-ledger edit. The count of write sites at HEAD equals the count at the branch point.
- **No fence support in any other checker**, `bin/check-intent.sh` explicitly included. Issue #257's premise that `check-intent.sh` is already fence-aware is **false** (measured: no fence tracking anywhere in the file), so it is neither the pattern to copy nor a file this task changes. ## Input space

**Reachable input classes** — what the parser really faces, all of them present in committed specs in this repository or producible by ordinary authoring:

1. A column-0 `- [ ] **ACn**` or `- [ ] **AC-N**` line inside a three-backtick fence, as an illustration of the grammar (the reported case).
2. A column-0 malformed AC label inside a fence — a glued suffix, a label with no digits — printed to show what the grammar refuses.
3. An indented `- check:` line inside a fence, with or without a preceding fenced AC line.
4. A column-0 `## ` heading line inside a fence, as part of a quoted spec skeleton.
5. A fence carrying an info string after its opening run (`markdown`, `bash`, `text`), which the opener deliberately does not validate.
6. A four-backtick fence containing a three-backtick fence — a spec quoting a fenced example.
7. A fence whose closer carries trailing text, and a closer shorter than its opener: both ordinary typos.
8. A fence opener indented by one, two or three spaces (inside a list item's continuation), by four or more spaces, or by a leading tab.
9. CRLF line endings throughout a file, and a lone trailing CR on individual lines.
10. An unterminated fence — a typo'd or deleted closer.
11. A tilde (`~~~`) fence, hand-authored.
12. An **indented** (non-column-0) AC-shaped example line, which the existing column-0 anchor already excludes and which stays excluded.
13. A spec with no fences at all — the overwhelming majority of the corpus, whose parse must not move.

**Out-of-scope synthetic extremes** — declined deliberately, each named:

1. A fence opener appearing inside an HTML comment, inside an inline code span, or inside a block quote (`> ` prefix). None is tracked; a block-quoted fence opens nothing because the opener regex admits only leading spaces. This declaration is what bounds the class, rather than a further round of patching once someone constructs one.
2. Interleaved tilde and backtick fences constructed so that one type's opener sits inside the other's region, in either order.
3. Backtick runs longer than a handful of characters used to construct pathological nesting depth, and escalations of that depth without bound.
4. Markdown block constructs this checker has never claimed to model: setext headings, list-item lazy continuation, tables, link reference definitions, and fences nested inside list items at arbitrary indentation.
5. Adversarial byte sequences: NUL bytes, a lone CR as a line terminator, unpaired UTF-16 surrogates, and any input that is not UTF-8 or ASCII text.
6. A spec constructed so that its entire `## Acceptance criteria` section is fenced. The behaviour is defined and fails closed (exit `2`, no criteria), and **AC17**(b) probes it, but the tracker is not tuned for it and no further guarantee is claimed.
7. Any input reachable only by an author deliberately attacking their own spec. The boundary and its ground: this checker parses committed, reviewed specs authored by the team, and it is an **honest-error tool rather than an adversarial-input parser** — the same boundary `bin/check-board-headings.sh`'s DECISION 3 already declares for the same state machine. A finding in class 1–7 is a documentation item, not a defect to forward-fix.
