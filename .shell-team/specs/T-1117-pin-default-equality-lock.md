## Problem

`templates/binding-default.conf` is the declared source of truth for which executor runs each inner-loop role, and its five `claude`-provider rows carry each role's own frontmatter `model:` pin by measurement rather than by convention (that file's own header, `:14`–`:18`). Under `.shell-team/specs/T-1057-loop-integration.md:59`'s DP6 **Branch B** — the branch `docs/loop-engineering/harness-invocation-parameters.md:227`'s `- gate-input: instrument-inadmissible — Branch B` row selects for this task — the pin is what actually routes a sub-agent while the conf is what the loop declares, so the two must not be able to disagree. Today their agreement is asserted only by T-1057's frozen **AC5**, which is evaluated when that spec's criteria are evaluated and not on any CI run. An edit to either side — a pin bumped without the conf, or a conf token bumped without the pin — would therefore ship green and surface later only as telemetry naming a model that never ran.

**What the population is, and why it is derived rather than listed.** The population is every delegated `bound` row whose **provider** field is `claude`, obtained by running `bash bin/check-binding.sh --config <default> --print-binding` and re-asserting the canonical form before trusting it. **Why two directions need one comparison.** A pin bumped without the conf and a conf token bumped without the pin are the same inequality read from two ends. One byte comparison per population row closes both, and the only thing that has to be added beside it is a **mandatory-presence** rule: a population row whose agent file carries no `^model:` line at all must be a violation rather than a pass, because "absent" is exactly the state a half-finished Branch A would leave behind.

**Why the exit codes split three ways.** `0` means every population row agrees. `1` means the invariant is violated on a readable input. `2` means the input could not be evaluated at all — and an **empty population is `2`, never `0`**, because a conf from which every `claude` row has vanished is the one shape in which a green result would be maximally misleading. The full condition table is **DP-4**'s, and every arm of it is promoted into **AC7**, **AC8** or **AC9**.

## Acceptance criteria

1. **The shipped default's own shape.** Six `bind` rows; five with provider `claude` and adapter `claude-cli` carrying the model tokens `opus` (twice) and `sonnet` (three times); one with provider `codex`, adapter `codex-cli` and the model token `provider-configured`; every `effort` column `-`; comment lines and blank lines interleaved; and column alignment padded with runs of spaces, so no field may be located by byte offset.
2. **A population row whose agent file carries exactly one `^model:` line** whose value either equals its conf token (today's state, five times over) or does not (the two mutation directions).
3. **A population row whose agent file carries zero `^model:` lines** — the shape a half-landed Branch A leaves — which is a readable input and an `1`, never a skip.
4. **A population row whose agent file carries more than one `^model:` line, or one whose value is empty** (`model:` with nothing after the colon, or only whitespace) — both `2`, and the empty-value case is explicitly *not* folded into the zero-line case.
5. **A population row whose agent file is missing, or present but unreadable** — `2`.
6. **A conf from which every `claude` row has gone.** Constructible under the shipped grammar, because `templates/binding-adapters.txt` registers `codex-cli codex` and the validator accepts all six inner-loop roles bound to it, so the empty-population guard is reachable rather than theoretical — `2`, never `0`.
7. **A delegated refusal.** A `--default` path that does not exist, a conf whose schema line is missing, duplicated, not first or of an unsupported version, an unknown or duplicated role, an unknown provider or adapter, a provider/adapter mismatch, an out-of-charset token — every one of them printing nothing on stdout, so the checker sees an empty delegation and must report `2`.
8. **A delegated output that is text but not the canonical form.** A first line that is not `schema <version>` with two fields, a `bound` row with other than six fields, a role appearing twice — each `2`. The row **count** and role membership are deliberately outside this set (see **DP-3**).
9. **Rows and files that are out of population under any value.** A `bind` row whose provider is not `claude`, including one whose own agent pin disagrees with its conf token — which is the shipped tree's real state for `codex-reviewer` — and an `agents/*.md` file carrying a pin but naming no `bind` row, of which the shipped tree has three.
10. **A `claude`-row count other than today's.** A role rebound to another provider, or a seventh role made bindable by a later task: the population is re-derived on every run and is never compared against a literal.
11. **A tree reached only through the two read-only affordances.** A conf at an arbitrary path and an agents directory at an arbitrary path, each resolved physically, with neither affordance opening a write path — the only way a fixture exercises a mutated pin or conf without touching the checkout.
12. **A checkout under `core.fileMode=false`**, where a working-tree `test -x` would lie about an exec bit and the git index mode is what actually ships.
13. **A host with no `shellcheck` on `PATH`, or one at a version other than the workflow's pin** — a fail-closed red, never a skip.
14. **A board that grows while the task runs**, appended to by this very loop, which is why every board-reading criterion anchors on a task-scoped line or on a base-relative survival comparison rather than on a count.

**Out-of-scope synthetic extremes** — inputs this spec explicitly declines to protect against:

1. **A host-authored `<base>/binding.conf`.** The lock's object is the plugin-shipped default; an adopter who rebinds a role in their own config is exercising a documented capability, and a finding that this checker does not police their file is a correct description of scope.
2. **`templates/binding-template.conf`.** The adopter-facing specimen, already dogfooded by its own CI step; it is not the shipped default and carries no relationship to any pin.
3. **A model token that is legal under `MODEL_RE` but semantically meaningless** (`zzz-not-the-pin`, `zzz-other-token`). These are fixture material only: the checker compares bytes and makes no claim about whether a token names a real model, so a finding that it accepts a nonsense token on both sides is out of input space.
4. **YAML frontmatter in its full generality.** The pin is read as a line-anchored `^model:` match. A `model:` key nested under another mapping, quoted, spread over a folded or literal block scalar, or written with a tab is out of scope; none of the nine shipped `agents/*.md` files carries any such shape, and a parser for them is a task with a spec of its own.
5. **A third provider or a custom adapter.** The shipped registry carries exactly `claude-cli claude` and `codex-cli codex`, and adding one is explicitly out of scope in the registry's own header.
6. **An adversarially authored conf, agent file or delegated stub constructed to defeat this checker's line-anchored reads** with no reachable authoring path that would produce it. A verdict this checker reaches that its own inputs do not support is squarely in scope; an enumerated-guard completeness argument against a hostile author is not.
7. **Concurrent mutation.** Two processes editing a pin and the conf while the checker reads them. These are sequential CI and local invocations.
8. **A rebased, force-pushed or squash-merged predecessor branch, a predecessor deleted without being merged, a checkout carrying the predecessor in neither namespace, and a detached `HEAD` with no merge base.** The first three are route-backs rather than cases any arm is widened for; the last two fail every base-reading criterion closed.
9. **Proof that the CI steps actually executed on a runner.** **AC4** reads the workflow's committed text; whether GitHub ran it is the run's own record and outside any artifact read.
10. **Non-UTF-8 bytes, CRLF line endings or a missing trailing newline in `agents/*.md` or the conf.** Every shipped file is LF-terminated UTF-8; a byte comparison would report a difference and that is the correct behaviour, but no criterion here is designed to diagnose it.

## Decision points

Resolved by `tech-lead`'s Routing Map (Part 1, D1–D10) and the coordinating session's review (Part 2, which overrode D8). Each is a settled decision, not an open question.

**DP-1 — read the conf by delegation, to the default file by path.** `bash bin/check-binding.sh --config <default> --print-binding`, whose contract is quoted in `## Summarized sources`. Never `bin/resolve-executor.sh --print-resolved`: that resolves the *effective* binding and a host `<base>/binding.conf` wins over the default, so the lock would silently change object on any adopter who authored one.

**DP-2 — two directions need one comparison.** One byte comparison per population row plus **DP-4**'s mandatory-presence rule closes both the pin-moved and conf-moved directions. Stated in the Goal so no reader concludes two mechanisms are owed.

**DP-3 — select the population by provider, and re-assert structure without re-asserting size.** Population = every `bound` row with provider `claude`; ground: only where the executor **is** the harness does a frontmatter pin route anything. The canonical re-assertion covers the schema line's shape and version, each row's six fields, and role uniqueness — but **not** the row count or role membership, because either would compile a population size or a role list into this checker. Those two properties are already held by `bin/check-binding.sh`'s `missing-role` refusal and `bin/resolve-executor.sh:375`–`:383`.

**DP-4 — the condition table and the exit split.** `0` every population row agrees; `1` invariant violated; `2` cannot evaluate.

| Condition | Outcome |
|---|---|
| `claude` row + `agents/<role>.md` with exactly one `^model:` line, values equal | contributes to `0` |
| same, values unequal | `1`, message naming the role, the pin value and the conf token |
| `claude` row + `agents/<role>.md` missing or unreadable | `2` |
| `claude` row + zero `^model:` lines in the agent file | **`1`** — a readable input with the invariant violated; the Branch A shape must redden, message naming #236 |
| `claude` row + more than one `^model:` line | `2` |
| `^model:` present with an empty value | `2` — and not folded into the zero-line case |
| non-`claude` row (`codex-reviewer` today) | out of population |
| `agents/*.md` with a pin but no conf row (`scrum-master`, `triage-orchestrator`, `drift-evaluator` today) | out of population |
| population empty | **`2`** (DP-5) |
| delegated `check-binding.sh` refuses, or its output fails the canonical re-assertion | `2` |

No "absent pin is acceptable" arm: T-1057 AC5 carries one because it had to be satisfiable under either branch, and a continuous lock must not. Retirement is #236's job and edits this checker.

**DP-5 — the empty-population guard is the point.** An empty population is `2`, never `0`. Measured at authoring time from the shipped grammar and the shipped adapter registry: a conf binding all six inner-loop roles to `codex`/`codex-cli` is valid, so the guard is reachable and **AC8** constructs exactly that, asserting the conf validates under the delegated validator first so the `2` is attributable to the empty population rather than to a refusal.

**DP-6 — `provider-configured` and non-model tokens.** The model column is the conf's fourth field, always present and `MODEL_RE`-legal. The checker compares bytes; selection is by provider alone. A hypothetical `claude` row carrying `provider-configured` would fail equality against any real pin, which is correct. **`provider-configured` must not become a skip token**, and **AC6** asserts the literal does not occur in the checker's code at all.

**DP-7 — T-1057 AC5: complement, not supersede.** AC5 stays byte-unchanged and frozen. Only its equality clause becomes continuous; its disjunctive pin-absent arm and its base-ref byte-identity clauses are assertions about T-1057's own diff and stay there. **AC12** carries both halves.

**DP-8 — documentation and the declaration** (Part 2's override of the Routing Map's D8). `- user-visible: yes`, discharged by an `- adopter-surface:` line naming the checker's own `--help` header contract, on the measured precedent of T-1099, T-1102, T-1104 and T-1113. No README or `docs/adopting.md` change: both name a checker only where an adopter runs one, and no shipped phase, skill or adopter command invokes this one. The version tier is unchanged by this: `yes` never implies MINOR by itself.

**DP-9 — the two mechanically-coupled suites, found at authoring time rather than at QA.** Neither is named by the Routing Map and both bind this task's new files the moment they land. `tests/check-binding/run.sh`'s `cb-adapters-not-forwarded-population` case enumerates live every `bin/*.sh` and `.github/workflows/*.yml` naming `check-binding.sh` and asserts each spells `--adapters` zero times, so the new checker must never spell that flag — the `--help` header describes its own affordances without borrowing the sibling's flag name. `tests/errexit-safe/run.sh` part (iii) re-derives every errexit-unsafe candidate site in `bin/` and loud-fails on one its registry does not account for, so every stderr write in the new checker takes the guarded form. **AC13** carries both, with the constraint and the suite run side by side.

**DP-10 — the testing affordances.** Optional read-only `--default PATH` and `--agents-dir PATH`, defaulting to `$SCRIPT_DIR/../templates/binding-default.conf` and `$SCRIPT_DIR/../agents` resolved physically (`cd DIR && pwd -P`), mirroring the shape `bin/check-binding.sh`'s `--config` and `bin/check-readme-version.sh`'s `VERSION_MANIFEST` already have. No write path; the flags exist so a fixture can exercise a mutated pin or conf without touching the checkout.

**DP-11 — version tier: PATCH.** Both `CONTRIBUTING.md` tests read not-met, applied jointly: the headline test fails (no adopter would recognize "the loop's own CI now cross-checks two of its config files against each other" as a release headline), and the default-reachability test fails (the checker runs in this repository's CI; no shipped phase, skill or adopter command invokes it — the PATCH bullet's "internal mechanisms, and capabilities that ship but stay latent behind an opt-in" shape).
