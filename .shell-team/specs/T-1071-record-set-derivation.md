## Problem

Five adverse gate rounds in T-1065 — three QA `FAIL`s and two Codex `REQUEST_CHANGES` — all landed on one root-cause class, and none of them touched that task's deliverable. Every instance lived in hand-written records prose: a step total stated as 68 against a live count of 71, "the two contract templates" where the fixture suite asserts three, a class-closure inventory claiming every whole-set phrase was inventoried while omitting one its own stated regex catches, and — after two explicit records-authoring premise changes had already been applied — a set delta whose widened command surfaced two specs beyond the original population while the prose disclosed one.

That fourth instance is the decisive datum: **discipline changes alone did not close the class.** The generator is structural. Set arithmetic — deltas, populations, bucket splits — is being performed by eye at the moment prose is written, and a hand cannot be held to an artifact by asking it more firmly. The repair is to make the arithmetic a tool's output that a record embeds, so the number in the record and the number in the tree are the same bytes rather than two hands' agreement.

- user-visible: yes — the deliverable is a new command, `bin/derive-populations.sh`, that lands on an adopter's `PATH` the moment the plugin is enabled, exactly as `gen-loop-replay.sh` and `resolve-executor.sh` do, and a norm shipped into five agent contracts that tells those agents to run it. **Goal (one sentence).** A record's set arithmetic becomes a tool's output: `bin/derive-populations.sh` takes two or more named population-extraction commands, runs them under a pinned collation, and emits one delimited derivation block — per-set status and counts, the union total, and a gap-free membership partition with every item listed verbatim and sorted — which a record embeds unchanged; and an authoring norm shipped into the five record-writing agent contracts requires that any population total, set delta or bucket split in a record be produced that way rather than counted by eye.

**What the block has to make impossible.** Three failure shapes, each drawn from the instances in `## Problem`, are closed by construction rather than by care: a **stated total that disagrees with its own listing** (the block's union count, its per-set counts and its bucket counts are all derived from one pass over the same items, and the criteria below re-derive each from the others); a **listing that silently drops members** (every item of the union appears in exactly one bucket, verbatim, so a partition with a gap is visible in the block itself); and a **command that failed being read as a set that was empty** (a command's exit status is recorded on its own set line, an unaccepted status refuses the whole derivation, and an accepted status with no output is reported as a set of zero items rather than as a failure).

**What "the record embeds it" means.** The block carries `<!-- BEGIN derivation: <label> -->` / `<!-- END derivation: <label> -->` markers and is preceded in the record by a `- reproduce:` line carrying the full command that regenerates it, so re-derivation is a line a verifying role runs rather than arithmetic a verifying role redoes. The markers exist for a second reason stated now so it is not mistaken for decoration later: they are the schema anchor the carved-out refusal-checker needs, which converts that successor from prose analysis into a cheap structural check.

**The norm's reach, and what it does not claim.** The norm is a canonical prompt block registered in `contain` mode against the five agent contracts that author or verify loop records — `pm-spec`, `tech-lead`, `engineer`, `qa-verifier`, `codex-reviewer`. It is prose a role acts on; **no checker enforces it in this task**, and the spec says so rather than implying a gate that does not exist.

**What the task leaves behind.** One new script under `bin/`, one committed-fixture suite under `tests/`, one canonical prompt block and its registry row, the five agent edits, one note at `docs/loop-engineering/record-set-derivation.md` carrying this task's own dogfooded derivations, the adopter-facing section in both READMEs, the CI wiring for the new script and suite, and an appended line in `.shell-team/test-recipe.md`.

## Pre-commitment

**Authorship: AI self-discipline. This is a rule this role imposed on itself; it is not operator-ratified and the operator is not its author.**

- **Trigger.** Two consecutive review or QA rounds producing independent Blocker/Major findings against the **same component** stop the patching. A third patch round against that component is not started.
- **Disposition, decided now so the trigger executes a decision rather than opening one.** The **droppable** component is exactly one: **the norm's prompt-block wiring** — the canonical block, its registry row and the five agent edits (**AC7**), together with the two body directives that describe them. It travels to a fast-follow issue carrying each round's findings verbatim as that issue's requirement list, alongside the carved-out refusal-checker whose design it would otherwise precede. Nothing else is droppable. Dropping it requires the ratified class-B re-freeze path, because **AC7** and the Goal sentence naming the norm both live inside the frozen block; the drop is proposed with the rounds' findings attached, not executed unilaterally.
- **Never-dropped.** The helper's **derivation correctness**: **AC3**'s `comm` agreement and count re-derivation, and **AC4**'s gap-free, overlap-free partition. These are the reason the task exists — a helper whose output a record embeds must be right, since embedding a wrong block is strictly worse than a wrong number a human might still catch by eye. If that floor is itself defeated in two consecutive rounds, the task **stops and returns to planning** rather than being patched: the same mechanism defeated across consecutive design generations is evidence about the design premise, not about the implementation's craft.
