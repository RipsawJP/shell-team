# N-agent launch fan-out: the launch record defined where the shipped step already references it, and an orchestrator-run probe that fires the whole fan-out once with real plugin-role agents, real aggregation and a real instance death

**Status**: READY_FOR_ARCH
**Owner**: pm-spec
**Task ID**: T-1083

**Branch**: `feature/1083-agent-launch-fanout`, created before this spec was written and stacked on `feature/1082-telemetry-discriminator`'s tip (PR #318). PR base stays `develop`; the PR is held open and merges at the sprint batch GO.

## Problem

Issue #277's third adoption precondition is the orchestration step that actually launches N agent instances for one phase. Two thirds of it shipped: `bin/aggregate-verdicts.sh` reduces N part files to one authoritative verdict (T-1074), `bin/check-fanout-instances.sh` refuses an unattributable aggregation (T-1082), and the prose step that tells an orchestrator how to drive both lives in `templates/prompt-blocks/fanout-orchestration.md`. What is missing is smaller than a mechanism and more damaging than a typo: that step tells the orchestrator to "state the chosen N and its ground … in the **launch record**" (line 5) and the repository defines no launch record anywhere — no path, no grammar, no writer, no reader. An adopter who follows the step cannot comply with it.

The second gap is that the whole step has never run. No `BEGIN fanout-verdict` block produced by real agents exists in this repository, and the one empirical result the step rests on — T-1073's `concurrent-overlapping` verdict — was measured entirely with `subagent_type=general-purpose, model=haiku` agents, with its own `plugin-role-confirmation` arm dropped and never executed (that note's `## Agent-type boundary` records the gap as `unobserved` rather than inferring past it). T-1084 and T-1085 launch plugin-role agents derived from `agents/*.md`. Shipping a dispatcher on top of a boundary nobody has crossed is the failure this task exists to prevent.

**Venue.** A throwaway `git clone --no-hardlinks` under `$TMPDIR`, checked out to this branch's branch point, is the only tree any probe agent touches. `git worktree add` is **never** used for this venue: a worktree registers under `.git/worktrees` in the real checkout, which turns cleanup into a destructive step this task takes no version of. No probe agent writes to the real checkout, and that is verified rather than promised: `git status --short` and `git ls-files --others --exclude-standard` are read in the real checkout after every arm and the result recorded on a `- probe-writes: none — <text>` line. Every filesystem path quoted anywhere in the evidence is written as a placeholder or in `$TMPDIR`-relative form; **no home-directory absolute path appears**, which is a public-repository hygiene requirement and was the exact defect that cost T-1073 a round.

**Unit and population.** The production unit is `bash bin/check-acs.sh <spec>` over real committed specs in the pinned clone — the same shell-process ladder T-1069 and T-1073 both used, so plugin-role launch overhead stays separable against a known baseline rather than confounded with it. The population is a set of real committed spec paths, written to a population file **before any instance is launched** and never re-selected after a verdict is seen. Its per-spec costs are measured singly, before any arm runs, so that the fan-out's own unit durations sit above the measured launch latency by a declared margin factor of at least **3** and below the liveness check's stall threshold; where no population satisfies both bounds, that finding is recorded and the verdict is `undetermined`. The unit is the run, never its verdict: a non-zero `unit_rc` from a stale merge-point-scoped lock is expected and is not read as a result about the spec it ran against.

**Clock source.** The probe records which clock it read and verifies it before relying on it: a source whose nanosecond field does not expand (BSD `date` emits a literal `N` for `%N`) is `unusable` and is substituted, with the substitution recorded. Every timestamp in the evidence is an integer of digits only, with no unit suffix inside the field.

**The launch record — grammar, frozen.** One file per fan-out at `<runs>/fanout-<label>.launch`, with `<runs>` resolved through `bin/team-paths.sh --get runs` and `<label>` the same `--label` value passed to both shipped checkers. Written before any instance is launched, except the two epoch fields, which are written at the moments they name. Lines, in this order, with ` — ` (space, U+2014 EM DASH, space) as the field separator:

- `launch-record 1` — the version line, first line of the file, exactly one.
- `- population: <path>` — exactly one; the path of the population file passed verbatim to `bin/aggregate-verdicts.sh --population`.
- `- requested-n: <digits>` — exactly one; the N the degree rule chose.
- `- achieved-n: <digits>` — exactly one; how many instances actually launched. `achieved-n` below `requested-n` is a legitimate recorded outcome, not a defect to hide.
- `- cap-ground: TEAM_FANOUT_MAX=<value>` or `- cap-ground: measured-cores=<value>` — exactly one; the ground of the cap, from that two-token closed vocabulary, discharging the shipped step's own "state the chosen N and its ground … in the launch record" sentence.
- `- assign: <instance-id> — <unit-id>` — exactly one per unit in the population, and the instance-id set of these lines equals the `--part` name set passed to `bin/aggregate-verdicts.sh`.
- `- liveness: <instance-id> — harness-tracked-background — <command>` — exactly one **per instance**, not one per fan-out, because the shipped step requires a liveness check alongside *each* instance and there are N of them. `<command>` is the launch command verbatim. `harness-tracked-background` is the only conforming mechanism token: a watchdog launched with a bare shell `&` inside a foreground Bash call dies with that call (measured, `harness-agent-concurrency.md:385`), so a bare-`&` launch is a non-conforming record rather than a weaker one.
- `- launched-epoch: <digits>` — exactly one; when the last instance's launch call was issued.
- `- completed-epoch: <digits>` — exactly one; when the last instance's completion was observed.
- `launch-record-end` — the terminator, last line, exactly one.

**Why no new checker is built, and what that leaves ungated.** Every field above that a checker could gate is already an argument to a shipped fail-closed checker: `- population:` names the file `bin/aggregate-verdicts.sh --population` reads, and the `- assign:` pairs are the `--part <instance-id>=<part-file>` assignments themselves, so a unit assigned to nobody is `uncovered-unit` (exit 3), a unit assigned twice is `duplicate-claim` (exit 1), and an instance id present in the record but absent from the telemetry is refused by `bin/check-fanout-instances.sh`'s consistency property. Building a third checker over the same facts would ship a second, divergent implementation of a closure two tools already fail closed on. The honest residual, stated rather than papered over: `- liveness:`, `- launched-epoch:`, `- completed-epoch:` and `- cap-ground:` are **audit-only** — no checker reads them, they exist so a later reader can reconstruct what ran, and the shipped block says so in those words.

**Arms.** Five, with a closed id vocabulary and a fixed drop order. `plugin-role-n2` — two instances of one `agents/*.md`-derived plugin role, launched as parallel `Agent` tool calls inside **one** orchestrator message, with the resolved `subagent_type` and model recorded verbatim; **never dropped**. `aggregation-live` — the same instances' real part files reduced by `bin/aggregate-verdicts.sh` and the result verified by `bin/check-fanout-instances.sh` against the probe's own real telemetry, emitted with `--instance` and `--seq auto`; **never dropped**, and the only end-to-end evidence precondition 3 has ever had. `instance-death` — one instance genuinely writes no part or a partial one and the aggregation is observed refusing with **exit 3** and the phase not advancing; built so the agent **ends naturally**, with no `TaskStop` and no `kill` anywhere; **never dropped**. `plugin-role-n4` — the same **launch and overlap-measurement** shape at `N = min(<unit count>, cap)`, and deliberately **no aggregation**: this arm runs no `bin/aggregate-verdicts.sh` and no `bin/check-fanout-instances.sh` pass and records no `- checker-result:` line of its own, so the end-to-end evidence stays the single `aggregation-live` pass rather than being duplicated by a wider arm that would add nothing to it; **droppable second**. `launch-refused` — an attempt to induce a genuine launch refusal; **droppable first**, and where it cannot be induced the arm records `unobserved` and nothing is fabricated.

**Evidence, three channels, borrowed verbatim from T-1073 rather than re-coined.** ① `agent-self-timestamps` — each instance's own first and last timestamps, the **primary** overlap evidence, the only channel measured from inside the agents. ② `batch-vs-sum` — the orchestrator's batch wall clock against the summed per-instance durations; a **necessary condition** for overlap, never sufficient alone. ③ `orchestrator-span-rows` — span rows carrying `--instance <role-qualified-id>` and `--seq auto`, emitted by the orchestrator, never self-emitted by an instance; **secondary, attribution-only**, and in this task additionally the input `bin/check-fanout-instances.sh` reads.

**Liveness, never dropped.** A per-instance liveness check runs alongside each instance, started at the moment that instance is launched, through a harness-tracked background launch and never a bare shell `&`. The evidence carries at least two heartbeat samples timestamped **inside** the window in which that arm's instances were still running — the positive control that the parent read the liveness signal before completion rather than after it — each watchdog's launch command verbatim, and its final disposition. This satisfies, for this arm's shape, the structurally-correct-watchdog requirement recorded in issue **#274**'s body — cited as **prior art**, since that issue is closed (`completed`, 2026-08-17): reading a requirement a closed issue put on record is legitimate, describing it as an open obligation this task discharges would not be, and nothing here reopens it.

**Verdict.** Exactly one, from T-1073's frozen five-value vocabulary used verbatim with no new token: `concurrent-overlapping` / `serialized` / `queued-partial` (with a measured cap `k`) / `launch-refused` / `undetermined`. Seven licence conditions, each recorded `met` or `not-met` with its own evidence: `plugin-role-subagent-type`, `production-unit`, `real-population`, `same-machine-session`, `clock-source-monotonic`, `overlap-margin-exceeds-launch-latency`, `aggregation-end-to-end`. Any condition reading `not-met` confines the verdict to `undetermined` or `launch-refused`.

**A negative result is a legitimate finding, and its disposition is fixed here rather than at the moment it lands.** If plugin-role agents serialize where general-purpose agents overlapped, that is the most valuable thing this probe could find — but its value is as an input to the next planning round, **not** as a deliverable this task's criteria pass on. The criteria below measure a `concurrent-overlapping` deliverable, and several of them are structurally unsatisfiable under any other verdict: an intersecting execution window does not exist when instances serialize, and neither an aggregation nor a per-instance timestamp exists when a launch is refused. This is the same exit the Pre-commitment's never-dropped clause already names for a defeated `plugin-role-n2` result — one boundary, one door, not two — and nobody on this task is under any pressure to produce a positive in order to avoid it.

## Input space

**Reachable input classes** — what this probe, this record grammar and this note really meet:

- **Harness outcomes genuinely reachable when a plugin-role agent is launched**: instances whose execution windows overlap; instances executed one after the other; a partial queue admitting `k < N` at a time; a refusal to launch at all (an unavailable or misspelled `subagent_type`, a permission refusal, a tool error); and a run whose evidence licenses none of those four. All five are ordinary results, which is why the borrowed five-value verdict vocabulary has somewhere to put each.
- **An instance that produces no part file, or a truncated one**, without anyone terminating it — an agent that finishes its turn having written nothing is an ordinary harness outcome, and `bin/aggregate-verdicts.sh`'s own header states that an instance that died and an instance that wrote nothing are the same operational fact.
- **Instance labels the shipped writer accepts**: role-qualified lower-case tokens under `bin/log-run.sh`'s `BINDING_TOKEN_RE` (`^[a-z][a-z0-9-]*$`). A bare numeric label is refused by that same character class, which requires a leading lower-case letter, and an omitted or explicitly empty value records `"instance":null` rather than an id — which is why the probe's ids are spelled role-qualified and are never omitted.
- **A degree the cap actually produces**: `N = min(<unit count>, cap)` with `cap` from `TEAM_FANOUT_MAX` when it is a positive integer, otherwise the measured core count, otherwise 2 — so `requested-n` and `achieved-n` can legitimately differ and the record has a field for each.
- **The unit's real cost distribution**: `bash bin/check-acs.sh <spec>` over real committed specs, whose per-spec cost varies by roughly an order of magnitude across this corpus — the reason the population is fixed and cost-measured before any arm runs.
- **Clock sources actually available on the probe host**, including one whose nanosecond field does not expand (BSD `date` emits a literal `N`), which the protocol requires the probe to detect and substitute.
- **A note read months later by someone who did not run the probe** — the primary reader of every evidence line, which is why the evidence quotes commands, records and raw values rather than only conclusions.
- **An adopter following the shipped step in either supported layout**, with `<runs>` resolving to `.shell-team/runs` or `tasks/runs`, and reaching `bin/` scripts by bare name with the plugin loaded — the reason the record's path is specified through `bin/team-paths.sh --get runs` and never as a literal.
