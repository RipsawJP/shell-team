## Lesson candidates

- `[common]` リリース単位の2腕 sweep（freeze sweep／blast-radius）は、そのリリースの累積 diff が `bin/`／`agents/`／`skills/`／`templates/`／`.github/` を一切含まない docs-only diff である場合、フルポピュレーションではなく、対象ファイルを読む `- check:` 行を持つ spec だけへスコープを絞るか、省略してその理由をリリースノートに残す。既存の2026-08-13 lesson「Freeze-time verification cost is priced by the task's deliverable class」（`.shell-team/lessons.md:1117`）を拡張する候補——今回の新しい点は、対象がタスク単位の AC 検証形状ではなく**リリース単位の2腕 sweep 自体**であること。発火条件: 直近の sweep 以降の累積 diff が `docs/`／`README*` ファイルのみに限られ、`bin/`／`agents/`／`skills/`／`templates/`／`.github/` の変更を一切含まないとき。誰が助かるか: リリース前に mechanism-class の full-population sweep を1回実施する運用を持つ、任意の spec 駆動開発ループ。source: `.shell-team/interventions/no-task.md` 2026-09-19エントリ、board T-1149 の `## Blast radius`／`blast-radius-deferral`、`.shell-team/lessons.md:1117`。
- `[common]` 「ユーザー可視の機構は adopter 向けドキュメントを同じタスクで出荷する」というゲート（本 repo では T-1061 の adopter-docs gate）が、そのタスクの凍結時点で adopter surface が「1つ存在するか」だけを問い、forward-only（既存 spec への retrofit をしない）である場合、同じ機構を記述する**他の既存ドキュメント**（本サイクルでは README／distribution／workflow のうち、機構出荷タスクが選ばなかった残り）が更新されないまま複数リリースにわたって残ることを検知しない。既存の2026-08-11 lesson「A spec for a user-visible capability carries an adopter-facing-documentation acceptance criterion as a freeze-time blocker」（`.shell-team/lessons.md:1107`）に隣接するが、あちらは「そのタスク自身が docs を落とすこと」を防ぐ設計で、こちらは「機構出荷後に残る**他の**出荷ドキュメントの陳腐化」を扱う点で異なる。発火条件: ある spec の `## Summarized sources`／`## Blast radius` 相当の節が、同じ機構を記述する複数の出荷ドキュメントの存在を認識しつつ、そのうち一部だけを編集対象にしているとき。誰が助かるか: 複数の adopter 向けドキュメント面（README／distribution guide／workflow guide 等）を持つ、任意の spec 駆動開発ループ。source: `.shell-team/specs/T-1061-adopter-docs-gate.md` `## Goal`／`## Non-goals`、board T-1148/T-1149 の `source:` 行、`.shell-team/lessons.md:1107`。
