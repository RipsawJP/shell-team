- decision: The sibling `team-paths.sh` is invoked explicitly through `bash "$sibling_team_paths" --get reviews` (existence checked with `[ -f ... ]`) rather than relying on `command -v`-style PATH resolution or requiring the sibling's own executable bit and shebang.
  reason: Two valid shapes existed — mirror the PATH branch (`command -v team-paths.sh` plus a bare exec, which requires the file to carry its own +x bit) or mirror the cwd-relative branch (`[ -f bin/team-paths.sh ]` plus explicit `bash bin/team-paths.sh`, which does not). A freshly-copied sibling (e.g. a plugin distribution that preserves file bytes but not permission bits, or a `cp` in the AC1/AC3 fixtures) is not guaranteed to carry the executable bit; requiring `-x` would make the shipped sibling resolution fragile to how it got onto disk. The explicit-`bash` shape is also the one `bin/close-out.sh` already uses for its own sibling `team-paths.sh` call, so this keeps the two sibling-resolution call sites in this codebase doing the same thing the same way.
  grounding: bin/close-out.sh:191 (`bash "$SCRIPT_DIR/team-paths.sh" --get todo`, the prior art this task's Notes for engineer cites); bin/codex-capture.sh's own pre-existing cwd-relative branch (`elif [ -f bin/team-paths.sh ]; then reviews_dir="$(bash bin/team-paths.sh --get reviews)"`), which this decision makes the sibling branch consistent with.
