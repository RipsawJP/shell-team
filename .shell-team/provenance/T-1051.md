- decision: attach the left boundary guard to the `sk-` alternative only, using the class `[^A-Za-z0-9]` (start-of-line or one non-alphanumeric character) written inside `RE_TOKEN`'s own single assignment line, rather than guarding the whole `gh[oprs]_|AKIA|sk-` alternation with one shared boundary, and rather than reusing `RE_HOME_PATH_BOUNDARY`'s class (which additionally excludes `.` and `-`).
  reason: the measured false-positive population (an identifier chain ending in the letters s+k before a hyphen, e.g. this repository's own kebab-case label convention) is confined to the `sk-` alternative; `gh[oprs]_`/`AKIA` have no measured false-positive carrier in this tree, and guarding them would suppress a real key that happens to follow an alphanumeric character — a false negative, which the checker's own documented bias ranks as the costlier error. Reusing the home-path boundary class verbatim would manufacture a new false-negative class for the token pattern, since a real key preceded by `.` or `-` must still fire (a token has no host-name-continuation concern the way a path does). Writing the guard inside `RE_TOKEN`'s existing single line adds no new `RE_*` variable, so the checker's rule count stays exactly what the frozen T-111 spec's AC10 prose states (nine), even though AC10's own `check:` line never asserts that count — a tenth rule would pass every machine gate while silently falsifying frozen prose.
  grounding: `.shell-team/specs/T-1051-inspection-ux-polish.md`'s `## Design decisions` DP1 and DP2 (the rejected group-guard design and its stated reason; the class-narrowing rationale; the single-line/no-tenth-rule requirement); `bin/check-pii-shapes.sh`'s own anchoring/boundary inventory entry for `RE_HOME_PATH_BOUNDARY` (the `(^|[^A-Za-z0-9.-])` class and its host-name-continuation rationale, which the token guard deliberately departs from); AC1 and AC2's `check:` lines (the behavioral and rule-count locks this decision is built to satisfy).
- decision: for `#179(a)`'s SIGPIPE exposure, ignore the signal outright (`trap '' PIPE`) rather than routing it through the existing `on_signal` handler with a new conventional exit code (e.g. 141, following the 128+N pattern HUP/INT/TERM already use).
  reason: measured live (forcing SIGPIPE to its true default, process-terminating disposition, since this execution environment inherits an anomalous SIG_IGN that masks the defect) that a bash builtin `printf`'s write to a closed pipe, under SIGPIPE's real default disposition, kills the whole process synchronously inside the write() syscall — before bash's interpreter ever reaches the trailing `||` guard already sitting after each of this file's two builtin-write sites (the print-hash deliverable and the courtesy `aligned:` line). Also measured: once SIGPIPE is ignored instead, the same write instead returns an ordinary non-zero exit status from the `printf` builtin (observed stderr: "printf: write error: Broken pipe", rc=1) — exactly the failure shape the existing `||` guards at both sites were already written to classify. Routing SIGPIPE through `on_signal` instead would introduce a NEW observable exit code for this signal and would directly contradict the courtesy `aligned:` print's own already-documented, deliberately-chosen behavior ("the exit code below is unconditionally 0 regardless of this printf's result") — a global on_signal-based PIPE trap would override that with an immediate `exit 141` the moment SIGPIPE arrives during that specific write, which is a behavior change T-1041 D3 never asked for and this task's Non-goals forbid re-litigating. Ignoring the signal makes both existing, already-correct `||` constructs (T-1041 D3's classified `fail_usage` for the deliverable write, and the pre-existing `|| true` for the courtesy print) work as originally designed, with zero new stderr write sites and zero new classified exit codes.
  grounding: `.shell-team/specs/T-1051-inspection-ux-polish.md`'s DP5 (the trap-route decision and the "measure before you trap" instruction) and Notes for engineer gotcha 5; `.shell-team/specs/T-1041-freeze-ux.md`'s D3 (the stdout contract; "unlike the `aligned` line ... whose SIGPIPE guard is correct because the outcome is already decided and the print is a courtesy, here the value is the deliverable ...
