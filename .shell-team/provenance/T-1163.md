- decision: A refused write is reported as `- run yourself: <command>` with single-quoted absolute paths; the exclude command carries a leading line break (`printf '\n.codex/agents\n'`) only when the existing file lacks a trailing newline.
  reason: The printed command must be runnable verbatim with bash -c and must keep every existing exclude byte; a fixed command would glue the entry onto an unterminated last line.
  grounding: `.shell-team/specs/T-1163-setup-prompt.md` decision 6 (Refused writes), **AC4** and **AC6**.

- decision: Exit status is computed from three flags with precedence 2 > 3 > 1 > 0, and the report is printed even when the exit is 2.
  reason: An operator whose run failed midway still needs to see what was already written; flags keep the precedence rule in one place at the end.
  grounding: `.shell-team/specs/T-1163-setup-prompt.md` decision 9 (Report) and **AC8**.

- decision: A refused agents write is detected by probing (`mkdir -p` when `.codex/agents` is absent, `[ -w ]` when present) instead of reading the generator's exit status, and empty directories this run created are removed if the generator then fails.
  reason: The generator's exit 1 and 2 mean role or binding errors and also appear on write failure, so the status alone cannot tell a refusal from an error; rolling back leaves no half-state.
  grounding: `.shell-team/specs/T-1163-setup-prompt.md` decision 5 (Drift), decision 6 and **AC5** / **AC6**.

- decision: The scaffold-file to template mapping used for the upgrade report is written into `bin/team-setup.sh`, and `tests/setup/run.sh` locks it by asserting a fresh scaffold produces no "differs from" line.
  reason: `bin/team-init.sh` is frozen by the byte-identity criterion, so its variables cannot be sourced; a locked copy is the drift-safe alternative.
  grounding: `.shell-team/specs/T-1163-setup-prompt.md` `## Notes for engineer` (Template diff) and **AC9** / **AC12**.

- decision: The git common directory is checked for a single quote or control character, together with the repository root and plugin root, before any write.
  reason: In a linked worktree the exclude path lives in the main repository and appears in a printed command, so it needs the same quoting refusal.
  grounding: `.shell-team/specs/T-1163-setup-prompt.md` decision 3 (Refusals before any write) and **AC2**.

- decision: Recorded measurement (the spec's unmeasured premise): `check-codex-agents.sh` writes under `$TMPDIR` only one `check-codex-agents.XXXXXX` scratch directory (with five staging files inside), removed on exit; `gen-codex-agents.sh` makes two short-lived `$TMPDIR` files per role and five staging files inside `--out-dir`, all renamed or removed. Nothing is left in `$TMPDIR` afterwards.
  reason: Measured with a `mktemp` shim on PATH and a fresh TMPDIR over a codex-cli run plus a second run; this scratch use sits outside the write set of decision 4, which governs the repository and HOME.

- decision: Before any write, setup refuses (exit 2, nothing written, the operator decides) when any component below the repository root of the base dir, its seven operating subdirectories, `.codex/agents`, the git directory's `info` or `info/exclude` is a symlink; no `- run yourself:` line is printed for it.
  reason: `mkdir -p` and the writers follow a directory symlink, so a repository that commits one would receive generated files outside the repository, which breaks the write-set bound; no single-artifact command can safely stand in for replacing a committed link, so the choice stays with the operator. Refusing every symlinked component (not only links that leave the repository) keeps the rule one line and fail-closed.
  grounding: `.shell-team/specs/T-1163-setup-prompt.md` decision 4 (Write set, exhaustive), decision 3 (Refusals before any write) and **AC1**.
