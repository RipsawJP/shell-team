- decision: introduced a second, distinctly-named snapshot file (`NOT_APPLY_ITER_FILE`, a plain `cp` of `$NOT_APPLY_FILE` taken once, right after the registry's own `sort -u`) as the `while read ... done <` source for the two mutation-self-check loops (content-rewrite and duplicate-site), instead of iterating `done < "$NOT_APPLY_FILE"` directly while also passing `"$NOT_APPLY_FILE"` to `comm` inside the same loop body.
  reason: shellcheck (0.11.0, the CI-pinned version) raises `SC2094` on a file that is simultaneously a `while` loop's stdin redirection and referenced again inside the loop body, even when every reference is read-only — confirmed by reproducing the warning in an isolated two-line scratch script and confirming it disappears once the loop's redirection source is a distinct path. AC11 requires `shellcheck "$R"` to exit clean with no severity filter, so this is a CI-observable contract, not a style nit — a `# shellcheck disable=SC2094` comment was the other option, rejected because it would blanket-suppress a diagnostic class at that line rather than removing the actual (if currently benign) double-open, and a future edit that turned one of those reads into a write would then go undetected.
  grounding: `tests/errexit-safe/run.sh`'s own comment immediately above `NOT_APPLY_ITER_FILE="$TMP/not-apply-iter.txt"` ("a distinct path from $NOT_APPLY_FILE ... purely so a static scanner cannot mistake the two independent reads ... for a read/write conflict"); `shellcheck tests/errexit-safe/run.sh` exit 0 (AC11).

- decision: split the registry derivation into two named functions, `derive_candidates()` (keeps `grep -n`'s raw `file:line:content` lines through its own `sort -u`, strips nothing) and `counted_keys()` (strips the line field and forms the `<count> <file>:<content>` key, called only afterward), rather than one function that does both steps inline.
  reason: D1's load-bearing derivation constraint ("the line field is stripped only afterwards, when the key is formed and the occurrences are counted... dropping the line field before `sort -u` would collapse them at the source and no downstream count could recover them") is a *sequencing* requirement.
