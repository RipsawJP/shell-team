- decision: the `### Dispatch` element (with its two templated `- dispatch: implement — ` / `- dispatch: verify — ` lines) is inserted into `agents/tech-lead.md`'s Routing Map fenced output shape immediately after `### Hand-off artifacts` and immediately before `### Out of scope`, rather than earlier in the shape (e.g. before `### Steps`) or appended after `### Out of scope`.
  reason: the fenced shape's existing element order reads as "what to do" (`### Steps`), "what gets produced" (`### Hand-off artifacts`), then "what is excluded" (`### Out of scope`); a per-axis routing decision is closer in kind to a hand-off artifact (a recorded output of the planning step) than to an exclusion, so placing it directly after `### Hand-off artifacts` keeps the shape's existing narrative order intact rather than splitting "things tech-lead outputs" across two non-adjacent positions.
  grounding: `agents/tech-lead.md` `## Output format`'s fenced block (the `### Steps` / `### Hand-off artifacts` / `### Out of scope` element sequence this task extends); `.shell-team/specs/T-1084-dispatch-routing-record.md` **AC5** (fixes only that `### Dispatch` occurs exactly once and carries the two templated lines, not its position relative to the other elements).
- decision: `bin/close-out.sh`'s new gate extracts each `- dispatch:` sub-bullet's four fields (`axis`, `value`, `modality`, `ground`) with four independent `sed -nE` passes over the same line — one pass per field — rather than a single pass splitting on a pipe- or control-character-joined capture group.
  reason: the ground field is declared free text that may itself contain further ` — ` sequences (spec Input space: "a ground field carrying an em dash inside that prose... must not truncate it"); a single-pass extraction joining all four captured groups into one delimited string for a later `read`/`IFS` split would need a delimiter guaranteed absent from the ground field's own text, and no such guarantee exists (the ground is free-form, so even an ASCII control character is not provably safe against a future adopter board). Four independent `sed -nE` passes, each anchored on the fixed number of preceding ` — `-separated fields and using `(.*)$` only for the final (ground) capture, avoid ever having to choose an inter-field delimiter at all.
  grounding: `.shell-team/specs/T-1084-dispatch-routing-record.md` Input space ("A ground field that carries explanatory prose after the priced-line id, and a ground field carrying an em dash inside that prose. The last field is free text, so the grammar's separator appearing inside it must not truncate it."); the board's own freeze-attestation sub-bullet (`.shell-team/todo.md`, T-1084 entry) recording that **AC9**'s own ground-extraction `sed` needed a `sed -nE` repair for BSD-sed portability — the same extended-regex form this gate's four passes use.
- decision: an anchored `- dispatch: ` sub-bullet that fails the four-field extraction entirely (its shape does not decompose into `<axis> — <value> — <modality> — <ground>` at all — for example, a line missing a separator) is treated as a malformed record and refuses close-out, even though none of **AC7**'s nine required fixture cases exercises this exact input.
  reason: the canonical block's own "Validation" bullet states the record "must match the grammar above... or the close-out refuses" with no carve-out for a structurally incomplete line, and the gate is fail-closed by the repository's own stated discipline ("Checkers must fail closed... a check that cannot evaluate its input reports an error; it never silently passes" — `CLAUDE.md` Working rules); silently treating a structurally-broken anchored line as if it were absent would let a board author's typo (a dropped separator) pass close-out unnoticed, which is exactly the audit gap this task's grammar exists to close.
  grounding: `templates/prompt-blocks/dispatch-record.md`'s own "**Validation.**" bullet ("every `- dispatch:` sub-bullet on the entry being closed must match the grammar above... or the close-out refuses"); this repository's `CLAUDE.md` "Working rules" ("Checkers must fail closed"); `bin/close-out.sh`'s own dispatch gate (the `if [ -z "$d_axis" ] || ... ; then fail ...` branch).
- decision: round-1 rework (cross-provider review round 1, commit `d69cb16`, two Majors) is fixed as a CLASS — "the gate validates a narrower line shape than the set of lines it must judge" — by (1) widening the candidate-scan anchor from `^[[:space:]]*- dispatch: ` (trailing space required) to `^[[:space:]]*- dispatch:` (no trailing-space requirement), so every whitespace-after-colon variant (tab, multiple spaces, none) is SEEN by the scan instead of silently bypassing it, and letting the UNCHANGED strict per-field `sed` grammar fail closed on the non-conforming ones via the existing empty-field check; and (2) tightening the ground-field check from `^(saving|recommendation|break-even|cost-input): $` (prefix + space only) to `^(saving|recommendation|break-even|cost-input): [a-z0-9-]+` (prefix + space + a non-empty id token), rather than inventing a second, separate emptiness check. A line not opening with the literal single-hyphen bullet marker "- dispatch:" at all (a double-hyphen "-- dispatch:", a missing colon, a space before the colon) is left outside this round's scope — that is the same anchor-literal boundary the pre-existing `pending:` gate above already has, not a new gap this task's diff introduces, and no reachable input class in this spec's frozen `## Input space` names it.
  reason: both Majors were reproduced live as one family (Major 2: a whitespace variant after `dispatch:` makes the whole line invisible to the scan, not merely refused on a looser check; Major 1: the ground check verified the prefix and the following space but never that a non-empty id token follows) — patching only the two literally-reproduced inputs (a tab, one empty-ground-id string) would have left every sibling variant (two spaces, zero spaces, an empty axis/value/modality field reached through the same "prefix matched, content unchecked" shape) open to the same defect wearing a different input, which this repository's own lessons corpus states is exactly the failure mode a class-scoped fix must close. Reusing the existing strict-field-extraction fail-closed path (rather than adding new bespoke checks for each whitespace variant) keeps the fix minimal: the anchor widening's only job is to stop excluding lines from inspection, and the grammar that already refuses malformed content correctly does the rest.
