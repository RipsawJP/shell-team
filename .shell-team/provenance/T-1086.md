- decision: the subject's domain is `csvstats`, a per-column CSV summarizer (parse a comma-separated file, report count/sum/min/max/avg per integer-only column, skip malformed rows, distinguish "file unreadable" from "zero usable rows"), rather than any of the other real-shaped candidates considered (a log-level counter, a bill-splitting ledger, a simple task-priority sorter).
  reason: the spec leaves the domain to the engineer's own choice subject to two constraints — it must differ from `wordstats`'s word-frequency domain (so a candidate cannot read a solution shape out of this repository's own committed prose) and its serial implementation cost should plausibly land in the same order as the recorded `engineer-phase-cost` figure (271772 ms, an authoring target rather than a gate). CSV column statistics is a real, self-contained problem with the same two-library-plus-CLI shape `wordstats` used (a parsing library, a stats/accumulation library, a CLI), is semantically distant from word-frequency counting (numeric aggregation vs. token counting), and its case space (missing file, header-only, malformed row, non-numeric column, numeric column, mixed order) is large enough to need real logic without ballooning past the target size band. A log-level counter was rejected as too close in *kind* to frequency counting (counting occurrences of a token) even though the domain label differs; a bill-splitting ledger and a task-priority sorter were considered and were viable alternatives with no decisive flaw, so this was a choice among several adequate options rather than a forced one.
  grounding: `.shell-team/specs/T-1086-subject-harness.md`, Goal, "Why the subject reuses T-1078's shape and is authored fresh anyway" paragraph (the shape-reuse requirement and the domain-difference requirement) and "The subject's own size band is an authoring target, never an acceptance threshold" paragraph; **AC10**'s own `wordstats`-absence sweep over all five harness files (verified clean, see hand-off).
- decision: the three `candidate-path:` values are placed at `lib/csvparse.sh`, `lib/colstats.sh` and `cli/csvstats` (not `bin/csvstats`), and the single `candidate-extra-dir:` is `check/` (not `tests/`).
  reason: **AC3**'s own body states the manifest may declare no `candidate-path:` or `candidate-extra-dir:` value beginning `bin/` or `tests/`, precisely so **AC9**'s self-containment sweep over `acceptance.sh`/`regenerate.sh` cannot fire on a legitimate venue-relative reference the oracle is obliged to name (both scripts must mention the CLI's own path to invoke it). The same criterion's own body names `cli/<tool>` and `check/` as examples of paths "as real-shaped as the forbidden spellings," so this is the shipped idiom rather than an invented one.
  grounding: `.shell-team/specs/T-1086-subject-harness.md` **AC3** body ("A CLI at `cli/<tool>` and a candidate test directory at `check/` are as real-shaped as the forbidden spellings"); `docs/loop-engineering/subjects/subject-01/manifest.txt` (the three `candidate-path:` lines and the one `candidate-extra-dir:` line); **AC9**'s own passing result this round (see hand-off).
- decision: the subject's CSV grammar is fixed to plain comma-splitting with no quoted-field escaping (a field never contains a comma of its own), stated explicitly in `README.md` and in `docs/loop-engineering/tier2-subject-harness.md`'s own Limits section as a design boundary rather than left for a candidate to infer.
  reason: RFC4180-style quoted-field escaping would materially raise the subject's own implementation cost past the size band the recorded `engineer-phase-cost` figure targets, without adding a distinction relevant to this harness's own purpose (comparability of one whole-implementation attempt's machine time). Leaving the grammar ambiguous would also let two candidates legitimately choose different escaping rules and score differently on the same input for a reason the interface contract never named, which would make the oracle's own verdict less trustworthy rather than more.
  grounding: `docs/loop-engineering/subjects/subject-01/README.md`, "The CSV grammar this subject uses, stated once so nothing is left to guess" paragraph; `docs/loop-engineering/tier2-subject-harness.md`, `## Limits and what is not computable`, "The oracle's own CSV grammar is deliberately the simple comma-split case" sentence.
- decision: `avg` is specified and implemented as `$(( sum / count ))` — bash's own truncating integer division toward zero — never a decimal average, a `bc`/`awk`-computed float, or floor-toward-negative-infinity rounding.
  reason: the candidate-rule `zero-dependency-bash` forbids `bc` and `awk` arithmetic, so a floating-point average would require a dependency the subject's own rules exclude; bash's native `$(( ))` operator already performs truncating integer division, so specifying exactly that operator's own semantics (rather than a rounding rule that would need extra logic to implement) keeps the reference behavior a one-line bash expression and removes any ambiguity about which of several plausible integer-rounding conventions (truncate, floor, round-half-up) a candidate should pick.
  grounding: `docs/loop-engineering/subjects/subject-01/interface.md`, the `column=<name> count=<n> sum=<v> min=<v> max=<v> avg=<v>` interface line ("`avg` computed as `$(( sum / count ))` (bash integer division, truncated toward zero) — never a decimal, never rounded"); `docs/loop-engineering/subjects/subject-01/README.md`, `- candidate-rule: zero-dependency-bash`; self-check: a throwaway, never-committed reference implementation (see hand-off) scored 7/7 against the committed oracle using exactly this operator, confirming the contract is satisfiable as specified.
