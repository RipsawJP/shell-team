# T-1061 decision provenance

- decision: `bin/check-adopter-docs.sh`'s `refuse()` helper prints the bare classification token ALONE on stderr (`printf '%s\n' "$1"`), with no `check-adopter-docs: <token>: <message>` prefix the sibling scripts (`check-binding.sh`, `resolve-executor.sh`, `check-intent.sh`) all use.
  reason: AC4's, AC5's, AC6's and AC7's own `- check:` lines assert the refusal with `grep -qxF -- '<token>' "$T/err"` — `-x` requires the WHOLE line to equal the token exactly, not merely contain it as a substring. A prefixed line such as `check-adopter-docs: declaration-missing: no declaration line found` would fail every one of those `grep -x` assertions even though the correct token is present, because the line as a whole is not equal to the token. Two options existed: match the sibling scripts' prefixed convention (readable, but would fail the frozen `-x` checks) or print the bare token (passes the frozen checks, at the cost of a less human-readable stderr line with no free-text explanation). The frozen criteria's own literal grammar decided it — this is not a stylistic preference against the sibling convention, it is what AC4/5/6/7 as written require.
  grounding: `.shell-team/specs/T-1061-adopter-docs-gate.md` AC4 (`grep -qxF -- 'usage' "$T/e"`), AC5 (`grep -qxF -- 'declaration-missing' "$T/err"` and four sibling `-x` assertions in the same criterion), AC6 (six `-x` assertions), AC7 (four `-x` assertions) — all four criteria's `- check:` lines use `grep -qxF`, never `grep -qF`.
- decision: the checker searches the WHOLE FILE (fence-aware) for `- user-visible:`, `- adopter-surface:` and `- adopter-docs-waiver:` occurrences, not just the region strictly between the intent block's BEGIN and END markers — even though the Goal text places the declaration's valid window inside the block.
  reason: AC6's `outside` fixture places a well-formed declaration entirely BEFORE the `## Goal` heading (outside the intent block altogether) and requires the exit token `declaration-misplaced`, explicitly NOT `declaration-missing` ("telling an author you put it in the wrong place is a different repair from you forgot it"). A search scoped to inside the block would never see that occurrence at all, making it indistinguishable from zero occurrences and reporting the wrong token. Scoping the count/duplicate/misplaced judgment to the whole file, then applying the BEGIN/Non-goals placement window only as a post-hoc classification of the ONE found occurrence's position, is what makes both outcomes (found-but-wrong-place vs genuinely-absent) observable from the same search.
  grounding: `.shell-team/specs/T-1061-adopter-docs-gate.md` AC6 (`outside` fixture + `test "$(grep -cxF -- 'declaration-missing' "$T/err" || true)" = "0"` — the explicit not-also-missing assertion).
- decision: the fence tracker is a direct line-for-line port of `bin/check-board-headings.sh`'s `extract_ids_to_file` CommonMark-aligned state machine (0-3-space-indented opener/closer, recorded run length, info string not validated, tilde fences out of scope), rather than a simpler "any line starting with three backticks toggles a boolean" heuristic.
  reason: DP5 explicitly requires the fence property to be "a grammar-level state property (fence open/close), so it is tracked explicitly rather than approximated by a line pattern," and Notes for engineer gotcha #2 names this exact prior art as the thing to reuse. A naive toggle-only tracker would still pass every fixture this spec's own criteria enumerate (none of them nests fences or varies run length), but AC16(b) requires the detector's own blind spots to be enumerated adversarially, and "does it distinguish an opening fence from a closing one when a fence line carries an info string" is one of the five items the criterion names outright — porting the already-hardened state machine (which recorded and matched run length across three review rounds on its own task) closes that blind spot by construction instead of leaving it to be found later.
  grounding: `.shell-team/specs/T-1061-adopter-docs-gate.md` DP5 and Notes for engineer gotcha #2 ("`bin/check-intent.sh` is safe from the same input for a different reason ... copying its approach is not sufficient here"); `bin/check-board-headings.sh`'s `extract_ids_to_file` (T-095, its own header documents the round1/round2 hardening this port inherits).
- decision: `.github/workflows/check-handoff.yml` gains a SECOND, separate `shellcheck` step (`shellcheck (T-1061 additions)`) for the two new files, rather than extending the existing single `run: shellcheck ...` line's argument list in place.
  reason: AC8's own `- check:` line requires every non-blank line the workflow's branch-point blob carries to still be present VERBATIM (byte-for-byte, `grep -vxFf`) in the working file. The existing shellcheck step is one gigantic single physical YAML line; extending it in place changes that line's bytes, so the branch-point's exact line would no longer exist anywhere in the file and the survival check would report it missing — confirmed by measurement (extending in place produced a red AC8 on the first attempt). AC8's OWN grep logic (`grep -F -- 'run: shellcheck '` matches every line with that prefix, not exactly one) tolerates two such lines and still finds all three required substrings across their union, so adding a second step satisfies both AC8's literal check and the "additive, no existing step displaced" property the same criterion states as its reason for the byte-survival clause.
  grounding: measured directly — a first attempt appending to the existing line produced AC8 exit 1 with `grep -vxFf` reporting the base's original shellcheck line as missing from head; `.shell-team/specs/T-1061-adopter-docs-gate.md` AC8 (`grep -F -- 'run: shellcheck ' "$W" > "$T/sc"` — a plain substring match with no line-count constraint, then three independent `grep -qF` checks against the combined `$T/sc` content).
- decision: the declaration grammar's canonical block (`templates/prompt-blocks/adopter-docs-declaration.md`) is exactly three lines — the two `- user-visible:` example lines and one prose sentence stating the mutual-exclusion discharge rule — rather than a longer block additionally spelling out the `no`-declaration rule, the closed refusal-token set, or worked examples.
  reason: `contain` mode (per `templates/prompt-blocks/registry.txt`'s own header) requires EVERY non-empty line of the canonical block to appear verbatim, as a fixed-string substring, in all three registered consumers — `agents/pm-spec.md`, `skills/run/SKILL.md` and `bin/check-adopter-docs.sh`. Each additional line in the block is a line that three independently-authored prose passages (a self-check bullet, a single-line SKILL.md sweep bullet, and a shell comment) would all have to reproduce character-for-character. Three short lines were verified to fit naturally inside existing prose in all three consumers without contorting any of them into unnatural phrasing; a fourth or fifth line was not similarly verified and each extra line increases the chance a future edit to any one consumer's wording silently breaks `check-prompt-sync` for an unrelated reason.
  grounding: `templates/prompt-blocks/registry.txt` header ("every non-empty canonical line must appear verbatim as a fixed-string substring in the consumer"); measured — `bash bin/check-prompt-sync.sh` reports `all registered prompt blocks in sync` against the three-line block as authored.
- decision: `bin/check-adopter-docs.sh`'s symlink-resolution bootstrap uses `pwd -P` at both `cd ... && pwd` sites, not the bare `pwd` the shape was originally ported from (`bin/check-interventions.sh`).
  reason: the AC16(d) full-population blast-radius sweep measured `.shell-team/specs/T-1057-loop-integration.md` **AC12** as base:PASS / head:FAIL — a genuinely new red this task caused, not named in this spec's own prediction table. AC12 locks the live set of `bin/` files carrying a bare `&& pwd)` as exactly equal to its own frozen `## The logical-pwd class table`; adding a new `bin/` file containing one, with no corresponding table row, breaks that equality in the "apply but undeclared" direction. Two repairs existed: request a T-1057 re-freeze to add this file to its table (touches a merged, frozen spec this task has no authority over and the pre-commitment's own scope excludes), or simply not introduce the bare form at all by using the repo's own more recent, better convention (`pwd -P`, already used by `bin/check-binding.sh` and `bin/resolve-executor.sh` for the identical ancestor-symlink reason). The second option is strictly better engineering regardless of T-1057's existence — it does not merely avoid the lock, it fixes the same latent defect check-binding.sh's own comments describe (an ancestor directory being a symlink, e.g. an adopter's `bin/` vendored from the plugin's real `bin/`, survives a bare `cd && pwd` untouched) — so it was chosen over amending a merged sibling spec.
  grounding: measured directly — `bash bin/check-acs.sh .shell-team/specs/T-1057-loop-integration.md` reported AC12 FAIL before the fix and PASS after it, on the identical working tree; `.shell-team/specs/T-1057-loop-integration.md` `## The logical-pwd class table` and its AC12 check line (the live-set-equals-declared-table assertion); `bin/check-binding.sh`'s own header comment (the ancestor-symlink rationale for `pwd -P`, ported verbatim into this file's updated comment).
