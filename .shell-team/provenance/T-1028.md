- decision: `bin/check-refreeze-class.sh` builds its two comparable line arrays with a plain `while IFS= read -r line; do arr+=("$line"); done < file` loop into indexed arrays, rather than `mapfile`/`readarray` (bash 4+) or an associative array keyed by line index.
  reason: Two implementation paths existed for turning each extracted region into something indexable for the line-by-line walk: (a) `mapfile -t arr < file`, the shortest form, or (b) a manual `while read` loop appending into a plain indexed array. `bin/gen-loop-replay.sh`'s own header comment states this repository's bar explicitly: "Pure bash, zero-dependency, bash-3.2-compatible (no associative arrays, no mapfile) — same bar as every other bin/ script in this repository." The host this task was authored on runs bash 3.2.57 by default (`bash --version`), where `mapfile` does not exist at all — using it would make the classifier fail outright on exactly the class of environment this repository's other `bin/` scripts are already proven against. (b) was chosen; indexed arrays (not associative) are already used elsewhere in `bin/check-intent.sh` (`ratified_from`, `attest_version`, …), so this stays inside the established idiom rather than introducing a new one.
  grounding: `bin/gen-loop-replay.sh:84-85` ("Pure bash, zero-dependency, bash-3.2-compatible (no associative arrays, no mapfile) — same bar as every other bin/ script in this repository."); `bin/check-intent.sh`'s `extract_task_records()` (its `ratified_from=()` / `attest_version+=(...)` indexed-array usage) as the established precedent this decision follows.

- decision: the identical-block classification (`structural`, D3's third clause) is proved with `cmp -s "$OLD_REGION" "$NEW_REGION"` over the two already-normalized temp files, and the line count used for the same-line-count clause is derived with `awk 'END{print NR}'`, not `wc -l`.
  reason: Two things were at stake. First, whether "identical" should be judged by hash equality (`[ "$OLD_HASH_COMPUTED" = "$NEW_HASH_COMPUTED" ]`) or by a direct byte comparison of the two region files: `cmp -s` was chosen because it is a direct property of the actual bytes being classified, with no dependency on `git hash-object`'s collision resistance standing in for byte-identity — the two computed hashes are still reported for their own sake (D1's caller-verification purpose), but they are not what identical-block detection is built on. Second, whether line counts should come from `wc -l` (which undercounts a file whose last line lacks a trailing newline) or `awk 'END{print NR}'` (which counts physical records regardless of trailing-newline status): the classifier's own `normalize_stdin`/`extract_region` pipeline always ends each region file with `awk`'s own `print` (which always appends a newline), so in practice the two would agree here — but `awk 'END{print NR}'` was chosen anyway so the line-count logic does not depend on that invariant holding, matching this repository's general preference for a directly-correct primitive over one that happens to work under a specific upstream guarantee.
  grounding: `.shell-team/specs/T-1028-class-m-refreeze.md`, D3 ("Two blocks that are byte-identical after normalization are structural(2), not mechanics... treating 'nothing changed' as a pass would make the classifier vacuous on exactly the input a careless caller produces."); `bin/check-refreeze-class.sh`'s own `extract_region()`/`normalize_stdin()` functions (the awk-`print`-terminated pipeline this reasoning depends on).
