- decision: The seven-member class enum is hardcoded as a bash `case` statement inside `bin/check-interventions.sh` (`is_recognized_class()`) rather than parsed at runtime from `templates/prompt-blocks/interventions-classes.md`.
  reason: Mirrors `bin/check-provenance.sh`'s self-contained design (no runtime dependency on another file's presence/layout) and follows the spec's own instruction to duplicate the canonical lines verbatim in the checker's header comment, with `bin/check-prompt-sync.sh` verifying the two copies never drift — the checker stays zero-dependency and pure bash rather than gaining a markdown-parsing responsibility.
  grounding: .shell-team/specs/T-1002-intervention-capture-channel.md "## Notes for engineer" ("put it in the script's header comment verbatim, em dash included"), DP-7.

- decision: `check-interventions.sh --task <id>` does not format-validate its own value (unlike `bin/check-design-note.sh`'s `--task`, which enforces `^T-[0-9]+$`) — it only compares the given string against the BEGIN marker's captured id.
  reason: A rigid `^T-[0-9]+$` check would wrongly reject the legitimate invocation `--task no-task`, since the reserved literal `no-task` is a valid id distinct from `T-NNN` (DP-2). No acceptance criterion requires format-validating `--task`'s own value, so adding one would be an unrequested rule that conflicts with the reserved literal.
  grounding: .shell-team/specs/T-1002-intervention-capture-channel.md DP-2 (reserved `no-task` id), AC6/AC7 (marker id acceptance and `--task` disagreement).

- decision: The entry-anchor regex (`ENTRY_RE`) and the class-validity check (`is_recognized_class`) are kept as two separate steps — an unrecognized class token still opens an "in_entry" scope and has its date/summary/effect fields parsed — rather than folding the enum alternation directly into the anchor regex so an unrecognized class line is never treated as an entry at all.
  reason: Keeping the anchor and the class check separate gives every entry the same field-parsing treatment regardless of class validity, so an entry with a bad class token but otherwise well-formed fields produces one clear violation path (invalid class) instead of a second failure mode where the line is silently reclassified as "not an entry" and its subsequent date/summary/effect lines are then reported as unrecognized non-blank lines with a confusing origin.
  grounding: bin/check-interventions.sh (`ENTRY_RE` / `is_recognized_class()` separation, and AC2's fixture for an unrecognized class `human-nudge`).

- decision: `skills/goal/SKILL.md`'s interventions translation combines `usage` and `structural` into a single reserved sentinel (`AC900006`), matching `check-provenance`'s own existing combining convention (`AC900004`) rather than giving interventions a third, separate sentinel for `structural`.
  reason: The provenance translation block already sits beside this one and already made this exact choice (DP-9); using the same combining shape for the sibling gate keeps the two translation blocks visibly parallel and avoids inventing a new shape that would only differ for the newer gate with no stated benefit.
  grounding: .shell-team/specs/T-1002-intervention-capture-channel.md DP-9 and AC23; skills/goal/SKILL.md's pre-existing check-provenance translation bullet (AC900003/AC900004).

- decision: `bin/team-paths.sh --print`'s columns are re-padded uniformly with a single `printf '  %-13s %s\n'` format applied to every key, rather than hand-adjusting each row's trailing spaces individually.
  reason: DP-6 explicitly authorizes re-padding (no suite pins exact spacing, only the `[[:space:]]+` separator rule), and a single format string keyed to the widest label (`interventions`, 13 chars) is less error-prone than manually recounting spaces per row whenever the widest key changes again in the future.
  grounding: .shell-team/specs/T-1002-intervention-capture-channel.md DP-6; bin/team-paths.sh (`--print` block).
