# T-111 decision provenance

<!-- BEGIN provenance: T-111 -->

- decision: `home-path-win` matches both a single literal backslash and a doubled (JSON/YAML-escaped) backslash between path segments, not only the single-backslash form a plain-text Windows path would use.
  reason: the spec's Input space lists "Added YAML ... and JSONL fixture lines" as a reachable class this checker must handle correctly, and a JSONL fixture line represents a Windows path with each backslash doubled per JSON string escaping — a single-backslash-only pattern would silently miss that whole reachable class, including the project's own already-tracked adversarial fixture carrying this exact shape.
  grounding: spec Input space item 3 ("Added YAML ... and JSONL fixture lines"); empirically confirmed against tests/rollup-track/fixtures/winpath.jsonl, whose `phase` field carries the Windows path with doubled backslashes.

- decision: `--all` enumerates files via `git ls-files --cached --others --exclude-standard` (tracked plus untracked-but-not-gitignored), not a raw filesystem walk from the repo root.
  reason: the spec frames `--all` as "the mode that sees [untracked files]" that diff mode cannot; `git ls-files` adds that coverage without also walking `.git/` internals or files a `.gitignore` rule already excludes, and without reimplementing gitignore matching by hand.
  grounding: spec DP-2, "Known limitation, to be documented: untracked files are not in a diff and are therefore not scanned in diff mode; --all is the mode that sees them."

- decision: `--all` skips binary files using a `head | tr -d '[:print:][:space:]' | grep -q .` heuristic, rather than no binary detection at all or shelling out to `file(1)`.
  reason: the spec's Non-goals state image content is not inspected; diff mode gets binary-skipping for free from git's own "Binary files ... differ" framing, but `--all` reads files directly and needs its own guard, and `file(1)` would add an external dependency this repo's bin/ scripts avoid.
  grounding: spec Non-goals, "Image content. Not inspected. Metadata only, if anything"; CLAUDE.md's "bin/ stays pure bash, zero-dependency" rule for this repo.

- decision: AC11's "neutralised positive fixture" is, for every pattern, the same near-miss fixture already built for that pattern's AC4-AC8 POS/NEG pair, not a newly authored, pattern-specific "broken positive" fixture.
  reason: AC9 only defines a documented placeholder form for four of the five patterns (home-path, home-path-win, and the two noreply email shapes); no placeholder exists for private-key or token, so the already-proven-clean near-miss fixture — the positive shape with its one distinguishing feature removed — is the uniform stand-in AC11 describes.
  grounding: AC11 ("Vacuity guard, fixture side (meta-assertion) ... a neutralised positive fixture"); AC9 naming only four placeholder forms.

- decision: the CI step "check-pii-shapes on the PR diff" runs `bash bin/check-pii-shapes.sh --base "origin/${GITHUB_BASE_REF:-develop}"`, falling back to `develop` when `GITHUB_BASE_REF` is unset (the push trigger, as opposed to pull_request).
  reason: the workflow fires on both pull_request and push to main/develop; GITHUB_BASE_REF is only populated by the Actions runner in the pull_request context, so a fallback is required for the push case, and develop is this repository's integration branch — the same default the checker's own internal chain falls back to.
  grounding: spec AC17 ("a separate required step runs the checker diff-scoped with an explicit --base"); spec DP-2's default base chain and Assumptions note on GITHUB_BASE_REF / fetch-depth: 0.

- decision: `RE_HOME_PATH` is a plain, unanchored substring pattern with no additional word-boundary or preceding-character guard, even though a stricter anchor was considered.
  reason: the literal two-slash requirement already rejects the AC4 near-miss fixture (a relative path with no leading slash) and the AC9 placeholder form (broken by `<`/`>` falling outside the name character class), which are the two negative cases the acceptance criteria actually require; a longer path segment merely containing "Users" as a substring cannot occur without also containing a literal "/Users/" substring, so a boundary guard would not change any tested behavior.
  grounding: spec AC4 ("a near-miss negative fixture that is not [reported], and the suite asserts the reported pattern id is exactly home-path"); tests/check-pii-shapes/run.sh section "POS/NEG pair: home-path".

- decision: in the "## What this gate does not cover" section of docs/pii-controls.md, the `--all`/tests-fixtures bullet was moved to sit immediately after the four scope-limit bullets (making one contiguous five-item list), with the "This gate sees shapes only ..." paragraph moved after that list instead of between the bullets; a blank line was added after the section heading; docs/pii-controls.ja.md was left unedited.
  reason: a paragraph line breaks a CommonMark bullet list in two, so with the paragraph sitting between bullets the final bullet rendered as its own orphaned one-item list; grouping all five bullets together and moving the paragraph after them fixes the rendering while every AC18/AC20 `grep -qxF --` line stays byte-identical (only order and surrounding blank lines changed). docs/pii-controls.ja.md has no fifth bullet (AC19 defines only four), so its bullets were already contiguous and it has no equivalent rendering defect — verified by inspection before deciding not to touch it.
  grounding: docs/pii-controls.md section "## What this gate does not cover" (post-fix ordering); spec AC18 and AC20 `check:` lines (`grep -qxF --` whole-line-exact on the same six lines, order-independent); spec AC19 (only four bullets required for docs/pii-controls.ja.md).
