- decision: bin/close-out.sh resolves and exports TEAM_REVIEWS_DIR lazily — only when the dispatch-grammar loop already parsing every `- dispatch:` sub-bullet captures a `spec-review` row whose value is exactly `cross-provider` — rather than eagerly resolving it up front in the same unconditional shape the interventions-directory resolution above it uses.
  reason: an eager, unconditional resolution (matching the interventions-resolver shape literally) broke `tests/close-out/run.sh`'s pre-existing `interventions-resolver-failure-exit2` fixture, which removes the scratch `bin/team-paths.sh` sibling to test a DIFFERENT resolver's failure path and carries no `- dispatch: spec-review` sub-bullet at all; that fixture's task never elects a spec review, so it must not pay for, or fail on, a reviews-directory resolution it has no use for. Gating the resolution on the already-captured election keeps `bin/close-out.sh`'s own bytes carrying the literal fragments AC8 requires (`TEAM_REVIEWS_DIR`, `--get reviews`, `check-spec-review.sh`) while restoring full backward compatibility.
  grounding: tests/close-out/run.sh — the `interventions-resolver-failure-exit2` and `interventions-resolver-failure-exit2 positive control` cases (both reproduced failing before this fix, both green after); bin/close-out.sh's own dispatch-grammar loop (the `if [ "$d_axis" = "spec-review" ]; then SPEC_REVIEW_ELECTION="$d_value"; fi` addition) and the `if [ "$SPEC_REVIEW_ELECTION" = "cross-provider" ]; then ... fi` guard around the new gate.
- decision: bin/check-entry-mode.sh's flagged-gap / flagged-gap-resolution id-pairing scan is written in bash (`[[ "$line" =~ $regex ]]` against named regex variables, with a resolution-stem-tested-first if/elif chain over the board entry's lines) rather than as an awk script with capture groups.
  reason: the spec's own worked stem-ordering-trap requirement needs a captured id per matched line, and POSIX/BSD awk (the default `awk` on macOS, one of this repository's two supported development platforms per its zero-runtime-dependency `bin/` rule) has no portable 3-argument `match(str, re, arr)` capture form — that is a gawk-only extension. Bash's own `=~`/`BASH_REMATCH` capture is pure-bash and portable across every platform `bin/` already targets, with no new runtime dependency.
  grounding: CLAUDE.md's "`bin/` stays pure bash, zero-dependency, and shellcheck-clean" rule; bin/check-entry-mode.sh's own `res_full_re` / `gap_full_re` variables and the `while IFS= read -r line || [ -n "$line" ]; do ... done <<< "$ENTRY"` loop using `BASH_REMATCH`.
- decision: both bin/check-entry-mode.sh and bin/check-spec-review.sh exit **2** (not 1) when the supplied `--task` value is not found as exactly one top-level `## Active` entry in the board.
  reason: an unresolvable task id is a caller/invocation problem (the wrong id was passed, or the board layout the caller assumed does not match reality) rather than a judgment about a correctly-identified entry's own content — it fits the spec's own §5 exit-code taxonomy ("2 a usage error or an unresolvable environment") rather than "1 a refusal about the input's content," since there is no content to judge yet.
  grounding: .shell-team/specs/T-1096-selection-trust-gates.md §5, "Exit codes are never conflated: 0 pass or not-applicable, 1 a refusal about the input's content, 2 a usage error or an unresolvable environment."; both scripts' `[ "$A_COUNT" -eq 1 ] || die "..."` lines.
- decision: bin/check-entry-mode.sh evaluates the flagged-gap/flagged-gap-resolution id-pairing check unconditionally — for every board entry passed to it, regardless of whether its `- entry-mode:` value is `pm-authored` or `operator-authored` — rather than skipping that half of the check when the mode is `pm-authored`.
  reason: the spec's own zero-gaps-zero-resolutions case is defined as the conformant nothing-to-answer shape independent of mode, and a `pm-authored` entry realistically never carries a `- flagged-gap:` marker (there is no separate author to flag a gap against), so unconditional evaluation is behaviorally equivalent to an operator-authored-only check for every real board entry while keeping the script to one code path instead of a mode-conditional branch that would need its own fixture coverage.
  grounding: .shell-team/specs/T-1096-selection-trust-gates.md §3, "the never-flagged case is undetectable — a run that flags nothing yields zero gaps and zero resolutions, which is the conformant nothing-to-answer case"; AC10's own `pm-authored` fixtures, which carry no `- flagged-gap:` line at all.
