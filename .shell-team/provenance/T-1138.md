- decision: implemented the `self-detected-host` value's token/ground split (D8's `codex-cli — <ground>` grammar) with plain bash parameter expansion over a `case` pattern containing the literal em-dash separator (`sdh_token="${sdh_val%% — *}"`, `sdh_ground="${sdh_val#* — }"`), rather than a `read`/here-string split (`read -r tok rest <<< "$sdh_val"`) or an ERE capture group fed through `[[ =~ ]]`.
  reason: the file's own `briefing-fidelity` check (`bf_first="${bf_val%% *}"` / `bf_rest="${bf_val#"$bf_first"}"`) already establishes this exact idiom for a single-space separator, so extending it to a multi-byte literal separator keeps one splitting convention in the file rather than introducing a second (a here-string) for one field alone. It also sidesteps a locale question a regex route would raise (an ERE bracket expression over the em-dash's 3 UTF-8 bytes under `LC_ALL=C` is exactly Gotcha 5's forbidden shape; a `case`/parameter-expansion literal match never decomposes the bytes, since glob matching is byte-literal, not class-based). Verified live: `%%` removes the longest matching suffix, which is anchored at the FIRST occurrence of the separator (a longer suffix starts earlier), and `#` removes the shortest matching prefix, anchored at that same first occurrence — so a ground that itself later contains the separator's bytes does not shift where token and ground split (traced by hand against the AC2/AC3 fixtures before committing, and confirmed by the live `check-acs.sh` run).
