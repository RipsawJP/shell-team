- decision: `ATTEST_FULL_RE`'s version field is written `v([1-9][0-9]*)` (rejecting `v0` and any leading zero) directly inside the full grammar regex, rather than accepting `v([0-9]+)` in the regex and validating `version_int >= 1` afterward the way `HASH_FULL_RE`/`version_int` already do for `- intent-hash`.
  reason: two structurally valid designs existed. (a) Mirror the existing intent-hash pattern: accept any digit string in the regex, then reject `v0` with a dedicated post-parse numeric check (a distinct code path and, potentially, a distinct message). (b) Fold the constraint into the grammar itself, so `v0` simply fails to match `ATTEST_FULL_RE` and is counted as a malformed record (D2 rule 1) alongside every other near-miss shape. AC4 lists `v0` in the same ten-item near-miss enumeration as the misspelled `sweep=` literal, the reordered field list and the space-after-comma violation — all of which are grammar failures, not post-parse numeric checks — so (b) keeps `v0` in the same failure class as its AC4 siblings and needed no second numeric-validation code path for the new record type. (a) was rejected because it would have made `v0` the only near-miss shape routed through a different branch (parse succeeds, then a separate check rejects it), for no behavioral gain — both routes land on the same `attestation` classification and exit `2`.
  grounding: .shell-team/specs/T-1018-freeze-attestation-gate.md AC4 ("... version `v0`; the version absent from the parenthesis; ...") enumerating `v0` among the ten grammar near-miss shapes; bin/check-intent.sh, `ATTEST_FULL_RE='^[[:space:]]+- freeze-attestation \(v([1-9][0-9]*), ...'` versus the pre-existing `HASH_FULL_RE='^[[:space:]]+- intent-hash \(v([0-9]+)\): ...'` plus its separate `version_int -ge 1` check further down the same file.
