- decision: a `mktemp` invocation whose assignment is followed by `&&` (rather than the canonical DP5 `|| exit 1` idiom) is classified as **guarded** (class a), on the same footing as the literal idiom, provided the `&&` sits immediately after the assignment and precedes every use of the resulting variable.
  reason: DP2's rung (1) is written as a functional test — "is every mktemp invocation on the line guarded, so that a failure exits non-zero before any path composed from the resulting variable is used?" — not as a textual match against DP5's specific idiom. `x=$(mktemp …) && rest` genuinely satisfies that functional test: the assignment's own exit status equals `mktemp`'s, and a failed left side of `&&` prevents `rest` (and any path composed inside it) from ever running. Two readings were available — a strict idiom-only reading (only the exact `|| exit 1` shape counts, everything else is unguarded) and this functional reading — and the choice moved real counts: files T-1000, T-1002, T-1004, T-1005, T-1010 and T-1020 carry sites guarded this way rather than via the literal idiom, which changes their per-file `classes:` fields and the corpus-wide `class-a-guarded` total (36, not a smaller number under the strict reading).
  grounding: `.shell-team/specs/T-1024-check-line-mktemp-guard.md`, DP2 rung (1) ("is every mktemp invocation on the line guarded, so that a failure exits non-zero before any path composed from the resulting variable is used?"); confirmed live by direct execution that a failed command substitution's exit status propagates to the assignment and short-circuits a following `&&`.

- decision: a `mktemp` occurrence that is not in command position — inside a quoted grep pattern, or inside a filename/heading that merely contains the substring `mktemp` (for example this task's own spec filename, `check-line-mktemp-guard.md`) — is treated as a **mention**, not an invocation, and contributes nothing to a line's guard/compose analysis; a line whose only `mktemp` occurrences are mentions lands in class (c) via DP2's rung (3) rather than being excluded from classification or bucketed into class (d).
  reason: DP1's population regex matches on the bare substring `mktemp` anywhere in a `- check:` line, which necessarily catches mentions (T-111's and T-112's negative-grep checks, and several of this task's own AC lines that reference the audit filename). DP2's ladder does not have a fifth "not applicable" rung for this case; rung (3)'s own wording — "mktemp present with no temp-path variable composed into a later path" — reads literally as covering the mention-only case (mktemp is present; nothing is composed), so this reading was taken over inventing an off-ladder category the frozen intent block does not define.
  grounding: `.shell-team/specs/T-1024-check-line-mktemp-guard.md`, DP1 (the population regex, "matches every line … that matches" the bare-substring pattern) and DP2 rung (3) ("mktemp present with no temp-path variable composed into a later path ⇒ class (c) no-path-composed").

- decision: an unguarded invocation's result used as a bare reference (`cd "$d"`, `rm -rf "$d"`, or any use with no path segment appended) is **not** treated as a "composed path" for DP2 rung (2); only a later use that appends a further segment (`"$d/x"`, `"${d}/x"`) counts, which is why `.shell-team/specs/T-1011-telemetry-event-rows.md:110` (`cd "$d" && …`) classifies as (c) rather than (b) even though its `mktemp` call is genuinely unguarded.
  reason: DP2 names the risk shape explicitly as "the root-anchored-expansion shape," and the Problem section's own worked example is a path being *built from* the failed variable (`"$d/raw.txt"` expanding to `/raw.txt`) — the hazard is a segment being appended to an empty string, not the empty string being used bare. A bare `cd ""` fails outright rather than silently redirecting into an unintended root-anchored location, which is a materially different (and less severe) failure shape than the one DP2 is naming; treating it identically to true path composition would have inflated the class (b) count with a shape the ladder's own rationale does not describe.
  grounding: `.shell-team/specs/T-1024-check-line-mktemp-guard.md`, DP2 ("the root-anchored-expansion shape") and `## Problem` (`"$d/raw.txt"` becomes `/raw.txt`); the specific site `.shell-team/specs/T-1011-telemetry-event-rows.md`, the `check:` line under its acceptance criterion whose `mktemp`-derived `$d` is used only as `( cd "$d" && … )`.
