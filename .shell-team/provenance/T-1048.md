- decision: split `check-durability.sh`'s exit-2 classification into `usage` (bad CLI invocation — missing/invalid `--phase`/`--task`/`--ref`, an unknown flag, an unexpected positional argument) versus `structural` (an unusable sibling resolver or registry file, a malformed registry row, an ambiguous glob match, malformed opt-out mode-file content, a phase with zero registered rows), rather than one flat exit-2 bucket or the reverse split.
  reason: DP6 requires following `bin/check-provenance.sh`'s classification convention "exactly", but neither DP6 nor DP2/DP7 enumerates which specific failure belongs to which of the two exit-2 tokens for a checker that (unlike check-provenance.sh) also resolves a sibling script and a registry file. `check-provenance.sh`'s own precedent treats "the caller's argument/file was malformed or absent" as `usage` and reserves `structural` for defects in the artifact's own internal shape — the same split this checker applies to the registry (an artifact this checker owns) and to the sibling/registry resolution (an install-time precondition, not something the caller's flags control).
  grounding: bin/check-provenance.sh lines 12-22 (die/fail_usage/fail_structural convention and what each covers); .shell-team/specs/T-1048-handoff-durability-barrier.md DP6 ("following bin/check-provenance.sh's convention exactly").
- decision: insert the new durability gate in bin/close-out.sh immediately after the T-1017 interventions gate and before the "build the Done entry" section — ahead of the T-1022 sibling-screen/source-line gate and the pre-write interlock — rather than at the very end of the gate ladder or interleaved with the T-1022 checks.
  reason: the Notes for engineer point at the T-1017 gate as "the exact shape to copy" (resolve the sibling, screen it, run it, exit 1 on refusal, all before any board write) but do not fix a position relative to the T-1022 gates. Placing it directly after T-1017 keeps every fail-closed input gate (T-068, T-1017, T-1048) grouped together, ahead of any board-shape work (MAIN_LINE parsing, the synthesized-board sibling screen, the pre-write interlock), so a durability refusal is never entangled with board-rewrite state.
  grounding: bin/close-out.sh's existing gate ladder (T-068 fast-follow gate, then the T-1017 interventions gate, then "# --- build the Done entry ---"); .shell-team/specs/T-1048-handoff-durability-barrier.md's Notes for engineer, "Prior art for the close-out gate" bullet.
- decision: pass `--ref HEAD` (not a resolved branch name or a caller-supplied override) when bin/close-out.sh invokes check-durability.sh at the close-out phase.
  reason: DP5 fixes `--ref` as explicit with no inference, but the spec does not name which literal value close-out.sh's own call site should pass. At close-out time the working directory's current commit (whatever branch or detached state it is on — DP11 wires the same seam close-out already trusts) is the only ref that is always resolvable and always means "what is about to be merged"; a hardcoded branch name would break in a detached-HEAD or renamed-branch checkout, and there is no existing close-out.sh state that already carries a caller-supplied ref to reuse instead.
  grounding: .shell-team/specs/T-1048-handoff-durability-barrier.md DP5 ("the fixed commit is an explicit --ref argument with no default and no inference") and B2/B3 (HEAD/detached-HEAD/linked-worktree all resolve identically); bin/close-out.sh has no other resolved-ref variable in scope at that point.
- decision: in tests/close-out/run.sh, make the durability opt-out (DP7's `working-tree-only`) the DEFAULT posture for every pre-existing fixture — auto-stamped from inside `write_conformant_interventions_record()` (derived from the interventions-record path's own `<root>/<base>/interventions/<file>` shape) plus two explicit `stamp_durability_skip` calls for the one non-standard path (`$OV1/elsewhere`) — rather than building committed spec/provenance/review records for every one of the suite's ~30 fixture roots, or leaving the new gate unexercised across the pre-existing corpus.
  reason: AC12 requires the WHOLE existing suite to keep passing once the gate is wired unconditionally at close-out, and the gate's own DP3 floor (an unborn/non-git directory is `no-recorded-commit`, fail-closed) means every fixture root needs at least one real git commit regardless. Retrofitting full durable spec/provenance/review corpora onto every pre-existing scenario (most of which test an unrelated gate — T-068, T-1017, T-1022 — and were never designed to carry those records) would be a disproportionate rewrite of test intent for a change this task did not ask for; declaring the opt-out is the same route DP7 gives a real adopter who does not want the observation, and a handful of DEDICATED fixtures (`closeout-durability-happy-path` / `-refuses` / `-checker-absent-exit2`) exercise the gate's real predicate instead, so the opt-out route is never the only thing tested.
  grounding: .shell-team/specs/T-1048-handoff-durability-barrier.md AC12 ("tests/close-out/run.sh exercises the new gate by name, and that suite exits 0") and DP7 (the working-tree-only opt-out); tests/close-out/run.sh's `stamp_durability_skip()` / `write_conformant_interventions_record()` and the `closeout-durability-*` section.
- decision: leave AC8 red rather than alter its `check:` line, alter check-durability.sh's use of `git hash-object --path=`, or otherwise make the criterion pass.
  reason: this repository's `git` (2.53.0) applies the `text` gitattribute's end-of-line normalization to `git hash-object <file>` even WITHOUT `--path=`, whenever `<file>` is a real working-tree file at its own real path (confirmed against `git-hash-object(1)`'s own documented behavior: `--path=` only changes which attributes apply when the file is read from stdin or from a location other than the path being hashed for). AC8's own fixture measures `raw != blob` as a precondition before trusting `norm == blob` as the criterion's positive signal, and that precondition is false in this environment — the two hashes are already equal without `--path=`, so the fixture's own non-vacuity control fails exactly as the spec's Notes for engineer anticipated ("a red there is an environment measurement to disclose, not a criterion to soften"). AC8 sits inside the frozen intent block; a pm-spec-owned re-freeze, not an engineer edit, is the only route to change it, and doing so is outside this role's authority.
  grounding: .shell-team/specs/T-1048-handoff-durability-barrier.md Notes for engineer point 3 ("confirm AC8's eol fixture actually normalizes here ... a red there is an environment measurement to disclose, not a criterion to soften") and AC8's own check: line; `git help hash-object`'s `--path` description, measured live in this environment (git version 2.53.0).

- decision: (rework round 1, codex review Blocker 2) compute and act on the `$TEAM_TODO` / `$TEAM_INTERVENTIONS_DIR` override-divergence check inside the durability-gate section of bin/close-out.sh (immediately before invoking check-durability.sh), rather than at each override's own board/interventions-directory resolution site earlier in the script.

- decision: (rework round 1, codex review Blocker 2) refuse on override divergence ONLY when check-durability.sh's own stdout does NOT contain `check-durability: skipped:` (i.e., only when it actually performed a real observation), rather than refusing unconditionally whenever an override diverges regardless of the checker's verdict.

- decision: (rework round 1, codex review Blocker 2) canonicalize override values and team-paths.sh's own resolution to absolute paths (via a new `_abspath()` helper: `cd "$(dirname path)" && pwd`/basename, falling back to a literal cwd-prefix when the parent directory does not yet exist) before comparing them for divergence, rather than a direct string comparison of the two raw values.
