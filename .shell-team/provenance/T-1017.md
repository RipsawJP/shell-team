  reason: D3's row (i) text states the record is "screened by close-out itself, before the checker runs" — read as "before the checker is invoked", this settles the ordering between record-screening and the actual `bash "$CHECKER" ...` call, but is silent on the ordering between record-screening and merely testing the checker's existence (D6's separate concern). Two orderings were both consistent with the frozen text: (a) screen the record first (what was built), or (b) test the checker's existence first. (a) was chosen because it is cheaper (no need to reason about the checker at all once the record already fails) and because AC2/AC8's fixtures already exercise "record missing, checker present" as the row-(i) case with no dependency on the checker's presence — keeping the record check as the single unconditional first gate keeps that independence obvious. No AC exercises the simultaneous-failure edge case (both broken at once) so this had no `check:` line to fall out of; it needed a judgment call.
  grounding: .shell-team/specs/T-1017-close-out-interventions-gate.md, D3's row (i) description ("screened by close-out itself, before the checker runs") and D6 ("The gate explicitly tests for the sibling script before invoking it and refuses with reason C"); bin/close-out.sh, the `if [ ! -f "$RECORD" ] || [ ! -r "$RECORD" ]; then ... exit 1; fi` block, which precedes the `CHECKER="$SCRIPT_DIR/check-interventions.sh"` existence test.

- decision: the checker's stderr (`CK_ERR`) is captured through command substitution into a bash variable (`CK_ERR="$(bash "$CHECKER" ... 2>&1 >/dev/null)" && CK_RC=0 || CK_RC=$?`) rather than into a second temp file cleaned up by a second `trap ... EXIT`.
  reason: this gate is inserted ahead of the existing `mktemp`/`trap 'rm -f ...' EXIT` block further down in `bin/close-out.sh`, and Notes for engineer flagged `trap ... EXIT` as non-additive (a second `trap` would silently replace the first, dropping its cleanup of `ENTRY_FILE`/`TMP_BOARD`/`GATE_ERR`) — offering two ways to avoid that: capture into a variable, or extend the single existing trap to also remove a new gate-owned temp file. Variable capture was chosen because it needs no temp file at all (zero risk of a leaked file under an unexpected termination between this gate and the later `trap` statement, and no coordination with a trap block physically ~90 lines further down in the file); the alternative (pre-creating the temp file here and extending the later trap) would have required either hoisting the `trap` statement earlier in the file — itself a change to where T-1016's `ENTRY_FILE`/`TMP_BOARD`/`GATE_ERR` cleanup is declared — or holding a bare, untrapped temp file for the span between this gate and that block.
  grounding: .shell-team/specs/T-1017-close-out-interventions-gate.md, "## Notes for engineer" ("`trap … EXIT` is **not** additive... either capture into a variable instead... or extend the single existing trap — do not add a second one"); bin/close-out.sh, the `CK_ERR="$(bash "$CHECKER" --task "$TASK" -- "$RECORD" 2>&1 >/dev/null)" && CK_RC=0 || CK_RC=$?` line, versus the pre-existing `trap 'rm -f "$ENTRY_FILE" "$TMP_BOARD" "$GATE_ERR"' EXIT` line it sits ahead of (unmodified, no second trap added).

- decision: the classification token in the checker's captured stderr (`structural` vs `usage`) is matched with a bash `case "$CK_ERR" in *'check-interventions: structural:'*) ... esac` glob comparison held entirely in memory, rather than piping `$CK_ERR` through an external `grep -qF`.
  reason: this repository's own operating record documents that `upstream-command | grep -q PATTERN` under `pipefail` can report a false failure — `grep -q` can exit on its first match before consuming all of a producer's output, sending it SIGPIPE, which `pipefail` then reports as the pipeline's own exit status even though the match was genuine. `bin/close-out.sh` runs under `set -euo pipefail`, so a `printf '%s' "$CK_ERR" | grep -qF -- '...'` construction used for classification would be exposed to exactly that risk on the one string this gate cannot afford to misclassify (the wrong classification changes the reported exit code, 1 vs 2, not just a message). Bash's own `case`/glob matching performs the same substring test with no subprocess and no pipe, so it cannot SIGPIPE at all — a strictly safer equivalent for a value that is already sitting in a shell variable.
  grounding: .shell-team/lessons.md, "## 2026-07-13 — Under `pipefail`, piping into `grep -q` can false-fail on SIGPIPE — verify through a temp file instead"; bin/close-out.sh, `set -euo pipefail` (top of file) and the `case "$CK_ERR" in *'check-interventions: structural:'*) ... *'check-interventions: usage:'*) ... *) ... esac` block inside the `CK_RC=2` arm.
