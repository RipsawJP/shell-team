- decision: ordered the cross-part checks (Phase 2 of `bin/aggregate-verdicts.sh`) as: duplicate-claim within one part, duplicate-claim across parts, out-of-population, unclaimed-record, sentinel exclusivity (`missing-sentinel`/`sentinel-with-verdicts`), and finally coverage completeness (`uncovered-unit`) last of all.
  reason: D6 itself only fixes that `uncovered-unit` is exit 3 (an "incomplete" refusal) while the rest are exit 1 (a "content" refusal); it does not fix an order among the exit-1 classes. Placing the exit-3 check last means a fan-out carrying BOTH a content defect and a coverage gap is reported for its content defect first — the class whose remedy differs from every other refusal's (re-running the missing assignment) is the one this ordering reserves for last, matching D6's own framing of why the code is separate at all. Every AC5/AC6 fixture in the frozen spec isolates exactly one defect class, so no fixture exercises the interaction directly; this choice is the one that reads most consistently with D6's own stated reason for the exit-3/exit-1 split.
  grounding: `.shell-team/specs/T-1074-fanout-orchestration.md` D6 ("the retry case separable from the corruption case... `3` is the case whose remedy is to re-run the missing assignments against the same fixed population, and `1` is the case where re-running blindly would repeat a defect"); `bin/aggregate-verdicts.sh`'s own `# Phase 2` comment block, which states this ordering explicitly.
- decision: placed the `- summary:` line FIRST inside the `verdict-region` marker pair, immediately after the BEGIN marker, followed by the `LC_ALL=C`-sorted verdict/sentinel multiset — rather than last, or interleaved by some other rule.
  reason: D4's partition-independence property requires the WHOLE extracted region to be byte-identical under every partition of the same population. The summary line's own three counts (units/verdicts/sentinels) are population-level totals, invariant under repartitioning by construction; fixing its POSITION as always-first (rather than, say, always-last, or omitted from the sort entirely with no fixed position) is what makes the region's byte-identity hold deterministically regardless of which partition produced it, since a fixed position is simpler to reason about and to verify than "the summary line floats somewhere stable" would be.
  grounding: `.shell-team/specs/T-1074-fanout-orchestration.md` D4 ("the emitted verdict region is byte-identical under every disjoint, exhaustive partition into parts, and under any ordering of records within a part or of the parts themselves") and **AC3** (which measures this property directly, run live and PASS in this round); `bin/aggregate-verdicts.sh`'s Phase 3 output-assembly block.
- decision: an unreadable or missing `--population` file classifies as a `usage` refusal (exit 2), not `empty-population` (exit 1).
  reason: the frozen spec's D6 vocabulary defines `empty-population` as a refusal about the population file's own CONTENT (it exists, is readable, and is genuinely empty); a file that cannot be read at all is a defect in the INVOCATION (the caller passed a bad path), the same class `bin/derive-populations.sh`'s own `--set`/`--label` validation treats invocation-shape defects as. No frozen `- check:` line in this spec exercises a missing/unreadable `--population` path, so this is a genuine implementation choice between two readings of the closed vocabulary, resolved toward the reading that keeps `empty-population` meaning "the file is there and says nothing" rather than "the file could not even be opened."
  grounding: `.shell-team/specs/T-1074-fanout-orchestration.md` D6 (the closed thirteen-token vocabulary, `usage` exit 2 vs `empty-population` exit 1); `bin/derive-populations.sh`'s own `die_usage` calls for malformed `--set`/`--label` invocations (the precedent this choice follows).
- decision: added a duplicate `--part` NAME usage-error check (two `--part` flags sharing one instance name refuse with `usage`, exit 2) — a case no frozen `- check:` line in this spec exercises.
  reason: `bin/aggregate-verdicts.sh` copies `bin/derive-populations.sh`'s skeleton per the spec's own Notes for engineer; that sibling script refuses a duplicate `--set` NAME the identical way (a usage error, not silently accepting the second value or silently ignoring the duplicate).
