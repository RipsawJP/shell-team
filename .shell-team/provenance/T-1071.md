- decision: computed union/bucket membership via a two-pass design — tag every item with the index of every set it belongs to (one row per (item, set) pair, built by iterating the per-set item files), then aggregate those tags into one row per distinct item carrying its full membership list — rather than an O(items × sets) per-item `grep -qxF` loop against every set's item file, or a single multi-file `awk` pass keyed on gawk's `ARGIND`.
  reason: the forbidden-token list rules out `ARGIND` (a non-POSIX gawk extension, and the spec's own forbidden-token enumeration is exactly the class it belongs to even though it is not individually named — the constraint is "POSIX awk only"), and a per-item subprocess-spawning grep loop scales as items × sets, which is the shape this task's own Non-goals ("No performance claim without its conditions") caution against manufacturing unnecessarily; the two-pass tag/aggregate design is a single linear pass per set plus one aggregation pass, using only POSIX-standard awk associative arrays (a normal awk feature, distinct from bash's forbidden `declare -A`).
  grounding: bin/derive-populations.sh (the "Tag every item..." and "Collapse the per-(item, set) rows..." comment blocks and their awk programs); .shell-team/specs/T-1071-record-set-derivation.md AC1's forbidden-token list and Non-goals' "No performance claim without its conditions" line.
- decision: forced `export LC_ALL=C` once, near the top of the script, so the pin reaches every child process the script spawns — including a caller's own `--set` command — rather than scoping the pin to only this script's own internal `sort`/`comm`/`awk` invocations.
  reason: AC6 requires the whole run's output to be byte-identical regardless of the caller's ambient locale; a caller's own `--set` command can itself invoke locale-sensitive tools (a `sort`, a `git` subcommand), and scoping the pin to only this script's own internal calls would leave those exposed to the invoking shell's own locale, defeating the guarantee the Goal sentence ("runs them under a pinned collation") states for the whole derivation, not just this script's own arithmetic.
  grounding: bin/derive-populations.sh (`export LC_ALL=C` immediately after `set -euo pipefail`); .shell-team/specs/T-1071-record-set-derivation.md AC6's check and Non-goals' "No unpinned collation" line.
- decision: ordered both the emitted bucket sections and the items within each bucket via one single full-line `sort` over "signature\titem" rows, rather than a `sort -t $'\t' -k1,1 -k2,2` two-key sort or a separate per-bucket sort pass.
  reason: tab (0x09) sorts below every ordinary set-name/`+` byte under `LC_ALL=C`, so a plain full-line sort already produces both the desired signature-grouping order and the correct within-bucket item order in a single pass — verified against AC2's own byte-exact expected stream (bucket order `A` < `A+B` < `B`); a two-key `-k`-restricted sort would be behaviorally equivalent here but adds surface area for no behavioral gain.
  grounding: bin/derive-populations.sh (`sort "$WORKDIR/sig-item" > "$WORKDIR/sig-item.sorted"`); .shell-team/specs/T-1071-record-set-derivation.md AC2's expected-stream construction (the `printf`-built `"$T/want"` file in its own `- check:` line).
- decision: repeated `--accept-status` entries naming the same set accumulate (their csv lists are concatenated with the default `0`) rather than the last flag overwriting earlier ones.
  reason: no criterion exercises repeated `--accept-status` for one name, so this is a design choice beyond what any AC pins; accumulating is the less-surprising behavior for a caller who wants to declare more than one acceptable non-zero status across separate flags, and costs nothing extra over an overwrite.
  grounding: bin/derive-populations.sh (`accepted_statuses()`); .shell-team/specs/T-1071-record-set-derivation.md AC5(b) (the single-status case this function's minimum contract is checked against).
