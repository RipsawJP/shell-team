# T-1058 decision provenance

<!-- BEGIN provenance: T-1058 -->
- decision: the two new per-run report lines, `providers:` and `review:`, are placed at the END of `bin/rollup-runs.sh`'s per-run block — after the pre-existing `window:` line — rather than interleaved earlier (for example, immediately after `verdict:`, where the derived data is thematically closer to the span-level breakdowns).
  reason: the spec requires the two lines to exist and to always be printed, but states no required position within the block, so a real choice existed between at least two reasonable placements. Appending at the end keeps every pre-existing line's own position byte-identical to the branch point (no existing `printf` call moved), which matters because `bin/rollup-track.sh` captures this script's whole stdout verbatim and `tests/is-span-row-parity/run.sh` and the T-1019 suite assert on `spans: N` by containment rather than by exact line number — an append-at-the-end placement is the one that cannot disturb either kind of consumer, whereas an interleaved placement carries no such guarantee for a consumer this task did not enumerate.
  grounding: `.shell-team/specs/T-1058-telemetry-binding.md` Goal item (3) ("adding exactly two lines to each per-run block") and DP7 ("Two lines per run block... always printed") state the requirement without fixing a position; `bin/rollup-track.sh`'s own header ("captures... this script's own output verbatim") and `bin/rollup-runs.sh`'s pre-existing six `printf` lines (byte-identical to the branch point in this diff).
- decision: `tests/rollup-runs/run.sh`'s pre-existing T-1011 AC30 regression (comparing `with-events.jsonl`'s roll-up output byte-for-byte against the separately fixtured `clean.jsonl`'s output) is rewritten to derive the "no event rows" comparison from `with-events.jsonl` ITSELF (grep out its own `"kind":"event"` rows) rather than continuing to compare against `clean.jsonl`.
  reason: `with-events.jsonl`'s span rows carry `seq` values 1/3/5/7 (interleaved with event rows sharing the same monotonic counter) while `clean.jsonl`'s span rows carry `seq` values 1/2/3/4 (no events at all) — the two fixtures were only byte-identical in output before this task because `rollup-runs.sh` never printed `seq` anywhere. This task's new `review:` line prints each reviewer span's own `seq` (`<span>#<seq>=<relation>`), so the pre-existing comparison would report a false regression (a genuine, correct difference in `seq` labelling) the moment it was left unmodified — confirmed by running the un-rewritten suite, which failed with `review: codex-reviewer#7=undetermined` vs `review: codex-reviewer#4=undetermined`. Deriving the "no events" side from the same file preserves the actual property T-1011 AC30 and this task's own AC5 require (this script's stdout for a file equals its stdout for the SAME file with every event row deleted) without weakening it to a coincidence that only held while `seq` was invisible.
  grounding: `.shell-team/specs/T-1058-telemetry-binding.md` AC5's own check (builds its "spans" comparison side by deleting event rows from the SAME scratch file, `grep -v -- '"kind":"event"' "$T/mixed" > "$T/spans"`, never from an unrelated fixture) and DP7 ("this reporter already skips every event row before any pass runs, so a derivation that reads only what the passes read cannot make the mixed-file and span-only outputs differ"); `tests/rollup-runs/fixtures/with-events.jsonl` and `tests/rollup-runs/fixtures/clean.jsonl` (the differing `seq` sequences, read directly); the pre-rewrite failure observed by running `tests/rollup-runs/run.sh` against this task's `bin/rollup-runs.sh` before this fix.
- decision: no `--help` flag was added to `bin/log-run.sh` (or to `bin/check-run.sh`/`bin/rollup-runs.sh`); the three new flags are documented only via the header comment block AC3 already requires and mechanically checks.
  reason: the task instructions' "the writer's own header documents the three flags" line is satisfied exactly by AC3's own check (`awk 'NR>1 && /^#/{print} NR>1 && !/^#/{exit}'` over the header, asserting `--provider`/`--effort`/`--adapter` appear there), and none of the spec's Acceptance criteria, Non-goals, or `## Notes for engineer` mention a `--help` flag. None of the three touched scripts implements `--help` today (confirmed by search), and the spec's Non-goals explicitly decline "no new script" and imply the smallest change that satisfies the criteria — adding a new flag/behaviour to an existing script's argument grammar (one none of its siblings carry) would be scope beyond what any criterion requires and beyond what the header-comment convention (used identically by `bin/check-run.sh` and `bin/rollup-runs.sh`, neither of which has `--help` either) already establishes.
  grounding: `.shell-team/specs/T-1058-telemetry-binding.md` AC3's `check:` line (the `awk`-extracted header-comment search, no `--help` invocation anywhere in it) and `## Notes for engineer` / `## Non-goals` (no `--help` requirement stated); a repo-wide search (`grep -n -- '--help' bin/log-run.sh bin/check-run.sh bin/rollup-runs.sh`) confirming none of the three scripts implements `--help`.
