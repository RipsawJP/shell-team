- decision: the approval record's five ` — `-separated fields (`approver=`, `producer=`, `approves=`, `date=`, `record=`) are extracted with sequential anchored `sed -E` substitutions using a greedy `.*` for every field including `approver=`/`producer=`/`approves=`/`date=` (not only the trailing free-form `record=` field), each re-anchored from the line start with the literal marker text for every field already known.
  reason: a greedy `.*` backtracks to the correct split point even when a field's own value carries trailing whitespace right up against the separator (AC12's padding-evasion case, `producer=alice   `), because the regex engine finds the rightmost position at which every subsequent literal marker can still match; a stricter `[^ ]*`/`[^—]*` character-exclusion class cannot recover the padding once excluded, and a plain string-split on the first occurrence of ` — ` would mis-split whenever an earlier field's value happened to be empty. The same anchored-literal-with-trailing-`.*` shape is already this repository's own idiom for a similar multi-field ` — `-separated record (bin/close-out.sh's `d_axis`/`d_value`/`d_modality`/`d_ground` dispatch-record extraction), so this decision also avoids introducing a second parsing idiom for one grammar family.
  grounding: `bin/close-out.sh`'s dispatch-record field extraction (the four sequential `sed -nE` lines assigning `d_axis`, `d_value`, `d_modality`, `d_ground`); `tests/check-oversight/run.sh`'s "trailing-padded producer still refuses after whitespace stripping" case, verified passing against this extraction.
