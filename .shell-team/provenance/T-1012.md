- decision: an event row with `"event":"human"` is adapted, in the template's data layer, onto the SAME `{type:"gate", agent:"human", label:...}` shape a plain `gate` event produces, rather than introducing a new `"human"` branch into `buildStepsB`/`computeSceneB`.

- decision: a `release` event's ball-settle destination (`agent`, in the adapted-event shape) is computed as `row.from != null ? row.from : "orchestrator"`, defaulting to `"orchestrator"` when the row carries no `from`.
  reason: T-1011's frozen 9-key event schema has no `agent` key on any event row at all (only `loop_id/run_id/seq/ts/kind/event/from/to/label`), and `release` is the one event id with NO required fields (D3's per-id table: handoff needs from+to, rework needs from+to+label, gate needs from+label, human needs label, release needs nothing) — so a release row may legitimately carry a `from` or may carry none. - decision: `TOTAL_MS` (the playback timeline's total duration) is computed as `cum > 0 ? cum : 1` rather than left as the raw accumulated sum.
  reason: an event-only run (D3's degraded shape ii, reachable when a run is interrupted before any span is recorded) contributes zero duration to `cum` (only `"work"`/span steps add to it), so the raw value would be `0`; every downstream consumer of `TOTAL_MS` (playback progress `simMs/TOTAL_MS`, the camera's distance/look-at easing) divides by it, and dividing by zero produces `NaN` that would propagate silently into the canvas transform and the transport's seek position — a "real page that renders the rows it has" (D3) failing silently is exactly the degradation-must-be-visible contract this task exists to uphold. The alternative of special-casing the whole render loop for a zero-duration timeline was rejected as a much larger, riskier change to the ratified playback code for the same outcome (a run with no spans still "plays", just instantaneously).
