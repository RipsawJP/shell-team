# T-113 decision provenance

<!-- BEGIN provenance: T-113 -->

- decision: no schema change to `bin/check-playbook.sh` — the rule is expressed only as comment text added to the `Source` field description block and to `bin/playbook-promote.sh`'s usage block, and every added/removed line in both files is a comment line.
  reason: the `Source` field description already accepts `n/a` as a value, so the rule is expressible with the existing schema; adding a schema token or a new validation branch would invent a second way to say something the format already says, and would duplicate the detection half that T-111's diff-scoped shape checker already covers when a lessons file is edited.
  grounding: the `Source` field description text in `bin/check-playbook.sh` ("<non-empty free text — task/issue/PR ref, external citation, or \"n/a\">"); AC3's comment-only diff lock.

- decision: the rule is stated at the four canonical authoring surfaces (`bin/check-playbook.sh`, `bin/playbook-promote.sh`, `agents/scrum-master.md`, `docs/templates/retro-template.md`) as authoring-time discipline only, and is not machine-validated for whether a `Source` value truly points at an in-repo artifact.
  reason: deciding whether a free-text `Source` string is an in-repo path, a task id, an external citation, or ordinary prose requires semantic judgment of content, which every checker in this repository deliberately declines to perform; a guesser at this seam would either reject a legitimate external citation or wave through a disguised identifying reference, so the real defense stays the human-approval gate plus normal pull-request review, and the rule is written where an author reads it rather than enforced by a validator.
  grounding: the structure-only disclaimer in `bin/check-playbook.sh`'s header ("NOT a semantic or security review"); the equivalent disclaimer in `bin/check-provenance.sh`'s header ("judges STRUCTURE ONLY ... never the truth of its content").

- decision: round-2 rework — the canonical rule line is now duplicated inside `bin/playbook-promote.sh` (a second copy near the top of the header, in addition to the pre-existing one inside the `--source` usage-block entry), rather than moved out of the `--source` entry or left as a single copy.
  reason: `--help`'s extraction (`sed -n '2,45p' "$script_path"`) only ever prints lines 2-45, and the whole `# Usage:` block — including the `--source` entry the rule was originally placed next to — starts at line 63, entirely outside that range; the codex-reviewer round-1 finding (Major) was that this makes canonical surface #2 unreachable by the one audience it exists for, a CLI user reading `--help` before typing `--source`. Moving the `sed` line itself would touch a non-comment line and break AC3's comment-only lock; removing the `--source`-adjacent copy would lose the placement the spec's "Notes for engineer" originally asked for (paired with the field it governs). Adding a second copy inside the displayed range keeps both properties: AC1 (`grep -qxF`) and AC2 (file-count, not occurrence-count) are unaffected by a same-file duplicate, and the diff stays comment-only.
  grounding: `bin/playbook-promote.sh`'s `--help|-h)` branch (`sed -n '2,45p' "$script_path"`); `.shell-team/reviews/T-113.md`'s round-1 Major finding ("canonical surface #2 ... 実際には `--help` に一切表示されない").
