- decision: the grammar example shown in all four new sections binds `tech-lead`/`pm-spec` to `claude opus high claude-cli`, `engineer`/`qa-verifier`/`ui-designer` to `claude sonnet - claude-cli`, and `codex-reviewer` to `codex gpt-5 - codex-cli` — a host-override example that visibly differs from `templates/binding-default.conf`'s all-`-`-effort row set, rather than transcribing the shipped default verbatim or inventing a minimal one-role example.
  reason: AC1/AC3's own positive control requires the reconstructed example to pass `bash bin/check-binding.sh --config` and to carry exactly six `bind` rows (one per role), but the spec does not pin which valid six-row config to show. Two materially different options existed: reprint `templates/binding-default.conf` verbatim (correct, but would read as "here is the file that already exists" rather than demonstrating what an *authored* override looks like), or show a config that visibly exercises the effort field's two legal shapes (`-` and a real value) and a non-default model per role, which is what a reader actually needs to see to author their own. The chosen config is observable content shipped to every adopter reading these four files.
  grounding: `.shell-team/specs/T-1060-adopter-binding-docs.md` AC1 (the `check-binding.sh --config` positive-control clause and the six-row-count equality clause); `templates/binding-template.conf`'s own header ("edit the provider/model/effort/adapter columns to assign which executor runs each ... role").

  grounding: `.shell-team/specs/T-1060-adopter-binding-docs.md` DP8 ("Code blocks are byte-identical across the two languages (AC2, AC4)" — scoped to the language-pair axis only, not the surface-family axis).
