- decision: The script refuses the forbidden option spellings through a closed argument grammar (only `--message-file` and `--`), not through a case arm that names each of them.
  reason: AC5 requires no non-comment line of the script to spell those options, so naming them in a refusal arm would fail the lock; a closed grammar also refuses spellings the arm would have missed.
  grounding: `.shell-team/specs/T-1169-team-commit-script.md` AC5 (`check:` greps non-comment lines) and `## Notes for engineer` (Gotchas, first bullet).

- decision: `git check-ignore` runs without `GIT_LITERAL_PATHSPECS`, in a subshell that unsets it, while `git add`, `git ls-tree` and `git diff` keep it exported.
  reason: git rejects literal pathspec magic for `check-ignore` (measured: exit 128, "pathspec magic not supported"), and the path grammar already excludes every glob character.
  grounding: `.shell-team/specs/T-1169-team-commit-script.md` decision 4 (paths) and AC5 (the file names `GIT_LITERAL_PATHSPECS=1`).

- decision: Whether a tracked path changed, and whether only its mode changed, is read from `git diff --raw` (old and new mode) instead of an `-x` test on the work-tree file.
  reason: `git diff` honours `core.fileMode` and the attribute filters, so a mode-only change and a touched-but-identical file are classified the way the commit would see them.
  grounding: `.shell-team/specs/T-1169-team-commit-script.md` decision 4 ("differs from HEAD in content ... mode is unchanged") and AC3 (mode-only case).

- decision: The refusal set goes beyond the spec's list in three places: a symlinked or nested-repository directory on the way to a path, the `REBASE_HEAD` and `sequencer` markers, and a post-commit mismatch when the new commit's parent is not the commit HEAD was at.
  reason: Each closes the same class as a listed case (a path that cannot be added as named, an operation in progress, a commit that is not the one this script made) at no cost to the listed cases.
  grounding: `.shell-team/specs/T-1169-team-commit-script.md` decisions 2, 4 and 6 and `## Input space` classes 5, 8 and 9.

- decision: The sibling-resolution idiom is kept although no sibling script is invoked; the resolved directory only names the script in the usage hint.
  reason: The task brief names the idiom, and keeping it means any later sibling resolves physically without a second resolver.
  grounding: `.shell-team/specs/T-1169-team-commit-script.md` decision 5 ("Siblings, if any, resolve through the script's own physical directory").

- decision: v2 stops a bad index before the commit through one shared entry scanner (`scan_raw`) used by both the pre-commit invariant and the post-commit verification, with exit 4 and no reset, rather than adding more per-shape preflight refusals.
  reason: The reviewed Blocker showed preflight refusals can only enumerate shapes; the invariant judges what git add actually staged, so shapes no preflight names still stop before the commit.
  grounding: `.shell-team/specs/T-1169-team-commit-script.md` `## Re-freeze record (v1 → v2, class-B)` and decision 6.

- decision: `GIT_CONFIG_COUNT` validation caps the count at four digits and refuses any key that is not exactly `safe.directory` in some letter case (pattern match, no trimming), checking pairs 0 to count-1 only.
  reason: A longer count overflows shell arithmetic into a negative bound and would skip the loop, so the cap closes that; exact-pattern matching leaves no whitespace or newline tolerance, as the decision states.
  grounding: `.shell-team/specs/T-1169-team-commit-script.md` decision 2 and AC23.

- decision: The scratch-copy cases disable one preflight refusal through a marker comment on its line (`leading-dir-refusal`, `mode-change-refusal`, `unchanged-refusal`) and the unchanged-file check was restructured into an if/else so one marked line carries it.
  reason: AC6 requires `pre-invariant-extra-staged` to show the invariant stops the commit when the preflight is off; the same device shows each of the invariant's two judgments (kind, set) stops a commit on its own, which a single combined case cannot.
  grounding: `.shell-team/specs/T-1169-team-commit-script.md` AC6 (`pre-invariant-extra-staged` description) and Notes for engineer (v2 bullet).

- decision: A case-variant parent directory of a tracked file on a case-insensitive filesystem is not refused by a new check; its measured outcome is recorded instead (see the hand-back).
  reason: The spec declares the shape outside the Input space and adding a case-folding comparison is a new mechanism beyond the ruled v2 scope.
  grounding: `.shell-team/specs/T-1169-team-commit-script.md` decision 4 (case-variant sentence) and `## Non-goals`.
