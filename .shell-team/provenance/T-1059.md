- decision: the rewritten prose at all five apply sites (`CLAUDE.md`, both `README*.md` design-choice bullets, both `AGENTS.md` copies) states elements (c) and (d) using the same hedge shape the three canonical sources themselves use — "changes which executor is resolved / which value telemetry records" for (c), "does not wire up an alternate-executor invocation path" and "does not guarantee ... once such a rebind exists" for (d) — rather than a flatter, unhedged phrasing such as "rebinding is fully supported" or "review is no longer cross-provider".
  reason: DP2 states the (c)/(d) line must never be crossed in either direction, and names the exact failure modes to avoid: (c) must not claim rebinding is "fully wired end to end" (false, per `executor-resolution.md`'s own closing clause), and (d) must not claim "review is no longer cross-provider" (false, since the shipped default is unchanged and a silent same-family substitution at invocation time is still forbidden). More than one grammatically valid phrasing of the same four elements exists, and the choice of phrasing is exactly what the cross-provider reviewer's primary judgement (`## Notes for engineer`) checks — so this is a real decision with observable-content consequences, not a mechanical fill-in.
  grounding: `docs/loop-engineering/task-envelope.md` `## The generalized invocation pattern` ("a missing CLI or a failed auth check is BLOCKED with the exact error, never a silent substitution of a same-family reviewer"); `templates/prompt-blocks/executor-resolution.md` ("a role's actual invocation still routes through that role's own pinned model value, not through this resolution"); `.shell-team/specs/T-1059-docs-release-notes.md` DP2.
- decision: the two new `CONTRIBUTING.md` bullets are inserted immediately after the bullet each one modifies — the title-rule bullet directly after "Tag the merge commit on `main` ...", the template-reference bullet directly after "Publish the release against that tag." — rather than appended together at the end of `## Cutting a release`.
  reason: AC6 only requires a plus-two bullet-count delta and the verbatim survival of every branch-point bullet; it does not fix where in the section the two new bullets land, so a real placement choice existed. DP6's own language ("The title-rule bullet sits beside the tag bullet, the template-reference bullet beside the publish bullet") names the adjacent placement, and placing each new bullet next to the step it actually governs reads correctly as a numbered/sequential procedure walked top to bottom, whereas grouping both new bullets at the section's end would separate each rule from the step it modifies.
  grounding: `.shell-team/specs/T-1059-docs-release-notes.md` DP6.
- decision: `docs/templates/release-notes-template.md`'s `## Highlights` and `## Migration notes` sections, inside the `<!-- BEGIN/END release-body -->` region, ship with an HTML-comment placeholder describing what goes there, rather than a literal filled-in worked example.
  reason: AC5 requires the region to contain the four headings and specific literals but does not specify literal-example vs comment-placeholder for the two content sections that vary per release. An HTML comment does not render in the published body if a preparer forgets to replace it (the comment is simply invisible), whereas a literal worked-example sentence left unedited would ship as if it were real release content — a materially worse failure mode for a template meant to be copied verbatim and then filled in.
  grounding: `.shell-team/specs/T-1059-docs-release-notes.md` AC5 (bounded to instruction-presence, not to any future release body's actual content) and DP5 ("the copyable body is delimited ... so the no-version-heading rule has a region to be measured in").
