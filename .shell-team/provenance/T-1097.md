- decision: the invalid-branch-name refusal (input space class 8) is implemented by shelling out to `git check-ref-format --branch "$TRIAL_BRANCH"` rather than a hand-rolled regex validator.
  reason: git's own ref-name grammar (consecutive dots, control characters, trailing `.lock`, a leading/trailing slash, and the rest of `git-check-ref-format(1)`'s rules) is exactly the boundary the spec's own out-of-scope declaration names ("`git check-ref-format`'s own verdict is the boundary; nothing beyond it is protected") — re-deriving that grammar in bash would drift from git's actual acceptance rules the moment either one changes, and this script already shells out to git for every other trial-branch check once `--trial-branch` is given.
  grounding: .shell-team/specs/T-1097-trial-branch-flag.md, `## Input space` → "Out-of-scope synthetic extremes" item 4 ("`git check-ref-format`'s own verdict is the boundary; nothing beyond it is protected"); bin/team-init.sh's `git check-ref-format --branch "$TRIAL_BRANCH"` line.
- decision: refusal 1 (no git work tree, including a bare repository) is detected by capturing `git -C "$TARGET" rev-parse --is-inside-work-tree` and refusing unless the captured value is exactly the string `true` — rather than, say, testing for a `.git` entry directly or parsing `git rev-parse --is-bare-repository`.
  reason: `--is-inside-work-tree` collapses both reachable no-work-tree shapes the spec names (no repository at all, where the command fails and the capture is empty; a bare repository, where the command succeeds and prints `false`) into a single non-`true` outcome, so one comparison refuses both without a second git call or a bare-repository special case.
  grounding: .shell-team/specs/T-1097-trial-branch-flag.md AC4 and `## Input space` item 5 ("Both refused by the same condition"); measured directly in this session (`git -C <bare> rev-parse --is-inside-work-tree` prints `false` exit 0; `git -C <no-repo> rev-parse --is-inside-work-tree` fails with a non-zero exit and empty stdout).
- decision: the argument-parsing loop treats an empty string (`''`) as a value for `--trial-branch` identically to a missing value or a dash-leading value — all three die with `--trial-branch requires a branch name` — even though AC7's six named forms do not include an explicit empty-string case.
  reason: the spec's own `## Input space` reachable-classes list names "a branch name git itself rejects (`bad..name`, a leading `-`, an empty value)" as a class this implementation must handle correctly; without this extra `case` arm, `--trial-branch ''` would silently set `TRIAL_BRANCH=""`, and the later `[ "$TRIAL_BRANCH_GIVEN" -eq 1 ]` gate (which does not re-test emptiness) would attempt `git check-ref-format --branch ''`, exiting 2 for the right reason but through a code path this task did not otherwise design for and with no guarantee of a `--trial-branch`-naming message.
  grounding: .shell-team/specs/T-1097-trial-branch-flag.md `## Input space` item 8 ("A branch name `git` itself rejects (`bad..name`, a leading `-`, an empty value)"); bin/team-init.sh's `--trial-branch)` case arm, `-*|'') die "--trial-branch requires a branch name" ;;`.
