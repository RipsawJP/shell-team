- decision: The mode read sits right after the path and symlink refusals and before the `team-init.sh` scaffold step, and a failed read (non-zero exit, missing sibling, value outside `tracked`/`local`) is a `die` (exit 2) in every mode.
  reason: The read has to precede every write so a failed read leaves the repository untouched, yet an earlier refusal (unsafe path, resolver failure) should keep its own message and exit status in tracked mode so the tracked report stays byte-identical with the base.
  grounding: `.shell-team/specs/T-1183-local-mode-setup-docs.md` D1 and AC3, AC4.

- decision: The `local` branch wraps the whole tracked probe block (section 8b) in an `if`/`else` instead of being threaded through its probes, and the `in_head` helper was moved above that branch so both arms share it.
  reason: Leaving the tracked block untouched in the `else` arm is the lowest-risk way to hold its output byte-identical; the cost is one moved function and an unindented body, which the spec explicitly allows (`bin/team-setup.sh` is not held to pure addition).
  grounding: `.shell-team/specs/T-1183-local-mode-setup-docs.md` `## Notes for engineer` (Byte identity) and AC3.

- decision: In `local` mode each directory is judged by `git check-ignore -v -z --stdin` on the directory path with a trailing slash, and counts as ignored only when the reported pattern does not start with `!`; the anchor-in-HEAD test (case a) runs first and takes precedence.
  reason: A trailing-slash path is evaluated as a directory even before it exists, git itself reports an ignored parent for the path, and a file-level rule such as a `<dir>/*.md` pattern does not match the directory, which is the spec's definition of ignored; checking the anchor first keeps a tracked directory out of the `info/exclude` advice because ignore rules do not apply to tracked files.
  grounding: `.shell-team/specs/T-1183-local-mode-setup-docs.md` `**Definition.**` and D1 cases (a)-(c).

- decision: In `local` mode setup prints one `Required:` item per directory that is not ignored (two in the legacy layout with an outside specs dir), each carrying its own `/<dir>/` line, instead of one combined item.
  reason: The spec handles the base dir and the outside specs dir one directory at a time, so a combined item would hide which directory is already ignored or tracked.
  grounding: `.shell-team/specs/T-1183-local-mode-setup-docs.md` D1 (one directory at a time) and AC7's legacy-layout label.

- decision: The `team-init.sh` summary addition is two static lines placed after the `does not appear in git status` pointer and before the `Next:` line; one names both modes, the other carries the single `git config shell-team.mode local` command.
  reason: Init must stay pure addition and invoke no git command without `--trial-branch`, so the lines are static text printed in every mode rather than a branch on the declared mode.
  grounding: `.shell-team/specs/T-1183-local-mode-setup-docs.md` D2 and AC6.

- decision: The new suite builds the close-out fixture as a default-layout board with one Active line at `READY_FOR_MERGE` plus a sentinel interventions record, relying on the shipped `autonomous` oversight default, instead of constructing an oversight profile.
  reason: Those are the only inputs the fail-closed gates require for an unenrolled repository, and the same shape is what `tests/close-out/run.sh` uses for its default-layout case.
  grounding: `.shell-team/specs/T-1183-local-mode-setup-docs.md` `## Notes for engineer` (The local-mode suite) and `tests/close-out/run.sh` (the AC5 default-layout case).
