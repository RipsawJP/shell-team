- decision: mark the `subject-role-plugin` licence-condition `met` — reading it as "the launch record correctly names the subject role for each `plug-*` id" — rather than `not-met` on the ground that no `plug-*` launch was ever `status=accepted`.
  reason: two readings of this un-cross-checked id were available. (a) an execution reading — "this arm was actually exercised under the named subject role" — which would be `not-met`, since all nine `plug-*` launches read `status=not-run`; or (b) a record reading — "the launch lines correctly map each `plug-*` id to `subagent_type=shell-team:tech-lead`" — which is `met` regardless of execution status, since the fifteen frozen `- launch:` lines carry the correct mapping whether or not the launch ran. The frozen spec's own text distinguishes exactly this kind of pair for the three ids it defines explicitly (`matrix-complete` is "a claim about the record, not about the execution"), and `AC11` states that `subject-role-plugin` is asserted independently by `AC5`'s own per-condition `subagent_type` mapping — a check that passes on the recorded grammar regardless of run status. Reading (b) is the one consistent with that precedent and with what `AC5` actually verifies; reading (a) would have required a machine-unbacked judgment call this note has no channel for. The recorded verdict (`instrument-inadmissible`) does not require this id `met` either way (`## Verdict and licence conditions`'s `licence-scope: instrument-inadmissible` list omits it), so the choice moves no gate — but it is still an observable claim a downstream reader of this note will read, which is why it is recorded here rather than picked silently.
