- decision: the AC8 (CRLF) fixture and AC10's positive-control (a closer carrying only trailing whitespace) are built at run time inside `tests/check-acs/run.sh`, while every other new fence-shape fixture is committed as a static `.md` file under `tests/check-acs/fixtures/`.
  reason: a committed CRLF `.md` file risks silent line-ending normalization by a future clone, editor or hook, and a committed fixture whose load-bearing content is trailing whitespace bytes risks those exact bytes being stripped by an editor save or pre-commit hook — both are literal-byte-fragile shapes this repository's own precedent already names and works around by building at run time instead of committing.
  grounding: `.shell-team/specs/T-1102-check-acs-fence.md` `## Notes for engineer` gotcha 6 ("Build every fixture at run time... a committed CRLF fixture is additionally fragile under `.gitattributes` normalization, so build the CRLF case at run time rather than committing it") and `.shell-team/test-recipe.md`'s T-048 rework1 entry (dynamic fixtures built specifically to preserve literal trailing-whitespace bytes that a static file would risk losing).

- decision: the fence closer's runtime-built `close_pat` regex string is assembled via single-quoted literal concatenation (`close_pat='^[ ]{0,3}`{'"$fence_len"',}[[:space:]]*$'`) rather than by backslash-escaping the backtick and `$` inside a double-quoted string.
  reason: a literal backtick or `$` inside a double-quoted bash string must be backslash-escaped to stay literal, which is easy to get wrong silently (a missed escape either opens a real command substitution or changes the anchor); concatenating single-quoted literal fragments around the one interpolated variable needs no escaping at all and mirrors this file's own pre-existing single-quoted regex-constant idiom (`AC_RE`, `CANDIDATE_RE`, `CHECK_RE`, and the new `FENCE_OPEN_RE`).
  grounding: `bin/check-acs.sh`'s own pre-existing `AC_RE='^- \[[ xX]\] \*\*AC-?([0-9]+)...'`-style single-quoted regex-constant definitions (unchanged by this task) and the new `FENCE_OPEN_RE='^[ ]{0,3}(`{3,})'` line this task adds in the same style.

- decision: each new fence-shape regression is shipped as a pair of static committed sibling fixtures (`fence-<shape>.md` / `fence-<shape>-unfenced.md`) rather than as one committed fixture whose unfenced control is derived at run time via `grep -vxF -- "$TIC"` (the idiom this spec's own inline `- check:` lines use to build both arms from one heredoc).
  reason: matches this suite's own pre-existing committed-fixture convention — one `.md` file per input shape, each fixture's only AC-shaped line being the shape under test, so a fixture's filename alone documents its provenance without a reader needing to open the generating `- check:` line — rather than mixing that convention with the spec's own derive-both-arms-from-one-heredoc style inside `tests/check-acs/run.sh` itself.
  grounding: `.shell-team/specs/T-1102-check-acs-fence.md` `## Summarized sources` bullet on `tests/check-acs/run.sh:1`-`:80` and `tests/check-acs/fixtures/` ("the committed-fixture convention (one `.md` per input shape, each fixture's only AC-shaped line being the shape under test so a negative proves the negative)"); the pre-existing `tests/check-acs/fixtures/pass.md`, `fail.md`, `hyphen-ac.md` etc. shipping in exactly that one-shape-per-file shape.

- decision: AC17(a)'s per-branch mutations ("remove the fence gate from the label branch only", "...from the candidate branch only", "...from the `- check:` branch only, and separately from the `## ` reset only") are each constructed, on the scratch worktree, as a targeted bypass condition inserted at the fence-suppression `continue` statement (e.g. `if [[ "$line" =~ $AC_RE ]]; then :; else continue; fi`) rather than by deleting a per-branch guard.
  reason: DP-2's shipped design places one unconditional fence gate before the if/elif chain rather than four separate per-branch guards, so there is no per-branch guard to literally delete; a targeted bypass that lets exactly one line class fall through the gate while the other three stay suppressed is the only construction that isolates one class's suppression at a time, which is what the criterion's own text requires ("each observed independently — this is what proves the uniform suppression is not one guard wearing four hats").
  grounding: `.shell-team/specs/T-1102-check-acs-fence.md` AC17(a)'s own enumeration of the four per-branch mutations and DP-2's uniform-suppression design; `bin/check-acs.sh`'s actual gate structure (the fence gate's `if [ "$in_fence" -eq 0 ]`/`else` block sits once, before the `if [[ "$line" =~ $AC_RE ]]` chain, with no per-branch copy of it).
