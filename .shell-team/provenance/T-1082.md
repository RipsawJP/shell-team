- decision: when a selected span row carries no `--span` key at all (a shape a real writer never produces for a span-mode row, since `--span` is a required flag), the uniqueness check (Phase 5) treats that row's role as the empty string rather than dying with a new class or silently excluding the row from the collision check.
  reason: the Non-goals section declares "a telemetry file that is not this loop's own writer output" out of scope beyond the malformed shapes the eleven stated classes already catch, and this checker is a structural reader over one canonical writer's output, never a full JSON parser; the empty-string fallback keeps the script from crashing on an unreachable-in-practice input rather than adding behavior no criterion asks for.
  grounding: `.shell-team/specs/T-1082-telemetry-discriminator.md` Input space ("A telemetry file that is not this loop's own writer output ... a finding demanding full JSON-parser behaviour is `out-of-input-space`"); `bin/log-run.sh` (`--span` is a required span-mode flag, so every real span row carries it).
- decision: the checker reads only the aggregation block's `- part:` metadata lines to build the declared part set for the consistency check; it never reads or validates the `- attribution:` lines that sit below the nested `verdict-region`.
  reason: the Goal paragraph defines consistency exactly as "the scope's instance set and the merged record's declared part set are equal in both directions" — the part set, not the attribution set — and no acceptance criterion mutates or asserts against attribution-line content; the Notes for engineer's mention of `- attribution:` lines names it as a parsing-technique model (marker-delimited extraction), not an additional property to enforce.
  grounding: `.shell-team/specs/T-1082-telemetry-discriminator.md` Goal ("the scope's instance set and the merged record's declared part set are equal in both directions"); `## Notes for engineer` ("Its part-file parser is also the model for reading the block's `- part:` and `- attribution:` lines" — read as a technique reference, confirmed against every `- check:` line in AC1–AC11, none of which touches an `- attribution:` line's content).
- decision: `docs/loop-engineering/telemetry-instance-verification.md`'s own dogfooded derivation reuses the identical two `--set` queries the spec's frozen `## Canon reconciliation` derivation uses, under a new label (`t1082-note-invariant-declaration-sites` rather than the spec's `t1082-invariant-declaration-sites`), instead of deriving a different population.
  reason: **AC12** requires the note's own derivation to be regenerated live at HEAD ("a working-tree read at HEAD, never a ref measurement") and forbids re-running the spec's own frozen, branch-point-pinned block; reusing the identical queries under a distinct label yields a genuinely re-runnable HEAD measurement whose numbers stay directly comparable to the spec's own canon-reconciliation figures, and the label had to differ so the note's own `- reproduce:` command cannot be mistaken for a re-run of the spec's frozen evidence region.
  grounding: `.shell-team/specs/T-1082-telemetry-discriminator.md` `## Notes for engineer` ("Measured-at-ref labels: not applicable ... The note's derivation is a working-tree read at HEAD and must be labelled as such ... deliberately not re-run by any criterion"); **AC12**'s own check body (extracts and re-runs only the `- reproduce:` lines present in the note file, never the spec file).
- decision: added `--iteration`/`--attempt` grammar validation (`^[0-9]{1,9}$`, refused as `usage`, exit 2) even though no acceptance criterion exercises a malformed value for either flag.
  reason: both values feed a later `$((10#$value))` arithmetic comparison in the scope-selection phase; leaving them unvalidated would let a non-numeric caller value abort the whole script with an uncaught arithmetic-expansion error under `set -euo pipefail`, rather than the classified refusal (empty stdout, one classified stderr line) the Goal paragraph requires of every non-zero exit — and the Input space explicitly names "small positive `iteration`/`attempt` integers" as the reachable class, which a typo can violate.
  grounding: `.shell-team/specs/T-1082-telemetry-discriminator.md` Goal ("On every non-zero exit, stdout is empty ... Every refusal prints exactly one classified line"); Input space ("small positive `iteration`/`attempt` integers").
- decision: a fanout-verdict block whose metadata carries zero `- part:` lines at all is refused with the existing `malformed-block` class rather than a new twelfth class.
  reason: the Goal paragraph closes the class vocabulary to the tokens the script's own header enumerates "and from no other," and **AC8** locks the header's token set to exactly the eleven required tokens; `malformed-block` already covers "the block's own metadata is unreadable," the same defect this catch instantiates, so introducing a twelfth token would both violate the closed-vocabulary intent and duplicate an existing class's meaning.
  grounding: `.shell-team/specs/T-1082-telemetry-discriminator.md` Goal ("`<class>` drawn from a closed vocabulary the script's own header enumerates and from no other"); **AC8** (the required eleven-token list, `usage block-not-found duplicate-block malformed-block malformed-row missing-instance invalid-instance instance-role-collision unattributed-instance uncovered-part no-rows`).
