## When the full loop fits (task aptitude)

**First branch — does the final verification surface close inside the loop?**

- **Closes inside the loop** (correctness is settled by *mechanical* verification — tests, lint, execution/output comparison): the full PM → Engineer → QA → Codex loop **fits**. QA and Codex can confirm the acceptance criteria empirically and statically, so a FAIL is caught inside the loop rather than after a human looks at the result.
- **Does not close inside the loop** (the final gate is *human visual inspection, a real renderer, or subjective evaluation* — e.g. slide/PDF layout, pixel-level UI polish, prose tone): the full loop is a **poor fit, or fits only in a limited way**. QA cannot substitute for the human eye, and the loop only surfaces the human visual gate at the very end, so a visual FAIL costs a whole round-trip and can churn the same code path for many rounds (observed in issue #171: 10+ rework rounds, final score 70/100).

**Provisional operation for visual-output tasks** (a stop-gap until a dedicated short-cycle / variant loop is built — roadmap #138): do **not** put such a task on a single full-loop pass. Instead run a short manual cycle (implement, render, human check) where the human views the real rendered output each turn; keep spec / QA in a supporting role rather than as the completion gate.

> This first branch is the same shape as the future v0.3.0 grounded-AI-evaluator's OOD-novelty / human-gate criterion (see docs/loop-engineering/v0.3.0-oversight-model-evolution.md §7): a verification surface that cannot be mechanically grounded escalates to a human, and the same signal will later feed that evaluator's decision.

**Substrate-reading checkpoint (T-1072).** A point where this orchestrator re-reads its own substrate mid-phase (a rehydration checkpoint) is a **child span** of the span it belongs to, named `engineer-rehydration`, using the `parent_span_id` field the row has carried since T-014 — no new schema key, no new flag, and no agent prompt block is edited for it (the emission is the orchestrator's own, not an agent's). **Within-phase fan-out (Tier-1, T-1074 — opt-in; no phase is rewired to use it by default).** A phase whose own verification work is mechanically enumerable (for example, one `bash bin/check-acs.sh <spec>` run per spec in a full-population blast-radius sweep) MAY be split across N instances of one role and reduced back to one authoritative verdict with `bin/aggregate-verdicts.sh`, rather than run serially by a single instance. Using this step is always an explicit choice for that phase; a loop that ignores it behaves exactly as it does today.

- The orchestrator enumerates the unit population once, fixed before any instance is launched, and never re-selected after a verdict is seen — write it to a population file before launching any instance.
- Every unit is assigned to exactly one instance: one output file per instance, and no shared append target — a shared, locked append target would only serialize the work this fan-out exists to parallelize.
- The degree rule is `N = min(<unit count>, cap)`, where `cap` is `TEAM_FANOUT_MAX` when it is set to a positive integer, otherwise the host's own measured core count (`getconf _NPROCESSORS_ONLN`), otherwise 2. The measured knee is machine-local, not a portable constant, so no degree literal is hardcoded here; state the chosen N and its ground (`TEAM_FANOUT_MAX` or the measured core count) in the launch record.
- A per-instance liveness check runs alongside each instance, started at the moment that instance is launched. A watchdog launched with a bare shell `&` inside a foreground Bash call dies with that call — only a harness-tracked background launch survives. A sub-agent's default foreground Bash timeout is `120` seconds; a unit that can exceed it needs an explicit per-call timeout on that instance's own invocation. Which mechanism supplies the liveness check is the operator's choice — no particular script is named or required here.
- Emit one `--instance <role-qualified-id>` span per instance, from the orchestrator — the orchestrator emits every span row, never the instance itself, because an agent cannot see its own token or duration usage. Instance ids follow the shipped writer's own grammar `^[a-z][a-z0-9-]*$` — a bare number is refused; use a role-qualified id such as `qa-1` or `qa-2`. Concurrent appends use `--seq auto` (T-1076) so no counter is carried across N instances. Record the aggregation step's own cost as `--span orchestrator --phase gate`, the same convention already used for other orchestrator-performed work.
- After every instance has finished, reduce the N part files to one authoritative verdict with `bin/aggregate-verdicts.sh --label <label> --population <population-file> --part <instance-id>=<part-file> [--part ...]`. A refused aggregation (any non-zero exit) does not advance the phase — treat it exactly like any other fail-closed gate and resolve the reported class before retrying.
- Seven invariants stay locked; the id set is derived from `docs/loop-engineering/phase-multiplexing.md`'s own closed-vocabulary line, and each below is declared unrelaxed or moved to implemented:
