At each of the three firing points — the same-class-2 count reaching two, a spec pre-commitment's factual trigger, and a loop-guard `STOP:<reason>` — answer four questions in writing before composing any escalation: is every item of the never-dropped set green; which findings in this firing class target auxiliary components, and which components are they; in what drop order did the pre-commitment record them; and weigh the aggregate cost against the cost of taking the next pre-priced exit in that order.
When every item of the never-dropped set is green, every finding in this firing class targets one of the named auxiliary components, and a pre-priced disposition exists for each of those components, the disposition for the earliest such component in the pre-commitment's recorded drop order executes on the loop's own authority and is recorded on the board with the four answers as its ground.
Escalation to the operator remains mandatory in exactly four cases: no pre-priced disposition exists for a targeted component; the never-dropped set is hit; the pre-priced disposition itself is destructive or irreversible; or the finding set is empty or unclassified — an empty or unclassified finding set escalates and never executes a disposition, because conditions (2) and (3) are vacuously true over an empty set and a predicate that cannot evaluate its input must report that rather than pass.
The fourth question's aggregate-cost answer is recorded for audit and does not gate the execution — the disposition was priced at freeze time, not re-litigated at the firing moment — and the three standing human gates are unchanged: batch GO, sprint planning, and destructive or irreversible operations stay exactly as they are.
