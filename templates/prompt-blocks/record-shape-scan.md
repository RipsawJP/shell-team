## Record shape scan before hand-off

- **Before you write your hand-off, run `PII_CHECK_TRACKER_KEY=1 bash "<plugin root>/bin/check-pii-shapes.sh" --all` on the record files you wrote or edited this round.** The scan reads the working tree, which is why it is the `--all` mode and not the change-scoped default: the default reads each changed path's committed blob, so a record you have not committed yet is invisible to it. Capture the command's stdout and stderr to a file you create under your own scratch directory — the requirement is a real file you own and can read back, not a specific `mktemp` incantation — and read that file back; record the exit status. A redirect or file-creation failure, or an exit status of `2`, is a scan that **did not complete**, and a scan that did not complete is never an absence of findings — fix the invocation and run it again. A `0` or a `1` is a scan that completed.
- **Shape scan in local record mode (T-1182).** Learn the record mode the way the rest of this prompt does (`shell-team.mode` in the clone's git config, read with `bin/team-mode.sh`, or the orchestrator's `Record mode for this repo:` line). In `local` mode the base dir is ignored, so `--all` reads none of your records and reports clean without having read one: run `PII_CHECK_TRACKER_KEY=1 bash "<plugin root>/bin/check-pii-shapes.sh" --paths <record file>…` naming each record file you wrote or edited this round, instead of the `--all` run above, and judge its `FINDING` lines as above. An exit status of `2` is a scan that did not complete and is never an absence of findings; if you wrote no record file this round there is nothing to name, so do not run `--paths` with no path and instead report the `- shape-scan:` line with `<N>` zero and `rc=n/a`. In `tracked` mode the instruction above applies unchanged.
- **Judge the filtered lines, never the bare exit status.** `--all` reports every path in the tree, so a `1` says something somewhere matched and says nothing about your own files. Read the `FINDING pattern=<id> path=<path> line=<n>` lines whose `path=` is one of the files you wrote this round.
- **A hit on your own file is fixed in place before the hand-off is written** — by describing the shape in words, or by assembling it from fragments — never by quoting the bytes again and never by passing it to the next role. A hit the checker's own documents declare as **accepted noise** (this project's design-point label vocabulary and same-outline standards identifiers, under the opt-in) is classified as such in the summary line instead of being edited away.
- **Quote the run's summary in your hand-off as one line, from a run made after any fix**: `- shape-scan: rc=<rc> — <N> record path(s) written this round — <M> finding(s) on them, <K> classified accepted noise — command: <the exact command you ran>`. Every count carries the command that produced it, for the same reason every other count in a hand-off does; a round in which you wrote no record file still carries the line, with `<N>` zero.
- **Report a finding by path, line and pattern id, never by quoting the flagged bytes** — the record you are writing is scanned by this same checker, so a verbatim quote adds a new site the fix has to reach too.
