**Within-phase fan-out (Tier-1, T-1074 — the `verify-mechanism` refinement's shipped default, T-1112).** A phase whose own verification work is mechanically enumerable (for example, one `bash bin/check-acs.sh <spec>` run per spec in a full-population blast-radius sweep) fans out across N instances of one role by default and is reduced back to one authoritative verdict with `bin/aggregate-verdicts.sh`, rather than run serially by a single instance. Using this step is always an explicit choice for that phase, recorded on the board's own dispatch line; the `serial` branch survives as the `verify-mechanism` axis's own conditional, for a population below the fan-out authoring threshold or where the slice-level isolation this step needs is not constructible in-session.

**The execution host.** A mechanism-class fan-out — the `verify-mechanism` refinement's own population — runs as N harness-tracked background shell slices launched by the coordinating session over isolated staged worktrees, one base and one head per slice, and is never sub-agent-hosted: sub-agent hosting has zero completed runs on this population, couples every slice to one stall-prone parent as a single point of failure, and stays prohibited until a pilot measures it.

- The orchestrator enumerates the unit population once, fixed before any instance is launched, and never re-selected after a verdict is seen — write it to a population file before launching any instance.
- Every unit is assigned to exactly one instance: one output file per instance, and no shared append target — a shared, locked append target would only serialize the work this fan-out exists to parallelize.
- The degree rule is `N = min(<unit count>, cap)`, where `cap` is `TEAM_FANOUT_MAX` when it is set to a positive integer, otherwise the host's own measured core count (`getconf _NPROCESSORS_ONLN`), otherwise 2. The measured knee is machine-local, not a portable constant, so no degree literal is hardcoded here; state the chosen N and its ground (`TEAM_FANOUT_MAX` or the measured core count) in the launch record.
- A per-instance liveness check runs alongside each instance, started at the moment that instance is launched. A watchdog launched with a bare shell `&` inside a foreground Bash call dies with that call — only a harness-tracked background launch survives. A sub-agent's default foreground Bash timeout is `120` seconds; a unit that can exceed it needs an explicit per-call timeout on that instance's own invocation. Which mechanism supplies the liveness check is the operator's choice — no particular script is named or required here.
- Emit one `--instance <role-qualified-id>` span per instance, from the orchestrator — the orchestrator emits every span row, never the instance itself, because an agent cannot see its own token or duration usage. Instance ids follow the shipped writer's own grammar `^[a-z][a-z0-9-]*$` — a bare number is refused; use a role-qualified id such as `qa-1` or `qa-2`. Concurrent appends use `--seq auto` (T-1076) so no counter is carried across N instances. Record the aggregation step's own cost as `--span orchestrator --phase gate`, the same convention already used for other orchestrator-performed work.
- After every instance has finished, reduce the N part files to one authoritative verdict with `bin/aggregate-verdicts.sh --label <label> --population <population-file> --part <instance-id>=<part-file> [--part ...]`. A refused aggregation (any non-zero exit) does not advance the phase — treat it exactly like any other fail-closed gate and resolve the reported class before retrying.
- Verify the aggregation is attributable before trusting it: `bin/check-fanout-instances.sh --telemetry <telemetry-file> --run-id <run-id> --phase <phase> --aggregation <aggregation-file> --label <label> [--iteration <n>] [--attempt <n>]` refuses (a classified exit code, empty stdout) unless every selected span row carries a discriminator, every discriminator conforms to the writer's own grammar, no id is claimed by rows of two different roles, and the scope's instance set and the block's declared part set are equal in both directions. A refused check does not advance the phase — treat it exactly like any other fail-closed gate and resolve the reported class before retrying.
- **The launch record.** One file per fan-out at `<runs>/fanout-<label>.launch`, with `<runs>` resolved through `bin/team-paths.sh --get runs` and `<label>` the same `--label` value passed to both `bin/aggregate-verdicts.sh` and `bin/check-fanout-instances.sh` above. Written before any instance is launched, except the two epoch fields, which are written at the moments they name. Lines, in this order, with ` — ` (space, em dash, space) as the field separator: `launch-record 1` — the version line, first line of the file, exactly one; `- population: <path>` — exactly one, the path passed verbatim to `bin/aggregate-verdicts.sh --population`; `- requested-n: <digits>` — exactly one, the N the degree rule above chose; `- achieved-n: <digits>` — exactly one, how many instances actually launched (a value below `requested-n` is a legitimate recorded outcome, not a defect to hide); `- cap-ground: TEAM_FANOUT_MAX=<value>` or `- cap-ground: measured-cores=<value>` — exactly one, the ground of the cap; `- assign: <instance-id> — <unit-id>` — exactly one per unit in the population, and the instance-id set of these lines equals the `--part` name set passed to `bin/aggregate-verdicts.sh`; `- liveness: <instance-id> — harness-tracked-background — <command>` — exactly one **per instance**, not one per fan-out, because a liveness check runs alongside *each* instance and there are N of them, and `<command>` is the launch command verbatim (`harness-tracked-background` is the only conforming mechanism token: a watchdog launched with a bare shell `&` inside a foreground Bash call dies with that call); `- launched-epoch: <digits>` — exactly one, when the last instance's launch call was issued; `- completed-epoch: <digits>` — exactly one, when the last instance's completion was observed; `- execution-host: coordinating-session — <ground>` — exactly one, recording that this fan-out was hosted by the coordinating session as harness-tracked background shell slices rather than by a sub-agent instance, with `<ground>` normalized to replace this checkout's own absolute path with the placeholder `<repo-root>`; `launch-record-end` — the terminator, last line, exactly one.
- `- liveness:`, `- launched-epoch:`, `- completed-epoch:`, `- cap-ground:` and `- execution-host:` are **audit-only** — no checker reads them; every other field above is already an argument to `bin/aggregate-verdicts.sh` or `bin/check-fanout-instances.sh`, so a unit assigned to nobody or twice, or an instance id absent from the telemetry, is already refused by the shipped fail-closed pair without a third tool reading the record.
- Seven invariants stay locked; the id set is derived from `docs/loop-engineering/phase-multiplexing.md`'s own closed-vocabulary line, and each below is declared unrelaxed or moved to implemented:

- invariant-lock: both-gates-green — declared — fanning a phase's own verification work across N instances changes only how many workers produce partial verdicts before aggregation; qa-verifier's PASS and codex-reviewer's APPROVE are both still required before READY_FOR_MERGE.
- invariant-lock: fail-closed-checkers — implemented — `bin/aggregate-verdicts.sh` refuses with a classified exit code and empty stdout rather than ever promoting a partial, incomplete or malformed result to the authoritative verdict.
- invariant-lock: bin-pure-bash — implemented — `bin/aggregate-verdicts.sh` is bash 3.2, zero-dependency (coreutils and POSIX awk only) and shellcheck-clean.
- invariant-lock: human-gate-set — declared — the three human gates (the sprint's own batch GO, planning approval, and confirmation before a destructive or irreversible operation) are untouched; width scaling changes only how many workers do a phase's own work, never which decisions require a human.
- invariant-lock: frozen-intent-no-concurrent-attest — declared — a spec's frozen intent block is still attested by exactly one role at one point in time, at Specify; Specify is never fanned out.
- invariant-lock: handoff-attributable — implemented — one instance writes one output file, no shared append target, and the merged record carries a per-unit attribution line naming the instance that produced it.
- invariant-lock: per-instance-telemetry-discriminator — implemented — each instance's call carries `--instance <role-qualified-id>`, and `--seq auto` makes concurrent appends safe with no caller-carried counter.
