The review instruction is written to `<PROMPT_FILE>` first and read back through command substitution, never substituted as free text inside a bare pair of double quotes on the invocation line itself: a command substitution's own output, once it has run, is not re-parsed for backticks, `$(...)`, `$VAR` or embedded double quotes — the same reason this file's own evidence-pass prompt template below embeds the perspectives file's full text through `<PROMPT_FILE>` rather than naming `<PERSPECTIVES_FILE>` as free text on the invocation line itself. An earlier shape of this line substituted the instruction directly into a bare `"<PROMPT>"`; both a primary and an adversarial Codex review pass on this task independently found that shell-unsafe (a backtick or `$(...)` in the instruction text could be executed, a `$VAR` expanded, or an embedded double quote could terminate the argument early and let the remainder of the instruction text be parsed as further shell tokens) — never repeat that shape. Every flag's effect below is the measured one (Claude Code CLI 2.1.268, live probes recorded in `.shell-team/provenance/T-1135.md`), not one inferred from `--help` text — an earlier shape of this line rested on the latter and was measured wrong before this one shipped. `--tools` names the built-in tool set the pass may use at all — `Read Grep Glob Bash`, which is where `Bash` is granted in the first place, and which excludes the Agent tool, `Write`, `Edit` and `NotebookEdit` by simply never naming them. `--allowedTools "Bash(git diff:*)" "Bash(git log:*)" "Bash(git rev-parse:*)"` is the git-only permission-rule allowlist that narrows `Bash` itself to those three subcommands; `--allowedTools` alone does **not** deny every other `Bash` call — measured: with `--allowedTools` present but no permission mode set, an unlisted `Bash` call still ran, because the adopter's own permission-mode setting decided it. `--permission-mode dontAsk` is what turns any tool call outside that allowlist into a harness denial instead — measured: the identical unlisted `Bash` call was refused under this mode, with the refusal recorded in the run's own `permission_denials` field, and this is the actual read-only-confinement mechanism, not `--tools`/`--disallowedTools` alone. `--strict-mcp-config` excludes every MCP server from the adopter's own configuration — measured: without it, every one of the operator's claude.ai connector tools stayed exposed to the pass, GitHub `push_files`/`merge_pull_request`, Gmail send, Slack send and Jira/Confluence write among them, none of which `--tools` touches, since MCP tools are not part of its built-in vocabulary at all. `--setting-sources ""` excludes the adopter's own user, project and local settings files from loading (the counterpart of the Codex recipe's `--ignore-user-config --ignore-rules --ephemeral`). `< /dev/null` closes stdin so the pass never waits on it. `--no-session-persistence` leaves no session state behind. **No `--model` is composed on this path** — the reviewer's model is whatever the host's own Claude Code installation is configured for, `provider-configured`-honest exactly as the shipped binding's Codex-path row already is;
