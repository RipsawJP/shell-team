The review instruction is written to `<PROMPT_FILE>` first and read back through command substitution, never substituted as free text inside a bare pair of double quotes on the invocation line itself: a command substitution's own output, once it has run, is not re-parsed for backticks, `$(...)`, `$VAR` or embedded double quotes — the identical `"$(cat "<BRIEFING_FILE>")"` pattern the T-1118 alternate-executor recipe above already relies on for the same reason. Every flag's effect below is the measured one (Claude Code CLI 2.1.268, live probes recorded in `.shell-team/provenance/T-1135.md`), not one inferred from `--help` text — an earlier shape of this line rested on the latter and was measured wrong before this one shipped. `--tools` names the built-in tool set the pass may use at all — `Read Grep Glob Bash`, which is where `Bash` is granted in the first place, and which excludes the Agent tool, `Write`, `Edit` and `NotebookEdit` by simply never naming them. `--allowedTools "Bash(git diff:*)" "Bash(git log:*)" "Bash(git rev-parse:*)"` is the git-only permission-rule allowlist that narrows `Bash` itself to those three subcommands;
