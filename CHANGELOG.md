# Changelog

Release history of the `shell-team` plugin — one bullet per release, newest first. Release history first moved out of `README.md`'s Versioning section into this file, and was later fully rewritten (reordered to newest-first, split into sub-bullets, and scrubbed of internal task/issue references) as part of public-release preparation; new release entries land here as part of this project's release process.

日本語版: [CHANGELOG.ja.md](CHANGELOG.ja.md)

- **v2.5.0**
  - **Mechanism-class verification sweeps now fan out in parallel by default.** A phase whose verification population is mechanically enumerable splits across N instances on the default shipped path — the previous "opt-in only" claim is removed from both READMEs because it is no longer true — and every fan-out's launch record now states its execution host: the coordinating session launching harness-tracked background shell slices over isolated staged worktrees, never a sub-agent hosting detached children, which stays prohibited until a dedicated pilot measures it. On this repository's own populations the parallel form measured a roughly 44% wall-clock saving on the phase an operator waits longest for.
  - **The freeze now derives the release tier itself and stops when the work outgrows the approved plan.** At every freeze — first and re-freeze alike — the release tier is re-derived from the spec's own declarations by applying the headline and default-reachability tests jointly, recorded on the board entry, and compared against the approved planning premise; on a mismatch the loop stops and issues a deviation notice carrying the exceeds-estimate statement, the continue-or-stop question, and a recommendation with its rationale — never a bare "proceed?". In its first live firing this gate detected exactly the premise break that renamed this very release.
  - **A plugin role's tool restriction is now verified enforced under concurrent launches.** A live differential probe — concurrently launched restricted-role instances beside an unrestricted control — produced the first physical evidence that a role's declared tool set is actually withheld from concurrently running instances, recorded as a loop-engineering note with its full protocol and evidence frozen byte-for-byte, and the stale documentation surfaces that predated the measurement were repaired to cite it.
  - **A quantitative claim on a board entry can now carry its own derivation command, validated and re-run by a fail-closed checker.** An opt-in `- count:` record grammar binds each relayed figure to the command that derives it; live validation re-runs every claim's command and refuses a mismatch, near-misses are collected and refused rather than silently skipped, and close-out refuses a malformed claim before any board write. On its first day in service the checker caught its own author's stale counts twice, and in the following task it caught a hand-transcribed tally the grammar did not yet cover — the measured boundary of what it closes.
  - **The scope-lock authoring convention now measures the whole base-to-worktree chain, rename-safely.** A spec's scope lock is taught to union four reads — the committed range, the staged delta, the unstaged delta, and untracked strays — with rename detection disabled on all three diff reads, because under git's default setting a rename's source path is invisible to every read at once, letting a staged rename out of a governed path report a clean scope while an unauthorized deletion hides inside it. The convention's canonical statement lives in one file with the second copy removed, both adopter guides name it, and the change applies forward only: no merged spec's frozen lock is repaired.
- **v2.4.0**
  - **A task's board entry can now carry a per-axis record of what the immediately preceding task in a stacked train elected, verified fail-closed before the freeze.** The coordinating session writes one `- dispatch-reflection:` sub-bullet per dispatch axis the entry itself records — naming the predecessor task, a verdict (`repeat`, `differs`, or `no-predecessor-row`), and a ground — in the same window as the dispatch transcription and before it, so a repeated mis-election surfaces inside the loop instead of waiting for an operator to ask. The entry-mode checker validates the family whenever it is present: grammar and per-axis coverage in both directions, verdict agreement against the predecessor entry's own recorded value (the predecessor is found in the Done section as readily as in Active), a single-predecessor invariant with a self-reference guard, refusal of duplicate or conflicting dispatch rows on either side, and a distinct, conformant no-predecessor form — while an entry carrying no reflection line at all still passes, so existing boards and non-adopting repositories are unaffected.
  - **The review and review-response skills now resolve their executor through the shipped resolver and a host's `binding.conf`**, so a host rebind recorded in configuration is actually exercised by the review path instead of silently ignored. The shipped default binding is unchanged.
  - **The binding consistency checker cross-checks the declaration body, refuses empty values, and guards its own population**, so a malformed or hollow binding declaration refuses instead of passing on a technicality.
  - **The close-out script refuses to move a board entry whose own flag is not ready for merge, and always states the issue-close consequence** — with an explicit note, when no issue is given, that integration-branch merges do not auto-close issues.
  - **The canonical two-arm verification sweep stages a frozen snapshot of the untracked telemetry corpus into its base arm**, resolved through the layout resolver and copied member by member as a real directory, so corpus-reading criteria stop producing base-arm false failures that every sweep previously had to re-classify by hand.
  - **The Japanese documentation set received a readability pass**, rewriting machine-translated phrasing into natural prose without changing any machine-checked token.
- **v2.3.0**
  - **A repository can now declare an oversight profile that requires a recorded human approval at declared loop seams.** A host writes `oversight.conf` selecting `autonomous` (the shipped default — changes nothing anywhere) or `governance-controlled`, which requires, at each declared seam, a board-recorded approval whose approver is distinct from the artifact's producer and whose anchor still names the artifact being gated — refusing fail-closed on anything it cannot evaluate. An enrolled repository cannot be de-enrolled by its declaration merely going missing: once the board carries any approval record, a vanished declaration refuses instead of silently reverting. The shipped documentation names the mechanism honestly — a self-declared conflict check with a content anchor, not an authenticated segregation-of-duties control — and enumerates what it does not close.
  - **Every executor pass in a review record now carries a verifiable input-fidelity block.** The reviewer records the executor invocation verbatim (absolute home paths normalized to a placeholder), a pass-role label from a closed set separating finding-generation from confirmation passes, the briefing-fidelity value that reached that pass, and a per-round raw-capture stem that is never overwritten across rounds. A new fail-closed checker validates presence and grammar — never a prompt's content — and the close-out gate refuses a record it cannot evaluate.
  - **Fenced code blocks are now inert to the acceptance-criteria parser.** An AC-shaped line quoted inside a backtick fence no longer executes or reports as a phantom criterion.
  - **The verify-axis dispatch election is split by work type**, so a fixture-suite half and a mechanism-class full-population diff carry independent, separately-grounded records.
  - **Machine-local session and scratchpad path shapes are screened from committed records**, alongside the existing PII shapes.
- **v2.2.1**
  - **The loop now refuses, at freeze time, a task whose recorded entry mode disagrees between its two written sources.** A new fail-closed checker reads two independently written committed records — the planning role's board sub-bullet and the orchestrator's dispatch transcription — and refuses to proceed when either is missing or they disagree, instead of trusting whichever prose a reader happens to look at. In its first live firing it caught a real two-writer transcription collision before the freeze.
  - **Close-out now refuses a task whose elected spec review never reached an approval verdict.** A new backstop checker locates the review record's final anchored verdict line under a closed four-form grammar and blocks close-out unless it reads approval — structurally immune to the prose-parsing defeat classes an adversarial review of the previous approach enumerated.
  - **Which record-integrity obligations earn a tested checker is now decided by a written rule, not case by case.** The tamper-resistance record gains a criticality rule: an obligation whose verdict gates a loop transition and is mechanically executable gets a tested script with its own fixture suite and CI wiring; the rest get a documented instrument, with a recorded reclassification path. Three obligations were promoted under the rule in this release alone, and the rule's own re-evaluation trigger fired and was recorded when the third one landed.
  - **The trial-adoption recipe is now executed, not just documented.** A CI-wired fixture suite extracts the shipped recipe from the adopting guide's own bytes (never a retyped copy, so a guide edit cannot silently diverge from what is tested) and runs it end to end in throwaway repositories — in both directory layouts and by both documented setup paths — turning the previously deferred execution findings into permanent regression locks.
  - **Starting a trial on its own branch is now one flag.** `team-init --trial-branch <name>` creates and switches to the trial branch before a single scaffold byte is written, refuses three named unsafe states with exit 2 and a specific remedy each, and leaves the no-flag path exactly as git-free as before; both adopting guides drop the two claims this correction made false. The flag is opt-in.
  - **The task board is now guarded against a silent structural-corruption class.** The board-heading checker asserts the presence and uniqueness of the board's structural headings unconditionally — independent of any base revision — where it previously only compared against a base; the duplicated-heading corruption this closes was found and repaired on this project's own live board, which the checker now lints on every push here.
  - **The loop now runs a written means-ends self-check at its escalation points before involving a human.** At the three escalation firing points, it answers four canonical questions (is the primary value still green; is this an auxiliary component; does a pre-priced disposition exist; what has this path cost so far) and executes an already-pre-priced drop on its own authority instead of inventing a new human gate — the three standing human gates are unchanged, and the answers can travel on the rework digest.
- **v2.2.0**
  - **You can now hand the team a finished spec and the full machinery still runs.** Who authors the spec is a recorded, per-task routing decision: the shipped default keeps the PM role authoring as before, while an operator who already wrote the spec drops it in and the PM role switches to a conformance formatter — shaping grammar and structure, flagging substantive gaps back to the author, never rewriting intent. Every downstream gate (the freeze sweep, QA, the cross-provider review) runs unchanged in both modes, and a fail-closed freeze-time read refuses to proceed when the recorded mode and the hand-off disagree.
  - **Spec documents now get their own cross-provider review before anything is frozen.** When a spec's correctness rests on premises the repository cannot measure itself, the planning role elects an extra review pass that reads the spec document at the Specify seam — before the intent hash is recorded — so a flawed premise is corrected as an ordinary author edit at zero re-freeze cost instead of surfacing after implementation as a ratification-grade repair. In its first live cycles this pass consumed eleven review findings pre-freeze that would previously have landed post-freeze.
  - **A green flag now says what it actually verified.** Every spec declares its verification ceiling — the level the loop's own gate can reach (`unit-and-static` or `real-environment`) — with per-criterion exceptions for work that stays human-owned, a non-vacuity rule so a declaration can never attest nothing, and a fixed disclosure token for the one case where nothing was verifiable at the declared level. QA transcribes the declared value verbatim onto its verdict and onto the board line a reader actually looks at, so `READY_FOR_REVIEW` reads "green *up to* this level; these items remain above it" rather than bare green.
  - **Trying the team on one ticket no longer requires committing to it.** The adoption guide gains a supported trial route: scaffold and operating files live on a dedicated branch the organization never merges, the full machinery runs intact, and teardown is one branch delete — with the propagation caveats, a global-gitignore remedy, and both directory layouts spelled out. The guide also records the decided rejection of an untracked local-only mode, with the specific fail-closed gates such a mode would silently disable named one by one.
- **v2.1.0**
  - **The team now decides, per task, how each phase runs — and records the decision.** The planning role applies a written precedence rule over two orthogonal axes (how the implement phase runs; how the verify phase runs), and the decision lands on the task's own board entry as a machine-validated `dispatch` record naming the axis, the chosen mechanism, whether a conditional trigger or the unconditional default applied, and the priced ground it rests on. The close-out gate refuses a malformed record, so a routing decision can no longer ride along as unstructured prose.
  - **Verify-phase fan-out is now reachable on the default path — no flag, no opt-in switch.** When the recorded verify-axis decision names the Tier-1 fan-out, the run skill's Validate step routes the phase's mechanically enumerable verification work to the shipped fan-out step as written: fixed population file, degree from the shipped cap rule, per-instance liveness, one part file per instance, reduction to one authoritative verdict, and an attribution check that refuses an unattributable aggregation. Measured live end to end on a real 90-unit verification population with 8 real instances: the fanned arm finished in 46.89% less wall-clock time than the same-population single-instance baseline, with the two arms' verdict regions byte-identical.
  - **Every fan-out launch now leaves a durable launch record.** One file per fan-out captures the population, the requested and achieved degree, the cap's ground, every unit-to-instance assignment, every liveness watcher's verbatim command, and the launch/completion epochs — so a fan-out that ran is distinguishable, after the fact, from one that merely claims to have run.
  - **Spec freezes got harder to get wrong.** The freeze gate now demands an instantiated two-arm base-ref discriminator on stacked branches (with the silent-fallback path refused outright), measures every borrowed-vocabulary count premise against the branch point's committed blobs before attesting, and re-measures tokens a sibling task carried onto the stack instead of inheriting their values.
  - **The changelog you are reading was verified by the machinery it describes**: this release's own verification sweep is the measured firing above.
- **v2.0.3**
  - **The board hand-off lint runs up to 17x faster on large boards.** The checker every push runs re-implements its hot inner scan; on this repository's own board a single run dropped from roughly 141ms to 8ms, with verdicts unchanged across the whole corpus.
  - **Concurrent telemetry writes can no longer corrupt the run log.** The telemetry writer now takes a never-stealing directory lock around each append and can derive the next sequence number under that same lock (`--seq auto`), closing the race that produced duplicate `(run_id, seq)` pairs in real logs; a writer that cannot acquire the lock refuses with a dedicated exit code and writes nothing rather than tearing a row. Rows can also name which instance of a role produced them (`--instance`), so records from parallel workers stay attributable.
  - **Experimental, unused by default: a within-phase verification fan-out mechanism.** A new `aggregate-verdicts.sh` reduces per-instance verdict files to one authoritative block — byte-identical under any partition of the same fixed work population — or refuses with a classified error rather than promoting a partial result; the run skill's Validate phase now names the opt-in decision point where an orchestrator may use it. No phase fans out unless deliberately chosen. This work traces to a request for implementation-phase parallelization that this release does not yet meet: the measured groundwork ships, the requested capability itself remains open.
  - **Version numbers now follow a written value rule.** `CONTRIBUTING.md` gains `## What a version number encodes`: the number encodes how much more useful the release is to whoever receives it — never work volume or diff size — which is why this release, despite its breadth, is a patch.

- **v2.0.2**
  - **Verification effort is now priced by what a task ships, not applied uniformly.** Every spec declares its deliverable class inside the frozen intent block — `mechanism` or `no-mechanism` — and a wording/docs/analysis task that changes no executable surface earns a narrower verification bill: a read-set-scoped impact analysis (with the indirection carve-out run or disclosed), CI-equivalence only for steps whose inputs the diff reaches, and mutation probes only for check lines the task itself adds. Anything touching scripts, tests, templates, CI or checker semantics keeps the full price.
  - **The reviewer's brief now states the verdict scope and severity calibration up front.** The orchestrator's review briefing names what gates the verdict for the task's deliverable class and how process-bookkeeping findings are weighted — stated before the round starts, with the reviewer's independence over what it finds explicitly untouched.
  - **Four loop-engineering studies land, giving the loop its first measured cost map.** Where per-task effort and wall-clock actually go (rework rounds are token-monotonic but not wall-clock-monotonic); how context accumulates across a sprint and why carrying it beats resetting it; whether phases can overlap (staged adoption gated on a contract redesign, with the shared-state contention inventory measured); and whether N agents can share one phase — including a measured verification fan-out pilot: 43.84% wall-clock reduction on the swept degrees, with the aggregated verdicts proven identical to the serial run's, and the finding that one outsized unit caps what any degree of parallelism can recover.
  - **Four operating lessons promoted into the corpus.** Freeze-time verification cost is priced by deliverable class; a reviewer's premise-level recommendation keeps its abstraction level when restated; an operator-facing report declares who owns a cited pre-decided disposition; and a stacked merge chain's retro window tolerates intermediate nodes with no board entry.

- **v2.0.1**
  - **The binding config's documentation now lands where a reader looks for it.** Both READMEs gain a pointer section naming the executor-assignment capability and where its full documentation lives; the adopting guide (English and Japanese) becomes the single canonical how-to, with the config grammar by example, every refusal a misconfiguration can reach, valid effort values, and the two-axis boundary of what a rebind does and does not change.
  - **A user-visible change now declares its adopter-facing documentation at freeze time.** Every new spec carries a `user-visible` declaration with a stated rationale; a `yes` additionally names the adopter-facing surface the documentation lands on (or carries an explicit waiver), and the freeze is refused otherwise — so a shipped capability can no longer reach a release with its documentation silently scoped out.
  - **The release-notes template's compare link now names the right range.** The `Full changelog` compare URL takes the previous release's tag and the new release's tag, instead of a placeholder pair a drafter had to notice.
  - **Shipped prose now matches the mechanisms it describes.** An accuracy pass across shipped prompts, skills, docs and records: the durability confirmation documents that it is skipped (not re-parameterized) when no board task is active; the test recipe records both siblings a scratch copy of the durability checker needs; the oversight page decides its instantiation-list boundary — the listed paths are the mechanically enforced surfaces, advisory instruction sources are named as also reached by the criterion; and the grep-scope convention states `git grep`'s actual symlink behavior (it skips a tracked symlink entry entirely) instead of a wrong mechanism claim.

- **v2.0.0**
  - **Executor assignment becomes host-configurable: a binding config, an adapter contract, and a fail-closed resolver connect who runs each role to a file the host owns.** A line-oriented `binding.conf` — validated by a new checker with a closed refusal vocabulary and fixed exit codes — binds each inner-loop role to `{provider, model, effort, adapter}`; a task-envelope contract document plus two shipped adapter definitions (`claude-cli`, `codex-cli`) declare what an executor receives, returns, and supports; and a per-role resolver answers "which executor runs this role, and may it be invoked at all" immediately before each invocation — the host's config first, the plugin-shipped v1-equivalent default otherwise, so a repository with no config keeps running exactly as before. Every failure refuses rather than substitutes: an effort value the bound adapter does not declare, a board-authority/channel conflict, an unavailable executor, an unusable config.
  - **Cross-provider review is now the shipped default with its rationale stated, no longer an unconditional invariant.** The reviewer ships bound to the Codex CLI in the plugin's shipped default binding because a model reviewing output from its own family shares its blind spots; a host may rebind it — which changes what resolution reports and what telemetry records, and the documentation claims exactly that much and no more. An unavailable or unauthenticated reviewer executor still blocks the loop, never a silent substitution.
  - **A loop that stopped ticking and a loop waiting on a human no longer produce the same silence.** Both loop skills write a gate-declaration artifact whenever they hand control to a human and clear it when they act on the answer, and a new out-of-band classifier — invoked by an external timer, reading persisted state read-only, writing nothing anywhere — answers `RUNNING` / `WAITING` / `STALLED` on stdout and the exit code, with every input it cannot read an error from a closed token set and never a healthy verdict.
  - **Telemetry spans record the resolved binding, and the roll-up derives provider relations instead of storing them.** A span can carry the resolved provider, effort and adapter; the per-run roll-up prints a provider census and one verdict per review round — cross-provider, same-provider, or undetermined — and rows written before this release always read `undetermined` rather than a fabricated answer.
  - **The freeze gate reads a spec the way it will be lived with.** The run skill's pre-freeze sweep now evaluates every criterion against the post-implementation tree state as well as the tree at freeze time, requires the downstream-impact disclosure to come from a full-population diff, and reads norm text destined for multiple surfaces for singular determiners before it is mirrored.
  - **Release pages follow two fixed rules from now on.** The title is the bare tag name, and the body is drafted from a shipped template — no in-body version heading, highlights transcribed verbatim from the changelog, migration notes only when an adopter must act. Forward-only: no earlier release is edited.
  - **Self-location hardening across the shipped scripts.** Five scripts that cross from `bin/` into the shipped `templates/` now resolve their own directory physically, so a symlinked ancestor directory — ordinary vendoring — can no longer make them read another tree's data; the two highest-impact cases are locked by fixtures observed failing on the pre-fix code.
  - **`team-init` scaffolds the binding specimen inert.** An adopting repository receives `binding.conf.example` — documentation, not an executor assignment; renaming it into effect is a deliberate act.
- **v1.8.0**
  - **A durability gate observes whether the loop's own records actually persisted, instead of predicting they will.** A new checker resolves each record a hand-off claims durable to a blob in a fixed commit and matches the working file against it, wired into both durability seams of the run skill alongside the existing status guards. Its record set comes from a shipped registry rather than from `git status`, so a record made invisible by a stray ignore rule — the exact failure two earlier prediction-based designs could not catch — is now caught rather than passing silently; opting a record out is possible only through a tracked mode file whose committed content matches its working copy.
  - **The credential-shape scan stops firing on this project's own hyphenated labels.** The OpenAI-style token pattern gains a left-boundary guard, so an ordinary word ending in the two letters before a hyphen and a long identifier is no longer reported as a key. The one real key shape the guard also suppresses — a key wedged immediately against a preceding letter or digit with no separator — is disclosed as a deliberate, bounded trade-off in the checker's own prose and in the PII-controls documents, and pinned in both directions by the suite, rather than left as a silent gap.
  - **The intent checker's help and hash handling fail cleanly.** `--help` wins whatever the flag order; a computed hash is refused unless it is forty lowercase hex before any consumer reads it; and the print path reaches its classified exit instead of dying on a broken pipe.
  - **A runtime acceptance criterion — the kind no command can verify — is reported and audited item by item.** Both the implementing and the verifying roles now carry the rule that every such criterion in a spec is discharged separately and completely, with each whole-set claim carrying the enumeration it summarises, so a compressed "all done" summary is a finding rather than a pass.
  - **The spec-writing and review roles gain mechanised contracts drawn from live operation.** A verification-mechanism pre-commitment names its drop order before the first review round; a repair must close the class of a defect rather than the reported instance; an obligation added to a shared prompt region reuses that file's own scoping idiom; and an append to an append-only record follows a full re-read of the record. Alongside, the grep-scope convention prefers a tracked-file enumeration over a recursive search, an anchor that guarded a repair by too weak a substring is tightened, and a test suite reads git output quote-safely.
  - **Criteria that were quietly going stale are now labelled, and a batch of documentation miscounts is corrected.** Two shipped specs gain the merge-point-scoped label on criteria whose reds are expected after a merge, a ledger count off by one is fixed, and several stale citations are corrected in a single editorial pass — behaviour unchanged, the records made honest.
- **v1.7.0**
  - **A freeze can print the hash it is about to record, and a refusal names its measured counts.** The intent checker gains a `--print-hash` mode — the same normalize-and-hash pipeline that verifies a frozen block, exposed so the recording side computes the value it is about to write instead of re-implementing the normalization by hand. Attestation refusals now print the actually-counted line totals as a ready-to-adapt remedy, and the freeze-gate sweep gains an explicit cross-join step: criteria already found red are checked against the requirement sets every other criterion asserts, not each in isolation.
  - **Spec check lines carry a written convention for how they observe the tree.** A diff-based criterion names a commit range rather than the working tree, so an unrelated uncommitted edit cannot fail it; a grep-based absence criterion names the files it reads outright, or scopes a recursive search, so a gitignored build artifact can neither satisfy nor violate it; and the counting discipline the generated playbook already carries is indexed from the same place rather than duplicated by hand. The one self-check item that prescribed the working-tree form is amended in place, with its staleness claim intact.
  - **The executable-bit lock now covers the test suites, in both directions.** Every tracked file under the test tree whose content begins with a shebang must carry the executable mode, and every executable entry must begin with a shebang — judged from the index, failing closed on empty or erroring git output, with synthetic controls for both directions and for the empty population. Eleven suite files that had been committed non-executable since their birth are normalized.
  - **Test suites no longer share guessable scratch paths.** Thirty fixed scratch-root assignments across twenty suites move to `mktemp` with explicit templates, and one suite's cleanup glob over a shared parent directory — which could delete a concurrent run's files — is confined to the run's own directory. Two invocations of the same suite can now run at the same time without colliding.
  - **Every cross-provider verdict records the judge that produced it.** The reviewer's verdict block gains a mandatory `Codex CLI` line carrying the verbatim output of that round's own `codex --version` run — recorded, never pinned: no minimum version, no comparison, no gate on the value — mirrored byte-identically in the advisory drift evaluator, and scoped so the finding-evaluation mode, which writes no verdict block, is not bound by an obligation it cannot discharge. The workflow quick-reference stops calling the version check implicit.
  - **A signal-delivery window that cannot be closed is documented where an operator will find it.** The two checkers that briefly ignore HUP/INT/TERM between creating a temp file and registering it for cleanup carry a byte-identical header paragraph describing the residual — including that a `mktemp` which hangs rather than fails makes the window uninterruptible — and the paragraph reaches `--help` through the existing dynamic header derivation. No behaviour changes.
  - **The retro input collector reads what is actually there.** Its spec resolver accepts any regular file rather than only conventionally-suffixed ones, and four documentation sites describing a legacy marker the resolver does not use are corrected.
  - **The lessons corpus grew from live operation.** Three new entries land — a relayed premise is re-measured at its primary source before it is written into a downstream prompt, with a matching hand-written rule in the planning role's procedure; an accounting criterion is written as a base-relative delta or a value-independent invariant, never an absolute literal; and stale frozen prose accumulates into one batched editorial pass rather than per-instance re-freezes — with the per-role prompt blocks regenerated from the corpus.
- **v1.6.0**
  - **A missing executable bit on a shipped script is caught by a machine, not by a reviewer.** A new repository-hygiene suite asserts that every tracked file under `bin/` carries the executable mode, judged from the git index (so a `core.fileMode=false` checkout cannot lie), failing closed when git itself fails or returns nothing — a partial listing followed by a non-zero exit is a failure, never a clean pass — and runs as a CI step. The defect class it locks was found only by a cross-provider review when it first shipped.
  - **The re-freeze classifier and the intent checker survive their own failure paths.** Temp-file tracking no longer relies on appends inside a command substitution (the registry lives in the calling shell, so the exit trap actually sees it); a comparison tool's I/O error is classified as a usage failure instead of reading as a legitimate "different"; both scripts handle HUP/INT/TERM with preserved exit codes and no temp residue, closing the window between file creation and cleanup registration; and both derive their `--help` text dynamically, so a header edit can no longer truncate it. Five new fixtures pin how the classifier judges indentation changes and tail additions to a frozen block.
  - **Two authoring disciplines are built into the spec-writing role.** A deliverable that prints a command beside a "measured at `<ref>`" label now requires an acceptance criterion aimed at the command's reading target — the named ref's committed bytes, never the working tree — and a frozen population-count criterion must either read a pinned ref or carry an explicit `stale-at:` re-measurement trigger, so declared and measured values cannot drift apart silently. The shipped audit document that exposed both classes is re-derived at a pinned ref as the first live application.
  - **Accounting criteria describe the shipped final state, and their anchors close at their subject's boundary.** A sprint of live-reproduced exploits drove two structural rules into the frozen-criteria practice: no criterion may count how many ratified repairs produced the current bytes (ledger history belongs to the intent checker), and no accounting match may be satisfiable by a substring, a prose mention, or an identical literal under another task's entry. Alongside: the reviewer's board boundary is stated as a rule in the orchestrator-facing skills, the write-surface enumeration carves out tool-internal state directories without licensing deliberate writes, and a frozen wording that mis-categorized the summarized-sources declaration line is corrected.
  - **A batch-merge retro must reconcile commit identity, not just count.** The retro agent's cycle-window norm now requires matching the returned merge commits against identity material the task framing already carries — merge SHAs always; pull-request numbers where the merge subjects carry them; fetching nothing — with every returned entry either matched or explicitly flagged foreign, and unverifiable membership recorded rather than presented as the cycle's. The decoy-fixture guards in the hand-off checker's suite are anchored to the full line shape including slot position, so a de-shaped fixture fails loudly instead of silently testing nothing.
  - **The errexit-audit's exemption registry no longer taxes every edit above a pinned line.** Its records move from `file:line:content` position pins — seven tasks each paid a manual re-measurement, and one pin coupled six suite sites — to position-independent, multiplicity-aware content keys: an occurrence count declared per record and compared against a live measurement, giving both "an unregistered write appeared" and "a registered write vanished or multiplied" from one mechanism. A byte-identical duplicate of an exempt line is escalated to human review instead of being absorbed, and the design's deliberate losses are documented in the spec that shipped it.
- **v1.5.0**
  - **The loop can repair a mechanically broken frozen `check:` line without a per-instance human GO — when, and only when, an operator grants it.** A new classifier, `bin/check-refreeze-class.sh`, judges whether a re-freeze delta is confined to `- check:` lines (`mechanics`) or touches intent prose (`class-b`); the board record retains the superseded hash and quotes every replaced line with its replacement; and the cross-provider review carries a mandatory item whose rejection reverts the re-freeze byte-for-byte and suspends the grant. The shipped default is unchanged: with no operator grant, every re-freeze still stops for a human. The knob, its record shapes, its honest enforcement limits and a sample grant block are documented in `docs/tuning-oversight.md` (and its Japanese counterpart) and `CONTRIBUTING.md`.
