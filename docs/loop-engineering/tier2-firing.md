## Firing protocol (frozen before execution)

Restated from `.shell-team/specs/T-1088-tier2-firing.md`'s frozen `<!-- BEGIN firing-protocol: T-1088 --> … <!-- END firing-protocol: T-1088 -->` region — a faithful restatement, paragraph by paragraph, for a reader who has not opened the spec, never a re-derivation of the protocol's own design choices.

**The arm.** Exactly one firing. `N = 2`. Subject `docs/loop-engineering/subjects/subject-01/`, at the version committed on this branch. No reps, no sweep of N, no second arm of any kind. Arm id `tier2-n2-subject01`; candidate ids `candidate-01` and `candidate-02` per the briefing's own candidate-id grammar.

**Venue construction, and the one shared diff base.** One throwaway `git clone --no-hardlinks` per candidate under `$TMPDIR`, detached at one pinned commit shared by both. `git worktree add` is used for no venue, because a worktree registers under `.git/worktrees` in the real checkout and turns teardown into a destructive step this task takes no version of. Each candidate venue is created outside its clone's tracked tree and populated by `regenerate.sh`, then made its own `git init` repository whose base commit is exactly the four regenerated files, so the candidate's diff is a real diff against one shared base. The oracle is always invoked from the clone's committed path, never the venue's own copy.

**What a candidate receives, and the boundary made mechanical.** Exactly two things: its own venue path, and the venue's own `README.md` brief. Never the judge briefing, never this spec, never the board, never the other candidate's venue or its output, and never any file naming this task — `regenerate.sh`'s copy loop is `for f in README.md interface.md manifest.txt acceptance.sh`, so no briefing byte can enter a venue unless the orchestrator puts it there, and the protocol forbids that in words.

**Launch mechanics, reused verbatim rather than re-invented.** The two candidate instances are launched concurrently and recorded on one launch record in the grammar above. Every instance — candidate, judge, gate and rework alike — carries a per-instance liveness check started at the moment of launch, harness-tracked-background and never a bare shell `&`, and an explicitly pinned per-call Bash timeout on every call it makes. `subagent_type` and model are recorded verbatim as **declared labels**, never upgraded into evidence of a resolved type. Telemetry is orchestrator-written with `--instance <role-qualified-id> --seq auto`; because the runs directory is gitignored, every span row this note relies on is quoted verbatim inside the evidence region.

**check-results.** Per candidate, `bash docs/loop-engineering/subjects/subject-01/acceptance.sh <venue>` invoked from the clone's committed path, its `acceptance: <n> passed, <n> failed` summary line quoted verbatim with its exit status. The result is carried at exactly the strength `- oracle-claim: enumerated-case-instrument` states and never widened: an `11 passed, 0 failed` is conformance to eleven enumerated cases, not conformance to `interface.md`'s frozen contract.

**The judge pass.** The judge instance's entire prompt is strictly the bytes between the briefing's two marker lines, marker lines excluded, handed verbatim and unedited, followed only by the two candidate input paths. The instance is context-free and general-purpose. The three conduct checks are executed exactly as written: per-candidate content checksums over a sorted `find … -type f -print0 | sort -z` listing recorded before and after the judge pass, asserted byte-equal; the judge's own recorded instance id asserted absent from the candidate instance-id set. A conduct check that fails is recorded as failed and disclosed, never re-run until it passes.

**The verdict line.** Exactly one real line of the grammar above, recorded at column 0 inside this note's evidence region and nowhere else in the deliverable — the repository's first legitimate instantiation, because a judge actually ran.

**The gates (issue #307 precondition 3).** The picked candidate's tree goes through a real `shell-team:qa-verifier` round and a real cross-provider `codex-reviewer` round; the reviewer is the Codex CLI and is never substituted. A gate instance's input is the candidate's venue path, the committed oracle's path and the venue's `README.md` `- subject-ac:` lines — never this task's spec, note or board. No gate instance is told which candidate won and none receives the judge briefing or the verdict line. Every gate round is recorded on its own `- gate-round:` line; no separate review file is created for a candidate.

**Round counting, fixed so the figure is commensurable.** As stated in `## Terms and closed vocabularies` above. A censored observation yields a bound, not a point value.

**The comparator, settled in the protocol rather than left to the analysis round.** As stated in `## Terms and closed vocabularies` above. Both candidates are gated, the loser strictly after the judge pass so no gate outcome can reach the judge, and the loser's gate run is labelled **instrumentation**: its gate machine-time is excluded from the arm's own cost accounting, while its **implementation** machine-time is the discard term and is included.

**Three consequences of that comparator, frozen before execution.** **(i)** Resolution granularity is 0.5 rounds: the estimator lands only on 0, ±0.5, ±1.0, …, so a one-round difference (0.5) sits below the modelled 0.739 and a two-round difference (1.0) sits above it — it can never land on the threshold, said in advance to foreclose a post-hoc reading of a near miss. **(ii)** A negative value is a real outcome — the judge picked the candidate needing more rework — and is the most decision-relevant thing one firing can say about judge accuracy. **(iii)** Gating the loser is instrumentation, not tier cost.

**The cost substitution.** This firing's own measured threshold is `(1 × discard_duration_ms + judge_duration_ms) / 1442049`, where `1442049` is `- cost-input: rework-round-cost` read from `docs/loop-engineering/phase-multiplexing.md`'s **committed blob** rather than the working tree, and `discard_duration_ms` is the discarded candidate's own **per-instance `duration_ms`** — never a launch-to-notification wall clock. That basis is not a preference: `docs/loop-engineering/tier2-subject-harness.md`'s own ratified correction measures that pricing the discard term against the baseline's headline `447352 ms` instead of the same-basis comparable `401338 ms` overprices it by ≈46014 ms per discarded candidate. The measured threshold is reported beside the modelled ≈0.739, with the protocol stating in advance that the modelled figure's `judge-pass-proxy` (≈794019 ms) is a QA-round proxy likely far above a real judge pass over two small trees, so a 0.5 observation could clear the measured threshold while missing the modelled one. Both readings are reported below; neither is suppressed.

**Pre-declared legitimate outcomes, each with its own consequence line written before the result is known.** As stated in `## Terms and closed vocabularies` above.

**Invalid-evidence rule.** At most one re-firing, recorded with the round and the reason that invalidated the first. A second invalidation stops the task. (Not exercised this firing — no re-firing is recorded in the evidence region below.)

**Pre-commitment (AI self-discipline — self-imposed by this loop at freeze time, NOT operator-ratified; this report says so accordingly).** Factual trigger: two consecutive review rounds landing an independent Blocker or Major against the same component. Never dropped: the firing chain itself. Droppable 1st: the loser's gate pass, demoting `rounds_avoided` to a one-sided bound. Droppable 2nd: the cap `K` reduced to 1, every observation censored. Defeat of a never-dropped component across two consecutive rounds stops the task and returns findings to issue #307. (Not exercised this firing — see `## Limits` below for the codex-invocation stalls, which were process retries, not independent Blocker/Major findings against the same component in two consecutive rounds.)

**Safety and hygiene, in T-1086's closed shape.** The real checkout is measured clean after each stage of the arm. No candidate path is ever materialised under `docs/loop-engineering/subjects/subject-01/` or left in the untracked set. Teardown is non-destructive. Every path in the evidence region is `$TMPDIR`-relative or a `<placeholder>`, and `bash bin/check-pii-shapes.sh` is run against every new record before its first commit.
