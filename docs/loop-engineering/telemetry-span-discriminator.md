# Telemetry span discriminator (T-1072)

`.shell-team/specs/T-1072-telemetry-span-discriminator.md` adds exactly one
new field to the span row, `instance`, appended after `adapter`; settles the
span-only key count as an invariant re-derived at every definition point

a substrate-reading checkpoint somewhere honest to live — as a **span**, not
as a relaxed event row, and as a **child span** over the existing
`parent_span_id` field, respectively. Neither convention adds a schema key.

## Why gate/orchestration cost is a span, not a relaxed event row

Gate and orchestration work this orchestrator performs itself has a
duration but no sub-agent call to attach it to. The event row that already
records the transition (`--event gate`, `--event human`) carries no cost
fields, doubly enforced by the writer's `SPAN_ONLY_FLAGS` rejection loop and
the linter's D2 shape-mixing rule — relaxing that would mean changing two
mechanisms and reopening a grammar T-1011 closed. The cheaper and more
honest repair, which `skills/run/SKILL.md`'s telemetry section now
documents verbatim, is that work with a duration is a **span**:

```
log-run.sh shell-team --run-id <run_id> --seq <seq> --span orchestrator --phase gate \
  --iteration <n> --attempt <a> --status <status> --duration-ms <d> || true
```

emitted **alongside**, never instead of, the paired event row — the event
row keeps recording *that* the transition happened, the span row records
*what it cost*. `--duration-ms` together with `--event` stays exit 2 with
nothing written (measured, not merely asserted, by **AC5** and **AC10**):
this convention never relaxes the event-row grammar.

## Why the rehydration checkpoint needs no schema at all

A substrate-reading checkpoint — a point where the orchestrator re-reads its
own substrate mid-phase — is a **child span** of the span it belongs to,
named `engineer-rehydration`, using the `parent_span_id` field the row has
carried since T-014:

```
log-run.sh shell-team --run-id <run_id> --seq <seq> --span engineer-rehydration --phase <phase> \
  --iteration <n> --attempt <a> --status <status> --parent-span-id <the span it belongs to> || true
```

No key is added for it, no flag is added for it, and no agent prompt block
is edited to emit it (**AC11** measures this directly: neither `bin/log-run.sh`
nor `bin/check-run.sh` contains the token `rehydration` or `checkpoint`
anywhere, and this task's diff carries zero paths under `agents/`) — the
convention is documented where the orchestrator's own emission guidance
lives, and the emission itself is the orchestrator's, not an agent's.
