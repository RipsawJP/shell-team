## The subject and its committed harness

**Domain and shape.** `docs/loop-engineering/subjects/subject-01/` commits five text files — `README.md`, `interface.md`, `manifest.txt`, `acceptance.sh`, `regenerate.sh` — implementing `csvstats`, a per-column CSV summarizer: given a comma-separated file whose first line is a header row, report count/sum/min/max/avg for every column whose values are integers in every usable data row, skip malformed rows by field-count mismatch, and handle a missing file or an empty result set with fixed stderr messages and exit codes. The shape is two library files plus one CLI entrypoint (`lib/csvparse.sh`, `lib/colstats.sh`, `cli/csvstats`), implemented as one whole rather than split across instances — the same shape `docs/loop-engineering/phase-multiplexing.md` line 205's `engineer-phase-cost` (271772 ms) was measured on, which is why this subject reuses that shape rather than inventing a new one: comparability with the one recorded per-implementation figure this repository has is the entire reason, not convenience. The domain itself — CSV column statistics — is deliberately not word-frequency counting: T-1078's own pilot subject, `wordstats`, is a two-library-plus-CLI tool over a *different* domain (tokenizing text and counting word frequencies), and its description is already committed prose in `docs/loop-engineering/phase-multiplexing.md`'s own `pilot3-evidence` region. A subject whose solution shape a candidate could read out of this repository would measure reading, not implementing — the reason `interface.md` and `README.md` are swept for the literal `wordstats` and found clean (**AC10**).

**Reusable, made mechanical.** Regenerable: `regenerate.sh` run twice into two fresh directories produces byte-identical four-file trees (**AC5**). Genuinely unimplemented: `acceptance.sh` run against a freshly regenerated venue exits non-zero, with seven cases and a real summary line (**AC6**) — confirmed against a throwaway, never-committed reference implementation during this round's own self-check, which scored 7/7 and exited 0, proving the subject is satisfiable at all without publishing that implementation anywhere in this repository. Uncontaminated: no candidate-declared path or directory (`lib/csvparse.sh`, `lib/colstats.sh`, `cli/csvstats`, `check/`) is ever committed here (**AC4**, bounded by **AC19**). Self-contained: neither committed script names `.shell-team`, `docs/loop-engineering`, or a `bin/`- or `tests/`-rooted path (**AC9**) — the manifest's own candidate paths (`lib/`, `cli/`, `check/`) were chosen precisely so that constraint and the oracle's own need to name those same paths never collide (**AC3**'s own stated reason).

**Mapping from T-1078's own closed sets, stated so a reader can see what carried over and what changed.** Five of six `- harness-legitimacy:` ids reuse T-1078's own `pilot3-legitimacy` vocabulary by name (`production-unit`, `real-mechanism`, `same-machine-session`, `arm-completion`, `repetition-variance`); the sixth, `oracle-satisfiable`, is new — this baseline's own oracle can fail to be satisfiable in a way T-1078's pilot never had to consider, because T-1078 ran a real partition of an already-known-working subject rather than measuring whether an *unimplemented* subject can be solved at all. T-1078's own `disjoint-partition-fixed-before-launch` id has no counterpart here: this arm runs one whole, unpartitioned candidate, so there is no partition to fix in advance. Five of seven `- harness-safety:` ids are inherited by name (`scratch-clone-venue`, `real-checkout-clean`, `no-real-writes-except-telemetry`, `teardown-non-destructive`, `liveness-watchdog`); T-1078's two worktree-specific ids (`worktree-add-clone-only`, `onto-never-checked-out`) are replaced by a single `no-worktree-add` — this arm uses no `git worktree add` for its venue at all, a throwaway clone only, so there is nothing checked out to compare an `--onto` against — plus a new `candidate-tree-never-committed`, closing a hazard T-1078's pilot never had to guard because its own subject files were never committed in the first place (its own Non-goal froze them to `$TMPDIR`).

## Baseline protocol as executed

**The arm and its unit.** One real engineer-role Agent instance implements the whole committed subject from a regenerated venue's own bytes, launched by the coordinating session — never a shell-process proxy, never this task's own engineer instance. The instance's input is exactly the regenerated venue (the brief, the interface contract, the manifest and the oracle copy the driver placed there) plus the venue path; it is given none of this task's own spec, note, board, or task machinery. Arm id: `subject01-serial-n1`.

**Venue.** Each rep runs in its own freshly-created throwaway `git clone --no-hardlinks` under `$TMPDIR`, checked out detached at one pinned commit that already carries the harness, with the venue directory created outside the clone's own tracked tree (or under an ignored path) so the instance's writes never appear as a clone-tracked change. `git worktree add` is used for no venue — a worktree registers under `.git/worktrees` in the real checkout, and this task takes no version of that as a cleanup step. Teardown removes only the throwaway clone directory; no `git worktree remove`, no `rm`, and no git verb of any kind is ever aimed at the real checkout. The real checkout is measured clean (`git status --short` and `git ls-files --others --exclude-standard` both empty) after every rep.

- baseline-basis: machine-time — the compute/token cost this arm's one real implementation attempt consumes, per `docs/loop-engineering/phase-multiplexing.md` line 226; this arm is a single serial instance, so its machine-time and calendar-clock figures coincide by the same reasoning that line already states for `rework-round-cost` and `judge-pass-proxy` — stated explicitly here rather than left for a reader to infer which basis a bare millisecond figure sits on.
- wall-clock-definition: quoted verbatim from `docs/loop-engineering/phase-multiplexing.md` line 257 — t0 is the orchestrator's own launch call for that arm; the arm ends at the last completion notification plus that arm's own landing spans, and orchestrator-idle gaps between a notification and the next command are excluded. This arm performs no landing (a Tier-2 baseline produces one candidate and discards nothing to compose), so the landing term is recorded as absent with its own reason rather than silently folded into the figure: the resulting wall clock sits below a T-1078-style landing-inclusive arm by that arm's own measured landing span — sub-second, 458–490 ms, `docs/loop-engineering/phase-multiplexing.md`'s own `pilot3-evidence` region.

**Reps and what a rep does not inherit.** Two reps, same host, one continuous session, each in its own fresh clone at the same pinned commit. Sub-agent instances share no context window with one another, which is the property that makes running a second rep of the same subject legitimate at all: rep 2's instance carries nothing that could have leaked from rep 1's own attempt. Execution order and cache warmth are recorded alongside the raw evidence. No inferential statistics: spread is disclosed descriptively or not at all — no significance test, confidence interval, variance model or regression anywhere in this note.

**Outcome per rep.** Each rep records its own wall clock, the committed oracle's exit status run against that rep's own produced tree (invoked from the oracle's committed path, never from the venue's own copy — the property that makes a venue-local edit to the oracle or the interface contract unable to change a score, Input space class 5), and that run's passed/failed case counts. A rep whose oracle fails is a recorded rep, not a discarded one. At least one rep with the oracle exiting 0 is what evidences the subject is completable at all; if no rep reaches it, `- harness-legitimacy: oracle-satisfiable` reads `not-met`, `- harness-ready:` reads `not-met`, and this note ships with that finding rather than with a re-cut subject.

**Telemetry and durability.** The runs directory is gitignored, so span rows survive only as verbatim quotes inside this note's own raw-evidence section: one orchestrator-written span row per rep (`--instance <role-qualified-id> --seq auto`), under one run id, with the runs directory resolved by default (`TEAM_RUNS_DIR` unset).

**Satisfiability, evidenced once and never re-derivable from committed bytes — a deliberate trade.** Proving the oracle can be satisfied at all would need a reference implementation, and committing one would defeat the harness's own uncontaminated property (Goal, "reusable" part 3). So satisfiability rests on the arm's own recorded rep, disclosed here rather than engineered around; each later arm re-establishes it as a side effect of running.

**The two figures this baseline is read beside**, quoted with a command that reads a committed blob rather than the working tree, and verified against that file's own committed blob at HEAD by durable anchor rather than by line number:

- reference-figure: engineer-phase-cost — 271772 ms — docs/loop-engineering/phase-multiplexing.md — git show HEAD:docs/loop-engineering/phase-multiplexing.md | grep -F 'cost-input: engineer-phase-cost'
- reference-figure: tier2-breakeven-threshold — ≈0.739 rounds at N=2 (own reproduction 0.7390810688673338) — docs/loop-engineering/phase-multiplexing.md — git show HEAD:docs/loop-engineering/phase-multiplexing.md | grep -F '0.7390810688673338'

**Verdict framework, applied in the following round.** Exactly one `- harness-ready:` line reads `met` when all six `- harness-legitimacy:` conditions read `met`, and `not-met` otherwise — both directions, no third value, no hedge. Neither that line nor any `- harness-legitimacy:` or `- harness-safety:` line is instantiated in this round: none of them can be truthfully written before the arm actually runs, and a specimen verdict here would be indistinguishable from a fabricated one.

## Reuse procedure and what regenerates from committed bytes

The steps below survive as a recorded artifact independent of whether `regenerate.sh` itself ships — the pre-commitment's second droppable component falls back on exactly this list (`.shell-team/specs/T-1086-subject-harness.md`).

- reuse-step: 2 — launch one real engineer-role Agent instance with the venue path as its only input, per the baseline protocol's own unit definition above — instructed to implement `manifest.txt`'s three `candidate-path:` files against `interface.md`'s frozen contract, optionally adding its own tests under the single declared `check/` directory.

- reuse-step: 4 — record the rep's own wall clock (per the wall-clock definition above), the oracle's exit status, and its passed/failed counts as one `- baseline-outcome:` line in `## Baseline evidence` above — repeat steps 1–3 in a second fresh venue for the second rep.

## Limits and what is not computable

**Fixed regardless of the arm's own result.** No inferential statistic — no significance test, confidence interval, variance model or regression — is computed over the two reps or over any series this note cites; spread, where disclosed, is descriptive only. Nothing here generalizes beyond this host, this harness version and this one subject: the launched model and `subagent_type` are recorded verbatim as declared labels in the raw evidence once it lands, and are not upgraded into evidence of a resolved type — whether the figure extends to another model, harness version, machine or subject is unobserved. No dollar figure, vendor price model or token multiplier appears anywhere in this note; every figure is either read from a named git-tracked source with the command that reads it, or measured live on the operator host and labelled machine-local. The oracle's own CSV grammar is deliberately the simple comma-split case — no quoted-field escaping is required of a candidate, and no fixture exercises one — a design boundary of the subject itself, stated explicitly in `README.md` rather than left to be inferred, not a limit of this measurement.
